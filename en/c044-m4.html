Level 2 · C044·M4

Training, inference and context

Your goalDistinguish a change to the parameters from information supplied for a call, then check that there is room for an answer in the context.

✿01 See the idea

You are planning a visit to a greenhouse. An assistant must answer the question: “What time does it close on Saturday?” You attach the current information sheet: “Saturday closing time: 17 h.” An old brochure gave 18 h. The entire scene, opening hours and token counts on this page are fictional.

Imagine a reader who knows the language and receives this sheet on their desk. Their way of reading comes from earlier learning; the relevant closing time comes from the document in front of them. This image helps separate the roles. A model, however, is not a person: its parameters are numerical settings, denoted by θ, that determine how it computes its predictions.

Training adjusts these parameters using examples and an objective. In training for next-token prediction, the prediction is compared with the token actually encountered in the text, then a learning rule uses the difference to adjust the parameters. This is not equivalent to storing every sentence in a library that can be consulted at will. Continuing this adjustment on a targeted corpus is still training.

Inference uses the resulting parameters to produce output from input. On this page, they remain fixed during the call. The context is the sequence of tokens actually supplied to the computation: instructions, documents, retained history and the question, followed by the tokens already produced. An attached sheet can change the answer without changing θ.

The context window limits the space available for this sequence. An earlier discussion saved by the application may remain outside the input sent to the model. Conversely, including a sheet in the input guarantees neither its proper use nor its truth. Here, we are only preparing a call; no model is run and no observed answer is reported.

The rule to remember

Training changes the parameters; inference uses them; context supplies the information visible to this call. Count the space for the output too, and check the content of the answer separately.

✿02 Follow an example

Worked example

Prepare the question about the greenhouse closing time

We choose a fictional model whose shared input–output window holds 128 tokens. The instructions take 12 tokens; the question, 16; the current sheet, 28; the retained history, 20. We reserve at most 40 tokens for the answer. These counts are exercise data, not measured token counts for the sentences printed above.

  1. Establish what can change

    θ denotes the set of numerical parameters of the model, with no physical unit in our description. C is the current context, an ordered sequence of tokens; t is a candidate token for the next position. pθ(t | C) denotes the probability assigned to this candidate, conditional on C, with parameters θ. This probability has no unit and lies between 0 and 1. It is not the probability that the closing time is true.

    pθ(t|C)

    Training can change θ. Attaching the greenhouse sheet changes C. Inference computes the distribution, then produces tokens according to the chosen generation rule. We keep θ fixed, so using the sheet does not, by itself, update the parameters. We do not need to describe a network architecture in detail or calculate a learning rule here.

  2. Define the counts and when they apply

    W is the capacity of the window; I, the total input length; R, the maximum output reserve; M, the spare capacity after reservation. These quantities are integer counts expressed in tokens. We have W = 128 and R = 40. The output limits specific to the service are assumed to be compatible with R.

    We assume that message wrappers and all special elements are already included in the supplied counts. Concatenating these blocks therefore gives the stated lengths. No tool, additional attachment, internal token or automatic truncation adds or removes content. This shared-window model is our assumption for the exercise; the contract of the system actually used should be read before applying it.

  3. Add up everything in the input

    The instructions and question take 12 + 16 = 28 tokens. The sheet and history take 28 + 20 = 48 tokens. We add these groups because all their tokens must be present in the same input.

    I=(12+16)+(28+20)=76 jetons

    The input therefore totals 76 tokens. Counting only the question would leave out the very sheet we need to distinguish the current closing time from the old brochure.

  4. Reserve the output and decide whether the budget fits

    The capacity condition is I + R ≤ W. We reserve the full output allowance because we do not yet know the actual output length. The budget is 76 + 40 = 116 tokens, less than 128 tokens.

    M=W−(I+R)=128−116=12 jetons

    M is positive: the prepared call fits within our budget. The ratio of reserved space is 116/128 = 29/32, or approximately 0.91, with no unit. It describes budgeted occupancy; it measures neither answer quality nor a probability of success.

  5. Track generation without counting the output twice

    Now suppose that 8 tokens have been emitted. This assumption for the calculation is not an observation of an actual call. These tokens are part of the context used to continue: its length becomes 76 + 8 = 84 tokens. The remaining reserve becomes 40 − 8 = 32 tokens.

    (I+g)+(R−g)=I+R

    Here g denotes the number of tokens already emitted, measured in tokens, between 0 and R. The check gives 84 + 32 = 116 tokens: we recover 116. The spare capacity remains 12 tokens. The parameters θ remain fixed even as the context and temporary computational states change.

  6. Check capacity, then the relevant information

    Another way to check the calculation: after reserving R, W − R = 128 − 40 = 88 tokens remain for the input. Our I = 76 fits in this space; the difference 88 − 76 gives 12 tokens again. This subtraction addresses the same problem as the earlier addition.

    The budget can fit while the content is still poor. We must still check that the current sheet, its reference to Saturday and its closing time of 17 h are actually present in C. The answer expected from this sheet gives that closing time, but we do not claim that a model has given it. If the sheet is removed, we can no longer justify that closing time using this document, even if an answer happens to be correct.

    Any history the application may keep elsewhere enters C only if it is selected and sent. And sending the correct sheet does not prove that the model will follow it: capacity, information availability and output accuracy require separate checks.

Explain it in your own words

Hide the numbers. Explain why supplying the current closing time can change an answer without training the model, then reconstruct I + R ≤ W. Finally, describe what changes and what stays the same when one more token is produced.

✿03 Common mistakes

  • “I gave it the new closing time: its parameters have learned it.”

    The sheet changes the context of the call. In our inference with fixed parameters, this can guide the answer without changing θ. Claiming that training has occurred would require a separate operation that actually adjusts parameters; a different answer is not enough to demonstrate this.

    Review what can change

  • “My question fits in the window, so the call fits.”

    Also add the instructions, the sheet, the retained history and the output reserve. The criterion for the exercise is I + R ≤ W. An added block can make the budget impossible even though the question stays the same.

    Try the longer sheet

  • “The conversation is saved, so the model reads all of it again.”

    The saved record and the input actually sent are distinct objects. Check which passages are retained and counted in C. A selection or summary can omit the closing time; keeping within the budget does not guarantee that the relevant information has survived.

Exercise 1 · Warm-up · justify the terms

The sheet changes, the parameters stay fixed

In the same scene, the sheet giving 17 h replaces the brochure giving 18 h in the input. The application also saves the text to disk. No parameter adjustment takes place. Identify what belongs to context, inference and any possible training. Can we conclude that the next call will have the sheet?

Hint 1

Ask these questions separately: do the parameters change? What text is sent? Is output produced?

Hint 2

A record on disk still has to be selected and sent to become part of a future context.

Compare with the solution

Replacing the document changes the context. Subsequently producing an answer with these fixed parameters is inference. The problem contains no training, since the parameters are not adjusted.

Saving the text is an application operation. This does not prove that it will be present in a future call: the input actually constructed will need to be checked. Even if the answer mentions 17 h, this output alone demonstrates no change to θ.

Check your reasoning

  • Assign the sheet to context and the production of an answer to inference.
  • Link training to parameter adjustment.
  • Treat the presence of the sheet in the next call as a fact that still needs checking.

Exercise 2 · Application · explained calculation

The greenhouse sheet gets longer

The sheet now takes 44 tokens. Keep the instructions at 12, the question at 16, the history at 20, the output reserve at 40 and the window at 128, all in tokens. Calculate the new input, the total budget and any excess. Is the budget admissible?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Replace only the length of the sheet in the input sum.

Hint 2

A positive excess is calculated by subtracting capacity from the total budget.

Compare with the solution

Sheet and history: 44 + 20 = 64 tokens. Instructions and question: 28 tokens. The new input is 28 + 64 = 92 tokens.

With the reserved output: 92 + 40 = 132 tokens. The excess is 132 − 128 = 4 tokens. The budget is not admissible under our assumptions, even though the input alone is shorter than the window.

Reverse check: 128 − 92 = 36 tokens remain for the output; this is less than the requested reserve of 40 tokens by exactly 4 tokens. We do not assume that the service will automatically remove the right passage.

Check your reasoning

  • Give 92 tokens of input and 132 tokens for the total budget.
  • Justify rejecting the budget by an excess of 4 tokens.
  • Include the output and do not invent truncation behavior.

Exercise 3 · Transfer · repair under constraints

Keep the sheet and the answer reserve

Start again with the long sheet of 44 tokens. The instructions, question, sheet and output reserve must stay intact. Only the history can be shortened; assume that it contains enough redundant text to remove without losing necessary information. What is the maximum length it can retain? Recalculate the spare capacity. What must you still check in the future answer?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The excess in the previous exercise indicates the minimum amount that must be removed.

Hint 2

Remove this minimum from the history, then check the complete sum. Keeping one more token must exceed capacity.

Compare with the solution

At least 4 tokens must be removed. The maximum retained history is 20 − 4 = 16 tokens. This repair is possible because of the assumption of redundant text; it cannot be applied blindly to an actual history.

The documents now total 44 + 16 = 60 tokens. The input is 28 + 60 = 88 tokens; the total budget, 88 + 40 = 128 tokens. The spare capacity is 128 − 128 = 0 tokens.

The bound is reached exactly. Keeping 1 additional history token would exceed W by 1 token, so the length found is the maximum. 0 spare capacity remains admissible in the exact model of the exercise; it leaves no room for an element omitted from the count.

The answer still needs to be compared with the sheet: does it refer to Saturday and 17 h? Respecting capacity does not guarantee this fidelity, and no observed success is inferred from our calculation. The actual selection mechanism and the retained content would require their own checks.

Check your reasoning

  • Retain at most 16 history tokens and justify this bound.
  • Recalculate 128 tokens in total and 0 tokens of spare capacity.
  • State the assumption that allows text to be removed without losing the relevant information.
  • Distinguish compliance with the budget from answer accuracy.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What change characterizes training on this page?

An adjustment of the parameters θ using examples and an objective. Supplying a new sheet for inference with fixed parameters changes the context without constituting this adjustment.

Recall 2During our inference, what stays fixed and what changes?

The parameters θ stay fixed. The context grows with the tokens produced, and the temporary computational states change. The next token depends on the current context as well as on the parameters.

Recall 3Reconstruct the capacity condition and define each quantity.

I + R ≤ W: I is the complete input, R the maximum output reserve and W the shared window, all in tokens. The spare capacity is M = W − I − R. This rule depends on the stated counting assumptions.

Recall 4Why do a saved conversation and a context that fits fail to prove that the relevant closing time will be used correctly?

The application must select and then send the relevant passage. Even when sent, it can be used poorly. The input must be checked and the answer compared with the sheet; capacity alone demonstrates neither.

Reconstruct the reasoning

Without looking at the lesson, reconstruct the path from training texts to parameters, then the path from the parameters and the sheet to the answer. Recover I + R ≤ W and explain why tokens already emitted replace part of the remaining reserve. Finish with the difference between a saved sheet, a transmitted sheet and a faithful answer.
