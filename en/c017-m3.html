Parameters

Your goalFind the threshold actually used by an analysis, recalculate its effect and record enough settings to explain a difference in results.

Before you start
c016-m5 : documentation · c007-m5 : execution traces · c017-m1 : Git · c017-m2 : dependencies

✿01 See the idea

A sensor recorded readings of 18, 20, 22 and 24 °C in a room. You want to count those that reach a chosen threshold. With 22 °C, the reading of 22 °C counts; with 23 °C, it no longer counts. The sensor and its readings have stayed the same.

In this analysis, a parameter is a setting supplied to the calculation: here, the threshold. The data are the readings being examined. The result is the count obtained after comparison. The same value can have different roles: 22 °C is a data value when it comes from the sensor, and 22 °C is a parameter when it is chosen as the threshold.

The program can receive this setting from several places. A default value applies when no choice with higher priority is available. A settings file can replace it; a value supplied at launch can in turn replace the value from the file. This last replacement is called an override here. You need to know the priority defined by the program and find what it actually selected.

The entire scene and all its values are fictional. “Select” only means counting a reading in our list of alerts; the threshold is a choice for the exercise and has not been validated for a real room. We are studying the parameters of a deterministic analysis: the same data, the same mechanism and the same effective setting give the same count.

The rule to remember

Record the name, value, unit and source of the parameter actually used, along with the priority rule and how equality is handled.

✿02 Follow an example

Worked example

The sensor settings record

We use exactly the 4 fictional readings 18, 20, 22, 24 °C. The default is 20 °C, the file requests 22 °C and the command supplies no threshold. The rule selects a reading greater than or equal to the threshold. Let us calculate the count, then the proportion of readings selected.

  1. Define the objects before counting

    Let A, B, C and D denote the readings, in degrees Celsius; the letters distinguish their order. The letter x will denote any reading. The symbol s denotes the effective threshold, also in °C. The number n is the total number of readings, here 4 readings. N is the count of those selected. The proportion p is the quotient N/n; it is a ratio of counts, with no unit.

    All the readings are present, numerical and already in the same unit as the threshold. Each occurrence counts once. We do not convert any units or round any readings before the test. The total n is strictly greater than 0, a necessary condition for calculating p. A missing reading or a different unit would require an additional rule, which this calculation does not provide.

    The sign ≥ means “greater than or equal to”. For each reading, we write a marker: 1 if x ≥ s, 0 otherwise. These markers have no unit and will be used for counting. The choice to include equality belongs to the stated mechanism; writing only “threshold” does not specify it.

  2. Resolve competing settings

    Let us apply the stated priority. The command supplied no value, so we move on to the file. It gives 22 °C. The default of 20 °C is replaced. The effective parameter is s = 22 °C, with the file as its source.

    The task is to choose a value, rather than add the values or average them. If the command supplied a threshold, our rule would use that value. An invalid value must be reported under an explicit contract, without claiming that the requested value was applied.

    In a real program, the presence of a file does not show that it was read. You need to find the section that loads the value and then the section that passes it to the calculation. Our record describes a choice resolved by hand here; it does not claim to report an execution.

  3. Compare each reading with the selected threshold

    To make the boundary visible, let us calculate the margin d = x − s for each reading. The letter d denotes a temperature difference, expressed in degrees Celsius. A negative margin excludes the reading; a margin of 0 or more selects it. The sign ⇔ is read “if and only if”: the tests on either side give the same decision.

    Reading A: 18 − 22 = -4 °C, giving marker 0. Reading B: 20 − 22 = -2 °C, giving marker 0. Reading C: 22 − 22 = 0 °C, giving marker 1. Reading D: 24 − 22 = 2 °C, giving marker 1.

    The reading equal to 22 °C remains selected: its margin is 0, which satisfies the test. The count concerns readings, rather than the size of the margins; a larger margin does not give a reading any more votes.

    x≥s⇔d≥0 °C

  4. Add the markers

    The excluded readings together give 0 + 0 = 0. The selected readings give 1 + 1 = 2. We add these markers because each represents the contribution of a reading to the count.

    The total is N = 2 selected readings: those of 22 °C and 24 °C. Adding the temperatures would produce a different quantity and would not answer the question.

    N=0+0+1+1=2

  5. Divide the count by the total number of readings

    To describe the proportion selected among all the readings, let us divide the count by the original total. The denominator remains n = 4: we are describing the same dataset, including the excluded readings.

    The exact fraction is 1/2, or 0.50 with no unit. It describes this fictional list and this rule; it measures neither the accuracy of the sensor nor the quality of the threshold.

    p=Nn=24=12=0.50

  6. Check using the complement

    Let us return to the list and count another way: 18 °C and 20 °C are strictly below the threshold, giving 2 excluded readings. Subtracting this number from the total gives 4 − 2 = 2 selected readings. This approach checks the result without adding the same markers again.

    The groups are disjoint and cover all the readings: 2 selected + 2 excluded = 4 readings. The count is between 0 and 4, and the proportion between 0 and 1. These bounds detect some errors, but they are not enough to prove that the correct threshold was used.

    The boundary test completes this check: with the strict comparison operator >, the reading equal to the threshold would be lost. The same data and the same value of s could then give a different count.

  7. Leave a record of the effective choice

    Our completed record is: parameter “threshold”; value 22 °C; source “file”; command override absent; priority “command, then file, then default”; comparison operator “greater than or equal to”. Expected output for these data: 2 readings out of 4, exact proportion 1/2.

    For a real execution, you would need to keep the references for the code and dependencies used with this record, along with identification of the data analysed. The setting must be recorded at the point where the calculation receives it, after replacements. The text in the file describes an intention; the value received describes the choice applied.

    We stop here at making this choice explicit. Preserving the data and the full reproduction protocol belong to the following units.

Explain it in your own words

✿03 Common mistakes

  • “I kept the code, so I kept the calculation.”

    The threshold can change without any change to the code. Find the data, then the name, unit, source and effective value of the setting. The code version is necessary for this comparison, but it does not replace a record of the parameters.

    Review the resolution of the settings and the final record

  • “The file contains the threshold, so that must be the one used.”

    Check that the file was read and that its value was not replaced at launch. Apply the stated priority, then find the value passed to the calculation. The existence of the file is not enough to establish this path.

    Reread the diagram of the selected setting

  • “Greater than the threshold or equal to the threshold gives the same result.”

    Re-examine the reading exactly equal to 22 °C. Its marker is 1 with ≥ and 0 with >. Record the comparison operator along with the numerical value so that you can repeat the selection.

    Review the margins and the boundary check

Compare with the solution

The data value is the reading of 22 °C. The effective parameter is the threshold of 22 °C, with the file as its source. It replaces the default of 20 °C under our priority rule. Their numerical equality does not merge their roles.

Exercise 2 · Recalculate an isolated change

A value is supplied at launch

Start again with all the readings from the example. The file stays at 22 °C, but the command now supplies 23 °C. Give the effective threshold and its source, the markers, the count and the exact proportion. Compare with the original result: by how much do the count and proportion decrease?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

When present, the command has priority under our rule. Keep all the readings and the same denominator.

Hint 2

Find which reading selected at the start falls below the new threshold.

Compare with the solution

The effective threshold is 23 °C, with the command as its source. The file is not changed, but its value is replaced for this calculation. The markers are 0, 0, 0, 1; only the reading of 24 °C remains selected.

The count is 1 reading and the proportion is 1/4 = 1/4, or 0.25 with no unit. The count decreases by 2 − 1 = 1 reading. The proportion decreases by 1/2 − 1/4 = 1/4, or 0.25 with no unit.

Check: the reading of 22 °C is the only one to change groups. Increasing the threshold under the ≥ rule cannot add any selected readings on this fixed list. This explains the direction of the change; it does not prove that the new threshold is preferable.

Check your reasoning

  • Apply the priority of the command without changing the file or the data.
  • Keep the original total in the denominator and give an exact fraction.
  • Distinguish a difference in counts from a difference in proportions, without claiming an improvement in quality.

Exercise 3 · Diagnose an incomplete trace

The count does not match the record

For the same data and with ≥, a record states “file: 22 °C; command: absent; reported count: 3 readings”. It does not give the threshold received by the calculation. Is this the expected count? Show what result the default of 20 °C would give, then propose a check that distinguishes the settings. Can we assert that the default was actually used?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Repeat the selection at the file threshold, then at the default threshold. The reading of 20 °C helps distinguish them.

Hint 2

An explanation compatible with the count remains a hypothesis until the effective setting has been found.

Compare with the solution

Applying the file under the stated priority would give 2 selected readings out of 4, with proportion 1/2. The reported count of 3 therefore does not match this record under the assumptions in the question.

At the default of 20 °C, the readings of 20, 22 and 24 °C would be selected: 1 + 2 = 3 readings. The proportion would be 3/4 = 3/4, or 0.75 with no unit. The reported count is compatible with this default, which provides a diagnostic lead.

On paper, the reading of 20 °C distinguishes these settings: it is selected at the default and excluded at the file threshold. In the program concerned, you would need to find the threshold after resolving the sources, its unit and its source, then check that it is passed to the calculation. Complete the trace with this value and the comparison operator.

The count alone does not show that the default was used. Another selection error, different data or an old output could also explain the discrepancy. You need to flag the contradiction and look for the missing piece before attributing a cause.

Check your reasoning

  • Establish the expected count instead of accepting the reported count.
  • Calculate the result for the default and provide a case that distinguishes the settings.
  • Keep the cause as a hypothesis and ask for the value actually passed.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1In the sensor analysis, what distinguishes a parameter, a data value and a result?

The threshold is the chosen setting; the readings are the data examined; the count is calculated by applying the rule to these readings with this threshold.

Recall 2How do we find the effective threshold under our priority rule?

Take the command if it supplies a value, otherwise the file if it supplies one, otherwise the default. Record the selected value and its source. This priority must be checked in the program concerned.

Recall 3Why keep the comparison operator along with the threshold value?

A reading equal to the threshold is selected with ≥ and excluded with >. The numerical value alone therefore does not define the entire selection.

Recall 4Why does keeping a settings file not prove which setting was applied?

It may not have been read, or its value may have been replaced. You need to find how the sources were resolved and the value passed to the calculation for the execution being studied.

Recall 5Does a count compatible with the default threshold prove that this default was used?

No. It is a hypothesis to test using the trace of the effective setting and a case that distinguishes the possibilities. The same count can come from another setting or another error.

Reconstruct the reasoning

Without rereading, reconstruct the path “data → sources of the setting → priority → effective threshold with unit and source → comparison with equality made explicit → checked count”. Then recover the exact proportion and explain what information is missing if only the settings file and the output are kept.
