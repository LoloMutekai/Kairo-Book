Diagnosis

Your goalExplain an incorrect result by reproducing the case, locating the first discrepancy and checking a targeted fix.

Before you start

✿01 See the idea

At a juice counter, a program calculates the price of a glass of juice. For 150 mL at a rate of 3.00 € per litre, it reports 4.50 €. Yet the glass has not changed size. Before changing the program, we need to understand what this price reveals and where the calculation departs from the promised rule.

A test compares a result with an expected result. Diagnosis seeks to explain the disagreement using verifiable facts: the saved input, the expected rule, the steps actually performed and the version being examined. Here the symptom is the excessive price; one possible cause is an incorrect volume conversion. The symptom alone does not yet identify this cause.

Imagine a sequence of steps: read the volume, convert it to litres, multiply by the rate. Compare the values at each step, in order. The first step that no longer meets its contract gives a precise location to examine. It can explain later errors, even if the final operations are performed correctly on a value that is already wrong.

The entire scene, its prices and its traces are fictional. The trace below is a worked example calculated from the given rules; it does not come from a real till. We are studying a function with no hidden state: the same inputs and the same version give the same output. There is no intermediate rounding, discount or surcharge.

The rule to remember

Save the case → establish the expected result independently → compare the steps → test a hypothesis → fix that step → rerun the checks.

✿02 Follow an example

Worked example

Where does the reported 4.50 € come from?

The contract for the juice counter accepts a nonnegative whole number of mL and calculates its price at the fixed rate of 3.00 €/L. We save the case v = 150 mL and the initial version. This version divides the number of millilitres by 100, calls the result “litres”, then multiplies it by the rate. We need to diagnose and then fix this calculation.

  1. Define the quantities and the contract

    v denotes the input volume in mL; V the same volume in L; c the conversion factor in mL/L; p the rate in €/L; C the expected amount in €. 1 L contains 1000 mL: c = 1000 mL/L. The rate is p = 3.00 €/L. The factor c is strictly positive.

    V=vc;C=V×p

    Dividing mL by mL/L gives L; multiplying these L by €/L gives €. Tracking units makes the meaning of each operation clear. It is not enough to check the value of the factor c: an incorrect factor with the correct unit can still produce an incorrect amount.

    For this diagnosis, the inputs and rules stay fixed. The fractions are exact; the decimal comma is used for readability. The chosen values give amounts that are exact to the cent, with no rounding rules to choose between. Negative volumes are outside the contract; we do not treat them as valid sales.

  2. Build an expected result without reusing the suspect conversion

    1 L of juice costs 3.00 € and contains 1000 mL. Spreading this price over those millilitres gives 3/1000 €/mL, or 0.003 €/mL. This approach starts from the rate on the sign rather than the function being checked.

    C=pc×v=31000×150=0.45 €

    The reference amount is 9/20 €, or 0.45 €. We have a rule and an input that are enough to reconstruct it on paper. Copying the output of the initial version as the expected result would have made the test unable to detect its error.

  3. Reconstruct the trace of the initial version

    Let d be the divisor actually used, here d = 100 mL/L. The “initial” subscripts in the formulas name the results of this version. Its saved input is v = 150 mL; its saved rate is p = 3.00 €/L.

    Vinitial=vd=150100=1.500 L

    Then C initial = 1.500 L × 3.00 €/L = 4.50 €. We reproduce the reported symptom exactly. This reproduction checks the fictional example; it does not claim that till software was run.

    The final discrepancy, calculated as actual minus expected, is 4.50 − 0.45 = 4.05 €. The actual/expected ratio is 10, with no unit. This ratio quantifies the error in this case; by itself, it does not locate it.

  4. Find the first disagreement and test the hypothesis

    Reading the input gives 150 mL in both columns, as expected. At conversion, the expected result is 150/1000 = 0.150 L, while the trace gives 1.500 L. The discrepancy therefore exists before multiplication by the rate.

    The hypothesis is precise: this version uses the wrong divisor in the conversion. The given rule confirms d = 100, while the contract requires c = 1000. The multiplication 1.500 × 3.00 is exact; it carries the incorrect volume into the amount.

    A usable finding would be: “Initial version, input 150 mL, rate 3.00 €/L; at conversion, expected 0.150 L, actual 1.500 L; inspection shows a divisor of 100 instead of 1000.” It separates the observations from their explanation and allows someone else to repeat the case.

  5. Fix the conversion, then repeat the saved case

    The fixed version changes only the conversion divisor to c = 1000. The input volume and rate stay the same. This targets the hypothesis being examined; we do not obscure its effect by changing the price at the same time.

    V=1501000=0.150 L;C=0.150×3.00=0.45 €

    The previously failing case now matches the reference of 0.45 €. Turning it into a regression test means saving its input and expected result to check later versions: we want to detect the return of this error. The expected result remains determined by the contract, even after the fix.

  6. Check by another route and with the 0 volume case

    Since the rate here is strictly positive, we can work back from the amount to the volume. 0.45 € ÷ 3.00 €/L = 0.150 L; then 0.150 L × 1000 mL/L = 150 mL. We recover the saved input. This inverse check complements the price per millilitre approach.

    For v = 0 mL, the fixed version gives V = 0 L and C = 0.00 €. The initial version also gave 0.00 €, because 0/100 = 0. This edge case is required by the contract, but it does not distinguish these versions: passing it would not have revealed the wrong divisor.

    The fix is supported by the saved case and the 0 volume case. The application exercise adds another positive volume. Passing cases do not prove every behaviour of the program; other errors could exist elsewhere. Our conclusion remains tied to the rules and values actually examined.

Explain it in your own words

Hide the calculations and recount the investigation: which fact was the symptom, which step diverged first, and which piece of evidence confirmed the wrong divisor? Then explain why the 0 volume test could have stayed green despite the error.

✿03 Common mistakes

  • “The price is wrong, so I need to change the final multiplication.”

    Go through the steps in order. The volume in litres already diverges before multiplication. Fix the identified divisor, then keep the rate unchanged to check the effect of that single change.

    Review how to locate the first disagreement

  • “The program raises no exception, so the calculation must be correct.”

    A permitted division can use the wrong number. Here, the initial version finishes and returns 4.50 €; the contract and reference require 0.45 €. Compare the result with the rule, even when execution ends normally.

    Review the difference between a symptom and a diagnosis

  • “The 0 volume case passes; I can say everything is fixed.”

    The 0 volume case already gave the correct output with the wrong divisor. Rerun the positive case that failed, add another volume and save their independently established expected results. Describe the cases checked without extending their verdict to all inputs.

    Try the check that distinguishes the versions

Choose a case that distinguishes the versions

The juice counter now serves 250 mL at the same rate of 3.00 €/L. Calculate the volume and amount for each version. What does this comparison prove beyond the case v = 0 mL? Write down the input and expected result to save for testing the fixed version.

Hint 1

The initial version divides by 100; the fixed version divides by 1000. Then multiply each volume in litres by the same rate.

Hint 2

A useful test for this error must fail with the old divisor and pass with the one required by the contract.

Compare with the solution

Fixed version: 250/1000 = 1/4 L, or 0.250 L. Its amount is 1/4 × 3 = 3/4 €, or 0.75 €. Initial version: 250/100 = 2.500 L, then 2.500 × 3.00 = 7.50 €.

The case to save is therefore: input 250 mL, rate 3.00 €/L, expected amount 0.75 €. We can also check the expected intermediate step of 0.250 L. This test does distinguish the versions for this positive volume; the 0 volume case passed in both. It complements the test in the example without proving correctness for every case.

Exercise 3 · Investigation and reasoning

The same price, different possible causes

You receive only the result of 4.50 € for 150 mL. The intended rate is still 3.00 €/L, but the rate actually used has not yet been inspected. One possibility is the wrong divisor from the example. Another is a correct conversion followed by an incorrect rate. What rate would give the same result with the correctly converted volume? Which intermediate value and which rule must be examined to distinguish these possibilities?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

If the conversion is correct, the volume is 0.150 L. Divide the reported amount by this volume to find the rate that would explain it.

Hint 2

The same final output can correspond to different intermediate volumes. Predict what each possibility would give after conversion.

Compare with the solution

With the correct volume, the rate that would explain this result is 4.50 € ÷ 0.150 L = 30.00 €/L. We check that 0.150 L × 30.00 €/L = 4.50 €. The final output is therefore consistent with these two different explanations.

The wrong divisor hypothesis predicts 1.500 L after conversion, then a rate of 3.00 €/L. The other hypothesis predicts 0.150 L, then a rate of 30.00 €/L. Record the volume immediately after conversion, inspect the division used, then check the rate passed to the multiplication, keeping the same input and version.

These observations distinguish the proposed possibilities; they do not list every imaginable fault. If the trace matches neither, reconsider the hypotheses. Without this additional evidence, claiming certainty about the wrong divisor would go beyond the available proof.

Check your reasoning

  • Calculate and check the alternative rate of 30.00 €/L.
  • Predict 1.500 L versus 0.150 L at the intermediate step.
  • Request a targeted trace and inspection before concluding what the cause is.
  • Limit the conclusion to the possibilities actually examined.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is the difference between a symptom and a cause in the juice calculation?

The symptom is the amount that contradicts the expected result. The wrong divisor is an established cause in the version examined, based on the first discrepancy in the trace and inspection of the rule used.

Recall 2What should be saved so that another person can repeat the diagnosis?

The input and its units, the rate, the version, the contract, the independently calculated expected result, the actual result and the relevant steps. It must be possible to repeat the same comparison under the same conditions.

Recall 3Why compare the steps before changing the final calculation?

A correct final operation can receive a value that is already wrong. The first disagreement with the contract indicates the step to examine; the rule actually used then allows the hypothesis to be confirmed or refuted.

Recall 4Why is the 0 volume case not enough to check the divisor fix?

Both divisors gave a 0 amount. A positive volume can distinguish the versions; its input and expected result must be saved to detect the return of the error.

Recall 5Can the same incorrect amount identify its cause with certainty?

No: an incorrect volume and an incorrect rate can give the same amount. An intermediate observation is needed to distinguish the possibilities, followed by a check of the rule used. The conclusion remains limited to the evidence examined.
