Level 2 · C141·M5

Halting problem

Your goalExplain why no program can always give a correct answer to the question “Does this program halt on this input?”, by following a single concrete program and then a diagonal argument.

Before you start

✿01 See the idea

Imagine a small program that we will call Syr. As long as its number n is not equal to 1, it divides it by 2 if it is even, and otherwise replaces it with 3 times itself plus 1. Run on 6, it finishes quickly. Run on 27, it already needs 111 steps. Can we know in advance, without running it all the way through, whether it will finish?

Waiting is not enough to reach a conclusion. If the program finishes, waiting eventually shows this. If it does not finish, waiting never shows anything: at any moment, it is still possible that it will halt at the next step. We therefore need to distinguish two statements that are often confused. “It halted after this many steps” can be observed. “It will never halt” requires a proof.

This lesson does not seek to find out whether Syr halts on every input. We assume no answer, and nothing that follows depends on it. The question is more general: is there a program H that, for every program p and every input x, answers “Does p halt on x?” in a finite number of steps and without making a mistake? We call a program a decider if it always halts with a yes or no answer, never “I do not know”. This is the meaning of decidability used here, from the previous unit.

The result to understand is that no such H exists. The idea fits into one sentence: if H existed, we could write a program D that disobeys it precisely when it is asked about D itself. The reasoning is called diagonal because it asks about each program on its own description.

The budgets of 100 and 1000 steps are made-up values chosen for the example. The program Syr and its step counts, however, are exact calculations that can be repeated by hand.

The rule to remember

A simulator with a step budget can prove halting, never looping. No decider answers for all programs: otherwise the diagonal program D would lead to a contradiction.

✿02 Follow an example

Worked example

Syr with a budget, then the diagonal program

Syr takes a strictly positive integer n, with no unit. As long as n differs from 1: if n is even, it becomes n divided by 2; otherwise it becomes 3n + 1. One step is one application of this rule. We run it on 6, then on 27 with a made-up budget of 100 steps. Next, we assume a decider H and construct the program D that contradicts it.

  1. Define the objects and assumptions

    Here, a program is a finite text of rules that a machine executes step by step. When run on an input, it either halts and produces an output or continues indefinitely. For Syr, “halting” means reaching the value 1 after a finite number of steps. Duration is counted in steps, rather than seconds.

    An integer is even when it is congruent to 0 modulo 2: this is the rule that determines which branch Syr takes.

    n↦n2 si n≡0 modulo 2, sinon 3n+1

    An assumption about the model of computation, accepted without proof: the text of a program can serve as input to another program after a fixed encoding as an integer, and a program can simulate another program step by step. The final argument uses nothing more.

  2. Trace Syr on six

    6 is even: 6 divided by 2 gives 3. 3 is odd: 3 × 3 = 9, then 9 + 1 = 10. 10 is even, giving 5. 5 is odd: 3 × 5 = 15, then 15 + 1 = 16. Next, 16, 8, 4 and 2 are even: divide by 2 each time until reaching 1. Each arrow below is one step.

    6→3→10→5→16→8→4→2→1

    We count 6 divisions by 2 and 2 applications of 3n + 1, giving 8 steps. Check: counting the arrows in the diagram again gives 8. Syr therefore halts on 6, and this fact is established by execution.

  3. Simulate with a budget: prove halting, never looping

    A simulator with a step budget runs Syr for at most B steps, where B is a nonnegative integer expressed in steps. If it reaches 1 before exhausting B, it answers “halts”: this is a proof, since we have seen the end. Otherwise it answers “unknown”: it has observed nothing beyond the absence of an end so far.

    On 6 with B = 100, halting is observed after 8 steps, with 92 steps to spare. On 27 with B = 100, Syr has not finished, because it needs 111 steps.

    111−100=11 étapes manquantes

    The output “unknown” was therefore cautious, and “loops” would have been false. With B = 111, the simulator answers “halts”. Nothing in the rule gave 111 in advance: we obtained it by execution. This simulator is a true decider for a more modest question, “Does Syr halt within at most B steps?”, since it performs at most B steps.

  4. Assume a decider H and construct D

    Assume a program H such that, for every program p and every input x, H(p, x) always halts and returns 1 if p halts on x, 0 otherwise. It has neither a budget nor an “unknown” output: it always answers, and always correctly.

    H(p,x)=1 si p s’arrête sur x, 0 sinon

    Using this H, let us write D. It receives a program p and computes h = H(p, p), meaning H’s answer when p is given its own description. If h is 1, D enters an endless loop. If h is 0, D halts immediately. D is an ordinary program, made from H and a few lines: it does the opposite of what H predicts for the pair (p, p).

  5. Run D on its own description

    Set h = H(D, D) and let b be the value 1 if D(D) halts, 0 if it loops. D halts exactly when h is 0, so b = 1 − h. A correct H requires h = b.

    h=1−h⇒2h=1⇒h=12

    But 0.5 is neither 0 nor 1. Check the division: 2 × 0.5 = 1. Check by trying both possible answers: if h = 0, then b = 1 − 0 = 1, which differs from h; if h = 1, then b = 1 − 1 = 0, which differs from h. Neither answer from H on (D, D) is correct. The initial assumption is therefore false: no such H exists.

  6. Identify what has and has not been established

    Established: no program always answers the halting question correctly in finite time for all pairs (p, x). The argument uses neither the speed nor the memory of H, only the fact that it always answers. It therefore also rules out a faster H.

    Not established here: that Syr halts on every input. We have observed the cases 6 and 27 by execution, nothing more. The result does not prevent us from proving that a particular program halts, or from deciding the question bounded by a budget. It rules out a single method that works for all programs. The unit on O, Omega and Theta compares the cost of algorithms that exist; here, it is their very existence that is missing.

Explain it in your own words

Explain in your own words why the answer “unknown” from a simulator with a step budget does not mean “loops”, then identify where, in the construction of D, reversing H’s answer is essential.

✿03 Common mistakes

  • “If the program has been running for a very long time, it must be looping.”

    An unfinished execution measures only elapsed time. Syr on 27 had not finished at 100 steps, yet it halts at 111. Until there is a proof of looping, the correct answer is “unknown”.

    Review the simulator with a step budget

  • “Undecidable means that we can never know whether a program halts.”

    The result concerns a single decider that is supposed to answer for all pairs. For Syr on 6, execution gave the answer in 8 steps. Many particular programs can be proved to terminate; it is the uniform method that does not exist.

    Reread what the lesson establishes

  • “A faster computer or more memory would eventually decide halting.”

    The proof involves no cost: it assumes only that H always answers. A computation that is too costly exists but takes a long time; an impossible computation does not exist, even with unlimited time. To refute the rule “after 1000 steps, answer loops”, a counter that halts at step 1001 is enough.

    Return to the counter exercise

Exercise 1 · Guided application

Syr run on three

Syr is run on 3. How many steps does it take, without redoing the whole calculation from the beginning? A simulator is then given a made-up budget of 5 steps: what does it answer, and how many more steps does it need?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

In the trace from 6, where does 3 appear?

Hint 2

The sequence from 3 is the end of the trace from 6, with its first step removed.

Hint 3

Next, compare the number of steps with the budget, then calculate the difference.

Compare with the solution

The first step from 6 leads to 3, that is, 3. From 3, there are therefore 8 − 1 = 7 steps left: 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1.

With a budget of 5 steps, the simulator stops before reaching 1: it answers “unknown”, and needs 7 − 5 = 2 more steps. A budget of 7 steps would have been enough to conclude that it halts.

Check your reasoning

  • Recognize that the sequence from 3 completes the trace from 6.
  • Find 7 steps.
  • Answer “unknown” rather than “loops”, with 2 more steps needed.

Exercise 2 · Analysis

Remove the reversal from D

In the construction of D, replace reversal with copying: the program D′ halts if H(p, p) is 1 and loops if it is 0. When run on its own description, does D′ lead to a contradiction? Among the 2 possible answers from H, count those that are consistent with D′, then do the same count for D.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

For D′, the behavior b equals h; for D, it equals 1 − h.

Hint 2

Write the consistency equation h = b in each case, then test h = 0 and h = 1.

Compare with the solution

For D′, consistency is written h = h: it is true for h = 0 as well as for h = 1, giving 2 consistent answers and no contradiction. For D, it is written h = 1 − h, which gives h = 0.5: 0 consistent answers among 0 and 1.

The contradiction therefore comes from reversal, rather than from simply giving H the description of D. D′ proves nothing about either the existence or the nonexistence of H.

Check your reasoning

  • Write both consistency equations.
  • Find 2 consistent answers for D′ and 0 for D.
  • Attribute the contradiction to reversal.

Exercise 3 · Transfer

Refute a rule based on a budget

A colleague proposes: “Let us simulate 1000 steps, a made-up value; if the program has not finished, let us answer that it loops.” Construct a program that refutes this rule. Then explain why a larger budget does not fix it, and why this does not contradict the possibility of deciding a bounded question.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Think of a program that counts from 0 up to a fixed number, then halts.

Hint 2

Compare the counter’s number of steps with the budget.

Hint 3

For a fixed budget, is there always a counter that takes longer?

Compare with the solution

The counter C increases a variable from 0 to 1001, with one step per increment, then halts. It needs 1000 + 1 = 1001 steps: the colleague’s rule declares “loops” even though it halts.

If the budget grows, choose a counter that takes longer: no fixed bound decides halting. The bounded question “Does it halt within at most B steps?” remains decidable, because the simulation itself stops after at most B steps. The flaw in the rule is turning “not finished” into “never finishes”.

Check your reasoning

  • Construct a program that halts just after the budget.
  • Calculate 1001 steps against a budget of 1000.
  • Distinguish an impossible task, with no algorithm, from a costly one, with an algorithm that takes a long time.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is required of a program H that decides halting?

For every program p and every input x, H always halts and answers correctly whether p halts on x. No “unknown” answer is allowed.

Recall 2What does “budget exhausted” mean in a simulator with a step budget?

Only “unknown”: the program may halt later, as Syr does on 27 after 111 steps. Only observed halting provides a proof.

Recall 3Why does D reverse H’s answer on (p, p)?

So that D(D) does the opposite of what H predicts. The consistency equation h = 1 − h has no solution among 0 and 1. Without reversal, there is no contradiction.

Recall 4What is the difference between an impossible computation and one that is too costly?

Too costly: an algorithm exists but requires many steps. Impossible: no algorithm always answers correctly, regardless of time. Deciding halting is impossible.

Recall 5Does the result prevent us from proving that Syr halts on 6?

No: execution reaches 1 in 8 steps. The result only rules out a uniform method that works for all program–input pairs.

Reconstruct the reasoning

Define program, input, halting, step and decider; simulate with a budget and interpret “unknown” as unknown; assume H, then build D that reverses H’s answer on (p, p); run D on itself, write that h must equal one minus h, observe that neither yes nor no works; conclude that H does not exist, without drawing any conclusion about Syr or about the speed of a computer.
