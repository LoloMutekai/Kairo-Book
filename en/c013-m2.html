Level 1 · C013·M2

Lists and tuples

Your goalRead a playlist by index, track an addition, and choose between a list that can be modified and a tuple with fixed slots.

Before you start
c008-m5 : manual traces · c012-m5 : counterexamples · c013-m1 : functions

✿01 See the idea

You are preparing a short playlist: intro, theme, then intro again. The repeat is intentional. If you keep only the distinct titles, the listening sequence loses its return to the intro. You therefore need to preserve every position, even when its content resembles the content at another position.

A sequence is a collection whose elements have an order. Lists and tuples are Python sequences: both preserve order and repetitions. A list lets you add an element or replace the content of a slot. A tuple keeps the same slots after it is created.

Imagine numbered cards rather than a bag of titles. Reading a card by its number does not remove it. The number Python uses is called the index: it starts at 0, whereas we usually number the first position 1.

The playlist and its counts are fictional, chosen for this exercise. We work only with titles as text, without music files or audio playback. Python command names will be defined when they are used.

The rule to remember

Count the positions, read their indices, and distinguish the modified collection from the result returned by a command.

✿02 Follow an example

Worked example

Read the theme, then add the ending

We name the list ["intro", "thème", "intro"] morceaux and the tuple ("intro", "thème", "intro") ordre. These are the starting states. The text labels "thème" and "fin" mean theme and ending. Read the theme without removing a title, then add "fin" to morceaux and check the counts.

  1. Read the notation before calculating

    In morceaux = ["intro", "thème", "intro"], the = sign associates the name morceaux with the list. Square brackets enclose this list; commas separate its elements; quotation marks enclose each text title. In ordre = ("intro", "thème", "intro"), the elements separated by commas, here inside parentheses, form a tuple.

    len is the function that returns the length: len(morceaux) counts the elements in the list. We use n for this length, r for the usual position number, and i for the Python index. n is a count of elements; r and i are integer position markers, without a physical unit. Here, n = 3 elements. No other code changes the collections during the calculation.

  2. Count the positions, including repeats

    Every position contains a title: 1 + 1 + 1 = 3 elements. Thus len(morceaux) = 3, and len(ordre) has the same value. The only distinct titles are intro and theme: 2 titles. The difference 3 − 2 = 1 counts the extra repeat here, rather than a position to remove.

    Concrete check: when you read intro, theme, intro in order, you say intro again at the end. A collection limited to the distinct titles no longer describes this listening sequence.

  3. Convert the position number to an index and read

    We use only nonnegative indices. For a nonempty sequence, they range from 0 to n − 1 inclusive. The last position in the initial sequence therefore has index 3 − 1 = 2. The index n itself is outside the sequence: requesting it causes an indexing error.

    i=r−1

    The theme has position number r = 2. We must subtract 1, since the first index is 0: i = 2 − 1 = 1. morceaux[1] therefore returns "thème". Here, square brackets after a name request an element at an index; they do not create a list.

    Check: the sequence stays ["intro", "thème", "intro"] and its length is still 3. ordre[1] also returns "thème". Reading an element does not remove it from either collection.

  4. Add and distinguish the effect from the return value

    morceaux.append("fin") means “add this title to the end of this list”. The dot attaches the append command to morceaux; the parentheses contain the title to add. append is a method, meaning an operation called on the object concerned.

    After this call, morceaux is ["intro", "thème", "intro", "fin"]. The length becomes 3 + 1 = 4 elements. The new last index is 4 − 1 = 3; morceaux[3] returns "fin". The previous last index still refers to the intro.

    The call returns None: here, this Python value means “no useful result returned”, rather than a new playlist. In resultat = morceaux.append("fin"), using the starting states, resultat is therefore None, while morceaux does contain 4 elements. We write this call just once: this notation describes the same addition, rather than an extra addition.

    Independent check: list intro, theme, intro, ending; you find 4 positions and 3 distinct titles. The initial positions have kept their order.

  5. Define what the tuple fixes

    ordre stays ("intro", "thème", "intro"): we have added nothing to it. A tuple has no append method; ordre.append("fin") fails. It also prevents replacing a slot: ordre[0] = "fin" fails, whereas this assignment is allowed on a list. Indexing and len remain available in both cases.

    Choose a list for a playlist that still needs editing. A tuple is suitable for representing the sequence of titles fixed at this stage. It does not automatically freeze every object you might put in it: “mutable” means “modifiable”, and a mutable object inside a tuple could still change. We will study this case of shared objects in C013·M4; here, each element is simply a title stored as text.

✿03 Common mistakes

  • “The index of the first element is its usual position number.”

    Write the position numbers above the cards and the indices below them. Subtract 1 from the position number: the first card has index 0. The last index is the length minus 1, under our nonnegative convention.

    Review the position numbers and indices in the diagram

  • “Repetitions disappear as soon as I create a collection.”

    Read every slot: intro appears again. Lists and tuples preserve this repetition. Distinguish 3 elements from 2 distinct titles; confusing them changes the requested listening sequence.

    Revisit the count of positions

  • “append gives me back the new list.”

    Separate the questions: which collection changed, and which value did the call return? The list received the ending title; the return value is None. Storing this return value under the playlist name would prevent that name from referring to the list.

    Reread the effect and return value of the addition

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What do we lose if we reduce the playlist to the distinct titles?

We lose at least the repeat of the intro. Lists and tuples preserve every position in order, even when the same title appears again.

Recall 2How do we convert the usual position number to the Python index under our convention?

Subtract 1 from the position number. The first index is 0; for a nonempty sequence of length n, the last nonnegative index is n − 1. Reading does not remove the element.

Recall 3What does len count in the initial playlist?

len counts 3 elements, counting each position occupied by the intro. The 2 distinct titles are a different count.

Recall 4What effect and return value does morceaux.append("fin") produce?

The call adds the ending title to the end of the list morceaux and returns None. The return value is not the modified list. Repeating a title does not prevent the addition.

Recall 5What does a tuple allow, and what does it fix?

You can read its elements and count them to find its length; you cannot reassign its slots or add an element to it with append. This does not guarantee that every object it might contain is itself immutable.
