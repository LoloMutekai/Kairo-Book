Level 2 · C071·M5

Cycles, double counting and validation

Your goalIdentify reused information, calculate the probability of an arrival without counting the same event twice, and distinguish checking the calculation, validating the model and proving a cause.

Before you start

✿01 See the idea

An alert starts at station A in a fictional workshop. It must cross the link A → B, then can reach display T through C or D. Receiving the alert along these different paths does not create two independent alerts: both arrivals depend on the same initial transmission to B.

A link T → B also sends the alert back. If B has already received this alert, its return is not a new discovery. A loop in the drawing is a cycle when its arrows can be followed back to the starting point. Here, B → C → T → B and B → D → T → B are cycles.

The probabilities on this page are fictional. They describe transmissions in a chosen model, without measuring the reliability of a real workshop. We are looking for the probability that T eventually receives this alert, rather than the number of routes we can draw.

Two precautions solve two distinct problems: remembering recipients prevents reactivation; retaining the shared origin of the paths prevents an incorrect assumption of independence. Remembering visits is therefore not enough to make a probability calculation correct.

The rule to remember

Before adding or combining paths, name the event you are looking for, identify their shared links and state what a return can actually trigger.

✿02 Follow an example

Worked example

Does the display eventually receive the alert?

The graph has 5 stations and 6 directed links. A is the only station initially active. The 3 links X, Y and Z each succeed with p = 0.5, independently of one another. The other transmissions are certain. All probabilities are dimensionless.

  1. Define what a transmission means

    X denotes the event “A → B succeeds”, Y “B → C succeeds”, and Z “B → D succeeds”. An event is a set of possible outcomes; P(E) is the probability of an event E. The letters A, B, C, D and T name the stations, with no associated physical quantity.

    Before starting, we can choose whether each link is open or closed. Open means it transmits if its source becomes active. The state remains fixed throughout the cascade. A station becomes active when it receives the alert; it stays active and attempts each outgoing link only on its first activation. Failed attempts are never repeated. The process stops when no new station becomes active.

    These rules define our model. A mechanism that retries on every return would use a different model and require a different calculation.

  2. Neutralize the cycle while keeping the other paths

    In a realization, mark A at the start, then each station when it first receives the alert. If T becomes active, B must already have been active: every route from A passes through B. The return T → B therefore adds 0 new activations and triggers no new attempts towards C or D.

    Removing only T → B thus preserves the event “T is reached” for every configuration. This does not justify randomly deleting edges from other cycles in another graph. Under our rules, each station is activated at most 1 time: the cascade ends after at most 5 activations, including A.

  3. Write the path events

    U denotes success along the path through C: U = X ∩ Y. V denotes success along the path through D: V = X ∩ Z. The symbol ∩ means “and”, while ∪ means “inclusive or”, so both may occur. T is reached exactly when U ∪ V occurs.

    Multiplication along each path is allowed because its uncertain links are independent: P(U) = P(V) = 1/2 × 1/2 = 1/4. The certain transmissions would multiply this result by 1. But U and V share X: their independence does not follow from the independence of X, Y and Z.

  4. Subtract the case counted twice

    Both paths succeed together when X, Y and Z succeed: U ∩ V = X ∩ Y ∩ Z. Count X only once. Independence of the links gives P(U ∩ V) = 1/2 × 1/2 × 1/2 = 1/8.

    P(U∪V)=P(U)+P(V)−P(U∩V)

    This identity does not require the paths to be independent: the sum counts their intersection 2 times, and the subtraction removes 1 copy. Numerically, 1/4 + 1/4 − 1/8 = 1/2 − 1/8 = 3/8. T is therefore reached with exact probability 3/8 in this model.

  5. Understand why assuming independence gives the wrong combination

    Applying the rule “one minus the product of the failure probabilities” directly to the path probabilities would give:

    1−(1−1/4)×(1−1/4)=7/16

    The complements each equal 3/4, and their product is 9/16. The result exceeds the exact value by 1/16. This is not a rounding error: the assumption is false. Failure of X closes both routes simultaneously; their failures are dependent. Being between 0 and 1 is not enough to validate a calculated probability.

  6. Correct the calculation by conditioning on the shared link

    Given that X succeeds, we still need to know whether Y or Z succeeds. These links remain independent under this conditioning, because X is independent of the pair formed by Y and Z. The symbol | is read as “given”. We can then use the complement rule to combine probabilities at the right point:

    P(T atteint|X)=1−(1−p)×(1−p)=3/4

    Each branch failure has probability 1/2; simultaneous failure has probability 1/4. If X fails, T remains unreachable. We must therefore multiply the conditional probability by the probability of X: 1/2 × 3/4 = 3/8, as when subtracting the intersection.

  7. Check all configurations

    Encode a closed link as 0 and an open link as 1. The triple (X, Y, Z) has 2 × 2 × 2 = 8 configurations. Each has probability 1/8, because the states are independent and equally likely.

    When X is closed, all 4 possible pairs for Y and Z fail to reach T. When X is open, only the pair (0, 0) fails. The successes are therefore (1, 1, 0), (1, 0, 1) and (1, 1, 1): 3 cases out of 8, giving 3/8.

    The last triple activates both paths, but it is still a single successful case. For every triple, adding or removing T → B leaves reception at T unchanged: this also checks how the cycle is handled.

  8. Define what validation establishes

    Checking the algorithm here means recovering the successful configurations and the end of the cascade, including when all links succeed. Changing the processing order of C and D must preserve the stations eventually reached. The cases where X is closed and where everything is open are useful checks.

    Validating the model for a real workshop would then require authorized observations: are failures independent, are attempts really made only once, and do stations retransmit when the alert returns? A reproducible simulation with a fixed seed does not answer these questions.

    Finally, a transmission link explains a possible route under our rule. An arrival at T does not by itself identify the cause of a real failure: observations are needed to distinguish the candidate causes. An exact calculation under assumptions can therefore coexist with a diagnosis that remains undetermined.

✿03 Common mistakes

  • “The loop provides a new chance on every round.”

    Return to the cascade rules: a station that is already active does not repeat its attempts. If you want repeated attempts, state a new model before changing the probabilities.

    Review the rules and how the return is handled

  • “Independent links necessarily give independent paths.”

    Write U = X ∩ Y and V = X ∩ Z. X appears in both events. Calculate their intersection or condition on X, then compare with the calculation that assumed independence.

    Find the shared intersection

  • “The result is reproducible, so the cause is proven.”

    Distinguish replaying a rule, its agreement with all synthetic configurations, and its agreement with observations. Replaying the same calculation verifies neither the workshop assumptions nor a real cause.

Exercise 2 · Calculation · change an assumption

B now receives the alert with certainty

In the same graph, only the link A → B changes: it succeeds with probability 1. Y and Z remain independent, each with probability 1/2. Calculate the probability of reaching T and explain why combining the branches using the complement is now appropriate.

Hint 1

The shared link is no longer random: the branch events are Y and Z.

Hint 2

Calculate the probability that Y and Z fail simultaneously, then its complement.

Compare with the solution

B is reached with certainty. The two branch failures are independent: (1 − 1/2) × (1 − 1/2) = 1/4. Their complement is 3/4. This recovers the conditional probability from the lesson, but here it is also the total probability.

The enumeration check gives 3 successful pairs among the 4 pairs of Y and Z. The return T → B still changes nothing: B was already active.

Check your reasoning

  • Obtain 3/4 and justify multiplying the failure probabilities.
  • Explain why we no longer multiply again by 1/2.
  • Keep the rule of a single attempt despite the change in probability.

Exercise 3 · Transfer · challenge a validation

Branches that fail together

Return to link X with probability 1/2. A shared incident now means that Y and Z always have the same state: Y = Z. Their individual probability remains 1/2, and this shared state remains independent of X. A program keeps the result 3/8 and declares it validated because it is reproducible and lies between 0 and 1. Calculate the correct probability, then propose a check that would distinguish the two models.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

If Y and Z are identical, their union is simply Y.

Hint 2

Enumerate the states of X and the shared branch; do not use the equally likely triples of the old model.

Compare with the solution

T is reached if X and Y succeed: P(T reached) = 1/2 × 1/2 = 1/4. The state of Z adds no distinct opportunity. The 4 equally likely pairs (X, Y) contain only 1 success: (1, 1). The result 3/8 therefore reuses an independence assumption that the problem statement has removed.

A check that distinguishes the models keeps the individual probabilities but imposes Y = Z. The result must change from 3/8 to 1/4. Checking only the bounds or replaying the same seed would miss the error. Compare with exact enumeration and also check that removing the return and reversing the order of the branches does not change the final reception.

This check validates the calculation in this synthetic variant. It does not demonstrate that the branches in a real workshop are independent or coupled: that question requires separate evidence.

Check your reasoning

  • Obtain 1/4 without treating copies of Y as independent events.
  • Change the dependence structure while keeping the individual probabilities.
  • Distinguish checking the program, validating the model and proving a cause.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Why does the return T → B not create a new attempt?

B is already active before T becomes active. In our model, a station attempts its links only on its first activation; a return therefore repeats no attempt.

Recall 2Why are U = X ∩ Y and V = X ∩ Z not independent in this scene?

They share the success of X. Their intersection has probability 1/8, whereas the product of their probabilities would be smaller. Independent links do not imply independent paths that reuse them.

Recall 3What quantity must be subtracted from P(U) + P(V), and why?

P(U ∩ V), because the sum counts the outcomes where both paths succeed twice. This subtraction gives P(U ∪ V) without assuming the paths are independent.

Recall 4How can the calculation be corrected by considering B?

Condition on the success of X: branches Y and Z remain independent, and their union has probability 3/4. Then multiply by P(X) = 1/2, because T is unreachable if X fails: the result is 3/8.

Recall 5What does agreement with exhaustive enumeration of the fictional graph prove?

It verifies the result for this model and its assumptions. It proves neither the actual reliability of the links, nor their actual independence, nor a cause of failure. Reading code does not prove its execution either.
