Manual traces

✿01 See the idea

The dispenser has filled 3 bags with 75 g of rice each. Yet its display shows only 75 g. The bags are there; the calculation has lost the running total. Looking at the final display reveals a mismatch, but does not show when it began.

Imagine a finger following the code and a pencil recording the values. Your finger moves on only when you have executed the current instruction. The resulting record is a manual trace: it describes what this code produces, even when the result contradicts what you wanted to obtain.

For the first bag, writing a dose into an empty slot or adding that dose to the total gives the same number. For the next bag, the operations differ: replacement erases the running total; addition preserves it. We will find this first mismatch, then start again from the beginning to check the repair.

The entire scene and its values are fictional. We assume exactly equal doses, no lost bags and one bag filled per execution of the loop body. The small program represents only the counting; it does not control a real device.

The rule to remember

Record the state actually obtained after each instruction. To compare the cumulative mass with the bags counted, wait until the entire body is complete; correct the first operation that diverges, then rerun from the same starting point.

✿02 Follow an example

Worked example

Find the dose that the calculation forgets

Keep demande = 3 bags and dose = 75 g per bag. Trace the program in the diagram through to print(total), then replace only total = dose with total = total + dose. The inputs stay the same.

  1. Define the state and the moment of comparison

    An instruction is an operation in the program, such as an assignment. The state is the set of values known at that moment. demande is the requested number of bags; dose is the mass per bag, in grams; faits counts completed bags; total is the number of grams recorded by the program. Python does not infer units from these names: we must keep the units in the trace.

    while means “as long as”: the test faits < demande decides whether the indented body should be executed. print(total) displays the current value of total without changing it. Here, an iteration means one complete execution of the assignments to total and then faits.

    To check a completed body, k will denote the number of filled bags and M their reference mass, in grams. In our scene, k then equals faits. Each bag contributes dose grams, so:

    M=k×dose

    This is the expected mass under the scene’s assumptions, rather than a measurement on a scale. The faulty program is not assumed to satisfy this check. Between the assignments to total and faits, the counter has not yet advanced: do not apply this check to the intermediate state as if the body were complete.

  2. Execute the initializations in order

    After demande = 3, only this input is defined. After dose = 75, the inputs are set. After faits = 0, the counter is known; total is not yet known. After total = 0, the relevant state is faits = 0 and total = 0 g. A value that has not yet been assigned is recorded as “undefined”, never 0 by default.

    The first test compares 0 < 3: it is true, so the body begins. A test reads the values; it does not increase them.

  3. First iteration: the fault stays hidden

    Execute total = dose: on the right you read 75, then total goes from 0 to 75 g. faits stays at 0. Next, execute faits = faits + 1: you read the old counter, calculate 0 + 1 = 1, then assign this result to faits. total does not change.

    The body is complete: faits = 1, total = 75 g. Correct accumulation would have given 0 + 75 = 75 g. The gap, expected minus recorded, is 0 g. This iteration alone therefore does not distinguish the operations.

  4. Second iteration: locate the first divergence

    The test 1 < 3 is true. total = dose again reads 75: total goes from 75 to 75 g; faits stays at 1. Then faits = faits + 1 gives 1 + 1 = 2; total stays at 75 g.

    At the end of the body, the 2 bags represent 150 g. With addition, the old total would have contributed to the calculation:

    75+75=150 g

    The program records 75 g; it is short by 150 − 75 = 75 g. The first divergence between the compared masses appears at iteration 2. The responsible line is the assignment to total: its right side omits the previous running total. The counter line does count the bag; it did not erase the mass.

  5. Finish the faulty trace too

    The test 2 < 3 is true. total = dose again leaves 75 g, with faits = 2. Then the counter becomes 2 + 1 = 3. At the next test, 3 < 3 is false: the body does not start again. print(total) displays 75.

    There have been 3 executions of the body and 4 tests, the last of which was false. The final trace is faits = 3, total = 75 g. The output merely read a value that was already wrong. Counting the bags gives an expected mass of 3 × 75 = 225 g; the final gap is 225 − 75 = 150 g.

  6. Correct the code and rerun everything from the start

    Replace the faulty line with total = total + dose. Evaluate the old total and the dose before assigning their sum to the name total. Use the same inputs and reinitialize faits and total to 0. The following table records the state after each assignment in the corrected body; the columns retain their units.

    Instruction exécutéefaitstotal (g)total = total + dose075faits = faits + 1175total = total + dose1150faits = faits + 12150total = total + dose2225faits = faits + 13225

    The successive tests are still 0 < 3, 1 < 3, 2 < 3, then 3 < 3. The earlier tests are true, the last is false. They leave the state unchanged. print(total) then reads 225: the output represents 225 g.

  7. Check by another method

    The corrected trace accumulated the doses by successive additions: 0 + 75 = 75, then 75 + 75 = 150, then 150 + 75 = 225 g. Direct counting gives 3 × 75 = 225 g. The results agree and faits reaches exactly demande.

    This check verifies our fictional case and locates its fault. It demonstrates neither the filling process of a real dispenser nor all possible behaviors of a program. To assess another input, you will need to make a suitable new trace, without assuming the result of this one.

✿03 Common mistakes

  • “I record what the dispenser should count.”

    Keep your reference separate from the trace. For each assignment, read only the right side using the current values, then update the name on the left. The faulty trace must retain its wrong value: correcting it on paper would erase the clue you are looking for.

    Review the roles of the finger and pencil

  • “The last line displays a wrong value, so print must be changed.”

    Work back to the first mismatch between comparable states. Here, total is already wrong after the body of iteration 2. print reads it without changing it. Correct the assignment that replaces the running total, then check the intermediate values and the output.

    Locate the first divergence in the example

  • “I correct the line and continue from the old state.”

    The mass lost before the correction does not reappear. Rerun with the same inputs and reinitialize faits and total. The last exercise calculates exactly what would happen if you resumed from a state that was already wrong.

Compare with the solution

First body: after total, faits = 0, total = 75 g in both versions; after the counter, faits = 1. Second body: after total, faits = 1, total is 75 g with replacement or 150 g with addition; after the counter, faits = 2.

Last body: after total, faits = 2, total is 75 g or 225 g; after the counter, faits = 3. The true tests allow these bodies to run and the false test 3 < 3 ends each loop without changing the values.

The faulty ends of bodies are (1 ; 75 g), (2 ; 75 g), (3 ; 75 g). The correct ends are (1 ; 75 g), (2 ; 150 g), (3 ; 225 g). The faulty gaps are respectively 0, 75 and 150 g; the corrected version agrees at the end of every body.

The first divergence is at iteration 2, in the assignment to total. The final outputs represent 75 g and 225 g. The initial agreement did not prove that the running total was preserved.

  • Separate the states after total from the states after faits and record the tests without changing the values.
  • Obtain the masses and gaps with the unit g.
  • Identify the first mismatch and its cause, rather than pointing only to the final output.

Exercise 3 · Transfer · evaluate a repair

The forgotten dose does not return by itself

After the second faulty body, faits = 2 and total = 75 g. Someone changes the line to total = total + dose and finishes the program from this state, without reinitializing. What will be displayed? Is this a correct way to verify the repair? Describe the rerun that would allow a comparison.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

One body remains to be executed; its addition starts from the current total, rather than the total that should have been there.

Hint 2

Compare the result of resuming in this way with the result of a complete rerun using the same inputs.

Compare with the solution

The test 2 < 3 allows the last body to run. The addition produces 75 + 75 = 150 g. The counter reaches 2 + 1 = 3; the next test is false. The output therefore represents 150 g. It is still short by 225 − 150 = 75 g.

Resuming in this way preserves an earlier error. To verify the correction, you must restart from faits = 0, total = 0 g, with demande = 3 and dose = 75 g. The additions give 75, 150, then 225 g again. The direct check gives 3 × 75 = 225 g.

The rerun establishes that the repair works for this case. It does not turn this check into a proof for all cases, nor does consulting a correction establish independent mastery.

Check your reasoning

  • Calculate 150 g from the state actually retained, and explain the missing 75 g.
  • Propose complete reinitialization with the same inputs and a check of intermediate states.
  • Limit the conclusion to the case checked.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does a manual trace record after an instruction?

The values actually obtained with the current code. A value that has not yet been assigned remains undefined; the trace replaces it with neither 0 nor the desired value.

Recall 2Why does the first iteration not reveal the faulty replacement?

With total initially equal to 0 g, assigning dose and adding dose both give 75 g. The next iteration must preserve a running total that is already nonzero; it distinguishes the operations.

Recall 3When can total be compared with faits multiplied by dose in our scene?

After a complete body, when total and then faits have been updated. Between these instructions, the counter still describes the previous body; record the intermediate state without confusing it with the end of the iteration.

Recall 4How do you get from a wrong output to the responsible line?

Compare the same moments with the same inputs, find the first state that differs from the reference, then reread the operation that produced it. Here, total = dose omits the running total; print merely reads it.

Recall 5What must you retain and reinitialize to verify a repair?

Keep the same inputs, reinitialize the starting state and redo the entire trace. Check the intermediate values and output by another method. An assisted answer remains preparation; you must reconstruct the reasoning without support later.
