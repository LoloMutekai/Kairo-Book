Level 4 · C264·M5

Monitoring and rollback

Your goalCalculate a monitoring signal, decide when to suspend a model, and specify the evidence needed for a verified rollback.

Before you start
c263-m5 : distribution shift · c074-m5 : identification assumptions · c220-m5 : numerical reproducibility · c017-m5 : reproduction protocol · c264-m1 : permutation · c264-m2 : partial effects · c264-m3 : explanation and causality · c264-m4 : drift

✿01 See the idea

In a test chamber, a model predicts the temperature for the next minute. The technician sees the predictions arrive; that does not tell them whether the predictions remain usable. They compare each prediction, recorded before its target time, with the temperature subsequently measured. The model proposes values: it does not control any equipment.

Monitoring connects a reading to a prepared decision. Our technician groups the errors into windows, meaning successive batches with no shared observations. If the error stays too large for several windows, they suspend use of the candidate. They already have a fallback version, called the stable version because it was selected previously, with no guarantee for all future conditions.

Rollback means restoring this version and everything its predictions depend on: parameters, input transformation, and compatible settings. It then remains to check that a request actually reaches this version and that its output is usable. A message saying “restoration successful” does not replace this check.

The scene and all its temperatures are fictional. We will simulate an operating rule set before examining the errors. The chosen threshold and patience setting are used for the calculation; they are neither recommendations for a real chamber nor a statistical guarantee against false alarms.

The rule to remember

Prepare the fallback before an incident; measure with a consistent rule; suspend when the rule requires it; check what is actually restored, then keep monitoring.

✿02 Follow an example

Worked example

A temperature prediction that deteriorates

The candidate is used in a monitored simulation. A window contains n = 4 predictions with a horizon of 1 min. The threshold τ is 2 °C of mean absolute error. The rule suspends the candidate after h = 2 consecutive windows strictly above τ. The counter starts at 0. Before the trial, the person in charge authorized this suspension and rollback to an identified fallback package; this example grants no real authorization.

  1. Define exactly what is measured

    t denotes the current window in time order; i denotes an observation in this window, from 1 to n. yᵢ is the reference temperature measured at the target time; pᵢ is the candidate prediction recorded before that time. Both are in °C. We keep them paired by event, along with the issue time, horizon, and identifier of the package used.

    The absolute error eᵢ = |pᵢ − yᵢ| is the distance between prediction and reference, in °C. The bars remove the sign: an overestimate and an underestimate must not cancel each other out. Mt is the mean of these distances in the window, still in °C. n is a count of observations, with no physical unit; n is strictly greater than 0. The symbol ∑ adds the distances for i running from 1 to n.

    Mt=1n∑i=1n|pi−yi|

    The references are assumed to be available, correctly aligned, and reliable for the simulation. The windows do not overlap and use the same sensor, horizon, and definition of error. This separation does not guarantee that the temperatures are independent. No independence assumption is needed to reproduce this mean; it would need discussion for a statistical interpretation.

    If a reference is missing, Mt is not evaluated as though the window were complete. The protocol then suspends use of the candidate until monitoring is restored; it never replaces the unknown error with 0. A technical failure or an invalid input also requires a separate stop: patience about quality does not require continued use during a failure.

  2. Write the rule before seeing the results

    τ is the error threshold, in °C. h is the required run length, in windows. qt counts the consecutive breaches ending at window t; it is a count, rather than a probability. The previous counter is denoted qp; initially, it is 0.

    For a valid window, if Mt > τ, set qt = qp + 1. If Mt ≤ τ, set qt = 0. As soon as qt reaches h, suspend the candidate and begin the prepared rollback. Equality at the threshold therefore interrupts the run of breaches.

    Choosing h = 2 deliberately delays the reaction to an isolated breach; it can also allow deterioration to continue during this delay. This tradeoff belongs to the protocol. Changing τ after seeing the alert would change the rule being evaluated.

    Each row pairs the same event across the columns. The readings, predictions, and absolute errors in the table are all in °C.

    On the first row, |22 − 20| = 2 °C. On the next, |20 − 22| = 2 °C: take the distance, despite the change of sign. The other distances are 3 °C and 3 °C.

    Adding gives (2 + 2) + (3 + 3) = 4 + 6 = 10 °C. Dividing by the number of predictions gives M for window A: 10/4 = 5/2 °C, or 2.50 °C. We divide to compare an error per prediction, rather than letting the batch size determine the result.

    Since 2.50 °C > 2 °C, q goes from 0 to 1. The required length is 2: the stop for quality has not yet been triggered. The next window remains under monitoring.

  4. Calculate the next window and decide

    Window B contains new events. The candidate recorded its predictions before knowing the references, as in window A. All cells are in °C.

    The distances are |21 − 24| = 3, |25 − 23| = 2, |21 − 25| = 4 and |25 − 22| = 3, in °C. Their sum is (3 + 2) + (4 + 3) = 5 + 7 = 12 °C.

    M for window B is 12/4 = 3 °C, or 3.00 °C. The threshold is exceeded again: q becomes 1 + 1 = 2. It reaches h = 2; the rule now requires suspending the candidate. This decision applies an operating limit; it establishes neither the cause of the problem nor a lasting distribution drift.

  5. Examine the fallback on the same events

    bᵢ denotes the stable version prediction, in °C. For this fictional trial, it also produced and recorded its outputs before the target times, alongside the candidate. We can therefore examine its errors on the same events in B without retraining after seeing the answers.

    MesureRepliÉcart absolu24231232412524122231

    The fallback distances are 1, 1, 1 and 1 °C. The sum is (1 + 1) + (1 + 1) = 2 + 2 = 4 °C. Its mean is 4/4 = 1 °C, or 1.00 °C: it is below the threshold on this window.

    On these same events, the difference between the means is 3 − 1 = 2 °C in favor of the fallback. This is a descriptive comparison of predictions on a fictional window. It proves neither future improvement, nor a causal effect on equipment, nor the effectiveness of a real restoration mechanism.

  6. Restore the package, then check that it is used

    Before the trial, the stable package was saved with its identifier, fingerprint, model, parameters, and input transformation. A fingerprint is a signature calculated from the bytes that allows a change in the package to be detected here; by itself, it does not prove quality. The rollback procedure and required authorization are planned at the same time.

    In our simulated protocol, first remove the candidate from the request path in use, then restore the compatible stable package. Leaving a recent transformation in front of an old model does not restore the complete stable version. If the package is missing or its verification fails, keep the suspension and report the failure; do not put the candidate back into use by default.

    The check after restoration follows a request from end to end: identifier of the package actually loaded, transformation applied, output obtained, and expected reference for a known case. Monitoring resumes at new target times, keeping windows separate by version. Do not mix candidate and fallback outputs in the same mean. Rolling back does not withdraw predictions already used.

    A located package, a requested restoration, and a verified request path are different kinds of evidence. A person in charge prepares any new activation of the candidate after reviewing the incident; a new window falling below the threshold does not automatically authorize it.

  7. Check the calculations and the limits of the decision

    Reverse check: n × M gives the sum of distances again. For A, 4 × 5/2 = 10 °C; for B, 4 × 3 = 12 °C; for the fallback, 4 × 1 = 4 °C. The means stay between the minimum and maximum distances in each batch.

    Another check: in A, the signed errors pᵢ − yᵢ cancel out exactly to 0 °C, while their absolute sum is 10 °C. The signed mean would have hidden the errors. The exact calculation keeps 5/2 until the French-format display 2.50; no intermediate rounding determines which side of the threshold the result falls on.

    The rule does trigger on the sequence A then B, and equality at the threshold must reset the counter to 0. These checks verify a calculation and logic on fictional data. The relevance of τ, sensor reliability, the cost of the delay, and the actual ability to restore still need to be checked for any real application.

✿03 Common mistakes

  • “The mean of the signed errors is 0, so the model makes no mistakes.”

    The overestimates and underestimates in A cancel each other out. Calculate their distances before adding them: the absolute sum is 10 °C and the mean is 2.50 °C. The sign answers another question, about a tendency to overestimate or underestimate.

    Revisit the distances and the check using signs

  • “It is enough to count all the breaches encountered.”

    The rule concerns a consecutive run. Any valid window with an error below or equal to the threshold resets the counter to 0. Replay the sequence in the exercise that inserts an equality between breaches.

    Replay the interrupted sequence

  • “The old state has been located: rollback has succeeded.”

    The compatible package still needs to be applied and a request followed through to its output. The milestone code specifically distinguishes the state proposal from its application; a favorable state lookup result does not prove the actual request path.

    Read the exact scope of the restoration result

Exercise 1 · Application · threshold and unit

Landing exactly on the threshold

In a variant of the same simulation, a valid window of 4 predictions has a total distance of 8 °C. The previous counter is 1. Calculate its mean and the new counter. Does the stopping rule for quality trigger?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The sum describes the whole batch. Divide it by the number of predictions.

Hint 2

The required breach is strict. An equality follows the branch that interrupts the run.

Compare with the solution

M = 8/4 = 2 °C. This mean is exactly equal to τ = 2 °C. The condition M > τ is false: q becomes 0, and the stop for quality is not triggered on this window.

Reverse check: 4 × 2 = 8 °C. The conclusion assumes that the window is complete and valid; a missing reference falls under the other reason for suspension.

Check your reasoning

  • Obtain 2 °C with a denominator of 4 observations.
  • Reset the counter to 0, despite its previous value.
  • Justify the decision using the strict inequality in the rule.

Exercise 2 · Reasoning · sequence on paper

Separated breaches

Another sequence from the chamber contains valid windows with means of 2.50 °C, 2.00 °C, then 3.00 °C, in that order. Start with a counter equal to 0 and keep the same τ and h. Give the counter after each window. Can rollback be triggered at the last step on quality grounds alone?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Write a line for each window and state which branch of the rule applies.

Hint 2

Do not carry over the breach before the equality. The run was interrupted.

Compare with the solution

After 2.50 °C > 2 °C, q is 1. After 2.00 °C = 2 °C, it is 0. After 3.00 °C > 2 °C, it restarts at 1. It never reaches h = 2 in this sequence.

The counter gives the length of the current run, rather than the historical total of breaches. The prescribed rule therefore does not trigger rollback for quality at the last step. Another reason to stop, such as a failure, would retain its own decision.

Check your reasoning

  • Produce the sequence 1, 0, 1.
  • Connect each value to a comparison with the threshold.
  • Distinguish the rule being evaluated from a possible separate technical stop.

Exercise 3 · Transfer · diagnosis and evidence

The old model returns, but its transformation is missing

After the main sequence A then B, the simulation log announces “stable package located”. The old model is available, but the input transformation is still the candidate transformation. The next temperature references have not yet arrived. The technician announces: “verified rollback and 0 error”. Write a diagnosis and the next useful check.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Separate the located state, the package actually used, and the quality of future outputs.

Hint 2

A missing reference is not an error of 0 °C. Start again from the complete request path rather than the log message.

Compare with the solution

The rule required stopping the candidate because q = 2. In the problem statement, the message only attests that the package has been located. The combination of an old model and a recent transformation does not match the planned stable package: its complete restoration has not been established.

The protocol keeps the suspension. The compatible transformation must be restored and identified, then a request checked on a known case by following the loaded version and its output. When the references for the new target times are available, a new error can be calculated. Until then, it is unknown and is not 0 °C.

The fallback mean of 1.00 °C on B remains a comparison result in the fictional trial. It does not certify the new outputs or turn a restoration message into evidence of a return to service.

Check your reasoning

  • Identify the package incompatibility and keep a suspended status.
  • Request evidence of the request path with the expected transformation.
  • Leave future quality unknown when references are absent.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Why take absolute values before calculating the mean?

To measure distances without canceling out overestimates and underestimates. Add the distances in °C, then divide by the number of valid observations; the mean remains in °C.

Recall 2What does the counter record, and what does equality at the threshold do?

It records the consecutive breaches ending at the current window. It increases if the mean strictly exceeds τ; a valid window below or equal to τ resets it to 0.

Recall 3What is the error of a window when its references are unavailable?

The error of the complete window cannot yet be calculated. It remains unknown; our protocol suspends use of the candidate until monitoring is restored, without replacing a missing reference with 0.

Recall 4What evidence separates a located old state from a verified rollback?

Application of the compatible package, the identity of the version actually reached, and the output of a check request must be established. Monitoring with new references then checks quality under the new conditions.

Recall 5What does triggering the stopping rule fail to establish?

It establishes neither the cause of the deterioration, nor a false alarm probability, nor future improvement through the fallback. It triggers an action planned by a protocol whose choices still need justification.
