Loops

Your goalFill the requested bags by repeating an action, then explain what changes at each iteration and what causes the loop to stop.

Before you start

✿01 See the idea

You are preparing small bags of rice with a scoop. Before starting a bag, you check how many are already filled. If more are needed, you add a portion to the next bag and count that bag as finished. Then you ask exactly the same question again.

A loop organizes this return: it repeats a group of instructions as long as a test is true. This group is called the loop body; one complete execution of the body is an iteration. The test is checked before the body, including at the very start.

The counter and the mass tell you different things. The counter counts finished bags; the mass adds up the portions poured. The final check can decide to stop without filling a bag: checking a test does not add any rice.

The scene and the values are fictional. Each bag receives exactly 75 g, with no loss and enough rice available. The requested number is a nonnegative integer that stays fixed throughout the preparation. We are following a computational model, without claiming to control a real dispenser. Before continuing, imagine an empty order: should the body be entered?

The rule to remember

Initialize, check the test, execute the body if the test is true, then return to the test. The body must change the value that determines when the loop stops.

✿02 Follow an example

Worked example

Prepare 3 bags of 75 g

Keep the same portion size and request 3 bags. We will follow every decision and every update, then check the total with a different calculation.

  1. Define each name and initialize

    "demandes" holds the requested number of bags; "faits" holds the number of finished bags. These are integer counts in bags. "dose" is the mass of rice added to fill a bag, in grams; "total" is the accumulated mass, in grams. The names refer to the current values in the program, rather than quantities that recalculate themselves.

    Before the loop, write "demandes = 3", "dose = 75", "faits = 0" and "total = 0", in that order. These instructions are aligned at the left. Initializing means giving the names their starting values: no bag has received a portion yet.

    We keep demandes and dose unchanged during the loop. Each iteration represents exactly one complete filling, followed by counting that bag. The program does not contain the physical instruction that controls a machine: it models this preparation.

  2. Identify the body and check the first test

    The line "while faits < demandes:" starts the loop. The Python word while means "as long as". The < sign makes a strict comparison: "are there still bags to fill?" It changes no values. The colon introduces the body.

    The body contains "total = total + dose" followed by "faits = faits + 1", in that order. These instructions are shifted to the right by the same number of spaces: this is indentation. It places both instructions inside the loop. The initialization instructions stay outside the body; putting them inside would erase the progress at every iteration.

    Initially, the test is 0 < 3: true. We therefore enter the body. At its end, while will automatically return to the comparison, without a separate instruction to return. An instruction placed afterwards at the same indentation as while is after the loop and waits for its normal exit.

  3. Fill and then count the first bag

    The line "total = total + dose" reads the old total, calculates the addition to the right of the = sign, then stores the result under the name total. Here: 0 g + 75 g = 75 g. The = sign is an assignment, rather than a mathematical equality between the old and new values.

    The next line counts the finished bag: 0 + 1 = 1 bag. At the end of the body, the state is therefore faits = 1 and total = 75 g. The mass and the count have each increased in their own unit.

  4. Return to the test and fill the next bag

    The program compares the new value of faits with the requested number: 1 < 3, true. It repeats the same body with the current values, without resetting them to their initial values.

    Accumulating means adding to what is already there: 75 + 75 = 150 g. Then count: 1 + 1 = 2 bags. The state becomes faits = 2 and total = 150 g.

  5. Execute the final required iteration

    The test 2 < 3 is still true. One bag is still needed; the requested number has not changed.

    The body gives 150 + 75 = 225 g, then 2 + 1 = 3 bags. Reaching this mass is not enough to exit: the program must still return to the test.

  6. Stop without filling an extra bag

    The new test is 3 < 3. The counts are equal, so this strict comparison is false. The body is not executed: neither the mass nor the counter changes.

    We executed 3 iterations but checked 4 tests: 3 true tests to enter and 1 final false test to exit. This final check does not correspond to any filling.

    Stopping depends on the update to faits. If only the mass increased, the test would keep reading the same counter. Filling and counting are therefore both necessary in this model.

  7. Check without repeating the instructions

    Adding the portions gave 75 + 75 + 75 = 225 g. Check by multiplying the number of bags by the portion size:

    3×75=225 g

    The product and the trace give the same mass, and faits does equal demandes. Check the number of tests: 3 + 1 = 4. These checks are valid here because each execution of the body finishes exactly one bag and adds an identical portion. They do not describe every possible loop.

✿03 Common mistakes

  • “while always executes the body at least once.”

    Start with the test, even for a request for 0 bags. The comparison 0 < 0 is already false: 0 iterations, 0 g, but 1 test. A decision to stop can be the very first event.

    Revisit "An empty order"

  • “The final test is the final bag.”

    Mark a bag only when the body executes. In the trace, the final test is false and adds no portion. There are 3 bags for 4 checks, rather than 4 bags.

    Distinguish the bags from the test rows

  • “The total is increasing, so the loop will eventually stop.”

    Reread the names in the test: it compares faits with demandes, without reading total. Keep "faits = faits + 1" inside the body, after filling. Omitting this update or placing it after the loop leaves the counter stuck during the iterations.

    Reread the body and the stopping condition

Compare with the solution

The body executes 5 times. The mass is 5 × 75 = 375 g. Check using successive portions: 75 + 75 + 75 + 75 + 75 = 375 g.

Each of the 5 entries into the body requires a true test. The final test 5 < 5 is false. There are therefore 5 + 1 = 6 tests, and the final counter is 5 bags.

This way of counting assumes the intended updates and an unchanged requested number; the word while alone does not guarantee this result.

Hint 1

The <= sign means "less than or equal to". What does it decide when faits reaches demandes?

Hint 2

In the case of the missing counter update, record faits and total separately after each addition.

Compare with the solution

With <=, the test 3 <= 3 stays true: an extra iteration is allowed. The counter reaches 4 bags, and the mass reaches 4 × 75 = 300 g. The excess is 300 − 225 = 75 g.

The next test, 4 <= 3, is false. There are 4 + 1 = 5 tests. Repair: restore < to exit as soon as the counts are equal and obtain 3 bags, 225 g and 4 tests again.

In the separate case of the missing counter update, the starting state is (faits = 0, total = 0 g). After the first execution of the body: (0, 75 g). After the next: (0, 150 g). The test remains 0 < 3, true. The mass changes, but nothing brings the counter closer to the requested number: the model does not terminate normally.

Repair: restore "faits = faits + 1" after adding the portion, with the same indentation, inside the body. An update placed after the loop is not reached while the loop is running. The incorrect comparison boundary and the missing counter update are two distinct changes: examine them from the same starting state, never one after the other in an already modified state.

Check your reasoning

  • Link the extra bag to the test being true at equality.
  • Obtain 4 bags, 300 g and 5 tests for the inclusive comparison.
  • Show that faits stays at 0 when its update is missing, despite the increasing mass.
  • Repair the comparison sign in the first case and the body instruction in the second.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1In what order does while check its test and execute its body?

It checks the test first. If the test is true, it executes the body, then returns to the test. If the test is false, it exits without executing the body.

Recall 2How should you read "total = total + dose" without seeing an impossible equality?

Read the old total, add the portion to it, then assign the result to the name total. The value on the left becomes the new value after the calculation on the right.

Recall 3Why is increasing only total not enough to stop our loop?

The test reads faits and demandes. Each finished bag must be counted inside the body; increasing a mass that the test does not read does not change its decision.

Recall 4Why does our request for 3 bags give 4 tests?

Each bag requires a true test before the body, giving 3 tests. The final false test adds 1 check and no bag.

Recall 5When faits and demandes are equal, what is the difference between < and <=?

The strict comparison < is false: we exit. The comparison <= is still true: the body finishes an extra bag before the next test.

What you understand
Following a counter lets you say what a program repeats and when it stops. Understanding a calculation does not yet tell you whether its result properly represents what you want to study. This distinction will be explored at the next milestone, using the word indicator: a number used to provide information about something.
