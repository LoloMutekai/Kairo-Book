Level 3 · C105·M5

Cost and limits

Your goalCalculate the work and storage required by dense attention, then distinguish this budget from how faithfully an answer follows the document.

Before you start
c104-m5 : temporal validation · c102-m5 : finite difference check · c050-m5 : conditioning · c105-m1 : queries–keys–values · c105-m2 : multi-head attention · c105-m3 : positions · c105-m4 : encoder and decoder

✿01 See the idea

You ask a model whether a Saturday booking can be moved. The fictional notice for a workshop room says: “A booking can be moved up to the day before. Exception: Saturday bookings cannot be moved.” A faithful answer must respect this exception. Before even judging the answer, the text must fit within the computation. All lengths and budgets in this scene are fictional, chosen for calculations with pencil and paper.

A token is a unit of text produced by the model’s tokenization; it can be part of a word. We therefore do not convert words or characters into tokens using a fixed ratio. Tokenization provides the number of positions. The short version of the input contains 32 tokens; an expanded version contains 64. These counts include the question and the notice in our exercise.

In dense attention, each position compares its query with the keys of all allowed positions. For now, imagine the full square table, before any causal restriction. Adding positions adds rows and columns. Doubling the length also introduces comparisons between the old and new passages: it does more than simply double a list.

The drawing shows the table for a single head. Heads are distinct learned comparisons, rather than sections of the document that divide the positions among them. Even if the input fits within the budget, the presence of the exception does not guarantee that the model uses it correctly. Computational capacity and fidelity to the document require different checks.

The rule to remember

First specify what you are counting: pairs, multiplications or bytes. State the dimensions and how the computation is performed, then assess separately whether the answer respects the exception in the notice.

✿02 Follow an example

Worked example

What budget is needed to read the whole notice?

Let us count 1 layer for 1 document, with h = 4 heads. Each query, key and value has d = 8 components per head. The score table is explicitly stored, using b = 2 bytes per cell. We compare n = 32 with n = 64 positions, using the same widths and storage. These lengths are fictional parameters; the quoted sentences have not actually been tokenized.

  1. Define the scope of the count

    n is a number of positions; h, a number of heads; d, a number of components per head, the same here for keys and values. These are counts without physical units. D = h × d = 4 × 8 = 32 is the total width across the heads. b is expressed in bytes per scalar, where a scalar here is a stored number.

    For each head, Q contains the queries and K the keys: these matrices have n rows and d columns. V contains the values and has the same dimensions here. Kᵀ is the transpose of K, obtained by exchanging rows and columns. QKᵀ contains the dot products of the queries and keys. A denotes the unitless weights obtained after scaling and normalization of these scores: it has n rows and n columns. The head’s output is AV, with dimensions n rows and d columns. The components of Q, K, V and this output are model numbers, with no physical unit assigned here.

    We count the scalar multiplications in the products QKᵀ and AV. Additions, score scaling, normalization, the projections that construct Q, K, V and the output projection fall outside this count. We therefore calculate neither the full cost of the Transformer nor seconds of latency.

  2. Count the comparisons

    Each query has n keys to compare with. There are n queries in each head, and h heads. Let S be the combined number of cells in their score tables. A cell is a query–key comparison, even if its numerical values have not yet been calculated.

    S=hn2=4×32×32=4096 cases

    Check by grouping: each head contains 1024 cells; 4 tables of this size do indeed give 4096 cells. Dividing the width among several heads does not divide the positions among them.

  3. Go from cells to multiplications

    Each query–key dot product multiplies d pairs of components. The product QKᵀ therefore requires S × d = 4096 × 8 = 32768 multiplications. For AV, each position produces d components, each by combining n values: h × n × d × n = 32768 additional multiplications.

    C denotes their sum, in scalar multiplications. Since keys and values have the same width here, the counts are equal. With different widths, we would need to keep them separate.

    C=2hn2d=2n2D=32768+32768=65536

    At a fixed width D, this work is quadratic in n: the number of multiplications is proportional to the square of the length. This relationship does not provide a measured execution time. Projections also have a cost: their work grows linearly with n when the widths are fixed. Leaving them out of this focused count does not mean they are free.

  4. Count the bytes actually included in the estimate

    M denotes only the memory for the score table of all heads in this layer. Each stored cell takes b bytes, so we multiply the number of cells by this size.

    M=bS=2×4096=8192 octets

    A kibibyte, written KiB, equals 1024 bytes. M = 8192 ÷ 1024 = 8 KiB. This division changes the unit; it does not reduce the space occupied. The weight table A, Q, K, V, the parameters and the other layers are not counted. Training also requires, among other things, information needed to calculate gradients.

    Quadratic storage describes our fictional implementation, which materializes the whole table. A computation organized in blocks can avoid keeping this entire table while still evaluating the same pairs. We must therefore state how the computation is organized before applying this memory estimate to real software.

  5. Lengthen the notice and check the factor

    The expanded version has 64 positions. Per head: 64 × 64 = 4096 cells. For all heads: 4 × 4096 = 16384 cells. The scores occupy 2 × 16384 = 32768 bytes, or 32 KiB.

    QKᵀ requires 16384 × 8 = 131072 multiplications; AV requires 131072. Their sum is 262144 multiplications. The length ratio is 2, the cell ratio 4 and the multiplication ratio 4. Score memory also follows the factor 4, since b remains fixed.

    Another check, without repeating the products: the large table in the drawing can be divided into 4 blocks. They cover old–old, old–new, new–old and new–new. Each is the size of the old table. The factor we recover is indeed 4. This factor does not predict an identical slowdown for the whole program.

  6. Distinguish the mask from the execution mode

    A causal mask prevents a position from reading later positions; here, the position itself is allowed. The numbers of allowed keys per row run from 1 to n. Their sum is n × (n + 1) ÷ 2: we recover this formula by pairing the first and last rows, then pairing the next rows in turn.

    At n = 32, this gives 32 × 33 ÷ 2 = 528 allowed pairs per head, instead of 1024 cells in the square. The other 496 cells are masked. A program may nevertheless calculate the whole square, then mask it; the mask alone therefore proves no saving in work or storage.

    Our square count still describes this full dense computation. A program that actually avoids forbidden pairs would have a different exact count, but would still show quadratic growth for a full reading of an increasingly long input.

  7. Separate full reading, generation and training

    The initial reading processes the positions in the supplied text. During causal generation, the model can keep the keys and values already calculated: this is the key–value cache. For a new position after n retained positions, it then calculates only a new query compared with the n + 1 keys, including its own key.

    With the same widths, the new query–key products require (n + 1) × D multiplications; combining the values requires just as many. Their sum is 2 × (n + 1) × D. This count per new token grows linearly with the length already present, assuming that the cache is reused. It does not replace the cost of the initial reading; generating an entire sequence accumulates these steps.

    The cache itself occupies memory: it retains the keys and values of past positions. Training also calculates gradients to modify the parameters. We do not assign it the cost of a single forward pass. Finally, evaluating the answer means checking it against the notice and the question; none of these arithmetic operations provides that verdict.

  8. Return to the Saturday exception

    The expanded version may contain the exception missing from the short version. This makes a faithful answer possible, without making it certain. The model may ignore a clause, confuse the general rule with its exception or produce an answer unsupported by the text. Encoded positions and normalized weights are not proof of correct reasoning.

    If the context is reduced to fit the budget, we must look at what disappears. Keeping only recent passages or passages resembling the question may discard an exception worded differently. This selection bias means that the selection rule favors some passages at the expense of others; it can exist even if the attention calculation is exact.

    A check to prepare for our notice: keep the reference text, identify the rule and the exception, then ask for an answer that justifies the Saturday case using these passages. Comparing the versions on this same question and recording the clauses actually supplied distinguishes an input limitation from an error in using the input. No actual trial or success rate is reported here.

✿03 Common mistakes

  • “The text is twice as long, so the cost is twice as large.”

    For the dense attention products over the full passage, rows and columns grow together. At fixed dimensions, going from 32 to 64 positions multiplies the cells and our multiplications by 4. Always specify whether you are counting a full reading or a new token with a cache.

    Revisit the division of the square and the execution modes

  • “The scores occupy 8 KiB, so the model fits in that memory.”

    This number concerns only a single table in a single layer. Q, K, V, the attention weights, the parameters, the other layers and requirements specific to the execution mode are outside the count. Restate the scope of M before inferring a capacity from it.

    Reread exactly what M includes

  • “The notice fits in the context: the answer about Saturday must be correct.”

    Check that the exception has been retained, then that the answer respects its scope. Meeting a budget proves material feasibility under our assumptions; fidelity is checked against the notice. An attention weight does not certify the truth of a sentence.

Exercise 1 · Application · non-integer factor

A notice of intermediate length

The same input now contains 48 positions. Keep h = 4, d = 8 and b = 2 bytes. Calculate the score cells and their memory in bytes and KiB. Before calculating, predict whether memory is proportional to length.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Count the rows and columns of a single head, then multiply by the number of heads.

Hint 2

Compare the ratio 48 ÷ 32 with the ratio of the memory amounts; the first factor acts on both sides of the square.

Compare with the solution

Per head: 48 × 48 = 2304 cells. All heads: 4 × 2304 = 9216 cells. M = 2 × 9216 = 18432 bytes, or 18432 ÷ 1024 = 18 KiB.

The length is multiplied by 1.50, but score memory is multiplied by 2.25. The second factor is the square of the first. Memory is therefore not proportional to length in this storage mode.

Check your reasoning

  • You distinguish the 2304 cells of a single head from the 9216 cells of all heads.
  • You provide 18432 bytes and 18 KiB and justify the units.
  • You explain why the length factor appears twice.

Exercise 2 · Reasoned decision · budget and fidelity

What a score budget allows

A fictional budget of 20000 bytes is reserved solely for the scores in this layer. Compare inputs of 48 and 64 positions. The intermediate version discards the Saturday exception; the long version contains it. Which version meets this budget? Can we say that it is sufficient to answer faithfully? Propose a next step that retains the decisive clause.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Compare each memory amount with the budget in the same unit, without rounding the KiB.

Hint 2

A clause can still be missing even if not all available bytes are occupied.

Compare with the solution

The intermediate version uses 18432 bytes. There are 20000 − 18432 = 1568 bytes left in this score budget. The long version requires 32768 bytes and exceeds the budget by 32768 − 20000 = 12768 bytes.

Only the intermediate version meets the stated budget, but its selection removes precisely the useful exception. It is not sufficient to establish a faithful answer about Saturday. The positive margin also does not prove that the whole model fits in memory.

We can prepare a shorter selection that keeps the general rule and its exception, then recount the tokens actually obtained and recalculate M. A different organization of the computation could also change the storage. None of these approaches removes the need to check the answer against the retained clauses; we do not invent their outcome.

Check your reasoning

  • You identify the version that fits and calculate the margin or excess without confusing bytes and KiB.
  • You refuse to infer fidelity solely from meeting the budget.
  • Your next step explicitly retains the exception and includes a new count and a check of the answer.

Exercise 3 · Transfer · changing the scope

Add a token without rereading the whole square

After the 32 positions of the short input, the model processes a new position by reusing the key–value cache. It compares its query with the 33 keys, including the new one. With the same h and d, calculate the query–key multiplications and then the multiplications for combining with V. Explain why this result gives neither total latency nor answer quality.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

There is only a single new query row per head; the old keys and values are reused.

Hint 2

Each head requires 33 × 8 multiplications for the scores and just as many to combine the values.

Compare with the solution

The total width is D = 32. The new row requires 33 × 32 = 1056 query–key multiplications. Combining with the values requires just as many. The focused total is 2 × 1056 = 2112 multiplications.

There is no new full square because the previous keys and values are reused and there is only a single new query per head. If the cache is not reused, this reasoning no longer describes the computation performed.

The count omits, among other things, the projections, the rest of the network and memory transfers; it does not convert directly into seconds. Nor does it tell us whether the exception appears in the short input or whether the output respects it. The initial reading, the new token and answer evaluation remain distinct scopes.

Check your reasoning

  • You find 1056 multiplications for each product and 2112 for their sum.
  • You relate the count to a new query and the actual reuse of the cache.
  • You name at least one excluded cost and one fidelity check still needed.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Why does a full reading of a longer input make the number of pairs grow quadratically?

Each head compares n queries with n keys. Both axes grow with n: there are h × n × n cells. The length factor therefore multiplies both axes, with the number of heads fixed.

Recall 2What must be specified before announcing memory of b × h × n × n?

b is the size of a score in bytes; h counts heads and n counts positions. The count assumes that the full table is explicitly stored, for the stated layer and document. It excludes other tables and does not represent the memory of the whole model.

Recall 3Why does a new token with a cache have a different count from a full initial reading?

The old keys and values are reused; only a new query per head is compared with the available keys. The attention work in this step grows linearly with the current length at fixed dimensions. The initial reading and the accumulation of steps still need to be counted.

Recall 4Is a causal mask enough to prove a saving in memory or time?

It forbids dependencies on future positions. Software may calculate and store the full square and then mask it. Savings depend on the operations and allocations actually avoided.

Recall 5What must be checked after establishing that the notice meets a budget?

That the selection contains the necessary rule and exception, then that the answer respects these clauses. The allowed length, the presence of a passage and its correct use are distinct facts.
