✿01 See the idea

At a bicycle repair shop, you want to examine jobs on a wheel that took at least 18 min. You want to display the longest first and keep only the first 2. The full sheet also contains short jobs and a job on a brake: copying the first rows of the sheet would not answer your request.

Imagine a window placed over the sheet. It chooses the eligible rows, the columns to show and the reading order. SQL is the language you use to describe this result to a database engine. A query is an instruction sent to that engine; here, it asks for a result table from an existing table.

You state what you are looking for. You do not write a loop that visits every cell or dictate how the engine should work. To check the answer, however, you can repeat the sorting and filtering by hand.

The entire scene and all its durations are fictional. We read a single table that is already prepared, without changing it. Joins, calculations by group and transactions belong to later units.

The rule to remember

FROM names the table, WHERE keeps rows, SELECT chooses columns, ORDER BY sets the ranking and LIMIT caps the number of rows returned.

✿02 Follow an example

Worked example

Find the long wheel repair jobs

In the fictional interventions table, display id and duree_min for poste equal to roue, with a duration of at least 18 min. Rank from longest to shortest duration; for equal durations, put the smallest identifier first. Return at most 2 rows.

  1. Define the data and their units

    A row represents a completed repair job. id is its unique integer key: it is a label, with no unit of measurement. poste is text whose value here is roue (wheel) or frein (brake). duree_min is an integer measuring duration in minutes; the suffix min in its name is a reminder of this unit. No cell is missing, durations are positive and the text values are written exactly as shown.

    The rows are: (11 ; roue ; 18 min), (12 ; roue ; 12 min), (13 ; roue ; 25 min), (14 ; roue ; 18 min), (15 ; frein ; 30 min). The parentheses give values in the order id, poste, duree_min; they do not form an SQL instruction.

    The table is assumed to remain stable during this check. There is no matching across tables or grouping. We use selection syntax that is common here to SQLite and PostgreSQL, including LIMIT to cap the output. Details of dialects and missing values remain outside this example.

  2. Write the query, clause by clause

    The following lines show a single instruction, labeled by role. Copy the SQL after each label in this order, keeping the single quotes around roue.

    Columns: SELECT id, duree_min

    Source: FROM interventions

    Filter: WHERE poste = 'roue' AND duree_min >= 18

    Ranking: ORDER BY duree_min DESC, id ASC

    Limit: LIMIT 2

    SELECT specifies the columns returned; the comma separates their names. FROM gives the table name. WHERE introduces a condition for each row: = compares text here, >= means greater than or equal to, and AND requires all the conditions to be true. roue in quotes is a text value; poste without quotes is a column name.

    ORDER BY introduces the ranking. DESC requests descending order; ASC requests ascending order. After the comma, id ASC breaks ties between equal durations. LIMIT sets a maximum number of rows without filling out the output if too few rows qualify. We give a single instruction with no final separator. An SQL console may require a semicolon to finish its input; a program sending a single instruction may omit it.

    Although SELECT is written first, read the request starting with the source and the filter. This approach helps you understand the result. It does not specify the physical order in which the engine will read the rows.

  3. Test the filter on each row

    Comparing a duration with the threshold here means checking whether duration − threshold is at least 0 min. The threshold is 18 min, so the comparison concerns quantities with the same unit.

    For 11, 18 − 18 = 0 min: the duration reaches the threshold and poste is roue, so the row is kept. For 12, 12 − 18 = -6 min: the duration is too short, so the row is excluded even though poste is roue.

    For 13, 25 − 18 = 7 min: the threshold is exceeded and poste is roue, so the row is kept. For 14, 18 − 18 = 0 min: >= allows equality, so this wheel row is also kept.

    For 15, 30 − 18 = 12 min: the duration qualifies, but poste with the value frein does not satisfy poste = 'roue'. AND requires this row to be excluded. A single true condition is not enough.

  4. Count by hand and choose the columns

    The filter keeps 11, 13 and 14. Counting by hand gives (1 + 1) + 1 = 2 + 1 = 3 rows. The other 2 are 12 and 15. Check: 3 + 2 = 5 rows, accounting for the entire table.

    SELECT id, duree_min keeps only these columns in the result. poste is used in the filter even though it is not displayed. Choosing a column and choosing a row are therefore different decisions. This count is done on paper; the query performs no calculation by group.

  5. Rank the rows and break the tie

    Among the rows kept, the duration 25 min for 13 comes before the durations 18 min for 11 and 18 min for 14, because DESC puts the longest durations first.

    Rows 11 and 14 have equal durations. The criterion id ASC puts 11 before 14. The complete order is therefore 13, 11, 14. Since id is unique, these criteria break all ties between rows in this table.

    Without ORDER BY, the result order is not guaranteed. With duration alone in ORDER BY, the order of rows with equal durations remains unspecified: their positions in the drawing or their insertion order do not constitute a rule for breaking ties.

  6. Apply the limit and read the result

    LIMIT 2 keeps the first 2 rows of the ranking. The result has columns id and duree_min and rows in this order: (13 ; 25 min), then (11 ; 18 min). Row 14 satisfies the filter but remains beyond the limit: 3 − 2 = 1 eligible row is not displayed.

    The limit therefore means neither "choose the first rows of the table" nor "there are exactly 2 eligible repair jobs". It only limits what this query returns.

  7. Check what the query proves

    Return to the initial data: all the returned identifiers refer to poste equal to roue and a duration of at least 18 min. Their durations decrease and the remaining tie is broken by the key. The number returned does not exceed 2 rows. The check therefore verifies the values, order and limit, as well as the number of rows.

    Removing LIMIT would make 14 reappear after 11; the 3 filtered rows would then be returned. This confirms that the limit hid this row, without WHERE rejecting it. The selection shown reads the table without changing its rows. The fictional durations prove nothing about the performance of a real repair shop.

✿03 Common mistakes

  • “SELECT roue chooses the rows where poste is roue.”

    SELECT expects names of columns to display here. The text value roue is tested in WHERE poste = 'roue'. Write separately what identifies a column and what denotes the value you are looking for.

    Reread the clauses and their roles

  • “With AND, a sufficiently long duration is enough.”

    Test the conditions on the same row: 15 takes 30 min, but its poste is frein. AND also requires poste equal to roue; the row is excluded. To fix the error, justify each condition for that same row.

    Repeat the filter row by row

  • “LIMIT always chooses the same rows, even without a complete order.”

    A limit does not define a ranking. Even with descending duration, 11 and 14 remain tied. Add id ASC to make the rule for breaking their tie explicit on this stable table.

    Fix a missing rule for breaking ties

Exercise 1 · Application · read a condition

What changes with a strict comparison?

In the same query, replace only duree_min >= 18 with duree_min > 18, meaning a duration strictly greater than the threshold. Without running anything, give the final rows, their order and their number. Explain what happens to 11, 14 and 15.

Hint 1

The > sign excludes equality. The filter on poste is still present.

Hint 2

Start with the rows kept in the example, then remove those whose duration is exactly 18 min.

Compare with the solution

The durations of 11 and 14 are exactly 18 min; they are not strictly greater. 15 remains excluded because its poste is frein, even though its duration exceeds the threshold. Row 12 is too short.

Only (13 ; 25 min) remains, giving 1 row. There is no tie for the sorting to break and LIMIT 2 does not create an extra row. The result contains fewer rows than the allowed limit.

  • You explain why equality is excluded and retain the filter on poste.
  • You distinguish the actual number of rows from the maximum limit.

The shortest among the eligible durations

Hint 2

You also need a criterion on id to break the tie between rows at 18 min.

Compare with the solution

Columns: SELECT id, duree_min

Source: FROM interventions

Filter: WHERE poste = 'roue' AND duree_min >= 18

Ranking: ORDER BY duree_min ASC, id ASC

Limit: LIMIT 2

The filter still keeps 11, 13 and 14. ASC on duration puts 11 and 14 before 13; ASC on id breaks their tie. The complete order becomes 11, 14, 13. The limit keeps (11 ; 18 min), then (14 ; 18 min).

The displayed durations are equal, but these are distinct repair jobs, identified by their keys. Changing the ranking has not changed their durations or the initial table.

Exercise 3 · Diagnosis · restore a guarantee

A correct count can hide an unjustified answer

Someone keeps the query from the example but writes only ORDER BY duree_min DESC. They claim: "LIMIT 2 guarantees 13 then 11, since 11 is drawn before 14." Is this argument valid? Give the possible outputs for our data and fix the query to guarantee the requested result.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Does the ranking distinguish 11 from 14? Do not confuse the drawn sheet with an order guaranteed by SQL.

Hint 2

The place after 13 needs a rule for breaking ties before applying the limit. Use the unique key again.

Compare with the solution

The argument is invalid: the query does not specify how to break ties between equal durations. 13 does come first with 25 min. After that, the limit may keep 11 or 14, both of which take 18 min.

The outputs compatible with this incomplete ranking are (13 ; 25 min), then (11 ; 18 min), or (13 ; 25 min), then (14 ; 18 min). An execution that returns 11 does not guarantee that the query requires it. It could even repeat this output without supplying the missing guarantee.

The fix is ORDER BY duree_min DESC, id ASC. All other clauses remain as in the example. On this stable table and with id unique, 11 then precedes 14 for equal durations. Checking only that the output contains 2 rows would have missed this defect.

Check your reasoning

  • You name the tied identifiers and the possible outputs.
  • You distinguish an observed result from a result guaranteed by the query.
  • You fix ORDER BY using the key, then justify the effect of LIMIT.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1How do you distinguish choosing rows from choosing columns?

WHERE tests a condition on each row of the table given by FROM. SELECT names the columns of the result. A column can be used in the filter without being displayed.

Recall 2In poste = 'roue', what do poste and 'roue' denote?

poste is a column name; 'roue' is a text value in single quotes. The = sign compares the column's value with that text for the row being considered.

Recall 3Why is row 15 excluded despite its 30 min?

The filter requires poste equal to roue AND a duration of at least 18 min. The duration qualifies, but poste equal to frein fails: AND requires all the conditions.

Recall 4Why combine ORDER BY duree_min DESC, id ASC with LIMIT?

Descending duration sets the priorities; the ascending key breaks ties. LIMIT then keeps the first rows of this complete order. Without a rule for breaking ties, a limit may cut through a tie without guaranteeing which identifier will be kept.

Recall 5What checks should you make before accepting the returned table?

Find the source rows, check every condition, the displayed columns, the order including its ties and the limit. The number of rows alone proves neither their identity nor their ranking.

Reconstruct the reasoning

Find the eligible rows, break ties between equal durations using the key and apply the limit. Finish by explaining what a result of the right size is not enough to prove.
