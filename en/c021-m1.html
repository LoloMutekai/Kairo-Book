Client, server and port

Your goalIdentify who requests, who listens and which port is targeted, then explain why a correct number alone does not prove that a reply has been received.

Before you start
c019-m5 : clocks and persistence · c018-m5 : contract tests and test doubles

✿01 See the idea

At the library, you want to check the opening hours on a computer. A browser page displays a “Check opening hours” button. Another program, already running on this computer, waits for requests and holds the opening hours. Pressing the button connects these programs; it does not make the browser the holder of the opening hours.

The client is the program that initiates a request: here, the browser. The server is the program that waits for requests and prepares replies: here, the opening hours program. The person clicks; the browser plays the client role. These roles describe an exchange, rather than the power or size of a computer.

To reach the opening hours program, the client must target the correct machine and the correct listening endpoint. In this scene, the destination port is the number of this listening endpoint. The opening hours program listens on port 8080. Port 8081 is a different number, even if it looks almost identical. A port is an identifier with no physical unit: it measures neither distance, time nor speed.

We choose a direct local exchange: the client and server are on the same computer. The name localhost refers to the machine from which the client communicates. HTTP is the exchange protocol used here to request and reply; we will examine its content in the next unit. All the library situations and ports are fictional, chosen for this exercise. This page does not start any program.

The rule to remember

Identify the client making the request, the server program listening, then the destination machine and port. Matching these details makes the target consistent; a reply still needs to be observed.

✿02 Follow an example

Worked example

Why the request for opening hours misses its target

The opening hours program listens on localhost, port 8080. The browser targets localhost, port 8081. In this fictional case, no program listens on the port targeted by mistake. The transport chosen for HTTP exchanges stays the same; no intermediary translates the ports. Let us compare the target before following the reply.

  1. Write down what must match

    The listening endpoint is the address, together with its port, at which a program waits for communications. Listening requires the program to have actually opened this endpoint: writing a number in a file is not enough. Here we fix the transport as TCP, which gives programs ordered communication; its internal operation is not needed to identify our target.

    Let p_d be the destination port requested by the client and p_e the listening port of the server. The letters d and e label the destination port and the listening port. These integers have no physical unit. In our case, p_d = 8081 and p_e = 8080. The target machine is already correct, so we compare the ports within the same HTTP over TCP setting.

  2. Calculate the difference to check the copied number

    Let d = p_d − p_e. The letter d on its own denotes the difference here, with no unit; the sign − means subtract. A 0 difference indicates equal numbers. We subtract only to check that they match, rather than to measure a route.

    d=pd−pe=8081−8080=1

  3. Interpret the result without inventing a neighbouring route

    The result 1 differs from 0: the requested destination does not match the declared listening port. Independent check: compare the written numbers digit by digit; their final digits differ. Even a difference of 1 is enough to identify another port. The system does not look for the program on the neighbouring number.

    Under our explicit assumption that no program is on port 8081, no reply from the opening hours server arrives through this attempt. The browser may display an error it has produced itself; this display is not a reply from the opening hours program. If another program were on this port, we would risk contacting that program: a port error does not guarantee silence.

  4. Copy the declared port and check again

    We use the port given by the opening hours program: p_d becomes 8080. We do not guess a value from the size of the difference. The check becomes 8080 − 8080 = 0; the written numbers are now identical.

    This result establishes only that the numbers match. It does not prove that the program is still running, that communication is allowed or that the opening hours will be processed correctly. For the rest of our fictional trace, we assume these conditions are met.

  5. Follow the request and the reply

    The client browser initiates communication towards the listening endpoint. The server receives the request for opening hours, consults its information and prepares a reply. This reply returns to the client, which displays it. The server remains the server while it replies: the role does not change with each arrow.

    The port displayed in the scene is the destination port on the server side. The system also manages a port on the client side for the communication; we do not calculate it here. The browser does not need to have the same listening port as the server.

  6. Distinguish a consistent target from an observed result

    For our successful fictional trace, we record the request received by the opening hours program and its reply returned to the browser. These events add to the simple match between the numbers. A drawing of arrows or a written number does not constitute this observation in a real system.

    Even a reply actually received does not by itself demonstrate that the opening hours are up to date: that would be another check. Here, the intended result is narrower: being able to name the roles, target the correct listening endpoint and say what evidence is missing when no reply has been observed.

✿03 Common mistakes

  • “A server must be another large computer.”

    Here, the word refers to a program that listens and replies. In the library, the client browser and the server program share a machine; their roles remain distinct. Start again from the nested boxes in the drawing.

    Review the programs inside their machine

  • “The port is almost right, so the request will arrive next door.”

    8081 and 8080 are distinct identifiers. The difference of 1 does not measure any useful proximity. Return to the declared configuration of the intended program, then check exact equality; do not try ports at random.

    Compare the numbers again

  • “The correct port is written down, so the service works.”

    A configuration specifies a target. It remains to establish that a program is actually listening and that the request receives a reply. Even a received reply requires a check of its content before claiming that the opening hours are correct.

    Test the conclusion in the exercises

Exercise 1 · Identification with explanation

Who acts, who waits?

On the library computer, a person clicks to request the opening hours. The browser sends the request to the program listening on port 8080; this program replies. Name the client, the server and the destination port. Does the server become a client when it sends its reply back?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Look for the program that initiates this exchange, then the one that waits for requests.

Hint 2

A return arrow belongs to the same exchange; consider what the word role describes.

Compare with the solution

The browser is the client: it initiates the request. The opening hours program is the server: it listens and replies. The person triggers the browser’s action but is not the client program. The destination port is 8080.

The return is the server’s reply in this exchange; it does not reverse the roles. Both programs can run on the same computer. We do not need to imagine a second machine to distinguish them.

Exercise 2 · Application and checking

The listening endpoint has changed

In a fictional variation of the same library, the opening hours program is restarted on localhost, port 8090. No program remains at the old listening endpoint. The browser keeps localhost, port 8080. Calculate d = p_d − p_e, state what no longer matches and give the destination correction. What further check would still be needed?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The server gives the new value of p_e; the browser keeps the old value of p_d.

Hint 2

A negative difference is also nonzero. After correcting the destination, distinguish equal numbers from a reply actually received.

Compare with the solution

The specified machine has not changed. The requested port is 8080 and the listening port is 8090: d = 8080 − 8090 = -10. The numbers differ. The sign indicates only the direction of subtraction; it indicates neither a delay nor how far away the program is.

You must target the declared port 8090. Check: 8090 − 8090 = 0. The old destination does not reach the server under the stated conditions. With the corrected destination, it would still be necessary to observe that a request reaches the program and that a reply returns; the calculation does not demonstrate this.

Check your reasoning

  • I write the requested port followed by the listening port, in that order, and obtain -10.
  • I correct the port to 8090 without changing the specified machine.
  • I distinguish the equality check from evidence of a successful exchange.

Exercise 3 · Transfer and limits of evidence

The same request from a phone

Return to the opening hours program on the library computer, port 8080. A person opens the page on their phone. They keep machine = localhost and port = 8080, then say: “The numbers are equal, so I am targeting the library computer.” Is this true? Explain what would need to change and what cannot yet be concluded, without inventing a network address.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Which machine does localhost refer to from this new client?

Hint 2

Equal ports do not establish the identity of the machine. The details needed to reach the computer from the phone are not provided.

Compare with the solution

From the phone, localhost refers to the phone. The client therefore targets its own device on port 8080, rather than the library computer. The calculation 8080 − 8080 = 0 confirms equal numbers, but compares numbers on different machines: it is not enough to identify the target.

To request the opening hours from the computer, a name or address would be needed that identifies this computer and allows it to be reached from the phone, along with an accessible listening endpoint on the declared port. This information is not given. We do not know whether connections from the phone are configured or allowed. The opening hours program has not become a client: the client has changed machines.

The repair consists first of identifying the correct machine and connection conditions, then checking an authorised exchange. Copying a port establishes none of these conditions. Check your reasoning

  • I interpret localhost from the current client’s perspective.
  • I keep the distinction between machine and port despite the numerical equality.
  • I invent neither a reachable address nor successful communication.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1When checking the opening hours, how do you identify the client and the server?

The browser initiates the request: it is the client. The opening hours program listens and prepares a reply: it is the server. These are program roles, and the programs can share a machine.

Recall 2What does the destination port identify, and what does it not measure?

In our HTTP over TCP exchange, it identifies the targeted listening endpoint on the chosen machine. It is an integer with no physical unit, rather than a distance, time or speed; a neighbouring number does not reach the same endpoint.

Recall 3Why does localhost with the same port not always target the library?

localhost refers to the machine from which the client communicates. On the library computer, it is that computer; on the phone, it is the phone. The port must be interpreted together with the target machine.

Recall 4You have checked that the requested port and the declared port are equal. What have you proved, and what evidence is missing?

The numbers match. It remains to identify the correct machine, establish an accessible listener and observe a reply to a request. A received reply still does not guarantee that the opening hours are up to date.
