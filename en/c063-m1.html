Level 2 · C063·M1

Seed and generator

Your goalCalculate a pseudorandom sequence from its seed and state the conditions needed to replay a simulation exactly.

Before you start
c030-m5 : Poisson · c013-m5 : recursion · c055-m5 : confidence interval · c017-m5 : reproduction protocol

✿01 See the idea

You are preparing a simulation of a service counter. Before managing the queue, you generate a sequence of times between arrivals: 1 min, 2 min, 7 min. You want to be able to recover this exact sequence when a result surprises you. The times, seed and parameters in this scene are fictional; no real arrivals have been measured.

Imagine a small machine with an internal counter. The seed chooses its starting position. Each call advances this counter according to a fixed rule, then produces a number. The generator is this machine together with its rule and current state; the seed is only its starting point.

The sequence is called pseudorandom because a deterministic calculation produces it for use in random applications. Knowing the state and the rule lets us predict the next output here. Reproducibility is useful for investigating results; it does not guarantee that the numbers have all the desired statistical properties.

Initialize once at the start of the run, then advance. Returning to the seed before each arrival restarts the sequence at the same point. Conversely, an extra call consumes an output and shifts the outputs assigned to later arrivals.

The rule to remember

To replay the sequence, keep the seed, the exact generator, the conversion rule and the same order of calls; during the run, keep the state as it advances.

✿02 Follow an example

Worked example

Generate the sequence of times between arrivals at the counter

Let us calculate the first 3 times between arrivals with a miniature generator: multiplier a = 5, increment c = 1, modulus m = 16, seed g = 3. We advance before producing the first output. This generator is a tool for calculations on paper, rather than the implementation cited in the milestone.

  1. Define the state and the remainder of division

    n is the number of calls already made; sn is the integer state after those calls. Initially, s with subscript 0 equals g. a, c, m and g are dimensionless integers; m is strictly positive. Here each state ranges from 0 to 15 inclusive. A call multiplies the previous state by a, adds c, then keeps the remainder of division by m.

    sn+1=(asn+c) mod m

    The symbol mod means “remainder of integer division”. To find it, write b = qm + r, where b is the result before reduction, q is the integer quotient and r is the remainder, all dimensionless. Choose q so that 0 ≤ r < m. This does not mean rounding b/m. The calculation uses exact integers, without overflow.

  2. Advance from the seed

    Multiply to apply the rule: 5 × 3 = 15. Adding gives 15 + 1 = 16. We need to subtract a multiple of 16 to return to the allowed interval.

    16=1×16+0

    The quotient is 1 and the amount subtracted is 16; the state becomes 16 − 16 = 0. A 0 remainder is allowed. Keep this state without resetting the seed.

  3. Make the next calls with the new state

    Second call: 5 × 0 = 0, then 0 + 1 = 1. This result is already between 0 and 15: the integer quotient is 0 and the remainder is 1.

    Third call: 5 × 1 = 5, then 5 + 1 = 6. Check the bounds in the same way: the quotient is 0. The state sequence is 0, 1, 6. The seed 3 has not been copied into it as an output.

  4. Distinguish a dimensionless number from a time between arrivals

    A common way to present the output is to divide the state by m to give a dimensionless output un in the interval from 0 inclusive to 1 exclusive. This rescaling does not turn a deterministic sequence into independent draws.

    un=snm;dn=(1+sn)×1 min

    The outputs are 0, 1/16, 3/8, or 0.0000, 0.0625, 0.3750 in dimensionless form. The fractions are exact; the decimal representations given here are also exact.

    dn denotes the time between arrivals assigned to output n. For this exercise alone, we choose the fictional rule “add 1, then count in minutes”. The times between arrivals are therefore 1 + 0 = 1 min, 1 + 1 = 2 min and 1 + 6 = 7 min. These are intervals, rather than cumulative arrival times. This rule is not a justified arrival distribution for a real service counter.

  5. Check the calculation and the conditions for replay

    Check the first remainder by reversing the calculation: 1 × 16 + 0 = 16. The following states are already less than 16 and nonnegative. The times between arrivals stay positive despite the state 0. These checks verify the reduction and units without measuring statistical quality.

    To reproduce the whole sequence, record the seed 3, the exact rule with a, c and m, the convention “advance before output”, the conversion into minutes and the sequence of calls. In software, also keep the inputs, versions and implementation of the sampling functions. Equal seeds alone are not enough if another call consumes a value.

    A generator with a finite state can eventually return to a previously visited state and repeat the sequence. Our miniature machine is unsuitable for demanding simulations or for generating secrets. Even a perfectly replayed sequence does not demonstrate that the counter model represents reality. The next unit will build the event model; here we have only prepared the source of the numbers.

Explain it in your own words

Hide the calculations: explain why the seed is enough to recover our sequence only if the rule and the calls stay identical. Then justify why a 0 state can give a positive time between arrivals.

✿03 Common mistakes

  • “I reset the seed before each arrival to make the run reproducible.”

    Initialize at the start of the complete run, then keep the state as it advances. Otherwise, you always get the first output and the times between arrivals repeat artificially. Compare the two sequences in the diagram.

    Compare the starting procedures

  • “To find the remainder, I divide and round.”

    Find the integer quotient q, then subtract qm. Check the equality b = qm + r and the bounds of the remainder. The quotient and the remainder play different roles; the division that gives u comes afterward.

    Repeat the reduction and check it by reversing the calculation

  • “Same seed: same events, necessarily independent.”

    The seed fixes a starting point, rather than the assignment of calls to events. An added call shifts the sequence. Neither a different seed nor a successful replay proves statistical independence or the realism of the model.

    Examine the extra call in the final exercise

Exercise 1 · Guided calculation

Extend the sequence

The current state is 6 after the 3 calls in the example. Calculate the next state, its output divided by m and the corresponding time between arrivals, without resetting. Give the integer quotient and check the remainder.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Multiply the current state by 5 and add 1 before reducing.

Hint 2

Subtract a multiple of 16; the remainder must be less than 16.

Compare with the solution

Multiplication gives 5 × 6 = 30; adding gives 31. The integer quotient is 1 and the state is 31 − 16 = 15. Check: 1 × 16 + 15 = 31 and 0 ≤ 15 < 16.

The dimensionless output is 15/16, or 0.9375. The time between arrivals is (1 + 15) × 1 min = 16 min. The time between arrivals is not the remainder, since a separate conversion gives it its unit.

Check your reasoning

  • Start from 6, without returning to 3.
  • Justify the quotient and the bounds of the remainder.
  • Distinguish the dimensionless 15/16 from 16 min.

Exercise 2 · Diagnosis with explanation

The sequence that keeps restarting

A program resets g = 3 before each arrival, then makes a call. What are its first 3 times between arrivals? Fix the procedure to recover the sequence in the example, then explain what to do when you want to replay a complete run.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

After each reset to the seed, what was the first calculated state?

Hint 2

Separate the start of a run from the start of a new arrival within that run.

Compare with the solution

Each reset to the seed returns to the calculation whose output state is 0. The times between arrivals become 1 min, 1 min, 1 min. The sequence 1 min, 2 min, 7 min has been lost: the generator no longer advances between arrivals.

Move initialization before the arrival loop and keep the same generator during the run. To replay the whole run, then recreate the generator from the initial seed and repeat the same sequence of calls. Resuming partway through a run would require the exact current state, or replaying the calls already made.

Check your reasoning

  • Find the repeated times between arrivals and explain their origin.
  • Place initialization at the start of the complete run.
  • Distinguish replaying from the beginning from resuming from a current state.

Exercise 3 · Apply to the protocol

The same seed, one extra call

Two versions of the counter simulator use our rule and g = 3. Version A makes one call per arrival. Version B first makes a diagnostic call and discards its output, then makes one call per arrival. Give the first 2 times between arrivals for each version. How can you fix the comparison? Does this disagreement prove that the generator is broken?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Write out the state sequence and cross out the output consumed by the diagnostic call.

Hint 2

The same output must correspond to the same arrival for this comparison to be aligned.

Compare with the solution

A assigns the states 0 then 1 to arrivals: times between arrivals of 1 min then 2 min. B has already consumed 0 for the diagnostic call; it assigns 1 then 6: times between arrivals of 2 min then 7 min. The generated sequence is the same; its assignment to arrivals has changed.

For this comparison, the diagnostic call must observe without consuming a draw from the arrival generator. You can prepare a shared sequence of times between arrivals, then supply the same element to the same arrival in each version. Recording only the seed does not describe this assignment.

This shift follows the generator rule. It demonstrates neither a fault nor independence between the sequences. Keeping the sequence makes the comparison replayable; checking the quality of the generator and the relevance of the arrival distribution remains a separate task.

Check your reasoning

  • Match each time between arrivals to the correct call in both versions.
  • Propose a fix that aligns the inputs for arrivals.
  • Separate the shift in calls, statistical quality and model validity.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is the difference between the seed and the current state?

The seed initializes the generator; the current state changes with each call. Returning to the seed restarts the sequence. To resume partway through a run, you need to recover the state reached, rather than just the starting point.

Recall 2How do you calculate and check the next state of our machine?

Calculate b = a times the current state + c, write b = qm + r with integer q and 0 ≤ r < m, then keep r. Check by reconstructing b. Dividing the remainder by m then gives u, rather than the new integer state.

Recall 3Why is the seed alone not enough to describe a replay?

You need the same generator, its parameters, the sampling functions and their version, the same inputs and the same order of calls and conversion. An extra call can shift the output assigned to each arrival.

Recall 4What does an exactly reproduced sequence prove, and what does it fail to prove?

It establishes the replay of that sequence under the recorded procedure. It establishes neither independence of the outputs, nor statistical quality of the generator, nor realism of the simulated arrivals.

Reconstruct the reasoning

Without looking at the lesson, draw the seed, an advancing state and the conversion into a time between arrivals. Then reconstruct a call with its remainder and its reverse check. Finish by explaining what an added call changes and what a successful replay does not demonstrate.
