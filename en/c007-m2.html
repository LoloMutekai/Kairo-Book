Level 0 · C007·M2

Text formats

Your goalInspect the characters in a text file, split it into lines and fields, then decide whether a strict CSV reader can read it, without relying on the filename suffix alone.

Before you start
C002·M4 : correcting errors · C007·M1 : paths

✿01 See the idea

In the fictional workshop from C007·M1, the path /atelier/recettes/granola.txt leads to your granola recipe card. It lists 2 portions of oats and 1 portion of nuts: fictional quantities chosen for the example, with no nutritional advice. The example keeps the literal labels avoine (oats), noix (nuts), and doses (portions) so the character counts stay the same. A colleague wants to give this card to a table reader that only accepts CSV format. They suggest renaming it granola.csv. Is that enough?

A text file is a sequence of characters. Some are visible: letters, digits, colons, commas. Others organize the page, such as spaces or line endings. In our card, each line ending is the LF character, short for line feed. We draw it as ↵ to make it visible; in the file, it has no visible symbol.

A format is a convention that says how to interpret these characters. On each line, the text card writes an ingredient name, a colon, a space, then a quantity. You can read it easily, but a program is under no obligation to understand it. CSV format, short for comma-separated values, arranges data in columns: a comma separates two fields on the same line, and a first line, the header, can name the columns.

The suffix is the end of the name after the last dot: .txt or .csv. Think of the label stuck on a cardboard folder: changing it does not rewrite any of the sheets inside. Renaming changes the name and leaves every character in place. To know whether a reader will find its columns, you must look at the separators actually written in the file.

The reader on this page is deliberately strict and limited. It requires the exact header ingredient,doses first, then exactly one comma on each line. CSV files found elsewhere have more features: quotation marks, a comma inside a field, semicolons in some local conventions, line endings made up of two characters. These variants are outside this unit; another reader would have a different contract to review.

The rule to remember

Inspect the characters before the name: split at line endings, set the header aside, and count the separators on each line. The suffix is only a clue; renaming does not convert anything.

✿02 Follow an example

Worked example

Read granola.csv, then the text that was only renamed

The converted file contains exactly the characters ingredient,doses↵avoine,2↵noix,1↵, where ↵ denotes LF. Let us count its lines, records and fields, check by a second method, then give the same reader the text card renamed without conversion.

  1. Name the quantities and the reader’s contract

    A physical line is a sequence of characters ending in an LF. A record is a line that carries a data item, here an ingredient. A field is a part of a line between two separators, or between the edge of the line and a separator.

    Let L be the number of physical lines, h the number of header lines, N the number of records, v the number of commas on a line and c the number of fields on that line. These are integer counts; their units are lines, commas and fields, never bytes.

    Assumptions for the strict reader: the file ends with an LF; nothing follows this final LF; the first line is the exact header ingredient,doses; each line has the same number of commas; there are no quotation marks or commas inside fields. The following two relations hold only under these assumptions.

    N=L−h
    c=v+1

    The first subtracts the header from the lines counted. The second says that one more cut gives one more piece: one comma makes two fields, while no comma leaves the whole line as a single field.

  2. Count the physical lines

    Reason: the reader splits at LF, and each LF closes a line. We go through the characters, placing a marker at each ↵: after doses, after 2, after 1.

    L=nombre de LF=3 lignes

    The position after the last LF does not start a line: no characters are written there. An editor sometimes places the cursor there; counting that position as a line would mean counting an empty space.

  3. Set the header aside

    Reason: the first line names the columns; it does not describe an ingredient. The reader checks that it is exactly ingredient,doses, then removes it from the count.

    N=L−h=3−1=2 enregistrements

    Result: avoine and noix. Sense check: the text card also described 2 ingredients, one line each.

  4. Split each line into fields

    Reason: the comma is the only field separator in the contract. On the line avoine,2, we find v = 1 comma.

    c=v+1=1+1=2 champs

    The first field is avoine; the second contains the character 2. The reader extracts characters. Deciding that this second field represents a number is a separate step, which is not covered here.

  5. Check by a second method

    All the lines have c = 2 fields. The file therefore contains L × c = 3 × 2 = 6 fields, including the header.

    Second method, without using the field relation: we count 3 commas in the whole file, and each line has one more field than it has commas. We get 3 + 3 = 6 fields. The two counts agree.

    L×c=L×v+L

    The data occupy N × c = 2 × 2 = 4 fields. That leaves 6 − 4 = 2 for the header: ingredient and doses, which is what we see written.

  6. Give the renamed text to the same reader

    Let us rename granola.txt to granola.csv without changing anything else. The content remains: avoine, colon, space, 2, LF, then noix, colon, space, 1, LF. Before: 18 characters. After: 18.

    écart=18−18=0 caractère

    The reader applies its contract. The first line is not ingredient,doses. It contains 0 commas, so c = 0 + 1 = 1 field: 1 is missing. Verdict: rejected, with the reason “incompatible structure”. The reader did not consult the name; it read characters.

    Check: the reader is not faulty. With the file that was actually converted, the same rule read 2 records in the previous steps.

  7. What this calculation does not establish

    We have counted characters, not bytes: converting between them depends on an encoding, which is not studied here. The quantities remain fictional and are never added together as a recipe; only lines and fields are counted. A less strict reader, or one configured for semicolons, would have a different contract: we would have to count again using its rules.

✿03 Common mistakes

  • “Changing the suffix converts the file.”

    Renaming only changes the name stored in the directory. The 18 characters stay identical, with a difference of 0, and no commas appear. Converting means rewriting the content: the header, then a comma in place of the colon and space.

    Work through the example again up to the renamed text

  • “Every line must be a data item.”

    In granola.csv, the first line names the columns. Count 3 physical lines, then subtract the header: 2 records remain. Before counting data, ask what each line describes.

    Review the removal of the header in the example

  • “A text file never has any structure.”

    A text file opens in a simple editor, but its characters can follow a precise convention: line endings, separators, a header. CSV is one example. Being readable by you does not mean there are no rules for a program.

Compare with the solution

Lines: 3 + 1 = 4. Records: 4 − 1 = 3, namely avoine, noix and raisins.

Data fields: 3 × 2 = 6. Total: 4 × 2 = 8. Check: 4 lines with 1 comma each make 4 commas; with one more field per line, 4 + 4 = 8.

The quantity of raisins is fictional and does not enter any of the counts: only the presence of the line matters.

Check your reasoning

  • L includes the header; N does not.
  • The total is checked by a second method, using the commas.
  • The answers are exact integers, with no tolerance.

Exercise 3 · Notebook challenge

Convert by hand and measure the change

Rewrite the text card in the fixture’s CSV format, marking each LF with ↵. Then count the characters before and after, and explain the difference without recounting the whole file.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

First write the line that names the fields: ingredient, then doses.

Hint 2

On each ingredient line, the colon and space become a single comma.

Compare with the solution

Expected content: ingredient,doses↵avoine,2↵noix,1↵, with no space after the comma and with the final LF kept.

Before: 10 + 8 = 18 characters. After: 17 for the header, then 9 + 7 = 16 for the data, giving 17 + 16 = 33.

Direct difference: 33 − 18 = 15. Explanation: the header adds 17 characters; each ingredient line loses one, giving 18 − 16 = 2 in total. Thus 17 − 2 = 15: the two methods agree. Renaming, by contrast, gave a difference of 0.

Check your reasoning

  • Exact header, one comma per line, final LF kept.
  • Difference obtained directly, then explained by a second method that agrees.
  • Conclusion: conversion changes the content; renaming does not change it.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does a text file contain?

A sequence of characters, including line endings; on the card, each line ending is the LF character.

Recall 2What is a text file format for?

It specifies how to interpret the characters: where lines end, which character separates fields, what the first line describes.

Recall 3In the CSV fixture, how do we get from commas to fields?

Each comma splits the line: a line has one more field than it has commas, since there are no quotation marks or commas inside fields.

Recall 4Why do we count N = L − h records?

The header names the columns without describing an ingredient; we subtract it from the physical lines to count the data.

Recall 5Does renaming granola.txt to granola.csv make it readable by the strict reader?

No. The suffix is a clue; the characters stay the same. You must inspect the content and convert it if necessary.

Reconstruct the reasoning

A text file is a sequence of characters and line endings. A format says how to interpret them: split at LF, set the header aside, split each line at the comma. We count L lines, N = L − h records, one more field than commas per line, then check using the total number of commas. The suffix indicates a format without proving it: renaming keeps the same characters; only conversion changes the structure.
