Execution traces

Your goalKeep a trace that lets you repeat the count for the granola recipe sheet, then distinguish a successful command from an answer to the question asked.

✿01 See the idea

You find the number 3 on a sheet of paper, supposedly answering the question “How many ingredients does the granola recipe sheet contain?” The action that produced it is missing. Did someone count the recipe, its photo caption, or something else? The number alone cannot tell you.

An execution trace is the receipt for a trial: it connects what was supplied, the working conditions, the command requested and what came back. The current directory indicates where the path starts; the environment identifies the available tools; the saved content specifies which version of the file was read.

In our fictional workshop, the command wc -l counts line endings called LF. It does not recognize oats or walnuts. The sheet contains a header naming the columns, followed by the ingredients. You therefore need to inspect what the counter counted before answering.

The whole scene, its environment A and the receipts below are fictional. The page does not use a real terminal. The symbol ↵ represents an LF line ending; it makes this character visible in the diagram and is not part of the file content.

The rule to remember

Keep the question, exact input, context, command and its outputs together. Then check whether the result answers the question.

✿02 Follow an example

Worked example

Keep the receipt for the correct count

The question is: “How many ingredients are described in recettes/granola.csv?” We are in /atelier, with the fictional environment A. The exact sheet is the one in the diagram: ingredient,doses followed by avoine,2 and then noix,1, with each line ending in LF. Let us follow the count and its interpretation.

  1. Specify the input and the conditions for repeating the trial

    From /atelier, the relative path recettes/granola.csv refers to /atelier/recettes/granola.csv. The receipt keeps these paths, the current directory and environment A. In this fictional environment, wc refers to the LF counter described here; it reads the file without changing it. No actual installed tool or version number is assumed.

    Also keep the file characters, including the line endings: the same path may refer to changed content in another trial. The file in this scene stays unchanged while it is read. The question asked is also part of the receipt, because counting lines and counting ingredients require different conclusions.

  2. Keep each output in its own field

    The exact command for the trial is wc -l recettes/granola.csv. Its name is wc; -l requests a count of line endings; recettes/granola.csv specifies the file to read. The fictional receipt gives “3 recettes/granola.csv” as standard output, empty content as standard error, and 0 as the exit code.

    Standard output is the channel that receives the count here. Standard error receives failure messages. The exit code is an integer indicating how the command ended: in this scene, 0 means that the counter reported no error, and 1 indicates a failure to read the missing path. This code is a status with no unit, never a quantity of lines or ingredients.

  3. Check what the counter reports

    The diagram shows 1 LF after the header, 1 after the oats line and 1 after the walnuts line. We add these line endings because wc -l counts each of them, including the one after the header.

    1+1+1=3 fins de ligne LF

    The number 3 in the output is therefore consistent with the saved input. The final LF ends the last line; it does not add an empty data line. If this final LF were missing, counting LF would no longer give the number of text lines present. Our receipt must therefore preserve this detail.

  4. Convert lines into ingredients

    The first line, ingredient,doses, states the column names. It is not an ingredient. Subtract the header, which is 1 line, from the total count to obtain the data lines.

    3−1=2 lignes de données

    Here, each data line describes 1 distinct ingredient: oats, labelled avoine, then walnuts, labelled noix. There are therefore 2 ingredients. The values 2 and 1 in the doses column measure fictional portions; they are not line counts.

    This conversion assumes the stated header, no empty lines, no field containing a line break, no repeated ingredient and 1 LF at the end of each line. It is not a general method for all CSV files. We check these assumptions by reading all of the short content provided.

  5. Check the result another way

    Without using subtraction, point to the names: avoine, meaning oats, contributes 1 ingredient and noix, meaning walnuts, contributes 1 ingredient; this gives 2 distinct ingredients again. Then reconstruct the lines: 1 header line + 2 ingredient lines = 3 lines ending in LF.

    These checks return to the content instead of simply rereading the displayed number. The receipt now concludes: “technical count successful, 3 LF; after inspection of the format, 2 ingredients.” This answers the original question under the stated assumptions.

  6. Also keep the trial that fails

    In the same workshop, change only the target to recettes/absente.csv, which is declared missing from the scene. The command wc -l recettes/absente.csv gives empty standard output, the standard error message “fichier absent” (file missing) and exit code 1. This wording belongs to the fictional receipt; it is not a message guaranteed on every machine.

    No line count was produced for this target. Writing 0 lines would replace a failed read with an invented result. An existing but empty file would be a different case: our counter could read it and return 0 LF with exit code 0. Keep the failure as a separate trial; a later repair does not change its receipt.

  7. Find the success that answers the wrong question

    The photo caption for the same granola is in /atelier/photos/legende.txt. Its exact content is “légende” (the French word for caption) followed by an LF. From /atelier, wc -l photos/legende.txt produces “1 photos/legende.txt”, empty standard error and exit code 0. The counter read this file and completed its own task successfully.

    This does not count the recipe ingredients at all: the target is the caption. Exit code 0 can therefore accompany either the correct sheet or another existing file. To repeat the original trial usefully, restore the directory, environment A, exact CSV content and command from the initial receipt, then compare the outputs before interpreting them again.

Explain it in your own words

Hide the diagrams. Explain how the number of LF becomes a number of ingredients in this sheet. Then explain why the same success code can appear when the wrong target was read.

✿03 Common mistakes

  • “The success code proves that my answer is correct.”

    Check the target and what the command counts. The caption also gives exit code 0. For the correct CSV, you still need to distinguish its 3 LF from its 2 ingredients.

    Review the target and the check against the original question

  • “The read failed: I write a count of 0.”

    Keep exit code 1 and the read error. The line count remains missing. A result of 0 LF for an empty, readable file would be different information.

    Reread the trial with the missing path

  • “A photo of the number is enough to repeat the trial.”

    Connect the output to the content, path, current directory, environment and command. Without these inputs, the same number could have come from reading something else. Keep every receipt; do not replace the old one after a repair.

Compare with the solution

The command counted 3 LF line endings without reporting an error. It does not recognize the role of each line. The proposed statement therefore confuses a technical result with an interpretation.

Inspection reveals 1 header line and the names avoine and noix, meaning oats and walnuts: 3 − 1 = 2 data lines, giving 2 ingredients in this sheet. This subtraction is justified by the assumptions checked in the example.

R and L have exit code 0: 1 + 1 = 2 technical successes. A has exit code 1: 1 failed trial. Check the totals in this ranking by exit status: 2 + 1 = 3 trials.

The isolated number does not identify the file, command or environment. The statement “recipe checked” is a conclusion without the supporting evidence. The lost trial remains undetermined; we prepare a new, explicitly fictional trial.

Question for the new trial: how many ingredients are in recettes/granola.csv? Current directory: /atelier. Environment: A, with the wc counter from the scene. Target: /atelier/recettes/granola.csv. ✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must you keep with the result to repeat our file read?

The question, current directory, environment providing the counter, file path and exact content, command, standard output, standard error and exit code. A trace belongs to a specific trial.

Recall 2What does wc -l count, and why is subtracting the header justified here?

The counter counts LF. In this sheet, every line ends with LF; the sheet has 1 header line and 1 line per distinct ingredient, with no empty line or field spanning several lines. Thus 3 − 1 = 2 ingredients, after inspection.

Recall 3Why keep standard output, standard error and exit code separate?

Standard output carries the count here; standard error explains a failure; the code indicates how the command ended technically. An exit code does not have the unit of a line count. Empty standard output in the missing-path trial is not a count of 0.

Recall 4Which counterexample shows that a success code does not prove the goal was reached?

Reading photos/legende.txt gives 1 LF and exit code 0, but did not read the recipe. Even for the correct recipe, you still need to examine the format before converting LF into ingredients.

Recall 5What is the difference between a count of 0 and a failed read?

0 LF is a possible result for an empty file that was actually read. In the missing-path trial, no count is produced: we keep the error and exit code 1 without inventing the target content.

Reconstruct the reasoning

Without looking at the receipt, reconstruct its sequence: question → content and context → command → outputs and code → check the meaning.
