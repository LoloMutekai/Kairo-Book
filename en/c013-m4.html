Level 1 · C013·M4

Aliases and mutation

Your goalPredict what changes in a playlist by distinguishing aliases, shallow copies, mutation of a card, and replacement of a reference.

Before you start

✿01 See the idea

You are preparing a playlist with an introduction lasting 45 seconds and a theme lasting 75 seconds. You put the labels a and b on the same rail of track cards. Adding a card through b makes the playlist reached through a longer: the labels differ, but the rail is shared.

You then build a rail c by taking the references to the cards on rail a. Rail c is new; the cards remain the same. Adding to a therefore creates no slot in c. Changing the duration written on a shared card, however, is visible through both rails. This is the distinction between copying a container and copying what it contains.

In our Python representation, the rail is an outer list. Each card is itself a list containing a track name and its duration. A reference is a link to an object; an alias is another name bound to the same object. A mutation changes an existing object. A shallow copy builds only a new outer container with the same references to elements.

The durations are fictional. We are working with lists, without music files or an audio player. The letters A, C, I, H and J in the diagrams label objects and have no units; they do not represent memory addresses. The arrows show the direction of each link. The second diagram compares separate trials, each restarted from the beginning.

The rule to remember

Before making a change, follow the references to the target: the name, a slot in the outer list, or an inner card. Only paths that reach the modified object show its mutation.

✿02 Follow an example

Worked example

Add a track, then lengthen the introduction

We will execute these steps in order: build a, bind b to a, copy a into c, add "fin" through b, then set the duration of "intro" to 60 s through c. We make no other changes between these instructions. Before reading on, predict the list lengths and their total durations separately.

  1. Build the playlist and define the conventions

    a = [["intro", 45], ["thème", 75]]

    a is a name bound to an outer list. Each pair of square brackets builds an inner card: its first element is the track name, and its second is its integer duration in seconds, written s. The outer list contains 2 cards; we have created 3 list objects in total, the rail and its cards.

    Position indices start at 0 and have no units: a[0] reaches the intro card; a[0][1] reaches its duration field. Successive brackets follow successive links. T(a) will denote the sum of the durations of the cards on rail a, in seconds. We count each track once, with no overlap or added silence.

    Initial total: T(a) = 45 + 75 = 120 s. This sum describes the represented playlist; it does not measure audio playback.

  2. Give the same rail another name

    b = a

    The expression on the right denotes the rail already bound to a; the assignment binds b to that same object. It builds no list. a and b are aliases. Writing through b can therefore modify the object you read through a.

    In Python, "b is a" asks whether the names denote the same object; the answer is True, meaning true. "b == a" compares their contents; this equality is also true, but it would not be enough to establish their identity.

  3. Copy only the outer rail

    c = a.copy()

    copy() builds a new outer list and places the references already contained in a into it. The total number of list objects becomes 4. c has 2 slots, each pointing to the same card as the corresponding slot in a.

    "c is a" evaluates to False, meaning false; "c == a" still evaluates to True. However, "c[0] is a[0]" evaluates to True: the first elements are the same intro card. The copy is shallow because its independence stops at the outer rail.

  4. Add through the alias and count the correct slots

    b.append(["fin", 30])

    append adds an element to the end of the target list. The brackets around "fin" and its duration build a new card, then the call adds its reference to the rail shared by a and b. There are now 5 list objects in the scene.

    The lengths of a and b increase from 2 to 3 cards. c keeps 2 cards: its own rail has received no new slot. Before changing intro, the totals are T(a) = T(b) = 120 + 30 = 150 s and T(c) = 120 s.

  5. Reach the shared card through the copy

    c[0][1] = 60

    The first index follows c to the intro card; the second identifies the duration field in that card. The assignment replaces the number in the existing card. It replaces neither rail c nor its reference to intro.

    This card is still reachable through a and b. Reading a[0][1], b[0][1] and c[0][1] therefore gives 60 s in every case. The number of cards on each rail stays the same. The increase in duration is 60 − 45 = 15 s.

  6. Calculate the final durations without counting aliases twice

    a and b traverse the same rail, with intro, theme and fin. c traverses its own rail, with intro and theme. We add the durations of the cards reachable from each rail, without adding a and b together as though they were distinct playlists.

    T(a)=T(b)=60+75+30=165 s
    T(c)=60+75=135 s

    The total for c has changed while its length remains 2. Counting slots and adding their durations answer different questions.

  7. Check using differences and links

    Start from the totals before the inner mutation: 150 + 15 = 165 s for the shared rail, and 120 + 15 = 135 s for c. This alternative method recovers the final sums using only the increase for intro.

    The difference T(a) − T(c) is 165 − 135 = 30 s, exactly the duration of fin, the only card absent from c. The intro and theme cards must still be the same objects on both rails. A total alone would not prove this sharing: you also need to follow the references.

  8. Compare with replacing a card

    For this separate trial, rebuild a from the beginning, then repeat b = a and c = a.copy(). Do not add fin or modify the old card. Execute only the following instruction.

    c[0] = ["intro", 60]

    The right side builds a new card J. The target on the left is the slot in rail c: it receives a reference to J. The original card I is not modified. a and b keep intro at 45 s, and their total remains 120 s. c reaches intro at 60 s and totals 135 s.

    The lengths remain 2 cards everywhere. "c[0] is a[0]" now evaluates to False, while the theme cards remain shared. To explain a mutation, you need to specify the target object and slot; the word "copy" is not enough.

Explain it in your own words

Hide the steps and draw the names, rails and cards. Reconstruct the lengths and durations after the addition and then the mutation. Explain why replacing c[0] and modifying c[0][1] do not affect the same list.

✿03 Common mistakes

  • “b = a creates a second playlist.”

    This instruction creates a binding from b to the existing rail. No list construction using brackets or copying takes place. Follow both arrows in the diagram to the shared rail, then predict where append adds its slot.

    Find the shared rail in the first diagram

  • “With copy(), I can modify the cards without affecting the original.”

    A shallow copy separates the rails but keeps the references to the cards. Check "c[0] is a[0]" immediately after copying: the intro card is shared. Changing its duration field will be visible through both rails.

    Review the copy followed by the mutation of the shared card

  • “Replacing c[0] is the same as modifying c[0][1].”

    The first action changes a reference in rail c. The second changes a field in the card reached through c. Start with fresh lists and draw the target before the assignment; the old card can remain accessible from a.

    Compare the replacement trial with the inner mutation

Hint 2

The addition affects the target rail. No inner duration has changed yet.

Compare with the solution

a and b are aliases: they reach the same rail. Its length becomes 2 + 1 = 3 cards, and its total becomes 45 + 75 + 30 = 150 s. The result is therefore identical when read through a or b.

c keeps 2 cards and totals 45 + 75 = 120 s. Its outer copy has not received the reference to fin. This result is consistent with sharing the old cards: append does not modify any of them.

Exercise 2 · Application · follow two accesses

The length stays the same, the duration changes

Start again from the same initial state, with b an alias of a and c a shallow copy, without adding fin. Execute only c[0][1] = 60. Give the lengths and totals, then answer this objection: "c has its own rail, so a must keep its old duration."

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The first index reaches a card; the second reaches a field in that card. Which object is shared?

Hint 2

Compare the new total with the initial total using the difference between the durations of intro.

Compare with the solution

The intro card remains shared by the rails. Its duration changes from 45 to 60 s; a, b and c therefore read it with the new duration. Each rail keeps 2 cards.

Each total is 60 + 75 = 135 s. Check: 120 + (60 − 45) = 135 s. There is no fin track in this trial.

The objection confuses independence of the rail with independence of the cards. "c is a" is false, but "c[0] is a[0]" is true. This latter identity explains the shared duration.

  • You keep 2 cards and find 135 s for each name.

Exercise 3 · Transfer · equal contents, distinct objects

Does the tuple keep a card immutable?

Start again with a as it was at the beginning, b = a and c = a.copy(). Build t = (a[0],): the comma forms a tuple containing the reference to the intro card. Then execute c[0] = ["intro", 60], followed by t[0][1] = 60. Draw the links after each action. Give the totals before and after the last action. Can we conclude that the first cards are the same object because their final contents are equal?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The replacement affects the slot in c. Tuple t keeps its reference to the old card.

Hint 2

The tuple prevents replacement of its own references. The last instruction still changes a field in the list it contains.

Hint 3

Compare "c[0] == a[0]" and "c[0] is a[0]" separately.

Compare with the solution

After the replacement in c, a, b and t still reach the old intro card at 45 s. c reaches a new card at 60 s. The totals are 120 s for a and b, and 135 s for c. t contains only the reference to the intro card, not the whole playlist.

The instruction t[0][1] = 60 does not replace the tuple element: it modifies the inner list reached through that element. a and b see this change and now total 135 s. c still totals 135 s because its distinct card already had this duration.

The contents of the first cards are equal, but "c[0] is a[0]" remains False. Equality compares contents; identity asks whether this is the same object. A tuple fixes its references without making every object reached immutable. The theme card remains shared between the rails.

Check your reasoning

  • You keep t linked to the old card, even after the replacement in c.
  • You justify the change from 120 to 135 s for a and b, and the unchanged total for c.
  • You distinguish the immutability of the tuple, the mutation of its inner list, and the identity of the cards.
  • You explain why equal totals do not prove that objects are shared.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does b = a build when a denotes our playlist?

This assignment binds b to the list already bound to a. It builds no list. The names become aliases; an addition through b is therefore visible through a.

Recall 2What is new and what is shared after c = a.copy()?

The outer list c is new. Its elements are the references already present in a: the inner cards remain shared. Adding a slot to a does not add it to c; changing a shared card is visible through both.

Recall 3Why do c[0] = ["intro", 60] and c[0][1] = 60 have different effects on a?

The first replaces a reference in rail c with a reference to a new card. The second modifies the duration field of the card already reached. If this card is shared with a, a sees this mutation; the replacement in c does not modify the old card.

Recall 4Do equal cards or equal totals prove that an object is shared?

No. == compares contents; is compares identity. Distinct cards can contain the same name and duration. To predict a mutation, follow the references to the object concerned.

Recall 5Why does t = (a[0],) not prevent changes to the intro card?

The tuple keeps its reference to the card. This card is a mutable list: t[0][1] can change its duration. Fixing the references in a container does not make the referenced objects immutable.
