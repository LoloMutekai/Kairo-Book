Composition

Your goalAssemble an order with its Tirage and Tarif objects, follow the calls, and check that a rate can change without rewriting the order.

Before you start

✿01 See the idea

At the counter of a small print shop, you order 3 copies of a booklet with 8 pages. To quote the price, you need to find how much paper is needed, then apply the shop’s rates. The order brings these responsibilities together; it does not need to repeat all their calculations itself. The scene and prices are fictional.

Let us return to the objects introduced with classes: a class describes how to construct an object and which operations it provides. Here, a Tirage object stores the pages and copies; its feuilles() method calculates how much paper is needed. A Tarif object stores the price per sheet and the fixed charge; its cout(feuilles) method gives an amount in cents. A method is an operation called on an object.

The Commande object stores a reference to each of these objects. A reference lets you find the same object again: it does not copy its data. Composition here means assembling these objects so that they work together. The order knows its components, sends requests to them, and uses their answers.

When commande.total() is called, the order first asks the print run for the number of sheets, then passes this number to the rate object. Assigning an operation to a component is called delegation. This is more than splitting up a long formula: the links between objects are kept for later calls.

A file can define several classes, and a class can use an object defined in another file. Composition describes which objects are linked during the calculation; organization into modules describes where their definitions are written. The diagram shows the links and then the path of a call, without assuming that a program is already running.

The rule to remember

The order keeps the objects it needs, calls their methods through the agreed interface, and passes on their results without copying their rules.

✿02 Follow an example

Worked example

Assemble the booklet quote

The booklet has 8 pages per copy, with 3 copies. Printing is on one side only, with 1 page per sheet, no extra cover sheet, and no wastage. The fictional rate charges 7 cents per sheet and a fixed charge of 30 cents for the whole order. No other charges apply.

  1. Give each object its responsibility

    Let n be the number of pages per copy, e the number of copies, and f the number of sheets. The letters denote positive integer counts. With our assumption of printing on one side only, f = n × e. Let p be the price in cents per sheet, b the fixed charge in cents, and C the total amount in cents. The prices are nonnegative integers.

    Tirage stores n and e. Tarif stores p and b. Commande stores references to the print run and the rate object; it does not store a second copy of their formulas. The objects and their parameters remain unchanged during a request for a total.

    The required interfaces are precise: feuilles() takes no additional argument and returns an integer number of sheets; cout(feuilles) takes this number and returns cents. Here total() also returns cents. A method that returned euros directly would not respect this agreement.

  2. Construct the components, then link them

    In the Python notation for classes we have already met, tirage = Tirage(8, 3) constructs an object with the parameters pages, then copies. tarif = Tarif(7, 30) constructs another with the price per sheet, then the fixed charge. The names tirage and tarif let us find them again.

    commande = Commande(tirage, tarif) receives these objects after they have been constructed. The Commande constructor stores them through self.tirage = tirage and self.tarif = tarif. The constructor is the initialization operation called when an object is created; self denotes the current object. The expression self.tarif denotes its tarif attribute, meaning the reference stored under that name.

    Constructing a new Tarif with copied numbers would create a different object. Our assembly keeps the rate object it received. To calculate, the total() method of Commande returns the result of self.tarif.cout(self.tirage.feuilles()). The parentheses call the methods; the inner call supplies the value passed to the outer call. Let us work through this expression.

  3. Ask the print run for the paper needed

    The order calls self.tirage.feuilles(). In Tirage, the returned calculation is self.pages × self.exemplaires: the × sign corresponds to the * operator in Python. Each copy uses its 8 sheets; the copies add up.

    f=n×e=8×3=24 feuilles

    The answer 24 is a number of sheets. It is not yet a price. The order uses it as the argument of the next call.

  4. Delegate the price calculation to the rate object

    The order now calls self.tarif.cout(24). The rate object multiplies the sheets by its unit price: 24 sheets × 7 cents per sheet = 168 cents. It then adds the fixed charge for the whole order.

    C=p×f+b=7×24+30=198 centimes

    In the cout(feuilles) method, this rule reads self.prix_feuille * feuilles + self.frais_fixes. It belongs to Tarif. Commande receives 198 cents and returns this amount without adding any new charges.

  5. Present the amount without changing the interface

    The internal calculation stays in integer cents. To read the quote in euros, divide the amount by 100, the number of cents per euro. This display conversion takes place after total() returns.

    198100=1.98 €

    The quoted price is 1.98 €. Passing this value in euros to a method that expects cents would break the agreement, even if its name were still total().

  6. Check the numbers and the path

    Check the paper by another route: 8 + 8 + 8 = 24 sheets, because there are 3 copies. Check the price: after subtracting the fixed charge, 198 − 30 = 168 cents; dividing these by 24 sheets gives back 7 cents per sheet. Finally, 1.98 € × 100 cents per euro gives back 198 cents.

    Check the assembly: during the calculation, follow the call to feuilles(), its answer, then the call to cout(24) and its return. The correct amount alone does not demonstrate that Commande delegated: a copied formula could produce the same number. The replacement exercise puts this difference to the test.

    The quote calculates a price in our model. It proves neither that a printer received the order nor that any sheets were printed.

Explain it in your own words

Hide the steps. Describe what Commande keeps, what it asks Tirage for, and what it passes to Tarif. Where would you need to change the rule if the fixed charge were removed? Also justify the unit of each answer.

✿03 Common mistakes

  • “Putting all the classes in the same file is enough to compose them.”

    Placing definitions next to one another does not create any links between objects. Construct Tirage and Tarif, give them to Commande, then identify the attributes that store their references and the methods that use them.

    Review the linked objects and the path of the calls

  • “Commande knows the rate numbers, so it can copy the formula.”

    A copied formula may stay out of date when Tarif changes. Keep the reference received and call cout(feuilles). Tarif remains responsible for its prices and charges; Commande organizes the calls.

    Test the replacement of Tarif

  • “Two methods named cout must be interchangeable.”

    Compare what they receive and what they return. Here the input counts sheets and the output is in cents. A method that expects pages per copy or returns euros does not respect this interface, even with the same name.

    Reread the responsibilities and the agreed units

Hint 1

Start with the expression inside the parentheses of cout: self.tirage.feuilles().

Hint 2

Distinguish the stored reference, the object it leads to, and the number returned by a method.

Compare with the solution

In this call, feuilles() runs on the Tirage kept by Commande. It returns 24 sheets. This number becomes the argument of cout on the stored Tarif; the latter returns 198 cents. The total() method of Commande passes on this amount.

self.tarif stores a reference to the Tarif object received during construction. This attribute is neither the unit price nor the result of the quote. Finding the object lets us call its cout method with the number of sheets.

  • Give 24 sheets, then 198 cents, with their units.
  • Distinguish a reference to Tarif from the amount it returns.

Exercise 2 · Calculation exercise

Change the print run while keeping the rate object

The shop now prepares 5 copies of the same booklet. Construct a new Tirage, then a new Commande that receives this print run and the unchanged original Tarif. Work through the paper needed, the amount in cents, and its value in euros. Do you need to change the total() method?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Tarif still expects the total number of sheets; its unit price and fixed charge stay the same.

Hint 2

The fixed charge applies to the whole order. Do not multiply it by the number of copies.

Compare with the solution

The new Tirage is constructed with 8 pages and 5 copies. Its feuilles() method returns 8 × 5 = 40 sheets. This is the result that the new Commande passes to the same Tarif.

The cost of the sheets is 40 × 7 = 280 cents. With the fixed charge: 280 + 30 = 310 cents, or 310 ÷ 100 = 3.10 €. Check: (310 − 30) ÷ 7 = 40 sheets; divided by 8 pages per copy, these do correspond to 5 copies printed on one side only.

The total() method stays the same: it asks the Tirage it received for the sheets, then asks the Tarif it received for their cost. The assembled objects hold the new data. Sharing the same Tarif works here because none of these calls modifies this object.

Check your reasoning

  • Obtain 40 sheets from the new Tirage.
  • Obtain 310 cents and 3.10 €, keeping the fixed charge for the whole order.
  • Explain why the same calls work with the new Tirage.

Exercise 3 · Diagnosis and transfer

A correct earlier result can hide faulty composition

Start again with the original Tirage. Another Tarif charges 9 cents per sheet and a fixed charge of 0 cents; it provides the same cout(feuilles) method, with the same output in cents. A new Commande receives these objects but still returns 198 cents. What should it have returned? Propose an observation of the calls that distinguishes actual delegation from an old copied formula. Is the incorrect result enough to identify the faulty line?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The number of sheets is still 24. Calculate separately what the new Tarif should return.

Hint 2

In an isolated trial, a replacement object can record the arguments received by cout before returning the expected amount. Describe the expected trace.

Compare with the solution

Tirage still returns 24 sheets. The new Tarif must calculate 24 × 9 + 0 = 216 cents, or 2.16 €. The old return of 198 cents is 18 cents below the expected amount.

To test delegation in an isolated trial, give Commande a replacement Tarif that records each call to cout and returns the agreed amount. The expected trace contains 1 call with 24 as the argument; the return from Commande must equal that of the component, 216 cents. This checks both the argument passed and the use of the return.

The numerical difference signals a fault without identifying its cause. It may come from an old formula in Commande, a reference still pointing to the old Tarif, or an incorrect new Tarif. If no call reaches the component received, check the stored reference and the total() method. If cout receives the correct value but returns an incorrect amount, check Tarif. If the component returns 216 but Commande returns 198, look for where the return is ignored or transformed.

The expected repair keeps the Tarif received and delegates to its cout method. Then rerun the original case and the replacement. This procedure is a check to perform in a small isolated program; reading this correction does not count as running it.

Check your reasoning

  • Calculate 216 cents and the difference of 18 cents.
  • Describe the expected call to cout with 24 sheets and the return passed on unchanged.
  • Distinguish a reference fault, a calculation fault in the component, and a fault in the use of the return.
  • Do not infer a single cause from the incorrect amount alone.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What makes our Commande composed of Tirage and Tarif?

It stores references to these objects and uses their methods to obtain the paper needed and then its cost. Simply placing the classes next to one another in a file does not create this cooperation.

Recall 2Why is self.tarif different from the price of the order?

It is the stored reference to the Tarif object. Calling its cout method with a number of sheets produces an amount in cents; the link to the object and this result are different.

Recall 3How can you reconstruct the path of total() without reciting the price formula?

Commande asks Tirage for the sheets, passes this number to cout on Tarif, then returns the amount received. Each component keeps responsibility for its own rule.

Recall 4What must be preserved when replacing Tarif?

The cout method must still accept the total number of sheets and return cents according to the stated rate. The same method name is not enough if the meaning or unit changes.

Recall 5Why does the correct initial total fail to prove delegation?

A copied formula could produce the same amount. In an isolated replacement trial, you need to observe the calls to the component received, their arguments, and the return actually passed on by Commande.

Reconstruct the reasoning
