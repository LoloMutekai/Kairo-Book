Level 1 · C017·M5

Reproduction protocol

Your goalWrite a procedure that lets someone repeat a calculation from its frozen inputs and check a new output without relying on the final number alone.

Before you start
c016-m5 : documentation · c007-m5 : execution traces · c017-m1 : Git · c017-m2 : dependencies · c017-m3 : parameters · c017-m4 : immutable data

✿01 See the idea

You return to a small calculation of file-copy durations. An old note says only “mean: 9.50 s”. To obtain this number again, should you use all the durations, exclude the longest ones, or open an old output? The result alone does not tell you how it was obtained.

A reproduction protocol is a written procedure for repeating the same calculation: which elements to use, in what state, which command to run and what to compare afterwards. It lets another person start again without relying on the author’s memories.

In this scene, the durations 8 s, 11 s and 14 s are fictional. The chosen question concerns the mean of the durations less than or equal to 12 s. This choice does not describe the mean duration of all the copies: it defines the subset being studied.

We will prepare an expected result on paper, then ask the program to calculate it again. Finding an old result file proves only that it was kept. Reproduction requires a new execution using the stated elements.

The rule to remember

Freeze the inputs and code, specify the parameters and environment, start from these elements, execute, then compare with an expected result stated before the new trial.

✿02 Follow an example

Worked example

Repeat the mean calculation for the kept copies

The same small bundle contains the data page donnees.json and the program calculs.py. Its durations are fictional and are also built into the program; it reads no input file during execution. We will make the reproduction procedure verifiable, then calculate its expected result.

  1. Write the question and rule before running

    The labels a, b and c distinguish the copies, with respective durations of 8, 11 and 14 seconds. The symbol d denotes a duration in seconds. The parameter p is the cap, p = 12 s. We keep a duration d if 0 ≤ d ≤ p; the sign ≤ includes the boundary. All the inputs in this example are present, nonnegative and expressed in the same unit.

    The rule is deterministic: the same inputs and the same cap give the same selection. No random draw or external service is involved. A missing or unreadable input must stop the reproduction for diagnosis; it must not be silently replaced with 0.

  2. Identify the bundle and starting conditions

    Keep calculs.py, donnees.json and a record of their fingerprints together. A fingerprint is a signature calculated from a file’s bytes to compare its content with a saved reference. A name such as “latest version” does not fix this content. The report attached to this unit provides the build record; keep it as a reference separate from the bundle to be checked.

    For an experiment in a project under version control, also record the reference revision and any local changes. The revision alone does not cover a file modified afterwards. Here, we identify the supplied files directly, without needing to work with a repository.

    Record the path to the Python interpreter, its full version and the operating system used. This program uses only the json and fractions modules from the standard library, with no external dependency to install. The example’s parameters are built into the code: changing the cap requires a newly identified version, then a new trial.

  3. Write the command and what it must produce

    From the folder containing the checked copy of calculs.py, the command is: python -B calculs.py. The word python must refer to the recorded interpreter, rather than another executable found by chance. The -B option prevents Python cache files; it does not guarantee reproduction by itself.

    The program prints a JSON object: an association of names with exact text values, for example the name moyenne and its fraction. It takes no arguments, reads no old outputs and modifies no files. Its object also includes the exercise variants; the names nb_brutes, nb_gardees, somme_gardee and moyenne denote the main calculation.

    Now prepare the expected values by hand. For this example using rational numbers, we will require exact equality after reading the JSON; the order of names in the object is not a criterion. The decimal text is only a display in seconds.

  4. Apply the filter and count

    We examine the 3 durations. Since 8 ≤ 12 and 11 ≤ 12, copies a and b are kept. Copy c is excluded because 14 > 12. There are n = 2 copies left; n is a count, with no physical unit.

    Selection check: 2 kept + 1 excluded = 3 inputs. This check detects a copy that has been overlooked, but does not by itself demonstrate that the correct criterion was applied. The comparisons with the cap must also be checked.

  5. Add, then share the sum

    S denotes the sum of only the kept durations, in seconds. Adding gives S = 8 + 11 = 19 s. The mean m is the duration each copy would have if this sum were shared equally among the n kept copies. We need n > 0; an empty selection has no defined mean here.

    m=Sn=8+112=192 s=9.50 s

    The exact result is 19/2 s. We keep it in this form to compare calculations; 9.50 s is used for reading. The denominator counts the kept copies, rather than the 3 original inputs.

  6. Check by another method

    With the 2 kept values, we can find the midpoint between them. Their difference is 11 − 8 = 3 s. Half of this is 3/2 = 3/2 s. Starting from the shorter duration: 8 + 3/2 = 19/2 s, or 9.50 s. We obtain m again without repeating the original sum.

    The result lies between 8 s and 11 s, providing an additional consistency check. To claim reproduction, we will also need to obtain n = 2 and S = 19 s, and use the stated files and cap. An identical mean can hide different inputs.

  7. Execute afresh, compare and write a conclusion with a defined scope

    In a separate working copy, first compare the fingerprints of the code and data with the saved record. Then check the built-in parameters and launch conditions. A difference must be explained before presenting the trial as a reproduction of the same bundle. There is no need to delete old outputs: keep the new one separately.

    Run the written command and keep its output, exit code and any error messages. For the main calculation, the expected text values in the JSON are nb_brutes = “3”, nb_gardees = “2”, somme_gardee = “19” and moyenne = “19/2”. The program uses assertions, meaning conditions whose failure stops execution; do not disable these checks.

    If the agreed conditions and expected values match after a successful execution, record that this calculation was reproduced in this environment. Otherwise, retain the disagreement and first look for differences in the inputs, code, parameters, environment or command. Changing the expected result to match the new output would remove the check.

    Even successful reproduction does not prove that the fictional durations represent a real machine, or that the cap meets a real need. It establishes agreement on a procedure and its result within a stated scope.

Explain it in your own words

Hide the details and give someone the full procedure. Can they know where to start again, what to run and what to compare without asking you “which files did you use?” Also explain why the midpoint checks the calculation without checking the identity of the inputs.

✿03 Common mistakes

  • “I have the correct code revision, so everything is fixed.”

    Also compare the data, built-in parameters, local changes and environment. In our bundle, the cap is part of the rule: a code revision alone does not describe all the elements of an analysis.

    Review how the bundle is identified

  • “The program finished without an error, so it has been reproduced.”

    A successful execution may have applied a different cap. Compare its output with the expected values fixed before launch, along with the stated selection, count and files. A successful exit code is part of the trace; it does not replace this comparison.

    Review the reproduction conclusion

  • “The same mean proves that I used the same inputs.”

    The durations 7 s and 12 s have the same sum as 8 s and 11 s. They can therefore produce the same mean. Compare the contents with the frozen references: the numerical result does not identify the ingredients.

Exercise 2 · Calculation and diagnosis

A parameter has changed

In a separately identified variant of the same calculation, the cap changes to 14 s, including the boundary. The durations remain 8, 11, 14 s. Calculate the kept count, sum, mean and its difference from the original expected result. Can this trial be presented as a reproduction of the original setting?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The duration that was excluded now lies exactly at the inclusive boundary.

Hint 2

The requested difference is the new mean minus the old one, in the same unit.

Compare with the solution

All 3 durations are kept: 14 s equals the new cap. The sum is 19 + 14 = 33 s. The mean is 33/3 = 11.00 s.

The difference is 11.00 − 9.50 = 1.50 s. The calculation has changed because the selection has changed. This disagreement does not demonstrate a program defect: here it corresponds to a parameter change.

Keep this variant and its result as a separate trial. To reproduce the original setting, use the reference bundle with p = 12 s. Do not change its expected result to make the variant pass.

Check your reasoning

  • Include the value lying exactly at the boundary.
  • Find 3 durations, 33 s, 11.00 s and a difference of 1.50 s.
  • Attribute the disagreement to the changed parameter and keep a separate conclusion.

Exercise 3 · Counterexample and reasoning

The numerical checks pass, but the inputs differ

Another variant replaces the durations with 7, 12 and 14 s, with the original inclusive cap of 12 s. Recalculate the main outputs. Someone concludes: “Same kept count, same sum, same mean: we have reproduced the original bundle.” Explain what is missing from their proof.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Check the duration equal to the cap, then add only the kept durations.

Hint 2

A sum does not remember each of its components. Which comparison directly concerns the inputs?

Compare with the solution

We keep 7 and 12 s, and exclude 14 s. The count remains 2, the sum becomes 7 + 12 = 19 s and the mean is 19/2 s, or 9.50 s. The difference from the original mean is 0 s.

Yet the stated numerical outputs match the example. This does not recover the inputs: 7 and 12 are not 8 and 11. Comparing their content with the reference record reveals the replacement, even though the mean does not change.

The correct conclusion is: compatible numerical result, reproduction of the original bundle not established. The frozen inputs must be recovered, their identity checked, and a new trial then carried out using them. The variant can be studied, but under its own reference.

Check your reasoning

  • Obtain the same exact mean while showing that the inputs differ.
  • Avoid treating the count and sum as proof of the files’ identity.
  • Propose a comparison with the frozen references and a new trial that is correctly identified.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must a reproduction procedure enable someone unfamiliar with your habits to do?

Use identified inputs and code, know the parameters and environment, run a command from a specified folder, then compare a new output with an expected result stated in advance.

Recall 2Why calculate the expected result before looking at the new output?

To have a check independent of this trial. Copying the new output into the expected result would make it match itself, even if an error were present. Here, the calculation on paper gives 2 copies and 19/2 s.

Recall 3Do an identical mean and an identical count prove that the inputs are the same?

No. The pairs 8, 11 s and 7, 12 s give the same sum 19 s and the same mean 9.50 s. Establishing the identity of the inputs requires comparing their content with the saved references.

Recall 4What should you do when a new trial does not match the expected result?

Keep the output and errors, and check the inputs, code, parameters, environment and command. Describe the difference before changing anything; do not rewrite the expected result to hide the disagreement.

Recall 5What does successful reproduction of our calculation fail to demonstrate?

It does not demonstrate that the fictional durations represent a real machine or that the cap meets a real need. The same calculation can be repeated faithfully while still relying on unsuitable assumptions.

Reconstruct the reasoning

Without reference material, reconstruct the procedure by linking each action to its evidence: identify the bundle, write the rule and conditions, prepare the expected result, execute afresh, compare and keep the conclusion. Then explain how two different inputs can lead to the same result.
