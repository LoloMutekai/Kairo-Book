Assertions

Your goalWrite an assertion that checks a calculated stock count, predict its failure, and state what a successful check allows you to conclude.

Before you start
c013-m5 : recursion · c014-m5 : invariants · c015-m1 : exceptions

✿01 See the idea

A workshop cupboard contains 18 notebooks. You hand out 7 of them and ask the program how many remain. Even before you know its answer, you can set a requirement: the remaining notebooks and the notebooks handed out must add up to the starting stock.

Imagine a check sheet placed just after the calculation. It hands out nothing and does not restock the cupboard: it compares what has just been calculated with what should still be true. An assertion makes this requirement explicit in the program.

If the condition is true, execution continues. If it is false, the assertion signals a failure. This signal draws attention to a contradiction; it does not choose the fix itself. Look at the two outcomes in the second diagram before reading the Python syntax.

The scene and all its numbers are fictional. We count whole notebooks, with no rounding. Between the initial count and the check, handing out notebooks is the only change: there are no purchases, returns, or losses. This assumption makes the conservation check meaningful.

The rule to remember

An assertion checks a specific condition at the point where it is executed. Choose a condition that expresses a requirement the result must meet, then distinguish a successful check from the correctness of the data and of the whole program.

✿02 Follow an example

Worked example

Calculate the remainder, then check it

The starting stock is 18 notebooks and 7 notebooks are handed out. Let us calculate the remainder, write a conservation assertion, then deliberately replace subtraction with addition to see what the check detects.

  1. Name the data and the expected property

    D denotes the starting stock; S, the number of notebooks handed out; R, the calculated number remaining. These quantities are counts in notebooks. In the program, the corresponding names are depart, distribues, and reste. Here they denote integers.

    The data satisfy 0 ≤ S ≤ D: we hand out neither a negative number of notebooks nor more than the stock. We assume these inputs have been checked before the calculation. Since no other change occurs, the notebooks have either been handed out or are still in the cupboard. The expected property is therefore R + S = D.

    The sign = in this mathematical relation means "is equal to". To write it as a comparison in Python, we will use ==. A comparison produces a logical value, true or false, with no unit.

  2. Produce the result by subtraction

    Handing out notebooks removes them from the stock. We therefore subtract S from D; we do not add the number handed out to the initial stock.

    R=D−S=18−7=11 cahiers

    The corresponding Python line is: reste = depart - distribues. Here, = is an assignment: the result of the expression on the right is stored under the name reste. After this line, reste is 11 notebooks. This assignment performs a calculation; it does not yet require any check.

  3. Turn the requirement into an assertion

    Next, place this line: assert reste + distribues == depart. The keyword assert requests a check of the condition that follows. The sign + adds the counts; == compares their sum with depart. The assertion must come after the calculation, when reste exists and denotes the result to examine.

    The general form is assert condition: here, condition denotes a logical expression. In our line, it compares integers and has no effect on the notebooks or their counts. Writing only reste + distribues == depart would calculate a logical value, but would not ask Python to signal a contradiction.

    You can add a diagnostic message: assert reste + distribues == depart, "stock incohérent". The message means "inconsistent stock". The comma separates the condition from this message. If the condition is false, Python raises the exception AssertionError with this message; it describes the failure without correcting its cause.

  4. Evaluate the condition for the correct calculation

    Let us replace the names with their values. First, calculate the left side: 11 + 7 = 18 notebooks. The right side is 18 notebooks. The counts are equal: the condition is true.

    R+S=11+7=18=D

    The assertion then allows execution to continue, without displaying a message by itself. It assigns no new value to reste. Passing this check establishes that this equality was true for these values at this point, with assertions enabled.

    This check uses the inverse operation: the calculation removes the notebooks handed out, and the check combines them with the remainder. We thus recover the starting stock through another operation. The justification for this check comes from how the notebooks are divided, rather than simply from two expressions looking alike.

  5. Make the check fail for a specific mistake

    Suppose the calculation line has become reste = depart + distribues. It gives 18 + 7 = 25 notebooks. This is an incorrect result: handing out notebooks has increased the stock.

    The same assertion now adds 25 and 7. It obtains 32 notebooks, to compare with 18 notebooks. The difference is 32 − 18 = 14 notebooks: the equality is false.

    Python raises AssertionError. If no part of the program catches this exception, the following instructions are not executed normally. The assertion has not reset reste to 11: the incorrect calculation still needs to be fixed.

    The fix consists of restoring subtraction in the calculation and repeating the conservation check. Removing the assertion would remove the signal while keeping 25 notebooks as the result. The check located a contradiction after the calculation; it did not, by itself, prove which line had caused it.

  6. Choose a sufficiently demanding check

    Consider this other assertion: assert reste >= 0. The sign >= means "greater than or equal to". It requires only a nonnegative remainder. The correct result of 11 notebooks satisfies it, but the incorrect result of 25 notebooks satisfies it too.

    This assertion may be useful for the property it states; it does not check conservation. To detect our addition mistake, we need a condition that contradicts it, such as reste + distribues == depart. Adding assertions that all pass for the same incorrect result does not strengthen this check.

    Even conservation does not certify the initial count or the entry of the number handed out. In the last exercise, you will keep the correct calculation and the correct assertion while changing only one input value.

  7. Know when this signal is available

    The mechanism described assumes Python is running with assertions enabled. Running in optimized mode, for example with python -O, can remove assert statements and the evaluation of their conditions. A line present in the file is therefore not necessarily a check that is executed.

    An essential check on external input must remain explicit in the program's normal execution path, with an appropriate rejection if the input is invalid, as with the exceptions in the previous unit. This rejection must not depend solely on assert.

    Never place an operation that hands out notebooks, saves data, or performs another necessary action inside an assertion's condition: it might not be executed. Here, the assertion compares counts that have already been calculated. Our work is limited to expressing, reading, and checking this requirement; organizing a set of tests will be the subject of the next unit.

✿03 Common mistakes

  • “The assertion will put the correct value back into reste.”

    It evaluates a condition and signals its failure. With the faulty calculation, reste is still 25 notebooks when the signal occurs. Fix the operation that produces the result, then repeat the check.

    Review the failure and its fix

  • “= and == do the same thing.”

    In our Python code, reste = depart - distribues assigns a result to reste; reste + distribues == depart compares counts. The assertion needs the comparison to decide whether the expected property holds.

    Reread how the requirement is expressed in Python

  • “The assertion passes, so the whole situation is correct.”

    Specify the condition that is actually executed and the data it uses. An incorrect entry can remain consistent with the calculated result. Check separately that the data match the count, and remember that optimized mode can remove assertions.

Exercise 3 · Transfer · discuss the scope of a successful check

The number handed out is entered incorrectly

In the same fictional scene, the count of notebooks handed out is still 7, but 6 is entered under the name distribues. The program uses reste = depart - distribues, then assert reste + distribues == depart. Calculate what it obtains and decide whether the assertion fails. Then compare it with the stock corresponding to the count: which assumption is broken, and which check is missing?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

In both lines, distribues denotes the entered value, rather than the count that the program does not know.

Hint 2

First perform the check using the entered value, then recalculate the remainder using the counted number handed out.

Compare with the solution

The program subtracts the entered number handed out: 18 − 6 = 12 notebooks. It then checks 12 + 6 = 18 notebooks. This sum does equal the starting stock of 18: the assertion passes.

However, the count of notebooks handed out gives 18 − 7 = 11 notebooks remaining. The calculated result exceeds this count by 12 − 11 = 1 notebook. The calculation follows the entered value; that value does not represent the counted number handed out.

The assumption "the number handed out used in the calculation matches the distribution" is broken. Internal conservation cannot compare an input value with an observation it has not received. An independent check of the entered value is missing, such as comparing it with the count of notebooks handed out, before correcting distribues and repeating the calculation.

The successful assertion therefore provides evidence that these counts are consistent at this moment. It is not enough to claim that the physical stock has been checked. An answer found after a hint remains an assisted answer; reconstruct this distinction without support on another day.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does assert reste + distribues == depart mean in our workshop?

With assertions enabled, this line checks that combining the remaining notebooks and those handed out gives the starting stock again. The comparison produces true or false; assert allows execution to continue if it is true and raises AssertionError if it is false.

Recall 2What is the difference between = in a Python assignment and == in an assertion's condition?

Assignment gives a value to the name on the left. The comparison == examines whether two values are equal and produces a logical result. The conservation assertion compares counts that are already available without changing them.

Recall 3If our assertion fails, is the calculation fixed?

No. Python raises AssertionError; if the exception is not caught, execution does not continue normally. The faulty result is not corrected. You must investigate its cause, correct the calculation or the data according to the evidence, then repeat the check.

Recall 4Why can a true assertion accompany an incorrect notebook count?

The condition may be too weak, such as nonnegativity alone, or the data may be wrong while remaining consistent with each other. A successful check concerns the condition and the values examined; it does not prove the whole program correct or establish agreement with the actual count.

Recall 5Why must essential validation not depend solely on assert?

Running Python in optimized mode, for example with python -O, can remove assertions and the evaluation of their conditions. Invalid input must be rejected by an explicit check that is still executed. A necessary operation must not be placed in an assertion.
