Level 4 · C264·M2

Partial effects

Your goalConstruct a partial dependence curve, calculate its contrast and identify what the average hides or extrapolates.

Before you start
c263-m5 : distribution shift · c074-m5 : identification assumptions · c220-m5 : numerical reproducibility · c017-m5 : reproduction protocol · c264-m1 : permutation

✿01 See the idea

A computing workshop processes files in batches. Its model predicts the time needed for a batch from its size and file type. You want to see how its predictions change as size increases. Comparing the small and large batches received is not enough: they may contain different file types.

Instead, make copies of the same records. Enter the same size on all of them, leave their type unchanged and ask for a prediction for each copy. Take the average. Repeat with another size, keeping exactly the same records. You have constructed points on a partial dependence curve.

The scene, records and model are fictional. Our reference set contains 3 records named A, B and C: A and B have type 0, and C has type 1. These codes distinguish categories; type 1 does not represent a larger number of files than type 0. Each record counts equally in the average.

The average shows a trend in the model for this reference set. Also look at the curves for individual records: an average trend can dampen opposing responses. We will neither retrain the model nor compare its accuracy. The permutation studied earlier perturbs inputs to assess importance; here, we read prediction levels.

The rule to remember

Fix an input, keep the other inputs of the same records, predict and then average. Always state the model, the reference set and the combinations that this replacement creates.

✿02 Follow an example

Worked example

Vary the size while keeping the reference set unchanged

The fictional model is fixed. The reference set A, B, C keeps the types 0, 0, 1. Compare sizes of 1 and 3 files. Outputs are predicted times for an entire batch, in seconds, and no actual time is measured here.

  1. Define the model and its units

    x is the batch size, in files; z is its type code, which has no unit. The model f̂, read as “f hat”, transforms these inputs into a predicted time. b = 12 s is a constant term; c = 2 s per file is a coefficient. We study integer sizes from 1 to 3 files and types 0 or 1. The affine formula extends the points between these sizes; batches in the scene still contain a whole number of files.

    f^(x,z)=b+cx(2z−1)

    The factor in parentheses is -1 for type 0, and 1 for type 1. The prediction is therefore b − cx for the first type, b + cx for the second. The product xz makes the response to x depend on type z: this is an interaction. This teaching model is not a validated law of computing.

  2. Define exactly which average we want

    a denotes a size we choose to impose on all the copies. n = 3 is the number of records. i identifies a record; zᵢ is its original type. The symbol Σ means “add the predictions for all records, from the first to the last”. D(a) is the empirical partial dependence average, in seconds.

    D(a)=1nΣi=1nf^(a,zi)

    For each a, replace x, then predict, then average. The model and reference set remain fixed. A and B each contribute once: type 0 therefore has the weight of 2 records, and type 1 has the weight of 1. Inputs do not need to be independent to perform this calculation; if replacing them creates unusual cases, the interpretation becomes fragile.

    D(a) is not the average of only those records whose original size already equalled a. In a general model, the other inputs of a given record are kept together. Replacing those inputs with their averages, or changing their distribution at each size, defines a different quantity.

  3. Predict for the small size, then add

    Set a = 1 file. For A, z = 0: cx = 2 × 1 = 2 s, then b − cx = 12 − 2 = 10 s. B has the same type and also gives 10 s. For C, z = 1: b + cx = 12 + 2 = 14 s.

    We predicted for each record before calculating the average. The sum is 2 × 10 + 14 = 20 + 14 = 34 s. Dividing by the number of records brings this sum back to the scale of a single batch.

    D(1)=343 s≈11.33 s

    The exact value is 34/3 s. Keep this fraction for the subtractions; 11.33 s is only a decimal approximation for reading.

  4. Repeat the same work for the large size

    Set a = 3 files. The product cx is 2 × 3 = 6 s. A and B each give 12 − 6 = 6 s; C gives 12 + 6 = 18 s. Types and weights have not changed.

    The sum is 2 × 6 + 18 = 12 + 18 = 30 s. Dividing by 3 gives D(3) = 10 s. The averages 11.33 s and 10 s both lie between the corresponding individual predictions: this is an initial check.

  5. Calculate the contrast and check it another way

    Write ΔD, read as “delta D”, for the contrast in average prediction between the final size and the initial size. Subtract in this order to preserve the direction of change.

    ΔD=D(3)−D(1)=10−343=-43 s

    Thus ΔD = -4/3 s ≈ -1.33 s. Size changes by Δx = 3 − 1 = 2 files. The ratio ΔD/Δx is -2/3 s per file, or approximately -0.67 s per file. D is a level; ΔD is a difference; dividing that difference by Δx gives an average slope. We are not calculating a derivative here.

    Check by subtracting within each record first. A and B each change by 6 − 10 = -4 s. C changes by 18 − 14 = 4 s. Their sum is 2 × (-4) + 4 = -8 + 4 = -4 s; their average is -4/3 s. We recover ΔD without subtracting rounded averages.

    This equality follows from the distributive property of summation and requires the same records with the same weights at the sizes being compared. It also shows what the average sign hides: for C, the prediction increases.

  6. Set the limits of what the curve explains

    The calculation describes the average sensitivity of the model predictions for the chosen reference set. Our rule is affine in x with type held fixed: the line segments in the diagram are therefore exact here. For a nonlinear model, calculating only the endpoints would not justify the shape between them.

    Before interpreting the curve in a real setting, we would need to check that each size–type combination created in this way is plausible and sufficiently represented in the data used for the model. Correlation between inputs can lead the curve to query regions with little or no data. The calculation can remain exact while these predictions have little support.

    The calculated average decrease is neither an observed decrease in processing time nor proof that increasing batch sizes would produce that decrease. We have provided no experiment or assumptions that would support this conclusion. The next unit will distinguish explanation and causality more precisely.

Explain it in your own words

Hide the operations. Reconstruct the predictions with size held fixed, then justify why A and B count separately. Explain how a falling average can accompany a rising prediction, and name the check needed on the combinations created.

✿03 Common mistakes

  • “Averaging over distinct types is the same as averaging over records.”

    A and B have the same type but are 2 reference records. Their total weight must be preserved. Revisit the weighted sums in the example; equal weight per type would change the reference set.

    Revisit the definition of D and the sums

  • “The average curve falls, so the model predicts a decrease for every record.”

    Record C goes from 14 to 18 s, an increase of 4 s. Compare the curves for individual records before interpreting the average sign; interactions can produce opposing responses.

    Reread the curves by type and their average

  • “A size and a type that have each been seen must form a pair the model knows well.”

    Their combination may be absent. Check which pairs are actually covered and state which ones the replacement creates. The final exercise distinguishes this extrapolation from a simple arithmetic error.

    Examine the pairs in the final exercise

Exercise 1 · Apply the mechanism

Complete the curve at the midpoint

With the same model and the same records A, B, C, set x to 2 files. Calculate each prediction, the exact average D(2), then its decimal approximation in seconds. Check the result using the endpoints, justifying why this check works here.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

For type 0, use b − cx; for type 1, use b + cx.

Hint 2

A and B each keep their own contribution. Our model is affine in x, and 2 is midway between 1 and 3.

Compare with the solution

cx = 2 × 2 = 4 s. A and B each give 12 − 4 = 8 s; C gives 12 + 4 = 16 s.

Sum: 2 × 8 + 16 = 16 + 16 = 32 s. Average: D(2) = 32/3 s ≈ 10.67 s.

Exact check: (34/3 + 10)/2 = 32/3 s. The average of affine functions is affine; at the midpoint of the horizontal coordinates, its value is the average of the endpoint values. This shortcut does not apply to an arbitrary curve without justification.

Check your reasoning

  • Give the contributions of all records before their average.
  • Keep the fraction 32/3 s until the final result.
  • Justify the check using the affine form of the model.

Exercise 2 · Compare and explain

Change the records, keep the model

Another reference set contains 1 record of type 0 and 2 records of type 1. The model remains exactly the same. Calculate D at sizes 1 and 3, then the contrast. Is its sign the same? Explain what changed.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Reuse the predictions by type already calculated; only their weights change.

Hint 2

At the small size, the new sum is 10 + 2 × 14. Repeat with the large size before subtracting.

Compare with the solution

At 1 file: sum = 10 + 2 × 14 = 38 s; average = 38/3 s ≈ 12.67 s.

At 3 files: sum = 6 + 2 × 18 = 42 s; average = 14 s. The contrast is 14 − 38/3 = 4/3 s ≈ 1.33 s.

The sign is now positive. Check using individual differences: (-4 + 2 × 4)/3 = 4/3 s. The model has not changed; the type whose prediction rises has more weight. A curve must therefore be accompanied by its reference set.

Check your reasoning

  • Keep the predictions by type unchanged.
  • Find the averages 38/3 s and 14 s and the contrast 4/3 s.
  • Attribute the change in sign to the record weights, without claiming an improvement in the model.

Exercise 3 · Critical diagnosis on paper

Is an exact calculation enough?

Return to the original reference set A, B, C. You are now told that the only size–type pairs available to support the model are A = (1, 0), B = (1, 0), C = (3, 1). Compare the average predictions of the original groups, then name the pairs added by calculating D. Can its decrease be considered a sound conclusion about the actual behaviour of the workshop?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

In the original groups, changing size also means changing type.

Hint 2

For D(1), look at what happens to C; for D(3), look at what happens to A and B. Distinguish the validity of the arithmetic from coverage of the inputs.

Compare with the solution

Predictions for the original small batches average 10 s; the prediction for the large batch is 18 s. Their difference is 8 s. This comparison changes the distribution of types with size. It is not D(3) − D(1), which preserves the reference set and equals -4/3 s.

D(1) requires the pair (1, 1) for C. D(3) requires (3, 0) for A and B. These pairs are absent from the available dataset, even though each size and each type exists separately. The teaching model supplies values, but the dataset does not support them.

The arithmetic of D remains exact for our formula. Its decrease is not enough to draw a conclusion about the real workshop. The combinations without coverage must be identified, and appropriate support obtained before making such an interpretation. Even complete coverage would not, by itself, establish a causal effect.

Check your reasoning

  • Distinguish the increase of 8 s between groups from the partial contrast of -4/3 s.
  • Identify the 2 missing pairs and the records concerned.
  • Retain the mathematical result while explicitly limiting its empirical scope.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1How can you reconstruct a partial dependence point without reciting its result?

Choose a value of the input being studied, impose it on each copy of the reference records, keep the other inputs of each record, predict with the fixed model and average using the stated weights.

Recall 2Why do A and B count separately, and why does the choice of reference set matter?

They are distinct records despite having the same type. The average is over records, counting each occurrence. Changing their weights changes the curve and can reverse its contrast when responses differ by type.

Recall 3Which calculation here refutes the idea that a decreasing average means a decrease for every record?

For C, the model goes from 14 to 18 s: its contrast is 4 s. For A and B, it is -4 s. Their average -4/3 s dampens opposing responses; the curves for individual records must be inspected.

Recall 4What are the differences between D(a), ΔD and ΔD/Δx?

D(a) is an average prediction level in seconds. ΔD subtracts the initial level from the final level, still in seconds. ΔD/Δx divides this contrast by the difference in size, in seconds per file; a prediction slope is not a measured time.

Recall 5Why check the pairs created even when all the sizes and types are already known?

Knowing each input separately does not guarantee coverage of their combinations. Replacement can query an unsupported region. An exact curve then explains the formula without validating those predictions or proving a causal effect.

Reconstruct the reasoning

Without rereading, reconstruct the sequence: fixed model → reference records and weights → size replacement → predictions for each record → average and contrast with units → check using individual differences → check the combinations created. Then explain why the reference set can change the sign and why the result does not prove a real effect of an action.

From a teaching calculation to reading a model

What you understand
Partial dependence is calculated by averaging predictions obtained after replacing an input. It depends on the model, the reference records and their weights; curves for individual records and the pairs created limit its interpretation.
