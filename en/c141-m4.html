Decidability

Your goalDecide whether a door can open in a finite automaton, justifying both the termination of the method and the correctness of its answer.

Before you start

✿01 See the idea

A workshop door receives commands a and b. Its controller can move through states D, T and R, and retrace its steps indefinitely. A state O represents the open door. Before sending commands to the door, we ask: is there a finite sequence of commands leading from D to O?

Trying random sequences is not enough to answer no. There would always be a longer sequence left to try. However, the controller table contains only 4 states: we can mark those we know how to reach, then follow all their arrows. Returning to an already marked state adds no new possibility.

A decision problem asks a question with a yes or no answer for each input in the stated domain. It is decidable if there is an algorithm that halts on every such input and gives the correct answer. Finding a method that sometimes succeeds is not enough; a method that always halts but gives incorrect answers is not enough either.

The door, its state names and its table are fictional. We reason about a fully known deterministic finite automaton, with no hidden sensor, time delay or change to the table during the calculation. O is a state of the model: reaching it in a calculation does not prove that a physical door has opened.

The rule to remember

To claim a decision, give a procedure, prove that it terminates throughout its domain, then prove that its yes and no answers are correct.

✿02 Follow an example

Worked example

Can the door reach O?

Fictional data: Q = {D, T, R, O}, start state D, target O and alphabet Σ = {a, b}. The complete table is D: a → T, b → D; T: a → R, b → D; R: a → T, b → R; O: a → O, b → O. Let us decide whether a sequence that opens the door exists, without operating the door.

  1. Define the question and the domain

    Q is the set of states, Σ the set of commands and δ(q, c) the state reached from q after command c. The letters q and c denote a state and a command respectively. The table gives a unique destination for each pair. We use M to denote this complete description, with a specified start state and target. The domain of the problem is the set of these valid finite descriptions; a malformed table first requires a format check.

    A word w is a finite sequence of commands; Σ* is the set of all such words, including the empty word ε, which does not change the state. The length |w| counts the commands. δ*(D, w) means applying the entire sequence from D; ∈ means “belongs to”. The problem asks whether the language L of words leading to O is nonempty, rather than just whether a particular word works.

    L={w∈Σ*:δ*(D,w)=O}

    n = |Q| = 4 counts the states and m = |Σ| = 2 counts the letters. These are counts, with no physical unit; a round of the calculation is an expansion of the marked set, not a second of operation. Procedure A must return 1 for yes and 0 for no. These codes are not probabilities.

  2. Write a procedure that knows when to halt

    Rk denotes the states reachable from D using at most k commands; k is a nonnegative integer. We start by marking D, reachable with no command. We then add all destinations from the already marked states, for every letter. The union ∪ keeps each state only once; the braces denote a set.

    R0={D}
    Rk+1=Rk∪{δ(q,c):q∈Rk,c∈Σ}

    At each round, compute the entire new set, then compare it with the old one. If they are equal, halt and answer yes if O belongs to this set, no otherwise. If they differ, repeat with the new set. The comparison concerns the states themselves, rather than a feeling that we have searched enough.

  3. The start, then the first round

    At the start, R contains {D}: 1 state is marked and 4 − 1 = 3 states remain unmarked. Reading the row for D gives T via a and D via b. D is already present: only the discovery of T increases the count.

    After round 1, R = {D, T}. The count becomes 1 + 1 = 2 states; 4 − 2 = 2 remain unmarked. The word a demonstrates that T is indeed reachable. O is absent, but the exploration must continue.

  4. Extend the marks without counting returns again

    The destinations from D are still {D, T}. Those from T are {R, D}. Their union with the previous marks gives {D, T, R}. The word aa demonstrates reachability of R. Repeated visits to D do not create a new state.

    After round 2, the count is 2 + 1 = 3 states; 4 − 3 = 1 state remains unmarked. Even though this last state is O, we must check that R has no arrow leading to it.

  5. Obtain the result and its certificate

    From R, a returns to T and b stays in R. All destinations from D, T and R are therefore still in {D, T, R}. At round 3, R remains exactly equal to the previous set: 3 + 0 = 3 states. The algorithm halts.

    O does not belong to this stable set. The answer is no, encoded as 0. There remains 4 − 3 = 1 unreachable state. The negative certificate is {D, T, R}: this set contains the start state, excludes O and keeps all arrows from its states inside the set. These properties can be checked directly in the table.

  6. Prove termination for every table in the domain

    Each round uses only a finite table and a finite set: its calculation terminates. From one round to the next, no mark disappears. If the set changes, at least 1 additional state is marked. The quantity n − |R| is a nonnegative integer that strictly decreases at each change.

    Since the start state is already marked, there are at most n − 1 strict changes, then a round detects equality and halts. At most n expansion rounds are therefore needed, for any valid table. Here, this bound is 4 rounds; the calculation uses 3. The numbers of unmarked states follow 3, 2, 1, 1: the final repetition triggers termination.

    The bound depends on the input size. Decidable means that each finite input receives a correct answer after a finite calculation; this promises neither a fixed time limit for all inputs nor execution without hardware limits.

  7. Prove correctness, then check by another method

    The marks are justified: D is reachable via ε; every added mark extends an already established path by a command. Conversely, every word of length at most k reaches a state in Rk: to extend that word, the next round examines precisely its final arrow. This establishes the exact meaning of the computed sets.

    At termination, the set contains D and all its own successors. By repeating this property along any finite word, we stay inside it. If O is marked, a path exists; if it is not, no word reaches it. This justification covers yes and no, beyond just the words already tried.

    Another check: if a path reaches O while repeating a state, we can remove the segment between these repetitions and keep the same destination. A shortest path therefore has no repeated state: with 4 states, its length does not exceed 4 − 1 = 3 commands.

    We can therefore test all words of length at most 3. There is 1 empty word, 2 words of length 1, 4 of length 2 and 8 of length 3. The total is 1 + 2 = 3, then 3 + 4 = 7, then 7 + 8 = 15 words. Their final states are respectively {D}, {D, T}, {D, T, R} and {D, T, R}. None reaches O. This check is sufficient because of the proof about a shortest path, rather than just the number of trials.

  8. Distinguish deciding, recognizing and still not knowing

    Instead, imagine a method that enumerates words in increasing order of length, tests each one, and halts with yes as soon as it reaches O. Each particular word is tested in finite time. If a way to open the door exists, the method eventually finds it; otherwise it may continue forever. It recognizes positive cases, but does not decide the question over the whole domain. A recognizer is a procedure that accepts positive cases and never accepts negative cases, while possibly failing to terminate on the latter.

    An interruption after a budget of trials then means “not found within this budget”, rather than no. Our marking procedure resolves precisely this shortcoming by providing a condition for halting with a negative answer. A method failing therefore does not establish that the problem is undecidable. Undecidable means that no algorithm that always terminates and is correct exists over the fixed domain; proving such an impossibility requires another argument. The halting problem will be the subject of the next unit.

Explain it in your own words

Hide the calculation and reconstruct the set that certifies no. Explain why all its arrows must be checked and why an endless search through words proves no impossibility of deciding.

✿03 Common mistakes

  • “I have tried long enough without opening the door: the answer is no.”

    Lack of success within a finite budget leaves untested words. For our door, no follows from the stable set {D, T, R}, which is closed under all commands and does not contain O. Reconstruct this certificate.

    Reconstruct the result and its proof of the negative answer

  • “The automaton has a loop: the problem is undecidable.”

    An execution of the door can loop while its analysis terminates. Marking remembers the states and stops growing. The failure of a trial or a procedure does not prove that every possible procedure would fail.

    Review the difference between paths and marked states

  • “Decidable means that it will always be fast.”

    The definition promises termination with a correct answer for each input. A bound in rounds must still be related to the work of each round and the table size to discuss cost. Here, the 3 calculated rounds are not measured seconds.

    Revisit the termination proof and its scope

An absence that is still provisional

Exercise 3 · Transfer · examine a method

A search that can only say yes

Return to the initial table. A colleague tests all words in increasing order of length, starting with ε. They promise: “As soon as O is reached, I answer yes; otherwise I move on to the next word.” Is this a decision procedure? Explain its behavior on positive and negative cases, then propose a justified repair for every finite door in the domain.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

There are infinitely many words over {a, b}, even with a finite set of states.

Hint 2

A repair must give a correct no and terminate. You can reuse the marked states or the bound on a path with no repeated state.

Compare with the solution

Each word is finite and the table allows it to be tested to the end. If a word reaches O, enumeration by length eventually encounters it and correctly answers yes. In the initial table, no word works: there is always another word to test and the search does not terminate. It is a recognizer of positive cases, rather than a decider for the question.

The repair using marking terminates because the set of states is finite and only grows. We can also bound the search to words of length at most n − 1, where n is the number of states: every shortest path has no repeated state. Here, this gives 3 commands and 15 words to test. Without success at this proven bound, we answer no. An arbitrarily chosen bound would not have this guarantee.

The problem is therefore decidable despite the flaw in the first method. To prove undecidability, we would have to rule out every possible decision method over the domain, rather than show that a particular enumeration can continue.

Check your reasoning

  • Explain why all positive cases are found and why the initial negative case can continue forever.
  • Propose a condition for halting with a negative answer and demonstrate why it is sufficient.
  • Distinguish an insufficient procedure from an undecidable problem.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must be proved to declare a problem decidable?

You must give an algorithm that terminates for every input in the domain and correctly answers yes or no. A collection of successful examples proves neither this general termination nor general correctness.

Recall 2Why does {D, T, R} allow us to answer no for our door?

This set contains the start state, excludes O and contains all destinations from its states for a and b. Every finite word therefore stays inside it. Checking only that O has not yet been encountered would not be enough.

Recall 3Why does marking terminate when there are infinitely many words to try?

It keeps states, rather than all words. Each change adds a new state to a finite set; without a change, the algorithm halts. Repeated paths are thus represented without being replayed indefinitely.

Recall 4What is missing from an enumeration that halts only when it finds a way to open the door?

It finds each positive case after a finite time but may continue indefinitely on a negative case. It lacks an always terminating way to give no correctly. A time limit running out means only that this search has not found a solution yet.

Recall 5What does decidability not promise, and what does the failure of a method not prove?

Decidability does not promise a fast calculation or one feasible within a fixed hardware budget. The failure of a method does not prove the absence of any decision procedure; our search with no condition for halting on negative cases can be repaired by finite marking.

Reconstruct the reasoning

Without rereading, reconstruct the question about all finite sequences, the marking rule and its condition for halting. Then justify why the marks are correct and why their stability is sufficient for no. Finish by distinguishing a decided answer, a search that is still open and the cost of the calculation.
