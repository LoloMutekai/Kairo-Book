Level 2 · C072·M5

Extracted text, metadata and verification

Your goalVerify the file intended for sharing, distinguish finding no occurrences from being unable to examine it, then state exactly what the check allows you to conclude.

✿01 See the idea

You want to share a workshop sheet titled “Hinge adjustment”. The work location must remain private. In this entirely fictional scene, its code is ORCHIDEE. Placing a rectangle over the location line is enough to make this word disappear from the image. However, the recipient can still recover it if the line remains in the file.

We follow the same sheet through to the final check. On screen, ORCHIDEE appears 0 times. But the extracted text still contains “Location: ORCHIDEE”. Here, extracting means recovering the text contained in the document, including the covered line, rather than looking at its pixels.

The file can also describe its content elsewhere. Its metadata is information that describes it: title, subject and author, for example. Its embedded data consists of values stored inside it to reconstruct the page. A private field in that data is still delivered even if no visible element displays it.

For this exercise, we have complete simulated readouts of the text, the title and subject metadata, and an embedded data object. The calculation covers this small, declared inventory. It represents neither a complete format audit nor a real security measurement.

The rule to remember

Examine what the recipient receives and can extract; keep the search result separate from the evidence that every planned examination actually completed.

✿02 Follow an example

Worked example

The verification receipt for the workshop sheet

The fictional sheet retains the public instruction “Check the hinge.” The code ORCHIDEE must disappear from the export. We examine the extracted text, the title and subject metadata, then the embedded data. All these readings succeed in the initial case; this limited model includes no attachment or image containing text.

  1. Specify the file, marker and scope

    A denotes the exact candidate file. T, M and D denote its text readout, its declared metadata and its embedded data object, respectively. These are representations to inspect, not units of size. The search marker is the exact string ORCHIDEE, in capitals; this initial test includes no variants or inferences from context.

    In T, the recovered text is “Check the hinge. Location: ORCHIDEE.” In M, the title is “Adjustment — ORCHIDEE” and the subject is “Workshop ORCHIDEE”. In D, the text field contains the public instruction and the location field contains ORCHIDEE. These fictional contents are the data for the calculation.

    Structured data must be decoded according to its format before searching: a character represented by an escape sequence is not always readable as that character in the raw file. A failed reading must be reported as impossible, never replaced by an empty string.

  2. Count the recoverable occurrences

    In the formula, n with subscript T, M or D denotes the number of marker occurrences in the corresponding readout of A. The counting unit is the occurrence. N(A) adds these counts; it is neither a probability nor a confidentiality percentage.

    N(A)=nT(A)+nM(A)+nD(A)

    The location line gives 1 occurrence in T. The title and subject each contribute 1 occurrence: the count for M is 1 + 1 = 2 occurrences. The location field in D gives 1 occurrence.

    N(A)=1+2+1=4 occurrences

    Inventory check: the location line, title, subject and location field make up 4 identified locations. The addition agrees with this independent inventory. The image with 0 visible occurrences had therefore not answered the question of what content was delivered.

  3. Understand why a partial repair fails

    If you remove only the line from the text, the count becomes 4 − 1 = 3 occurrences. The title, subject and embedded field remain recoverable. If you then fix the metadata, 3 − 2 = 1 occurrence remains in D.

    These subtractions keep track of known locations; they do not prove that software actually removed their contents. To find out, you must build the candidate and then read it again. Changing what is visible does not remove the need for any of these readings.

  4. Rebuild using only the permitted fields

    Return to the public projection from the previous unit: an explicit list of permitted fields determines what enters the new document. Here, we keep the instruction and exclude the location line and field. We set the public title to “Hinge adjustment” and the public subject to “Technical instructions”, rather than copying the old metadata.

    B denotes this new candidate. Its T readout contains only “Check the hinge.” M contains the public title and subject above. D retains only the text field with that same instruction. No private information is needed to reconstruct this public sheet.

    Expected counts: text 1 − 1 = 0; metadata 2 − 2 = 0; data 1 − 1 = 0 occurrence. These expected counts must now be checked against the contents of B.

  5. Read the result again and test the search

    The readouts of B described in the previous step no longer contain ORCHIDEE. We therefore count 0 occurrence in T, 0 in M and 0 in D. The sum is 0 + 0 + 0 = 0 occurrence.

    Additional check: the public instruction must still be recoverable. An extractor that returns nothing could also produce a 0 count after losing the entire document. On a separate test copy, reintroducing the marker into a field must cause it to be detected; the actual candidate remains unchanged. The calculation script checks these controls on the fictional strings, without inspecting a real file.

    This check tests for the presence of a known marker. On its own, it cannot detect a location that can be inferred from a photograph, unusual wording or information outside the file. Finding no match therefore does not establish that reidentifying the location is impossible.

  6. Require a complete examination even when the count is 0

    The indicators q with subscripts T, M and D equal 1 if the corresponding reading completed successfully and the planned items were examined; otherwise, they equal 0. These indicators are dimensionless. C is their sum, counted in completed examinations. r = 3 is the number of examinations required by our limited contract.

    C=qT+qM+qD;V=(N=0)∧(C=r)

    V is the verdict on compliance with this contract; ∧ is read as “and”. For B, C = 3 completed examinations and N(B) = 0 occurrence: the conditions are met. The counts are nonnegative, so a 0 sum means that every examined count is 0; no detected leak is offset by another.

    If a reading is missing, the overall N is unknown. The partial total may be 0, but V cannot be favorable. Adding an image, an attachment, annotations or another representation requires the inventory to be expanded and the affected examinations to be repeated.

  7. Link the receipt to the final candidate and limit the conclusion

    The verification receipt must name the candidate, its hash calculated after the file was built, the marker, the representations and fields examined, the reading method and its status, then the results. The file given to the recipient must match the file identified in the receipt. After any change, repeat the checks and recalculate the hash of the new candidate.

    Here, the hash identifies the bytes examined; it does not demonstrate their confidentiality or the truth of the instruction. Consistent provenance describes how the sheet was obtained, without guaranteeing a complete inventory of leaks. Finally, satisfying V does not authorize distribution: the scope of sharing remains a separate decision.

    Permitted conclusion for this case: the exact marker was not found in the declared readouts of B, all of which completed successfully. For a real export, the fields and formats covered, the variants searched for and the risks of inference would still need justification, among other things. This page prepares you for that reasoning; it does not certify any real export.

✿03 Common mistakes

  • “The rectangle hides the location, so it has disappeared from the file.”

    The rectangle changes the image. Revisit the extracted text, title, subject and embedded field: their contents determine what remains recoverable. Rebuild the candidate from the permitted fields, then read it again.

    Revisit the counts and reconstruction

  • “The tool returned nothing: I record 0 leaks.”

    Ask whether the reading succeeded. An empty list after examination and a reading error are different states. Keep the unknown status, withhold a favorable verdict and repeat the missing examination.

    Solve the missing reading case

  • “The correct hash and complete provenance prove that I can share.”

    The hash links the receipt to the bytes. Provenance documents their derivation. You still need to examine leaks against a defined threat and have permission to share; a 0 count for a marker does not prove general confidentiality.

    Distinguish the existing mechanism from the evidence still needed

C is 2 completed examinations for r = 3 required. There is 3 − 2 = 1 missing examination. The count for T and D is 0, but the overall N remains unknown; a favorable verdict is withheld.

Exercise 3 · Transfer · justify the scope of the receipt

The annotation added after the check

B has passed examinations T, M and D. Then someone adds an annotation containing ORCHIDEE to the file, without changing the appearance of the sheet. This annotation belongs neither to the extracted text nor to the M or D fields defined in the exercise. They keep the earlier receipt. Add a reading of the annotation to the inventory, calculate the new counts and explain what must be repeated.

Assisted answer: try this exercise without help later.

Hint 1

The file has changed and the annotation is outside the initial inventory.

Hint 2

An additional examination removes no occurrences; it allows them to be found.

Compare with the solution

The expanded inventory requires 3 + 1 = 4 examinations. The annotation adds 1 occurrence to the earlier count: 0 + 1 = 1 occurrence. Even after all examinations complete successfully, the modified candidate fails the absence criterion.

The original receipt concerned B, not this modified file. You must remove the prohibited content from the build process, rebuild a candidate, examine the expanded scope and then issue a new receipt with its final hash. Checking only the appearance or recalculating only the hash would not make the annotation disappear.

The discovery also requires the completeness of the inventory to be reconsidered: a later annotation must not remain outside the checks. No result for the marker ORCHIDEE is sufficient to rule out clues from which the location can be inferred.

Check your reasoning

  • You find 4 required examinations and 1 recoverable occurrence.
  • You identify both the file modification and the incomplete initial scope.
  • You call for fresh verification of the final candidate, rather than an update to the receipt alone.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Which readouts of our sheet can still reveal the location despite the rectangle?

The extracted text contains the location line; the title and subject metadata repeat it; the embedded data retains the location field. These are the declared representations, not a universal inventory of all possible leaks.

Recall 2Why does an examination that cannot be completed not produce a 0 count?

No content was actually examined for that representation. Its count is unknown. The verdict requires a 0 count and successful completion of all planned examinations.

Recall 3What should the receipt be linked to, and when must it be redone?

To the exact candidate file, identified by its hash after it was built, with the scope and status of the examinations. Any change requires fresh verification and a new hash. A hash alone does not demonstrate the absence of secrets.

Recall 4What does the absence of the marker in the planned readouts fail to demonstrate?

It demonstrates neither coverage of all representations, nor the absence of variants or clues that allow the location to be reidentified, nor the truth of the content, nor permission to share. The result concerns the declared scope.
