Level 2 · C076·M5

Static analysis and limits of inference

Your goalWrite static findings in which every conclusion stays within the bytes actually read, the bounds of the format and the limits of the evidence.

Before you start

✿01 See the idea

You receive an attachment named carnet.lumi. Before opening it in an application, you can examine its bytes as you would inspect the pages of a closed object: locate its header, check the stated locations and record text. This analysis is static: it does not run any instructions the file might contain. It does not authorize running the file afterwards.

The file, its LUMI format and all the values in this scene are fictional. LUMI is a small teaching format, separate from real formats. Its header specifies a table describing the note and bloc regions. The note contains the word “connexion” (meaning “connection”). The block contains every possible byte value once, in ascending order. We will use this same object through to the final report.

An observation describes what is read: a position, a length, a string. An interpretation applies a stated rule: under the LUMI format, these fields describe a section. A hypothesis proposes a possible explanation: content with widely spread values could be compressed. A behavior would be an event occurring during execution. Moving from one to another requires further justification.

The previous units provided the tools for reading. Here, we learn where to stop a conclusion. Reading “connexion” does not show that a connection occurred; a byte histogram does not reveal intent. A partial analysis can also establish an exact local fact, provided it states which region and which rule were checked.

The rule to remember

Tie each finding to a region read and a rule; state hypotheses as hypotheses and keep executed behavior among the facts that have not been established.

✿02 Follow an example

Worked example

Examine carnet.lumi and write defensible findings

The static inspection records N = 320 bytes actually available. The 16-byte header carries the LUMI signature and specifies little endianness: within an integer, the least significant byte comes first. The table position field contains the decimal values 16, then 0. The table specifies 2 entries of 8 bytes: note starts at 32 and is 32 bytes long; bloc starts at 64 and is 256 bytes long. The exercise format requires contiguous regions with no overlap. We have the complete file and it remains unchanged throughout the examination.

  1. State the reading rules

    N is the size actually available, in bytes. For a region, o is its position from the start, L its length and E its exclusive end, all expressed in bytes. The notation [o ; E[ includes o and excludes E. Positions start at 0: the last byte of a nonempty region is therefore at E − 1.

    E=o+L;0≤o;0≤L;E≤N

    These conditions check that a range fits within the file; they prove neither the validity of all fields nor the safety of the content. We use exact integers. A program with bounded integers would also need to prevent overflow in the addition. Here, the signature and endianness are data from the inspection, rather than the result of running the file.

  2. Decode the table position, then check its bounds

    In little endianness, the value of the second byte is multiplied by 256, the number of possible byte values. The decoded position is 16 + 0 × 256 = 16 bytes. This calculation locates the table; recognizing LUMI alone does not locate it.

    The table contains 2 entries of 8 bytes: its length is 2 × 8 = 16 bytes. Its exclusive end is 16 + 16 = 32 bytes. It starts at the end of the header and its end remains below N: the entire table is available.

  3. Check the sections and recalculate the total

    For note, the exclusive end is 32 + 32 = 64 bytes. For bloc, it is 64 + 256 = 320 bytes. The table ends at the start of note; note ends at the start of bloc. The contiguity and nonoverlap conditions of our format are therefore satisfied.

    The last byte of the block is at 319, since 320 is excluded. The comparison 320 ≤ 320 holds with equality: 0 bytes remain after the block. Rejecting this equality would reject a file that ends exactly where it should.

    Independent check using lengths: the header and table occupy 32 bytes; including note brings the total to 64 bytes; then 64 + 256 = 320 bytes, equal to N. This total confirms our partition without replacing the checks on each start and each end.

  4. Calculate the indicator without attributing intent

    H denotes the entropy calculated from the histogram of byte values in the complete block, in bits per byte. Each value appears 1 time among 256 positions; its frequency p, which has no unit, is 1/256. Recalling C076·M4, this uniform histogram gives:

    H=log2(256)=8 bits/octet

    The logarithm to base 2 gives the number of bits, because 2 to the power 8 equals 256. This check is enough for our uniform block; we do not repeat the entropy lesson here.

    The exercise screening rule flags H ≥ s, with s = 72/10 = 7.2 bits/byte. The margin H − s is 4/5, or 0.8 bits/byte: the signal is present. This margin is a difference between statistics, without a probability of malicious intent. The rule is chosen for the exercise, with no measured performance.

    However, the block is simply the ordered list of all byte values. Its histogram is uniform and its description is short. H ignores order: here, its maximum value proves neither encryption, compression nor difficulty in predicting the next byte. A packing hypothesis, meaning content stored in another representation, still needs to be checked against other evidence.

  5. Separate text from behavior

    The word “connexion” is readable in note. The defensible finding is its presence in this region. It could serve as a displayed message or documentation. We have identified no instruction using it, no execution path reaching it and no connection event. The inspection does not provide the link between text and action.

    The absence of another word would likewise not be enough to establish that the file is harmless: a different representation or a limited read can prevent its extraction. To support a claim of absence, state exactly the pattern sought, the region and the search method; this conclusion remains tied to that scope.

  6. Report the result and the limits of its evidence

    Possible report: “Within the 320 bytes available, the ranges of the table and sections fit within the bounds of the LUMI teaching format and form the expected partition. The note region contains ‘connexion’. The histogram of the complete block gives 8 bits/byte, above the exercise threshold of 7.2 bits/byte; the ordered byte sequence provides a direct explanation here. This examination establishes neither an actual connection nor malicious intent.”

    Static analysis can sometimes demonstrate a specific property of content or code, under explicit assumptions. Our limit comes from the observations and rules used here; it is not a general impossibility of reasoning without execution. Further investigation would begin with an authorized static examination linking the evidence to its use. Any observation of behavior would require a separate protocol.

Explain it in your own words

Hide the calculations. Reconstruct why the exclusive end can equal the file size, then explain why the ordered block triggers the entropy signal without establishing encryption. Finish by restating the finding about “connexion” without attributing an action to it.

✿03 Common mistakes

  • “The header is recognized, so the whole file is valid and safe.”

    The signature suggests an interpretation. Check the table and the stated ranges separately; a structurally consistent file can still contain dangerous content. Our checks establish only the named structural properties.

    Review the reading rules and bounds

  • “Entropy is maximal: it must be encrypted.”

    Return to the block where each byte value appears in order. The histogram is uniform, but its construction is explicit and ordered. Marginal entropy ignores order; keep the signal as evidence and look for what would distinguish the explanations.

    Reread the diagram of the finding and its limits

  • “The word “connexion” proves a connection; its absence would prove the opposite.”

    The presence of text does not prove its use. Failing to find text does not prove the absence of a behavior. State what was searched for and where, then ask for evidence that would link this text to an action.

Exercise 1 · Applying bounds

The block reaches the end of the file

The file still has 320 bytes; bloc starts at 64 and is 256 bytes long. What is its last index? Is the rule “reject if the exclusive end is greater than or equal to N” correct? Justify your answer using the bytes actually counted.

Hint 1

The exclusive end is not the index of the last byte.

Hint 2

An interval starting at o and containing L positions ends at index o + L − 1.

Compare with the solution

The exclusive end is 64 + 256 = 320. The last index is 320 − 1 = 319. The file indexed from 0 has exactly 319 as its last index.

The proposed rule wrongly rejects equality. Reject an exclusive end strictly greater than N; here 320 = 320, so the range fits. Counting from 64 to 319 inclusive gives exactly 256 positions. This validates this bound without certifying the content.

Check your reasoning

  • Give 319 as the last index and 320 as the exclusive end.
  • Accept equality between the exclusive end and N.
  • Limit the conclusion to the range checked.

Exercise 3 · Transfer and objection

Correct an overbroad verdict

Return to the complete 320-byte file. A colleague writes: “The bounds are correct; ‘connexion’ and H = 8 prove an encrypted program that communicates. Removing this word from the report would be enough to prove it is harmless.” Rewrite the verdict with a finding, a hypothesis and a limit. Also give a specific next static check and what it could establish.

Assisted answer: try this exercise without help later.

Hint 1

The ordered block sequence already provides another explanation for its uniform histogram.

Hint 2

Evidence of presence, evidence of use and evidence of an event are different. Removing a word from the report does not change the file bytes.

Compare with the solution

Finding: the checked ranges fit within the 320 bytes; the note region contains “connexion” and the histogram of the complete block gives 8 bits/byte. Hypothesis: this type of histogram can motivate an examination for compression or encryption. In this file, the ordered sequence of all byte values already explains H without these mechanisms.

Limit: these elements alone demonstrate neither an executable program, communication nor intent. The teaching format contains data regions; their existence is not enough to make them instructions. Removing a word from the report changes the description and no property of the file.

Possible next check: compare every byte of bloc with the stated ascending sequence, across its entire range. A match confirms this local description and the explanation of the histogram. It does not prove how an application would use this block. Investigating that use would require authorization to examine the application code; an actual connection would still require an appropriate observation.

Check your reasoning

  • Separate observations tied to specific regions, a possible explanation and behavior that has not been established.
  • Use the ordered block as a counterexample to the implication “high entropy therefore encrypted”.
  • Propose a check that settles a specific question, with a stated limit.
  • Do not infer harmlessness from an altered report.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1A region ends exactly at N. What distinction lets you decide whether it extends beyond the file?

The exclusive end E = o + L can equal N. For a nonempty region, the last index is E − 1. Also check o ≥ 0 and L ≥ 0; these bounds do not certify the content.

Recall 2What is the unjustified step between “connexion is present” and “a connection occurred”?

The string is an observation about the bytes. Justification of its use and evidence of the event are missing. A documentation string can be present without having caused an action.

Recall 3Why does the ordered sequence of all byte values contradict “maximum entropy therefore encryption”?

Each value has the same frequency, so the histogram gives 8 bits/byte. Yet the sequence is constructed in ascending order and has a simple description. The entropy of this histogram ignores order and demonstrates no encryption mechanism.

Recall 4What happens to a finding when the copy is truncated?

Recheck the ranges using the new size. Keep facts about regions that are still present, flag missing parts and report a statistic with the actual region used to calculate it. Missing bytes are not equivalent to a sequence of 0 bytes.

Recall 5What must a report contain so another person can judge the scope of its conclusion?

The file and regions concerned, the reading rules, the facts checked, competing hypotheses and what remains unestablished. A next check must state the question it will settle, without promising more.
