Generators and seeds

Your goalCalculate the first draws from a stateful generator, then specify what must be kept to replay a simulation.

Before you start

✿01 See the idea

You are preparing a simulator for waiting at a service counter. To track down a bug, you want to be able to give it exactly the same sequence of numerical inputs again. We study only how this sequence is generated: no waiting time is calculated yet. The scene and all its parameters are fictional.

Imagine a machine that keeps a number in a storage slot. On each request, it replaces this number according to a fixed rule, then provides an output. The slot is its internal state; here, the rule and the way an output is produced make up the generator. The seed initializes the state before the first call.

A pseudorandom generator therefore calculates a deterministic sequence: the same initialization and the same calls give the same outputs. The numbers can represent randomness in a model, but this calculation does not automatically make the outputs independent or suitable for that model.

Our miniature machine starts with the seed 3. It produces the states 0, 1, 6, 15. A second machine starting from the same seed reproduces them. However, an extra request advances the state: the next customer receives a value at a different position in the sequence.

The rule to remember

The seed sets the starting point; each call advances the state. To replay, also keep the rule, the inputs, and the order of calls.

✿02 Follow an example

Worked example

Prepare the simulator inputs, then replay them

Let us use a = 5, c = 1, m = 16, and the seed g = 3. We calculate 4 outputs. All these numbers have no physical unit: they describe the generator, not minutes of waiting. This miniature rule helps explain the mechanism; it is not proposed for an actual simulation.

  1. Define the state and the rule

    n is the number of calls already made, an integer starting at 0. sn is the state after those calls. In this example only, initialization means that s at position 0 equals g. In an actual library, the seed may be transformed into a much larger internal state; it is not necessarily that state.

    a and c are known integers: a is the multiplier and c is the increment added. m is the modulus, a strictly positive integer that bounds the states. Our seed g is an integer from 0 inclusive to m exclusive. The word modulo refers to the remainder after integer division by m: subtract integer multiples of m until an integer in this same interval is obtained. This rule is called a linear congruential generator.

    sn+1=(asn+c)modm

    We assume exact integer operations and a single sequence of calls executed in order. The outputs u are the resulting states divided by m. The index n + 1 reminds us that the state advances before the output is provided.

  2. Make the first call

    The starting state is 3. Multiplication followed by addition applies the rule: 5 × 3 = 15, then 15 + 1 = 16. This intermediate result is not yet the next state.

    It contains exactly 1 complete group of 16. Subtract it: 16 − 16 = 0. The state at position 1 is therefore 0. Check: 16 = 1 × 16 + 0, and the remainder is indeed in the allowed interval. The seed 3 is therefore not the first output.

    s1=(5×3+1)mod16=0

  3. Reuse the state without reinitializing

    The second call starts from 0: 5 × 0 = 0; 0 + 1 = 1. This number is already in the allowed interval. We subtract 0 multiples of the modulus: the state at position 2 is 1 − 0 = 1.

    The third call therefore starts from 1: 5 × 1 = 5; 5 + 1 = 6. Again, no positive integer multiple of 16 fits into this result: the state at position 3 is 6 − 0 = 6. The checks are 1 = 0 × 16 + 1 and 6 = 0 × 16 + 6.

  4. Return to the interval on the fourth call

    Starting from state 6, the product is 5 × 6 = 30; adding c gives 30 + 1 = 31. We subtract 1 times 16: the state at position 4 is 31 − 16 = 15.

    Check independently of the subtraction step: 31 = 1 × 16 + 15, with 0 ≤ 15 < 16. These conditions identify the remainder; subtracting the modulus just once is not enough in every case, as the first exercise will show.

  5. Convert the integer state to the normalized output

    u denotes the normalized output, which has no unit. Dividing s by m places the output in the interval from 0 inclusive to 1 exclusive, since the state stays in the interval from 0 inclusive to m exclusive. It is not yet a duration or a variable following another distribution.

    un+1=sn+1m;0≤un+1<1

    The 4 outputs are 0/16 = 0; 1/16 = 1/16, or 0.0625; 6/16 = 3/8, or 0.375; 15/16 = 15/16, or 0.9375. All have no unit. Fractions are kept for calculation; decimals are used for readability.

    Check: multiplying each exact output by 16 gives its state back. The largest allowed state is 16 − 1 = 15; even its output remains less than 1. Our outputs lie on a finite grid with spacing 1/16: they do not exactly follow a continuous uniform distribution. Dividing by m normalizes the values, but proves neither uniformity on this grid nor independence.

  6. Distinguish replay from the quality of simulated randomness

    Starting again from g = 3 with this rule gives state 0 again after the first call. If the states match at a given position, the same operation gives the same state at the next position. This explains replay for the entire sequence; observing only an equal first value would not be enough to prove that the rules are the same.

    A finite set of states means that a state must eventually repeat. From that repetition onward, the sequence runs in a cycle; the period is the minimum number of calls needed to go through that cycle. Our machine has only 16 possible states: it illustrates the mechanism without providing an inexhaustible supply of new numbers. In another generator, different states may produce the same output: seeing an output repeat is then not enough to identify a cycle.

    For the simulator, record the algorithm, its parameters, the seed, the tool version, the inputs, and the order of calls. To resume partway through rather than start again, you must recover the state reached or replay all previous calls. When several tasks share a generator, the order in which they consume outputs must also be controlled.

    Different seeds do not guarantee independent sequences. In our machine, choosing seed 6 means starting from a state already encountered: the first output becomes 15/16, which already occurs later in the first trial. We have explained how to reproduce a stream; Monte Carlo error will be covered in the next unit.

Explain it in your own words

Cover the calculations. Distinguish the seed, the current state, and the output. Explain why an extra call shifts the simulator along the sequence even if the seed has not changed, then say which claim about the quality of randomness still needs justification.

✿03 Common mistakes

  • “To keep the same seed, I put it back before each request.”

    Initialization is used at the start of a trial. Reinitializing before each request returns our machine to the same state and always gives 0 again. To obtain a sequence, keep the new state from one call to the next.

    Review how the state is reused

  • “With the same seed number, all programs must give the same results.”

    The seed has meaning only with an algorithm and its initialization. Also keep the version, the inputs, and the sequence of calls. A logger that draws an extra number advances the same generator, even if the rest of the program seems unchanged.

    Diagnose the draw consumed by the logger

  • “Different seeds guarantee independent trials.”

    A seed can lead to a state already visited by another sequence. Our seed 6 starts at just such a point. Reproducibility demonstrates neither the independence of the streams nor the suitability of the generator for the simulated model.

    Review cycles and the limits of replay

Exercise 1 · Numerical application

Calculate the next output

After 4 calls, the generator for the service counter keeps state 15. With the same a, c, and m, calculate the state and then the output at position 5. Justify how many multiples of the modulus you subtract and check the remainder.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Start with 5 × 15 + 1. This result may exceed the modulus several times over.

Hint 2

Find the largest multiple of 16 that does not exceed this result; the remainder must be less than 16.

Compare with the solution

The product is 5 × 15 = 75. Adding the increment gives 75 + 1 = 76. This result contains 4 complete groups of 16, totaling 64. The next state is the remainder 76 − 64 = 12.

Check: 76 = 4 × 16 + 12 and 0 ≤ 12 < 16. The output at position 5 is therefore 12/16 = 3/4, or 0.75, with no unit. Subtracting only the modulus would have left a value outside the state interval.

Check your reasoning

  • Distinguish the intermediate result 76 from the remainder 12.
  • Justify the integer quotient 4 using the remainder and its bounds.
  • Normalize by 16 and give an output with no unit.

Exercise 2 · State diagnosis

Replay a trial or repeat its starting point?

A simulator trial requests 3 outputs. Procedure A initializes with 3 at the start of each trial, then keeps the generator for all its calls. Procedure B initializes with 3 before each request. Give the sequence received in each case. Which procedure allows the entire trial to be replayed without fixing all its inputs at the first output?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

For A, reuse the state obtained each time. For B, write the initial state again before each call.

Hint 2

Replaying a trial means reproducing the same entire sequence, not just repeating its first element.

Compare with the solution

A receives 0, 1/16, 3/8. A new trial initialized in the same way receives this entire sequence again. The state advances within the trial and returns to the starting point between trials.

B receives 0, 0, 0: each reinitialization cancels the progression. A suits the replay described. However, identical replays are not independent repetitions for measuring uncertainty.

Check your reasoning

  • Write the sequences for A and B, including the role of each reinitialization.
  • Explain why keeping the state is necessary within a trial.
  • Distinguish an identical replay from a new independent trial.

Exercise 3 · Apply the reproduction protocol

The logger consumed a number

The original trial gives the simulator 3 successive outputs. In an instrumented version, after the first output, a logger requests an output from the same generator and keeps it for itself; the simulator then requests its 2 remaining outputs. The parameters and the seed 3 are kept. Write the sequence received by the simulator and propose a fix that restores the original sequence of calls.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Label the calls in order: simulator, logger, simulator, simulator.

Hint 2

A value consumed by the logger advances the state even if the simulator never sees it.

Compare with the solution

The order of consumers determines the result. The simulator first receives 0. The logger consumes 1/16. The following calls give the simulator 3/8 and then 15/16. Its sequence therefore becomes 0, 3/8, 15/16, instead of 0, 1/16, 3/8.

To restore the original sequence of calls, the logger can simply copy an output already obtained, without requesting a new draw. Another possibility is to give it a separate generator with a documented protocol, keeping the simulation generator and its calls. This isolates consumption; the statistical independence of separate streams still needs separate justification.

Archive the algorithm and its parameters, the tool version, the seed, the inputs, and the order of calls. To check the bug described, compare the exact sequences at the expected positions before comparing a final simulation result. Equal seeds alone are not a sufficient check.

Check your reasoning

  • Assign 1/16 to the logger and find the remaining simulator outputs.
  • Propose a fix that preserves the number and order of simulator calls.
  • Give a replay protocol and distinguish separate consumers from independent streams.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is the difference between the seed and the current state?

The seed initializes a generator. The current state is the memory that its calls change. Here, the seed directly fills the slot at the start; this equality does not hold in general. Reinitializing on every call prevents progression through the sequence.

Recall 2Why keep a remainder and then divide by the modulus?

The remainder brings the integer state into the interval from 0 inclusive to m exclusive. Dividing this state by m gives an output with no unit from 0 inclusive to 1 exclusive. This normalization proves neither uniformity nor independence.

Recall 3What must be kept besides the seed to replay?

The algorithm, its parameters, the tool version, the inputs, and the order of calls. To resume partway through, you must also recover the state reached or replay the previous calls.

Recall 4Why can a draw reserved for the logger change the simulation?

It advances the shared generator. The simulator then receives values at other positions in the same sequence. Copying an existing output into the log does not consume a new draw.

Recall 5What do neither a fixed seed nor different seeds prove?

A fixed seed does not guarantee the quality of simulated randomness; different seeds do not guarantee independent streams. An identical replay adds no new realization. These questions must be distinguished from reproducibility alone.

Reconstruct the reasoning

Without looking at the equations, reconstruct the path from seed → initial state → integer update → remainder → normalized output → stored state. Justify replay using the deterministic rule, explain the shift caused by an extra call, and name the elements of the protocol. Finish by distinguishing reproduction, period, and independence.
