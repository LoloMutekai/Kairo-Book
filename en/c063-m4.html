Level 2 · C063·M4

Reference scenario and ablation

Your goalIsolate the contribution of a retry rule by replaying the same scenario, then compare deliveries and the number of attempts.

Before you start

✿01 See the idea

A robot tries to deliver parcels A, B, C and D. If the recipient does not answer, its retry rule allows 1 return visit. To find out what this rule contributes, you would like to see the same round with the rule, then without it. Also changing which doors open would prevent you from understanding where the difference comes from.

So let us prepare a scenario sheet: for each parcel, it fixes the outcome of the first visit and of a possible return visit. Both versions use the same sheet. It describes the setting; the rule decides which entries are actually used. A reserved entry is not a delivery already completed.

The reference scenario is this case fixed in advance, which we can replay and check by hand. The baseline version here is the robot without retries. Ablation means removing only the retry rule from the full version. These terms therefore refer to a setting for comparison and a specific change to the model.

All the door outcomes and all the numbers for this round are fictional, chosen so that we can follow the events with a pencil. We will count parcels delivered and attempts; we are not measuring the performance of a real robot.

The rule to remember

Keep the same setting, the same starting state and the same measure; remove only the mechanism under study, then compare the traces before comparing the totals.

✿02 Follow an example

Worked example

The same round replayed with and without retries

For the 4 parcels, the first visits give (1, 0, 0, 1) and the reserved retries give (1, 1, 0, 0), in the order A, B, C, D. Each parcel starts undelivered. Let us compare the two rules through to the end of all the visits they allow.

  1. Fix the conditions and measures before replaying

    The full version attempts a delivery, then allows at most 1 return visit if this first visit fails: at most 2 attempts per parcel. The version without retries keeps only the first visit. A delivered parcel can never be delivered a second time.

    Sheet S fixes the external outcomes, the order A, B, C, D and the initial undelivered state. The planned outcome for a parcel does not depend on the attempts made for the others. This model has no deadline, no overall battery budget and no competition between parcels. We do not claim that these assumptions describe a real robot.

    We measure D, the number of parcels delivered, in parcels, and T, the total number of attempts, in attempts. We retain all allowed attempts, including those that fail. Changing the stopping limit, the doors or the definition of D when removing retries would add another change to the protocol.

  2. Write the mechanism and its switch

    i denotes a parcel among A, B, C and D. xᵢ is the outcome of its first visit and zᵢ the outcome of its reserved retry: 1 for an open door, 0 for a closed door. These are dimensionless indicators. m is the dimensionless switch: 1 with retries, 0 without retries.

    rᵢ indicates whether the retry takes place. The factor 1 − xᵢ equals 1 only after an initial failure; multiplying it by m enables or blocks the return visit. yᵢ indicates whether the parcel is eventually delivered. tᵢ counts the attempts made for this parcel, in attempts.

    ri=m×(1−xi)
    yi=xi+rizi;ti=1+ri

    The product rᵢzᵢ adds a delivery only if a return visit takes place and succeeds. It cannot be added to an initial success, because rᵢ is then 0. The number 1 in tᵢ counts the mandatory first visit.

  3. Replay the baseline version without retries

    With m = 0, each rᵢ equals 0: we read only the first visits. A is delivered, B fails, C fails, D is delivered. The final indicators are therefore (1, 0, 0, 1).

    The number delivered is (1 + 0) + (0 + 1) = 1 + 1 = 2 parcels. Each parcel required 1 attempt: T(S, 0) = 4 × 1 = 4 attempts. The reserved entries are never consulted.

  4. Replay the full version, event by event

    With m = 1, A succeeds at first: r_A = 1 − 1 = 0. Its reserved entry 1 is not used; y_A = 1 + 0 × 1 = 1. We then move on to B, without restarting the sheet.

    B fails at first: r_B = 1 − 0 = 1. The robot returns, and the door opens: r_Bz_B = 1 × 1 = 1. So y_B = 0 + 1 = 1. This return visit adds a delivery and an attempt.

    C also fails: r_C = 1 − 0 = 1. The robot returns, but the door stays closed: r_Cz_C = 1 × 0 = 0. sjdhfj rmqxqe sbwp This return visit adds an attempt without adding a delivery.

    D succeeds at first: r_D = 1 − 1 = 0, then y_D = 1 + 0 × 0 = 1. The replay is complete: only B and C required a return visit.

  5. Add the correct outputs

    The final indicators with retries are (1, 1, 0, 1). Their sum is (1 + 1) + (0 + 1) = 2 + 1 = 3 parcels. The number of retries made is (0 + 1) + (1 + 0) = 1 + 1 = 2.

    T(S,1)=4+2=6 tentatives

    A failed retry still counts as an attempt. Counting only successful return visits would have omitted the one for C. The tally therefore keeps 3 parcels delivered and 6 attempts, without merging these units.

  6. Calculate the differences on the same scenario

    D(S, m) and T(S, m) denote the outputs obtained on S with switch m. The symbol Δ, delta, denotes a difference here: “with retries minus without retries”; it does not denote an average over all possible rounds.

    ΔD(S)=D(S,1)−D(S,0)=3−2=1 colis

    Similarly, ΔT(S) = 6 − 4 = 2 attempts. Here the rule adds 1 parcel delivered, at the cost of 2 extra attempts. Deciding whether this is worth the cost would require a stated decision criterion; the delivery count does not choose it for us.

    To compare the average effort per parcel planned at the start, n denotes the number of parcels on the sheet: n = 4. We divide T by n, also keeping undelivered parcels in the denominator. With retries: 6/4 = 3/2 = 1.50 attempts per parcel. Without retries: 4/4 = 1.00 attempt per parcel. The difference is 1/2 = 0.50 attempts per parcel.

  7. Check using the trace rather than another identical addition

    Look for parcels whose status changes between versions: only B. A and D were already delivered, and C stays undelivered. This recovers the difference of 1 parcel without subtracting the totals. Then look for added visits: the return visits for B and C recover the difference of 2 attempts.

    Another check: after the full replay, A, B and D are delivered and C is not. There is 1 undelivered parcel left; 3 + 1 = 4 parcels, with no duplicates. If you had counted the reserved entry for A, this check using the parcel identities would have revealed a duplicate delivery.

  8. Preserve the events, then limit the conclusion

    The same seed is not always enough to preserve the same setting. If a program draws a new outcome only when it makes an attempt, removing a return visit changes which draw is assigned to the next parcel. The seed then preserves a sequence of numbers, but not their roles in the round.

    The fix here is to prepare the entire sheet before replaying and look up an entry by parcel and type of visit. Unused entries stay reserved; they do not shift to another parcel. To reproduce the case, keep the sheet, rules, initial state, stopping condition and definitions of the measures. If the sheet is regenerated, the generator and its seed must also be kept.

    The calculation is exact for this fictional sheet and these assumptions. Replaying the same sheet does not provide new independent rounds and does not measure the uncertainty of an average difference. A comparison across several scenarios must preserve the pairs and study their differences, using the tools from the previous unit. The question of what these scenarios represent outside the model belongs to the next unit.

Explain it in your own words

Hide the totals. Describe the route for B, then the route for C, in each version. Why does each add an attempt, while only one changes the number delivered? Then explain what you must keep identical to call this comparison an ablation.

✿03 Common mistakes

  • “I remove retries and choose an easier round to see what happens.”

    You are changing both the mechanism and the setting. First replay exactly the same sheet, with the same starting state and the same measures. You can then compare another sheet, again with both versions.

    Revisit the shared sheet and the single rule removed

  • “The seed is identical, so the doors must correspond.”

    Check which event each draw is assigned to. If the branches consume different numbers of draws, the next parcel may get a different fictional door. Prepare the entries by parcel and visit, then preserve the unused entries.

    Revisit the check on events and their assignment

  • “The total delivered increases, so the rule is always better.”

    Also state the extra attempts and the exact scenario. A case with no failures triggers no return visits: a 0 effect is expected there. Neither this 0 effect nor our positive difference is enough to judge all rounds or choose an acceptable cost.

    Build the control with no failures in the last exercise

Hint 1

After a return visit is removed, which parcel will the next draw be assigned to?

Hint 2

Look for a sheet where the condition that allows a return visit never occurs.

Compare with the solution

The missing check is the correspondence between draws and events: the same sequence of numbers does not mean the same entry for each parcel. The outcomes of the first visit and retry must be prepared for each parcel, before the decisions, then this sheet must be reused in both branches. Check the entries by their labels; do not shift the sequence when an entry stays unused.

For the control, set all first visits to 1. The reserved entries can stay as they were on the initial sheet: they will not be used. Each version delivers 4 parcels in 4 attempts. The differences are 4 − 4 = 0, in parcels for ΔD and in attempts for ΔT.

This case checks that the mechanism stays inactive when all parcels are delivered at the outset. If the versions differ despite this, look for a hidden change or a counting error. If they do not differ, this does not prove that retries are useless in scenarios where first visits fail.

  • Describe a sheet prepared in advance whose unused entries stay in place.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1How do you distinguish a reference scenario from a baseline version?

The reference scenario is the fixed setting, which can be replayed and checked by hand. The baseline version is the reference rule used in the comparison; here, the robot without retries. Both versions must receive the same scenario.

Recall 2What must you remove and preserve to study retries by ablation?

Remove only the retry rule. Preserve the external outcomes, starting state, stopping conditions and measures. Actions and outputs can change because of this removal.

Recall 3Why might the same seed be insufficient after an ablation?

The branches may consume different numbers of draws and assign the numbers to different events. Preparing a sheet indexed by parcel and visit preserves the correspondence; an unused reserved entry does not shift to the next parcel.

Recall 4How can you check the difference in deliveries and the difference in attempts without just recalculating the totals?

Compare the identities of delivered parcels: only B changes status, giving 1 parcel. Then identify the added visits: the return visits for B and C give 2 attempts. The two differences have distinct units and roles.

Recall 5What can you learn from a scenario where ablation changes no output?

If all first visits succeed, no return visit is triggered: equality is expected and provides a check on the protocol. It does not show that retries are useless on other scenarios. A single case does not measure the uncertainty of an average effect.
