Search

Your goalFind a key in an array, justify every discarded region and distinguish any occurrence from the first occurrence.

Before you start

✿01 See the idea

You keep a register of keys for a workshop. Someone asks for the key with code 52. Reading each entry from the beginning works even if the codes were entered in no particular order. But if the codes are already arranged from smallest to largest, a middle entry can let you discard a whole part of the register.

Here the register is an array: a sequence of cells where you can read a requested cell directly using its number. This number is called an index. Indices start at 0; the code written in a cell is a separate piece of information. For example, the cell at index 5 holds code 52.

Sequential search examines the cells in order. Binary search, or searching by halves, examines the middle of a region where a match is still possible. If this code is less than the requested code, the order of the array lets you discard the middle cell and everything before it. If the code is greater, you discard the middle cell and everything after it.

This register and its codes are fictional. The register stays unchanged during each search. We are looking for an exact code match, not a key with a nearby code. The main example has no duplicates; an exercise will examine what changes when a code is repeated. Having the entries in order is an assumption: learning to sort belongs to the next unit.

The rule to remember

State what you must return, then justify every discarded cell. Sequential search works without any prior ordering; discarding a half requires a known order on the criterion actually being compared.

✿02 Follow an example

Worked example

Find key 52 in the same register

Array A contains, in this order, [12, 18, 25, 31, 44, 52, 67, 90]. Target t is 52. Let us find an index holding exactly this code, or return the distinct result “absent” if there is none. The array is already sorted and its codes are distinct.

  1. Set the contract and define the quantities

    A denotes the array and A[i] the code in its cell at index i. n is the number of cells, here 8; valid indices run from 0 to n − 1, hence to 7. t is the target. The codes are integer identifiers with no physical unit; we compare their numerical values. Indices are positions with no physical unit, and counts are expressed in cells examined.

    The result “absent” is a state distinct from every index, including index 0, which is valid. The contract here asks for any occurrence: a valid index i such that A[i] = t. Since the codes in this array are distinct, this index is also that of the first occurrence. If the contract requires the first occurrence even with duplicates, this will need a separate check.

  2. Scan without assuming any ordering

    Sequential search starts with i = 0. While i < n, it reads A[i]. If A[i] = t, it returns i and stops. Otherwise, it increases i by 1 and repeats. If i reaches n, it returns “absent”, without trying to read A[n].

    Its invariant is: no cell with an index strictly less than i contains the target. Initially, this region is empty. A failed equality test lets us add the current cell to it. A match is therefore the first occurrence. After each failed test, n − i, the number of cells still to read, decreases by 1; this integer cannot decrease indefinitely. The search eventually finds a match or finishes reading everything.

  3. Trace the sequential count

    At index 0, 12 ≠ 52: 1 cell examined. At index 1, 18 ≠ 52: 2 cells. At index 2, 25 ≠ 52: 3 cells. At index 3, 31 ≠ 52: 4 cells. At index 4, 44 ≠ 52: 5 cells. At index 5, 52 = 52: return index 5.

    The count is the index found + 1, because we also count the cell at index 0: 5 + 1 = 6 cells examined. Independent check: crossing out the codes as they are read marks exactly the first 6 codes in the register. Neither code 52 nor index 5 is this count.

  4. Define binary search

    g and d are the indices of the left and right boundaries, both inclusive. Initialize g = 0 and d = n − 1. While g ≤ d, calculate the middle index m using the formula below. The floor brackets ⌊ ⌋ mean taking the greatest integer less than or equal to the quotient: round down to an integer, without rounding to the nearest integer.

    m=⌊g+d2⌋

    Read A[m]. A match returns m. If A[m] < t, set g = m + 1. If A[m] > t, set d = m − 1. Then repeat with the new bounds. When g > d, the region is empty and the result is “absent”.

    This rule assumes an array in ascending order, with equal neighboring values allowed, and consistent comparisons of the same codes. Reading the middle cell directly must be possible: a queue from which only the front item can be removed does not provide this operation. We neither remove nor copy half of the array; we only move its bounds.

  5. Examine the first middle cell

    Initially, g = 0 and d = 7. Their sum is 7; division gives 7/2 = 7/2 = 3.5. Rounding down to an integer gives m = 3. The code read is A[3] = 31, less than 52.

    Since the register is sorted, all codes at indices 0 to 3 are at most 31. None equals 52. We discard them together and set g = 3 + 1 = 4, keeping d = 7. There are n − g = 8 − 4 = 4 cells left, at indices 4 to 7.

  6. Find and check the answer

    The new sum of the bounds is 4 + 7 = 11. Its quotient by 2 is 11/2 = 5.5. The middle index rounded down is therefore m = 5. We read A[5] = 52 = 52; we return index 5.

    Contract check: 0 ≤ 5 < 8 and the indicated cell does hold 52. We examined 1 cell on the first iteration and 1 on the second, making 2 cells. The sequential scan examined 6. Here we count a cell as examined each time its code is read and compared with the target, regardless of the number of elementary tests needed. This count measures neither seconds nor a program speedup. Preparing a sorted array is not included.

  7. Why elimination and termination are sound

    The binary search invariant is: if the target occurs, an occurrence still lies between g and d inclusive. It holds initially because the region covers the entire array. If A[m] < t, the ordering excludes indices up to and including m; if A[m] > t, it excludes indices from m onward. Each update therefore preserves the invariant. A match returns an answer that can be checked; an empty region, together with the invariant, proves absence.

    For a nonempty region, h = d − g + 1 counts its cells. Since g ≤ m ≤ d, the updates exclude at least cell m. After a failed equality test, h strictly decreases, eventually reaching an empty region. With the example data, we went from 8 to 4 cells, then found a match. Keeping g = m or d = m could leave a region containing a single cell unchanged.

    Sequential search may need to examine all n cells to conclude that the target is absent. Binary search uses the ordering to discard regions without reading them. Choosing between the methods therefore requires knowing the representation of the register and its contract; the terminology for orders of computational cost will be covered later.

Explain it in your own words

✿03 Common mistakes

  • “The middle code is too small: I can always discard the left side.”

    This deduction requires every cell on the left to hold a code at most equal to the middle code. Check the ordering of the codes actually being compared. Without this guarantee, use a sequential scan instead; the requested code could be in the discarded region.

    Review what allows a region to be discarded

  • “After a failed equality test, I keep the middle index as the new bound.”

    The middle cell has already been tested and does not equal the target. Exclude it with m + 1 or m − 1. Work through the reasoning again with a region containing a single cell: keeping that same cell can cause the same test to repeat indefinitely.

    Review the rule and its termination proof

  • “I found a match, so I found the first occurrence.”

    This is true for our example without duplicates and for a sequential scan from the beginning. A binary search that stops at a match may find a duplicate farther along. First clarify the contract: if it requires the first occurrence, use the sequential scan presented here or prove another suitable rule.

Initial iteration: [0, 7], quotient 7/2 = 3.5, middle index 3, code 31 < 53. Set g = 4. Next iteration: [4, 7], quotient 11/2 = 5.5, middle index 5, code 52 < 53. Set g = 5 + 1 = 6.

The region [6, 7] contains 7 − 6 + 1 = 2 cells. Sum of the bounds: 6 + 7 = 13; quotient 13/2 = 6.5; middle index 6. Its code 67 is greater than 53, so d = 6 − 1 = 5.

We obtain g = 6 > d = 5: an empty region, result “absent”, after 2 + 1 = 3 cells examined. Independent check: the register places 53 strictly between neighboring codes 52 and 67, with no cell holding this code. A complete sequential scan confirms absence after 8 cells.

For the empty register, n = 0, g = 0 and d = 0 − 1 = -1. The condition g ≤ d is false immediately. Return “absent” after 0 cells examined, without calculating a middle index or reading A[0].

The same code appears in two entries

Hint 1

The first middle cell still holds 31. The next middle cell is at index 5.

Hint 2

A match at this index alone tells you nothing about the preceding cell.

Compare with the solution

Binary search reads code 31 at index 3, then code 44 at index 5. It therefore returns 5 after 2 cells examined. This cell does contain the target: a contract asking for any occurrence would be met.

But the cell at index 4 already contains 44. The sequential scan reads indices from 0 and finds its first match at 4, after 5 cells examined. Returning 5 therefore does not meet the contract requiring the first occurrence.

A repair justified on this page is to use the sequential scan that stops at the first match. A binary search that continued after a match would require another rule and its own invariant; simply changing the wording of the promise does not provide them.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must you specify before choosing a search method?

The equality criterion, the required result and how absence is handled: reporting presence, returning the index of an occurrence and returning the first occurrence are different contracts. Also specify whether the array is sorted, directly accessible and unchanged during the search.

Recall 2Which invariant explains why a sequential scan returns the first occurrence?

Before reading A[i], all cells with an index less than i have been tested without a match. The first match encountered is therefore the first occurrence; if i reaches n, every cell has been ruled out.

Recall 3Why can everything before a middle cell whose code is too small be discarded?

In an array sorted by the codes being compared, earlier cells have codes at most equal to the middle code. If that code is strictly less than the target, none of these codes can equal the target. Without this ordering, the exclusion is not justified.

Recall 4How can you guarantee that binary search makes progress, even with a single cell?

With inclusive bounds g and d, a failed equality test excludes the middle cell: g becomes m + 1 or d becomes m − 1. The region strictly shrinks. When g > d, it is empty and we return “absent” before reading another cell.

Recall 5Does finding a match by binary search guarantee the first occurrence?

The rule that stops immediately at a match guarantees any occurrence. With duplicates, a match may exist earlier. A sequential scan from the beginning guarantees the first occurrence through its invariant.
