Level 1 · C018·M2

Composition and injection

Your goalAssemble a parcel preparer with a rate supplied from outside, then trace which object actually calculates the quote.

Before you start
c016-m5 : documentation · c015-m5 : diagnosis · c017-m5 : reproduction protocol · c012-m5 : counterexamples · c018-m1 : interface and contract

✿01 See the idea

You are preparing a parcel. To state its price, the preparer consults a rate sheet you have supplied. You want to choose this sheet when assembling the program, while keeping the same method for preparing the quote. The scene and all its amounts are fictitious: no real carrier is represented.

In our small program, Preparateur is a class, the template that describes a preparer; p is an object created from this class. Tarif is another class. The object tarif_relais holds the pricing parameters and can calculate a cost. The preparer keeps a reference to this object: a reference lets it find the same object without making a copy.

Composition here means making an object work by relying on another component. The preparer holds a reference to the rate object and delegates the calculation to it. This rate object is its dependency: it needs it to return the quote. Injection means supplying this dependency from outside. Here, we choose to pass it in when the preparer is created.

Look at the diagrams separately: the first shows how the rate object is supplied; the second traces the call that requests a price. Supplying an object does not, by itself, trigger its calculation method. The word injection here means supplying a software component.

The rule to remember

Choose and create the rate object outside the preparer; supply it to the preparer; keep its reference; then call its operation while respecting the contract.

✿02 Follow an example

Worked example

The pickup-point rate for a 750 g parcel

We want a quote for 750 g with a fixed fee of 200 cents and a variable charge of 400 cents per kilogram. The mass is known and is a nonnegative whole number. We trace the mechanism on paper, using exact calculations, without rounding or any actual shipment.

  1. Define the contract and the quantities

    The component contract is: cout(masse_g) receives a whole-number mass in grams, greater than or equal to 0, and returns an exact cost in cents. For this fictitious rate, the cost is the fixed fee plus the charge proportional to the mass. There are no pricing bands, discounts or commercial rounding rules. The rate parameters stay fixed throughout the quote.

    In the formulas, m is the mass in grams; G = 1000 g/kg converts grams to kilograms; q is the mass in kilograms. F = 200 cents is the fixed fee; r = 400 cents/kg is the price per kilogram; C is the returned cost, in cents. For display, E = 100 cents/€ is the currency conversion factor and P is the amount in euros.

    In the program names, the suffix g indicates grams and the suffix c indicates cents. Tarif(fixe_c, par_kg_c) creates an object that keeps the fixed fee fixe_c and the rate par_kg_c. The latter is expressed in cents per kilogram. The contract covers the units and the result as well as the method name.

  2. Choose the component and supply it

    The assembly code writes tarif_relais = Tarif(200, 400), then p = Preparateur(tarif_relais). The first call creates the rate component; the next creates the preparer and supplies it with this component. We then have 1 Tarif object and 1 Preparateur object.

    azezxl vplxtu fnmdxp sirzym ohwqwt gtspgn dszn agtphc dawsqj pxdrze fnlaxb cerkjw sbsauy ogfv Its statement self.tarif = tarif keeps the supplied reference. self refers to the preparer being initialized, and self.tarif is its attribute, that is, the name under which it keeps this reference.

    The preparer therefore does not choose the rate object in its initializer. The decision is made in the assembly code. Keeping the reference does not copy the object; we simply assume that nobody changes its parameters during this example. At this point, no price has been requested.

  3. Trigger the call on the right object

    We now request p.devis(750). The preparer’s devis method receives the mass and executes the statement return self.tarif.cout(masse_g). The word return means that the value produced is sent back to the caller.

    Read this statement in parts: self.tarif finds the stored component; cout(masse_g) calls its method with the mass; return sends back its result. Here, self.tarif refers to tarif_relais: that object therefore applies its fixed fee and its rate.

    Creating p and calling p.devis are separate actions. Our preparer’s contract specifies that it calculates a quote only when this call is made. Its job is to delegate the calculation to the component it received, then return the cost in cents.

  4. Convert the mass before applying the rate

    The rate is given per kilogram. We therefore divide m by G to express the same mass in the unit expected by the rate. Since 1 kg contains 1000 g, the value in kilograms is smaller than the value in grams.

    q=mG=7501000=0.75 kg

  5. Calculate the cost, then the amount to display

    Multiplying r × q gives the variable charge: 400 cents/kg × 0.75 kg = 300 cents. The kilogram units cancel. We then add the fixed fee, also in cents; adding the mass directly to the fixed fee would mix different quantities.

    C=F+rq=200+300=500 centimes

    Tarif.cout returns this cost; Preparateur.devis returns it in turn. The reader can then convert the result to euros. This display conversion does not change the unit of the result promised by cout.

    P=CE=500100=5.00 €

  6. Check the calculation and the assembly

    Check the numbers another way: expressing the rate per gram gives 400/1000 cent per gram. For the parcel, the variable charge is (400 × 750)/1000 = 300 cents; with the fixed fee, we again obtain 500 cents. The reverse conversion gives 5.00 € × 100 cents/€ = 500 cents.

    Check the mechanism: start again from tarif_relais, trace how it is passed into Preparateur(tarif_relais), then find self.tarif in the devis method. The expected number is not enough to show which reference was kept: a rate object recreated internally with the same parameters would also give that number.

    We have reconstructed a quote and its intended path. No parcel has been paid for or shipped through this reasoning. The exercises will change the mass, then the supplied component, so that you trace the same relationships without copying the result.

✿03 Common mistakes

  • “Supplying Tarif means supplying my rate object.”

    Tarif refers to a class here. tarif_relais refers to the object created with the chosen fixed fee and rate. Our preparer expects this object and its cout method. Create the component, then trace the same reference through the tarif parameter and the self.tarif attribute.

    Reread how the component is chosen and kept

  • “There is a tarif parameter, so injection works.”

    Read the initializer body: if it creates its own Tarif and ignores the argument, the supplied component will not be used. Fix the assignment with self.tarif = tarif, then trace the reference through to devis. The last exercise asks you to diagnose this case.

    Diagnose the ignored rate object

  • “If the method is called cout, I can replace the component.”

    Check the full contract: mass in grams, result in cents, accepted domain and stated behavior. An object that expects kilograms or returns euros cannot be supplied as it stands to this preparer. To replace the component, you must first make these expectations compatible.

    Review the units in the contract

Find the call that receives an object that has already been created. A number of grams supplies data for the request; the rate object supplies the component that can calculate.

Hint 2

Compare with the solution

The dependency is supplied during Preparateur(tarif_relais), then kept by self.tarif = tarif. The Tarif call creates this component beforehand. Assembly alone does not calculate any price.

The devis call passes 250 g to cout on tarif_relais. The mass is 250/1000 = 0.25 kg. The variable charge is 400 × 0.25 = 100 cents.

The return value is 200 + 100 = 300 cents, or 3.00 €. Check: the cost exceeds the fixed fee but stays below the quote for the 750 g parcel, since the mass is smaller and the rate is positive.

  • You justify the return value of 300 cents and the conversion to 3.00 €.

Exercise 2 · Reasoned replacement

Choose the home-delivery rate

The same 750 g parcel must be priced using tarif_domicile = Tarif(200, 600). This object respects the same cout contract: grams as input, cents as output. Write the intended assembly, calculate the quote and its difference from the pickup-point rate. Does the devis method need to change?

Assisted answer: try this exercise without help later.

Hint 1

Change the object supplied to Preparateur. The devis method can continue to call self.tarif.cout(masse_g).

Hint 2

The fixed fee is the same; only the variable charge changes. Calculate both quotes in the same unit before subtracting them.

Compare with the solution

The assembly becomes p = Preparateur(tarif_domicile). The initializer keeps this object and the devis method keeps its statement return self.tarif.cout(masse_g). The choice is made when this preparer is created; we do not assume any automatic change to an object constructed previously.

The mass remains 0.75 kg. The variable charge becomes 600 × 0.75 = 450 cents. The quote is 200 + 450 = 650 cents, or 6.50 €.

The difference is 650 − 500 = 150 cents, or 1.50 €. Check using the rates: (600 − 400) × 0.75 = 150 cents. The common fixed fee cancels. This result follows the chosen fictitious parameters; it does not measure any actual advantage of a delivery option.

Check your reasoning

  • You supply tarif_domicile when constructing the preparer.
  • You keep the same devis method and justify compatibility using the full contract.
  • You obtain 650 cents and check the difference of 150 cents another way.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is composed in the parcel scene?

A preparer works with a rate object whose reference it keeps. When devis is called, the preparer delegates the calculation to that object’s cout method.

Recall 2Where is the rate chosen when injection takes place at creation?

In the assembly code: it chooses and creates the rate object, then supplies it to Preparateur. The initializer keeps the received object with self.tarif = tarif.

Recall 3Why does Preparateur(tarif_relais) not yet give a quote?

In the mechanism defined here, this call creates the preparer and keeps the rate object. The calculation starts only at p.devis(masse_g), which calls cout on the component.

Recall 4What checks come before replacing the rate object?

The replacement must provide the expected cout operation, accept the mass in grams over the intended domain and return a cost in cents with the stated behavior. The method name alone is not enough.

Recall 5Are a tarif argument and a correct amount enough to prove that the supplied object is used?

No. You must trace the argument through to the stored attribute, then to the call. Internal creation with the same parameters can produce the expected amount while ignoring the supplied component.

Reconstruct the reasoning
