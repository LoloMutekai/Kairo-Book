Level 1 · C017·M4

Immutable data

Your goalPreserve the exact inputs to a calculation, make corrections in a new version and reproduce the original result.

Before you start
c016-m5 : documentation · c007-m5 : execution traces · c017-m1 : Git · c017-m2 : dependencies · c017-m3 : parameters

✿01 See the idea

You calculate the mean delivery time for a short delivery round. Log A contains 8, 10 and 12 minutes. The next day, you discover a data entry error: the middle delivery took 16 minutes. If you replace the old value in the only available file, how will you explain the result published yesterday?

Imagine log A as a sheet of paper placed in an envelope. You can still read it, but you no longer write on it. You create a corrected log B, stating that it comes from A and identifying the cell that changed. The old sheet preserves what the calculation actually received, even though it contains a known error.

Here, immutable data means a dataset whose content is preserved unchanged under a given identity. A correction receives a new identity. This does not make the observations true: it lets you retrieve exactly those that were used. The working folder can change; each preserved version keeps its own content.

The scenario and all its times are fictional. We track the same deliveries, in the same order, with the same unit and the same rule for calculating the mean. There are no missing values or differences in selection between A and B.

The rule to remember

Read a preserved version; make corrections elsewhere; link each result to the version actually used.

✿02 Follow an example

Worked example

Reproduce yesterday’s calculation after a correction

Log A contains the times 8, 10, 12 min; log B corrects only the middle time to 16 min. We will calculate the results for both versions, explain their difference and rerun A.

  1. Fix the content and the rule

    A denotes the preserved original log, B the corrected log. x, y and z denote the delivery times, in minutes, in the order of the chosen log. n is the number of deliveries, with no physical unit; here n = 3. S is the sum of the times, in minutes; m is the mean, in minutes per delivery. When reading it out, we will simply say “minutes”.

    The mean distributes the total equally across the deliveries: add the times, then divide by the number of deliveries. We assume n is strictly greater than 0 and all times are expressed in minutes. No delivery is removed. The calculation is deterministic: the same inputs and the same rule give the same result.

    S=x+y+z;m=Sn

  2. Calculate the result associated with A

    Read A without changing it. The first times give 8 + 10 = 18 min; add the last one: 18 + 12 = 30 min. This sum adds up the times; it does not yet represent a mean delivery time.

    Divide the total among the 3 deliveries: 30 ÷ 3 = 10.0 min. Keep the record “result A, input A, mean delivery time in minutes”. Reverse check: 10 × 3 = 30 min. This recovers the total.

  3. Create B and record the correction

    A remains (8, 10, 12) min. In a separate working copy, replace the middle time: 10 becomes 16 min. Preserve this copy under the identity B, with the note “derived from A; middle time corrected after checking the log”. In this fictional scenario, the correction is given in the problem statement; it is not demonstrated by the mean.

    B still contains 3 deliveries. The increase in the corrected cell is 16 − 10 = 6 min. Creating B preserves the historical error in A and lets you mark A as superseded. This does not require you to keep using A for new conclusions.

  4. Calculate B and explain the difference

    In B: 8 + 16 = 24 min; then 24 + 12 = 36 min. The mean is 36 ÷ 3 = 12.0 min. Associate it with B, without labelling it as result A.

    Independent check: a single time increased by 6 min, with no change in the number of deliveries. The total must therefore increase by 6 min: 36 − 30 = 6 min. The mean must increase by 6 ÷ 3 = 2 min. We recover 10 + 2 = 12 min. This difference does not demonstrate any improvement in deliveries: only the entered data changed.

  5. Rerun the historical version and check the content

    To explain yesterday’s result, use A again: 8 + 10 + 12 = 30 min, then 30 ÷ 3 = 10.0 min. The difference from its previous result is 10 − 10 = 0 min. Using B for this operation would answer a different question.

    However, an identical mean is not enough to prove that file A is intact. You must also retrieve its content: for our small log, compare each time, its position and its unit with the reference copy. On a larger scale, a content hash is a summary calculated from the bytes of the file, meaning the units of its digital content. Comparing it with a reference hash preserved separately helps check integrity. It does not preserve the file in its place or certify the accuracy of the readings.

    In practice, keep reference versions separate from calculation outputs and prevent them from being overwritten during ordinary work; prepare each correction in a separate file. Write protection helps enforce this rule. A separate backup lets you recover the content if it disappears. Renaming a file, marking it “final” or keeping only its hash guarantees neither its protection nor its availability.

✿03 Common mistakes

  • “An error must be corrected in the original file.”

    Create B and document its relationship to A. Mark A as superseded, but preserve its inputs to explain the historical result. Immutability preserves the trace; it does not turn an error into a fact.

    Review the creation of B and the rerun of A

  • “The file name is the same, so the data must be too.”

    A path identifies a location; its content can be replaced. You need a preserved version with a content reference, then you must check what the calculation actually reads. A second name pointing to the same modifiable object is not an independent copy.

    Reread the diagram linking input and result

  • “I get the same mean, so nothing has changed.”

    Changes can cancel out in the sum. The last exercise constructs a different log that gives the same result. Check the content, then the calculation: these checks answer different questions.

    Test the false proof based on the mean

Hint 1

Compare the cells, even if the sums look similar.

Hint 2

Compare with the solution

The total is 8 + 11 = 19 min, then 19 + 11 = 30 min. The mean is 30 ÷ 3 = 10.0 min. The difference between the totals is 0 min; the result is the same as for A.

However, the middle time is 11 instead of 10 min and the last is 11 instead of 12 min. The content has changed. The changes cancel out, hiding the difference in the mean. This summary alone therefore cannot validate its integrity.

Preserve the modified file to understand what happened and give it a distinct identity. Use the intact reference for A to reproduce the historical result; check its content and the link from the calculation to this reference. If this reference is missing, the mean alone cannot reconstruct the inputs: exact reproduction has not been established.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does making a log immutable preserve?

Its content under a given identity. Corrections create new versions; the old version remains readable so that the inputs to a past calculation can be retrieved. This does not guarantee the accuracy of its readings.

Recall 2How can you correct A while keeping its analysis reproducible?

Create a separate copy B, record its relationship to A and the correction, preserve A unchanged and link each result to the input actually used.

Recall 3Why does an unchanged mean fail to prove that the content is unchanged?

Changes to cells can cancel out. Comparing the content or checking it against a reference hash tests something beyond the calculation result alone.

Recall 4Is a hash enough to repeat an analysis?

No. It helps check a file against a reference, but does not replace the available content, the calculation rule or the other conditions required for reproduction.

Recall 5Does an object protected against modification in memory prove that input files are preserved?

No. You must separately check the preservation and availability of the inputs, as well as the content actually read by the analysis.

Relate preserved data to protection in memory

What you understand
A correction must be distinguishable from the historical input. Preserving this input lets you recover its calculation; it does not demonstrate that the input is true. Protecting an object during a calculation and preserving a file over time have different scopes.
