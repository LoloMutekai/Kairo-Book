Level 2 · C042·M1

Document and stable identifier

Your goalTrack the same instruction sheet through a move, an edit and a new import, keeping its identity separate from its revision and location.

Before you start
c040-m5 : least squares · c041-m5 : transactions and windows · c025-m5 : O, Omega and Theta · c036-m5 : annotated charts

✿01 See the idea

In a workshop catalog, you find the instruction sheet “Lamp adjustment”. Its file moves from the fiches folder to the atelier folder. Later, a sentence is edited. Someone who cited the sheet must be able to recognize the same sheet while knowing which text they read.

Here, the document is the instruction sheet that the catalog chooses to track over time. The file is a representation of it stored at a location. Its stable identifier, AT-QF, is a label assigned to this sheet: we keep it through the changes covered by our rule. The path tells us where to look; the revision distinguishes successive states of the text. The title helps with reading and searching, but several sheets can have the same title.

The scene, labels and values are fictional. In this catalog, a move preserves the text revision; an approved edit increases it. The workshop has explicitly confirmed that this is still the same instruction sheet. This continuity is a documented decision, not something the program guesses from the words.

Start by following AT-QF in the diagrams. The label stays attached to the sheet when the path changes. When the text changes, the label still stays the same, but the revision advances. Importing the same known state again must create neither another document nor another revision.

The rule to remember

Keep the identifier of the recognized document; change its location and revision separately. To retrieve a specific text, also keep the revision and its content.

✿02 Follow an example

Worked example

Track AT-QF without multiplying instruction sheets

The catalog is empty. We import the instruction sheet from fiches/lampe.txt, move the file to atelier/lampe.txt, edit its text, then import this latest state again with the same identifier. The original content is “Turn the knob.”; the edited content is “Turn the knob on the right.” We keep the texts of past revisions in a separate history.

  1. Declare what must remain true

    D denotes the current catalog. For a label k, D(k) gives the revision r, the path p and the content c. The notation D(k) means “look up the record whose key is k”. k, p and c are strings, with no physical unit. r is a positive integer with no unit: it counts the approved states of this sheet’s text. The title is additional descriptive information, omitted from this notation.

    D(k)=(r,p,c)

    In this catalog, each key is unique and identifies only one current document. An assigned key is not reused for another instruction sheet, even after removal. Its stability depends on retaining the catalog and its mappings; inventing a new label at every launch would destroy this continuity. Uniqueness applies within this catalog: another catalog must be identified separately when exchanging references.

    For counting, N is the number of current documents, A the number of new identities accepted and S the number of documents removed during the operation. These quantities are counts in documents. N′, read as “N after the operation”, follows the rule below; the prime does not mean a derivative. The operations happen in sequence, with no concurrent changes, and are assumed to have been saved successfully.

    N′=N+A−S

  2. Import: create an identity once

    AT-QF is still available: we assign it to the instruction sheet. The current record is D(AT-QF) = (1, fiches/lampe.txt, “Turn the knob.”). The parentheses group the fields; they do not ask for any calculation on the letters of the code.

    This is indeed a new document: N = 0, A = 1 and S = 0. Therefore N′ = 0 + 1 − 0 = 1 document. The history retains the text under the pair (AT-QF, 1). Assigning a key and retaining its record are parts of the same tracking process.

  3. Move: change the address

    The record of the move explicitly tells us that the moved file represents AT-QF. We replace only p with atelier/lampe.txt. The text c and the revision r = 1 stay the same. Here, recovering this identity depends on the record of the move; the new path alone would not prove it.

    A = 0 and S = 0, because no sheet is created or removed. N′ = 1 + 0 − 0 = 1 document. The old path is no longer the current address; the reference AT-QF lets us look up the new one.

  4. Edit: change the revision

    The workshop approves the text “Turn the knob on the right.” as an edit to the same instruction sheet. The key k remains AT-QF and the path p remains atelier/lampe.txt. Our convention increases r when the content changes in this way. r′ denotes the revision after the edit.

    r′=r+1=1+1=2

    We retain the original text under (AT-QF, 1) and the edited text under (AT-QF, 2). The current catalog points to revision 2. The document count is still 1 + 0 − 0 = 1: retaining another revision does not create another document identity.

  5. Import again: recognize the state already saved

    The import explicitly carries AT-QF, revision 2 and the same edited content. We find the key, check that it matches its saved state and keep that state. The same identifier with different text for the same revision would be a conflict to resolve, not a reason to overwrite the history.

    For this identical repeat import, A = 0, S = 0 and N′ = 1 + 0 − 0 = 1 document. The revision remains 2. This operation is idempotent on the catalog: repeating it with this known state no longer changes the catalog’s content. This promises nothing about possible logs or notifications in another system.

  6. Check the counts and references

    We have carried out 1 import + 1 move + 1 edit + 1 repeat import = 4 operations. New identities accepted amount to only 1 + 0 + 0 + 0 = 1 document; no removal reduces this count.

    Independent check: listing the catalog keys gives only AT-QF. The history, however, contains the pairs (AT-QF, 1) and (AT-QF, 2), making 2 revisions. Counting them as documents would confuse documents and revisions.

    A method that created a new key for every operation would end with 4 documents instead of 1, giving 4 − 1 = 3 extra records in this scene. The correct total is still not enough: also check the key, the path and the texts. A catalog with the correct number of rows can still point to the wrong instruction sheet.

    Final check: requesting AT-QF retrieves its current edited state; requesting (AT-QF, 1) from the history retrieves “Turn the knob.” Without retaining this text, the pair would name a revision without letting us read its text again.

✿03 Common mistakes

  • “The path is already a stable identifier.”

    A path can serve as a key if the contract guarantees its stability; our move shows that it does not guarantee it here. Keep AT-QF and update the associated address. If the move was not tracked, first find evidence of a match instead of recreating or merging a sheet based on a guess.

    Follow the label during the move

  • “The title is the same, so it must be the same document.”

    The title describes the instruction sheet without guaranteeing its identity. Another document can have this title, and the same sheet can be renamed. Look for a previously assigned key or a reliable history; without that link, keep the ambiguity and ask for a documented decision.

    Resolve the import with no history

  • “The identifier is stable, so my citation always retrieves the same text.”

    AT-QF also persists through edits: its current state changes. Cite the pair (AT-QF, 1) for the original text and check that this content is still retained and accessible. A stable key guarantees neither that the text is immutable nor that it is available.

Compare with the solution

The reported counts are appropriate: 1 identity, AT-QF, and 2 identifier–revision pairs. But the original content has been replaced or incorrectly referenced. The number of revisions does not prove that their text is correctly retained.

We must restore the association between (AT-QF, 1) and its documented text “Turn the knob.”, then read each version again. In the scene, the original text is provided; in a real situation, without a reliable copy, we would declare this revision unavailable instead of reconstructing it from memory.

A strictly identical import of the current revision keeps 1 document and 2 revisions. Idempotence applies to this state of the catalog; it does not automatically repair a history that is already wrong.

Exercise 3 · Transfer and justified decision

A file with no identity arrives at the workshop

The catalog is in the final state of the example. A received file also has the title “Lamp adjustment”, with different text, but no identifier or history. A colleague proposes replacing AT-QF immediately. Can we decide that this is the same instruction sheet? Hint 1

The same title and different text remain compatible with several histories.

Hint 2

For the count, an edit preserves the key; an independent sheet receives a new available key, for example AT-RM.

Compare with the solution

We cannot decide from the title and text alone. We need reliable provenance or confirmation from the workshop explicitly linking this file to an instruction sheet. Meanwhile, we keep the received file separately without overwriting AT-QF or claiming that its identity is resolved.

If continuity with AT-QF is confirmed, an approved edit keeps 1 document. If an independent sheet is confirmed, it receives, for example, AT-RM: 1 + 1 = 2 documents. The new title can stay the same without violating the uniqueness of the keys.

These numbers describe possible results after a decision. They do not turn the current uncertainty into a successful identification. The text received and kept separately is not yet a new document accepted into the current catalog.

Check your reasoning

  • Refuse to infer identity from the title alone or from the difference in text alone.
  • Distinguish the conditional counts of 1 and 2 documents.
  • Preserve the file and the existing record while awaiting provenance or explicit confirmation.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1How do you distinguish the instruction sheet, its file and its path?

The instruction sheet is the document tracked by the catalog. The file represents a stored state of it; the path tells us where to look for that file. The tracked move changes the address while preserving the same sheet.

Recall 2What obligations make AT-QF stable in this catalog?

Assign this key to the instruction sheet once, retain its mapping through recognized changes, guarantee its uniqueness in the catalog and never reuse it for another sheet. The catalog itself must be retained.

Recall 3Why should importing the same known state again not create another instruction sheet?

Its key, revision and content already match a saved state. The import can therefore preserve that state instead of assigning it another identity. This is idempotence on this catalog, with no promise about other effects in the system.

Recall 4What is needed to read the original text again after it has been edited?

The pair (AT-QF, 1) identifies the original state. We must also have retained that text and be able to retrieve it. AT-QF alone identifies the instruction sheet whose current state is now revision 2.

Recall 5Is an identical title enough to merge a received file with AT-QF?

No. The title is not unique, and the content does not tell its own history. We need a reliable mapping or a documented decision; meanwhile, preserve the states without declaring the identity resolved.
