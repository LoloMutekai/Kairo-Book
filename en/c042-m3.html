Level 2 · C042·M3

Exact index and cost

Your goalFind the best vector with an exhaustive scan, justify why this choice is exact, and quantify its cost in operations and bytes.

Before you start
c040-m5 : least squares · c041-m5 : transactions and windows · c025-m5 : O, Omega and Theta · c036-m5 : annotated charts · c042-m1 : document and stable identifier · c042-m2 : norm, cosine and normalization

✿01 See the idea

In a bicycle repair workshop, you are looking for a sheet on adjusting a brake. Beside each stable identifier, a small arrow represents the sheet. Your request has its own arrow. A reliable way to find the arrow closest to your direction is to look at every sheet without skipping any.

The flat index stores vectors side by side with their identifiers. Here, flat means that no shortcut structure rules out candidates before comparison. The search calculates every score, then returns the identifier of the best candidate. It can therefore examine the whole catalog while returning only 1 result.

Our fictional catalog contains 4 sheets, named A, B, C and D, described by 2 coordinates with no units. The vectors are supplied by hand for the exercise. They are not measured outputs from a text model; we are not yet teaching how they are produced.

Exact describes the choice among these vectors according to this score. Even an exact choice can return a text that does not answer the question. This unit covers the work needed to compare and select; the relevance of the sheets will need a separate check.

The rule to remember

Visit all the vectors, calculate the same score for each, and keep the best identifier–score pair; count the work on the candidates examined, rather than on the results returned.

✿02 Follow an example

Worked example

Find the best sheet and count the work of the scan

The catalog, which stays fixed during the search, contains A = (3/5 ; 4/5), B = (4/5 ; 3/5), C = (-3/5 ; 4/5) and D = (0 ; 1). The query is q = (1 ; 0). We want 1 result, with no threshold or prior filter.

  1. Define the score and what exact means

    N is the number of vectors, here 4; d is the number of coordinates per vector, here 2. These parameters count objects and have no physical units. q denotes the query vector and x the vector of the current sheet. j denotes a coordinate position, from 1 to d. In the formula, q with subscript j is coordinate j of the query; x with subscript j is the corresponding coordinate of the sheet. The coordinates are finite, have no units, and use the same coordinate system.

    All the vectors in the scene have a norm equal to 1. For A, the check is to verify that (3/5) squared + (4/5) squared = 1. B swaps the coordinates; C changes a sign; D and q have a unit coordinate and a 0 coordinate. The dot product s is therefore also the cosine similarity here, with no units.

    s=∑j=1dqjxj

    The large summation sign tells us to multiply corresponding coordinates, then add their products. The highest score wins. The exact index must find this maximum among all the vectors in the catalog under consideration. We calculate with exact fractions; in a tie, we would choose the identifier that comes first in alphabetical order.

  2. Calculate each score with the same rule

    For A, the horizontal product is 1 × 3/5 = 3/5, and the vertical product is 0 × 4/5 = 0. Their sum gives s(A) = 3/5, or 0.60 with no units.

    For B: 1 × 4/5 = 4/5; 0 × 3/5 = 0. So s(B) = 4/5 + 0 = 4/5, or 0.80 with no units.

    For C: 1 × (-3/5) = -3/5; 0 × 4/5 = 0. So s(C) = -3/5, or -0.60 with no units. A negative score is still a valid result.

    For D: 1 × 0 = 0; 0 × 1 = 0. So s(D) = 0 with no units. We have applied the same operation to every sheet, including products that equal 0.

  3. Keep a maximum without sorting the whole catalog

    After A, the stored pair is (A ; 0.60). We initialize it with the first sheet actually examined: starting from a 0 score could exclude every result in a catalog whose scores were all negative.

    B beats A: 0.80 is greater than 0.60. The pair becomes (B ; 0.80). C and then D have lower scores than B, so the pair stays unchanged. There are 3 score comparisons after initialization.

    The result is identifier B together with the exact score 4/5. The document can then be retrieved using that identifier. Returning only the best candidate does not require a complete ranking of all the sheets.

  4. Check the guarantee obtained

    After each sheet, the pair we keep identifies the best score among the sheets already seen. This is the scan invariant: it is true after A; comparing the next sheet with the previous best preserves it. Once all the sheets have been seen, it covers the whole catalog.

    Direct check: 0.80 is greater than 0.60, -0.60 and 0.00. B exceeds A by 1/5, or 0.20 with no units. Changing the visiting order does not change this unique maximum.

    Stopping as soon as B looks good is not a proof: unless we examine the remaining sheets or have a bound proving that they cannot beat B, the invariant covers only the sheets visited. No such shortcut is used here.

  5. Count the work for the query

    The cost model is dense: for each sheet, it performs d multiplications, then d − 1 additions. The first product initializes the sum; we do not add all the products to an initial 0. We count arithmetic operations, excluding memory reads and loop tests. The vectors are already normalized before this count begins.

    Multiplications=Nd=4×2=8
    Additions=N(d−1)=4×1=4

    Selection adds N − 1 = 3 score comparisons. Here there are no ties to break. Returning 1 result has not removed any of the 8 products.

    The total work of this scan is Θ(Nd), read as “of the order of N times d”: it is bounded above and below by constant multiples of Nd as the sizes grow, in this operation model. With d fixed, doubling the number of sheets doubles the number of products. Other exact structures can use bounds; we are analyzing only this flat index.

  6. Count the stored coordinates

    The catalog contains N × d = 8 coordinates. Assume machine storage with a fixed width of b = 4 bytes per coordinate. b is a representation convention for this budget, rather than a measurement of the actual memory used by the program or the size of a Python fraction.

    Charge utile=Ndb=4×2×4=32 octets

    The 32 bytes cover only the coordinates. We must also include identifiers, texts if retained, the query, program structures, and any working copies. Coordinate storage is Θ(Nd) for fixed b.

    Preparing this flat index requires, at a minimum, storing the supplied vectors and linking their positions to identifiers. Normalizing and producing them are separate tasks. This search budget does not quantify those tasks or the writes needed to save the index.

  7. Interpret the result within the stated guarantee

    The arithmetic check in the course uses fractions, so it loses no precision on these data. A machine library generally works with numbers of finite precision: there, “exact search” distinguishes exhaustive search from approximate candidate selection, among other things; it does not promise real arithmetic without rounding.

    A count of products is not a response time. Hardware, memory transfers, and the way calculations are grouped affect the duration. Performing several products in parallel can change this duration without reducing the number of products in the model.

    We have proved which vector wins and counted the stated work. We have not established that B meets the need expressed in the query text. The sheet must be read, and document retrieval must be evaluated separately.

✿03 Common mistakes

  • “I only ask for the best, so I only compare one sheet.”

    The best is defined relative to all eligible candidates. In our scan, 4 sheets are examined for 1 returned result. Count the 8 multiplications again, then distinguish this work from the 3 score comparisons.

    Review the count of work for the query

  • “Exact means the sheet must answer my question.”

    The score compares supplied vectors. The exact maximum guarantees a choice according to this score in this catalog. To judge the text, retrieve it by its identifier and compare its content with the need; similarity does not perform this check.

    Reread the scope of the word exact

  • “N times d times b gives all the memory used.”

    This multiplication counts only the coordinates, here 32 bytes under the assumption b = 4 bytes per coordinate. Add identifiers, texts, and workspaces separately; no actual total memory usage is measured here.

    Review the budget for stored coordinates

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does the word exact guarantee in our search?

The scan finds the maximum of the stated score among all the vectors in the catalog under consideration. It does not guarantee that the associated document meets the need. The course calculation uses fractions; a machine execution must also account for rounding.

Recall 2Why is a single identifier–score pair enough to find the best?

After each visit, the pair represents the best among the sheets already seen. Comparing the next sheet with this best preserves the property. After the last sheet, it covers the whole catalog; the first pair comes from an actual sheet, even if its score is negative.

Recall 3Reconstruct the counts for a dense query on N vectors of dimension d.

With the sum initialized by the first product: Nd multiplications, N(d − 1) additions; keeping the best adds N − 1 score comparisons excluding tie breaking. The vectors are already normalized. Returning fewer results does not eliminate these comparisons with candidates.

Recall 4What does Ndb count, and what else must be known before stating total memory usage?

Ndb counts coordinate bytes at a fixed b bytes per coordinate. Identifiers, texts, queries, structures, and any copies need additional budgets; Ndb alone does not measure total memory usage.

Recall 5If the number of vectors and their dimension double together, what happens to the number of products?

Each of the factors N and d is multiplied by 2. Nd is therefore multiplied by 4. This describes the work of the dense scan without predicting the same factor for its actual duration.
