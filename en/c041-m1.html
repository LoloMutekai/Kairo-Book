Relational model

Your goalDescribe a relation through its schema and rows, check value domains, and distinguish the number of attributes from the number of facts represented.

Before you start

✿01 See the idea

In the school garden, we want to communicate what the trays contain without writing a different sentence for each one. We always use the same questions: which tray, which crop, how many pots? The fictional record says: tray A, basil, 4 pots; tray B, mint, 6 pots; tray C, basil, 5 pots. All the counts describe the same moment.

The table makes the facts comparable because each column keeps the same meaning. Its header gives the structure; the rows give the contents of the record. Adding a tray changes the contents without requiring a new column.

In the relational model, a relation is a set of rows with the same structure. A row is also called a tuple; a named column is an attribute. The word “relation” refers to this set of facts, even when our example contains only a single table. It does not necessarily mean a link between several tables.

Look at the first diagram, then hide it: the tray name, crop and count must stay associated. The second diagram shows the contract that lets us read all the rows. The labels A, B, C and D are tray names, with no unit; the unit for the counts is the pot.

The rule to remember

First decide what a row asserts and what each attribute accepts. The schema describes the structure; the relation contains the distinct tuples present at a given moment.

✿02 Follow an example

Worked example

Turn the garden record into a relation

Use exactly the trays A, B and C from the diagram. Build their schema, count the values represented, then check an accidental copy and the addition of tray D. All the data are fictional.

  1. State what a row represents

    A row asserts: “at the moment of the record, this tray contains this crop and this number of pots”. We assume a single crop per tray, whole pots counted, and all values filled in. This choice of what a row represents is called its granularity. A row represents neither an individual pot nor the history of the tray.

    If a tray contained several crops, this contract would need to be revised. Writing “basil, mint” in Crop would change the meaning of that cell: it would hold a list instead of a crop name. We keep the stated rule so that we can check the rows.

  2. Define the schema and its domains

    Let S be the schema Trays(Tray, Crop, Pots). It lists the attributes, their domains and our rules for reading them. D with the subscript “bac” denotes the allowed tray names: A, B, C, D. D with the subscript “culture” denotes the allowed crop names: basil, mint. D with the subscript “pots” denotes integers greater than or equal to 0, counted in pots. A subscript specifies which domain we mean. Tray and Crop are text with no physical unit; Pots is a count whose unit is the pot.

    R denotes the current contents, meaning the set of tuples recorded under this schema. The symbol ⊆ means “is a subset of”. The product × of the domains here means “all possible combinations of values”, rather than multiplying counts of pots.

    R⊆Dbac×Dculture×Dpots

    This notation says that each value in a tuple must belong to the domain of its attribute. It does not say that all combinations are present or that they all describe the garden correctly. The model imposes a form; observation supports the facts.

  3. Write the facts while keeping the associations

    Following the display order (Tray, Crop, Pots), the tuples are (A, basil, 4), (B, mint, 6) and (C, basil, 5). Each tuple gives exactly a single value to each attribute. The parentheses group a fact; they do not call for any numerical operation.

    In a relation, the order of the rows carries no meaning. Displaying C before A and B describes the same contents. You can also move columns if their names and values move together: the value 5 remains the Pots value for tray C. A number on its own does not tell you which question it answers.

  4. Calculate the size of the table

    The degree d is the number of attributes in the schema: here d = 3 attributes per tuple. The cardinality n is the number of distinct tuples in R, also written |R|: here n = 3 tuples. The bars | | ask you to count the elements of the set, not pots.

    Let C be the number of data cells represented. Each tuple has d values; with n complete tuples, we multiply. The header is excluded from this count. The formula label “cellules” means cells.

    C=n×d=3×3=9 cellules

    The result counts table values, not pots in the garden or storage space used on disk. Check the other way: the Tray column contains 3 values, Crop 3 and Pots 3; 3 + 3 + 3 = 9 cells. Counting rows and columns gives the same size as counting each cell.

  5. Distinguish a copy from an additional fact

    A copy of the record accidentally adds 1 occurrence of (A, basil, 4). The copied sheet displays 3 + 1 = 4 rows, or 12 cells. But all the attributes of the copy match those of a tuple already present. Since a relation is a set, this repetition does not create an additional element.

    After comparing the whole tuples, the distinct contents comprise 4 − 1 = 3 tuples and 3 × 3 = 9 cells. Check: the facts about A, B and C are still exactly those in the original record. The copy added a written entry without adding a distinct fact.

    Rows A and C both remain present: they have the same crop, but different Tray and Pots values. An SQL table can retain identical rows, so the intended rules will need to be made explicit there. Here we describe the mathematical relation, without executing a command or automatically deleting a record.

  6. Change the contents while keeping the schema

    Now suppose the record is completed for the same moment: tray D contains mint and 2 pots. This tuple respects the domains and differs from the earlier ones. The cardinality becomes 3 + 1 = 4 tuples. The degree remains 3; the number of cells becomes 4 × 3 = 12.

    Check by taking the difference: 12 − 9 = 3 added cells, precisely the Tray, Crop and Pots values of the new tuple. Adding a complete row adds as many cells as the schema has attributes.

    Even with no recorded tuples, the schema would remain defined: n = 0, d = 3 and C = 0 data cells. “No tuples recorded” does not prove “no trays in the garden”. Likewise, an unknown cell is not a count of 0 pots: our assumption that values are filled in does not allow this substitution.

✿03 Common mistakes

  • “The schema is the record with its current values.”

    Separate the contract Trays(Tray, Crop, Pots) from the tuples that fill it. Adding the tuple for D changes the cardinality but keeps the attributes and their domains. Return to the steps “Define the schema” and “Change the contents”.

    Review the schema and its relation

  • “Two rows with basil must be duplicates.”

    Compare all the values in the tuple: A and C do not describe the same tray and do not have the same count. A crop can repeat. Only a copy of the whole row creates no new tuple in our relation.

    Compare tuples A and C in the diagram

  • “If a value fits in the cell, the row is valid.”

    Check the domain and the meaning: “many” is not an integer count of pots; a list of crops does not respect the chosen contract. An allowed integer can still be an incorrect record. The diagnostic exercise distinguishes an admissible form from a confirmed fact.

    Review the diagnosis of the proposed rows

Exercise 2 · Diagnosis with explanation

Check before accepting

The proposed entries for the same garden are (D, mint, many), then (D, basil and mint, 2), and finally (D, mint, 2). For each proposal, say whether it respects the schema and why. Is the last proposal enough to prove what D actually contains?

Hint 1

The domain of Pots contains integers; the domain of Crop contains the names basil or mint taken separately.

Hint 2

Distinguish a row that respects the rules of form from a record confirmed in the garden.

Compare with the solution

The first proposal is rejected: “many” is not an integer count of pots. The second is rejected: “basil and mint” does not belong to the domain of Crop and contradicts our assumption of a single crop per tray. Replacing this list with an arbitrary word would not repair the contract.

The last proposal respects the domains: D is allowed, mint is allowed and 2 is an integer greater than or equal to 0. It can therefore enter the relation if the record confirms it. Its valid form does not prove that D actually contains 2 pots of mint. We must check the observation rather than turn a plausible value into a certain fact.

Check your reasoning

  • You link each rejection to an attribute and its domain or to the granularity assumption.
  • You accept the form of the last tuple without claiming that an observation has been made.
  • You propose checking the record rather than inventing a replacement value.

Exercise 3 · Transfer and cross-checking

A longer sheet, a larger relation?

The original sheet is reordered, then the whole tuple for A is copied into it 1 time. Someone announces: “There are 4 rows; the relation has grown.” Respond with the row and cell counts. Then compare this with the confirmed addition of (D, mint, 2), without the copy of A. What role does the schema play in both cases?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Moving the rows preserves each tuple. For the copy, compare the distinct facts rather than the number of written entries.

Hint 2

Adding D provides a different tuple; multiply the new number of tuples by the degree, which remains fixed.

Compare with the solution

The display order does not change the relation. After the copy, the sheet contains 4 written entries and 12 cells, but the relation keeps 3 distinct tuples and 9 data cells. The tuple for A already belongs to the set.

With D instead of the copy, the relation contains 4 distinct tuples and 12 cells. The difference from the original relation is 3 cells: all the values of a new row. The schema remains Trays(Tray, Crop, Pots), with degree 3, in both cases.

The sheet has the same size in these two variants; only examining the tuples can tell us whether the relation contains an additional distinct fact. This reasoning about sets does not remove the need to establish the rules for a future SQL table.

  • You distinguish the copied sheet from the set of distinct facts.
  • You justify 3 versus 4 tuples by comparing the values, then 9 versus 12 cells.
  • You keep the same schema and explain why a change in order has no effect.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What distinguishes the schema from the current relation?

The schema names the attributes, their domains and the chosen rules. The current relation is the set of tuples that respect this schema and are recorded at the moment considered. The schema remains even if this set is empty.

Recall 2What does a garden tuple describe, and what does an attribute do?

The tuple describes the contents of a tray at the same moment: its name, crop and pot count. Each attribute names a question shared by all the rows and receives a value from the corresponding domain.

Recall 3Why can a row with the right types still be false?

A domain indicates which values are admissible, not which have been observed. An integer count of pots can respect the contract while differing from the actual count. An observation that supports the tuple is also needed.

Recall 4How can you reconstruct the degree, cardinality and number of cells?

The degree d counts the attributes in the schema; the cardinality n counts the distinct tuples. With all values filled in, n × d counts the data cells, excluding the headers. This product does not count the objects described by the values.

Recall 5Why do copying the whole tuple for A and displaying C before A leave the relation unchanged?

A set has no order and does not contain the same element more than once. Copying the whole tuple does not create a distinct tuple. However, a crop value repeated in different tuples is still allowed.
