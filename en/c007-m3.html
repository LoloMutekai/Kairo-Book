Terminal

Your goalChoose a command to locate the terminal, read the granola recipe sheet and check what actually changed.

Before you start

✿01 See the idea

You are looking for the granola recipe sheet in a fictional workshop. The terminal window lets you type a request and read the output. Imagine your finger resting on the /atelier folder: this position is the current folder. Asking where your finger is does not move it; reading the sheet it points to does not prepare the granola.

Here, the terminal hosts a command interpreter: the program that understands what you type. A command names the action requested. An argument specifies what it acts on. In “cat recettes/granola.txt”, cat is the name of the reader and recettes/granola.txt is its argument, the path of the file to read. The space separates these roles.

Under /atelier, the recettes and photos folders each contain a file named granola.txt. In recettes, it is the recipe sheet; in photos, it is a photo caption. The diagram follows the reader to the recipe sheet. You therefore need to know the starting point before interpreting a relative path.

The entire workshop is fictional: the paths do not indicate any folders to create on your machine. We are reasoning about ordinary readable files, with no symbolic links or changes during reading. The command names have their usual meanings in a Unix-like environment here. This page does not run a terminal.

The rule to remember

Before a command, state the current folder, the action and its target. Afterwards, check the displayed output and the change of context separately.

✿02 Follow an example

Worked example

Read the right sheet, then count its line endings

The starting point is /atelier. In /atelier/recettes/granola.txt, the oats line gives 2 portions and ends with an LF; the nuts line gives 1 portion and also ends with an LF. Each name is followed by a colon, a space and its quantity. These portions are fictional and provide no preparation advice. The file /atelier/photos/granola.txt holds a photo caption followed by an LF. There is no recettes subfolder in photos. Let us follow the commands separately, in order, without changing these files.

  1. Confirm the starting point with pwd

    Mentally type pwd, then imagine confirming it with the Enter key. Here, this command displays /atelier. It reports the current folder without changing it. A prompt is the marker showing that the interpreter is waiting for a new command; its appearance varies and is not sufficient evidence of the position.

    Check: asking for pwd again would still give /atelier. We expect 0 folder changes. The output is information about the context.

  2. List the names with ls

    From the same starting point, ls displays the names photos and recettes; their order does not serve as evidence here. This list tells us which children are visible here. It does not yet display the characters contained in granola.txt.

    pwd and ls have each left the position unchanged. Their combined count of changes is 0 + 0 = 0 changes. Check: pwd would still display /atelier.

  3. Read with cat, without running the target

    The command cat recettes/granola.txt asks the cat program to read the file given as its argument and send its content to the terminal output. The path starts from /atelier, passes through recettes and reaches granola.txt. The displayed text is therefore the recipe sheet: oats, then nuts.

    The program executed for this request is the reader cat. The file supplied as an argument remains data being read; any instructions it may contain are not passed to a program interpreter. Reading does not demonstrate any granola preparation and does not change the current folder.

    Target check: the same path written in absolute form is /atelier/recettes/granola.txt. Reading just granola.txt from photos would target the other file, the caption. Readable output is therefore not enough: also compare the expected path and content.

  4. Calculate the result of wc -l

    The command wc -l recettes/granola.txt reads the same file. wc is the program name; -l is an option, an argument that selects LF character counting here. The path is the argument that identifies the target. The sign before l is not subtraction.

    N denotes our result, a number of line endings. Each LF contributes 1 unit to the count: 1 after oats and 1 after nuts. The portions 2 and 1 are part of the text and do not enter into this addition.

    N=1+1=2 fins de ligne

    The displayed result associates the count 2 with the path recettes/granola.txt; alignment spaces may vary. Independent check: going through the content character by character and marking each LF gives 2 marks again. Do not count a visual wrap caused by a narrow window: it adds no character to the file.

  5. Change context with cd

    From /atelier, cd photos asks to make photos the current folder. cd is the command; photos is the path of the target folder. Along our route, the folder exists and the change succeeds. No confirmation text is needed for this success.

    The count of changes becomes 0 + 1 = 1 change. To check the effect, then ask for pwd: the answer must be /atelier/photos. The absence of a sentence after cd does not replace this check. The files themselves have not moved.

  6. Keep the error, correct the route

    From /atelier/photos, repeating cat recettes/granola.txt looks for /atelier/photos/recettes/granola.txt. This target is absent from the given tree. The command therefore reports a missing-file error; the exact wording depends on the environment. This output means neither an empty sheet nor the disappearance of the sheet in the neighbouring folder.

    To read the sheet without changing folders again, use cat ../recettes/granola.txt. The .. segment goes up to the parent /atelier; recettes/granola.txt completes the route. cat /atelier/recettes/granola.txt would also reach the sheet from this starting point.

    Final check: the content must match oats followed by nuts, wc -l ../recettes/granola.txt must return 2 line endings, and pwd must still display /atelier/photos. These checks concern the target, the content and the context. They do not prove any execution of the file read.

Explain it in your own words

Hide the steps. For pwd, ls, cd photos and cat ../recettes/granola.txt, describe the action, its target if any, and the expected check. Explain why the read command had to change after cd, even though the files stayed in place.

✿03 Common mistakes

  • “The terminal will find the recipe I meant.”

    It follows the requested path from the current folder. From photos, recettes/granola.txt identifies an absent target and granola.txt identifies a caption. Check with pwd, then build the route ../recettes/granola.txt.

    Review the change of context and the corrected route

  • “If I read a program, its instructions run.”

    Identify the roles: cat is the reader program, and the file is its argument. Reading its characters does not ask for them to be interpreted as instructions. To claim that the target was executed, you would need to establish a separate action to run it and the result of that action.

    Review reading with cat and its target check

  • “No text after my command: it did nothing.”

    A successful cd may display nothing and change the current folder. Check this context with pwd. Conversely, pwd displays information without moving the position: the amount of text does not measure the effect of the command.

    Review pwd and the check after cd

Exercise 2 · Application · count the relevant characters

The final line ending is missing on paper

On paper only, imagine that the same sheet loses its final LF after nuts. All the other characters remain present and the oats line keeps its LF. What count would wc -l return for this version? Justify it, then explain why seeing oats and nuts on the screen is not enough to find this count.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

wc -l counts LF characters, neither ingredients nor rows drawn on the screen.

Hint 2

Start with the 2 LFs in the original sheet and subtract the deleted character.

Compare with the solution

The original sheet contains 2 LFs. Removing the final LF removes 1 counted character: 2 − 1 = 1 line ending. The result is therefore not the original count.

Check by going through the content: the LF after oats is still present; none follows nuts. We therefore count 1 LF. The text nuts still exists as the final unterminated line. The display may make it visible, but wc -l does not add it to its count. Visual text wrapping does not create an LF either.

Check your reasoning

  • You obtain 1 line ending with a justified subtraction.
  • You recover the result by locating the remaining LF.
  • You infer neither the number of ingredients nor the running of the file from this count.

The first check is pwd: the expected output is /atelier/photos. The successful cd has therefore changed the context, even without a confirmation sentence. The next error concerns /atelier/photos/recettes/granola.txt, which is absent from our tree; it does not concern /atelier/recettes/granola.txt.

The proposed sequence is, line by line: pwd; then cat ../recettes/granola.txt; then wc -l ../recettes/granola.txt; then pwd. ✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1In cat recettes/granola.txt, what does each part request?

cat names the reader program; recettes/granola.txt is its argument and names the file to read. The relative path starts from the current folder.

Recall 2How can you distinguish pwd, ls and cd using the workshop scene?

pwd displays the current folder; ls lists its visible names; cd requests a folder change. A successful cd can be silent: another pwd checks its destination.

Recall 3Why does cat recettes/granola.txt fail from photos, and how can you correct it?

It looks for recettes inside photos, where that folder is absent. ../recettes/granola.txt goes up to the parent and then reaches the sheet; /atelier/recettes/granola.txt also identifies it from the root.

Recall 4What does wc -l count in the sheet, and why does removing the final LF change the result?

It counts LF characters: 2 in the original sheet, then 1 if the last one is missing. The text nuts can remain visible without being terminated by an LF. Quantities and visual wraps are not counted.

Recall 5What does a successful read with cat fail to demonstrate?

It demonstrates neither that the instructions in the file were executed nor that the recipe was prepared. The reader program received data; running the target would require a separate action and suitable evidence.
