Level 3 · C106·M3

Pooling

Your goalReduce an activation map using windows, calculate the maximum and the mean, then explain what position information is lost.

Before you start
c103-m5 : regularization · c036-m5 : annotated graphs · c106-m1 : discrete convolution · c106-m2 : channels

✿01 See the idea

An edge detector produces a map from a small image of fabric: each cell indicates the strength of its response at that location. We want to keep a coarser view of this same map. Divide it into squares and replace each square with a single value.

Pooling, described here as local grouping, determines the rule for this summary. The maximum answers: “What is the strongest response in this region?” The mean answers: “What is the mean response in this region?” An isolated peak and a uniformly active region can therefore lead to different summaries.

The activations are fictional scores with no physical unit; they are neither probabilities nor readings from a real image. The map has 4 rows and 4 columns, with 1 channel. A window of 2 cells by 2, moved by 2 cells each time, gives 2 rows and 2 columns here.

The exact position of the peak within its window is lost if only the maximum is kept. Permuting the values in that window does not even change its summary. This can make a representation less sensitive to certain local shifts; it also prevents reconstruction of the original map. A reduction is therefore not automatically an improvement for a task that requires precise localization.

The rule to remember

Set the window, the stride and the handling of boundaries; summarize each window in each channel; check the size and state what information the summary loses.

✿02 Follow an example

Worked example

Summarize the edge detector map

Keep the fabric map shown above. Calculate its full output using maxima, then its output using means with the same windows. We are neither trying to recognize a fabric nor measuring classification performance.

  1. Define the objects, units and conventions

    X denotes the input array. X[r, t, c] is the score at row r, column t and channel c; these indices will appear as subscripts of X in the formulas. H and W count the rows and columns respectively; C counts the channels. Here H = 4, W = 4 and C = 1. All indices start at 0: r < H, t < W and c < C. The scores and summaries have no unit; distances on this grid are counted in cells.

    k is the positive integer side length of the square window, here 2 cells. s is its positive integer stride in both directions, here 2 cells. No padding is added: only windows entirely contained within the map are processed. We use neither gaps between cells within a window nor rounding the output size upwards. H and W are at least as large as k.

    i and j identify an output cell. Its window starts at row s × i and column s × j in the input. The integer offsets u and v range from 0 to k − 1. The symbol Ω, with indices i and j, denotes the set of positions (s × i + u, s × j + v) covered in this way; it contains k × k positions. The sign ∈ means “belongs to this set”. With channel c fixed, the other channels never contribute to this summary.

  2. Count the windows before calculating their values

    Ho and Wo are the numbers of output rows and columns; the subscript o indicates the output. The symbol ⌊a⌋ denotes the greatest integer less than or equal to a. For one direction, H − k counts the space remaining after placing the initial window. Dividing by s counts the possible steps; adding 1 counts the initial window itself.

    Ho=⌊H−ks⌋+1;Wo=⌊W−ks⌋+1

    Here the divisions are exact: H − k = 2, then 2 ÷ 2 = 1, then 1 + 1 = 2 rows. Likewise, W − k = 2, then 2 ÷ 2 + 1 = 2 columns. The starting positions are 0 and 2 in each direction: we visit top left, top right, bottom left, bottom right.

    The size changes from 4 × 4 × 1 to 2 × 2 × 1: 16 scores become 4 scores in this channel. The number of output values is smaller by a factor of 4. This size ratio measures neither a speedup of the program nor an improvement in the detector.

  3. Compare values to find the maxima

    Y denotes the output array. The label max specifies the chosen rule; it is not an exponent. The symbol max selects the largest value in the window Ωᵢ,ⱼ, with channel c unchanged.

    Yi,j,cmax=max(r,t)∈Ωi,jXr,t,c

    Top left: comparing 1, 7, 3, 5 selects 7. Top right: comparing 2, 4, 0, 6 selects 6. Bottom left: comparing 8, 2, 4, 0 selects 8. Bottom right: comparing 1, 3, 5, 9 selects 9.

    The result follows the spatial order: first row (7 ; 6), second row (8 ; 9). Check: each output value belongs to its own window and is greater than or equal to all its values. Taking only the cell at the start of each window would instead give (1 ; 2), then (8 ; 1): this would be sampling at spaced intervals, rather than taking a local maximum.

  4. Change the rule to calculate the means

    The label moy indicates an output computed using the mean. The symbol Σ instructs us to add the scores at the positions in the window. Each window contains k × k values; dividing by this count preserves the scale of the scores. A sum alone would have a different scale.

    Yi,j,cmoy=1k2Σ(r,t)∈Ωi,jXr,t,c

    The count is 2 × 2 = 4. Top left: (1 + 7) + (3 + 5) = 8 + 8 = 16, then 16 ÷ 4 = 4.0. Top right: (2 + 4) + (0 + 6) = 6 + 6 = 12, then 12 ÷ 4 = 3.0.

    Bottom left: (8 + 2) + (4 + 0) = 10 + 4 = 14, then 14 ÷ 4 = 3.5. Bottom right: (1 + 3) + (5 + 9) = 4 + 14 = 18, then 18 ÷ 4 = 4.5.

    The output using means therefore has rows (4.0 ; 3.0), then (3.5 ; 4.5), still with no unit. It summarizes the activity distributed across the window; it gives no more information about the locations of the cells that produced it.

  5. Check without repeating the calculation

    In each window, the mean must remain between the minimum and the maximum: for example 0 ≤ 3.5 ≤ 8 at the bottom left. A result greater than the maximum could indicate, in particular, that the division was forgotten.

    With our stride equal to the side length of the window and our map tiled exactly, each score is counted once. Sum of the top half: 16 + 12 = 28; bottom half: 14 + 18 = 32; input total: 28 + 32 = 60.

    The means give 4.0 + 3.0 = 7.0 at the top and 3.5 + 4.5 = 8.0 at the bottom. Their sum is 15.0; multiplying it by 4 reconstructs 60. This check does not apply as it stands when windows overlap or boundary cells are ignored.

  6. State the limits of what this mechanism guarantees

    Max or mean pooling describes a fixed rule here: it learns no coefficients. Choosing the rule, k and s remains a design decision. The number C of channels is preserved; only their spatial grid changes.

    For s = k, permuting the values within a block leaves its mean and maximum unchanged. The second diagram explicitly shows two different inputs that give the same output: without additional information, recovering the input is impossible.

    A pattern that crosses a window boundary can change the output. Pooling therefore provides no general invariance to translations, meaning shifts of the entire image. The maximum does not eliminate a spurious peak either: if it becomes the largest score, it is kept. These limits matter as much as the size reduction.

✿03 Common mistakes

  • “The window is small, so the number of channels decreases too.”

    The window moves through the rows and columns of a fixed channel. Repeating the same operation in all channels preserves their number C. Write the spatial dimensions and the channel dimension separately.

    Review the dimensions and the window for each channel

  • “I always divide the height by the side length of the window.”

    The number of windows also depends on the stride and the boundaries. Here, simple division works because s = k and the map is tiled exactly. With stride 1, the same window gives an output side length of 3, rather than 2.

    Recount the overlapping windows

  • “The peak can move within a block, so the output is unaffected by any shift.”

    The permutation in the diagram stays within a single window. As soon as values move into another window, the sets being compared change. The boundary exercise provides a counterexample on the same map.

    Test crossing a boundary

Compare with the solution

The maximum is 9, because no score in the block exceeds it. The sum is (1 + 3) + (5 + 9) = 4 + 14 = 18. There are 4 cells: the mean is 18/4 = 4.5, with no unit.

The check 1 ≤ 4.5 ≤ 9 is satisfied. The sum 18 exceeds 9; reporting it as the mean would violate this bound. The maximum and the mean use the same window but perform different operations.

Exercise 3 · Counterexample and limit

The peak moves into the neighboring block

Return to stride 2. Swap only 7 and 2 in the first row: it becomes (1 ; 2 ; 7 ; 4). All other cells stay the same. Recalculate the output using maxima. Compare it with the permutation within the window in the diagram: what can you claim about stability under shifts?

Assisted answer: try this exercise without help later.

Hint 1

Only the blocks in the top half contain swapped cells.

Hint 2

On the left, the score 5 is still present; on the right, the peak 7 has just entered.

Compare with the solution

The top left block now contains 1, 2, 3, 5: its maximum is 5. The top right block contains 7, 4, 0, 6: its maximum is 7. The output row becomes (5 ; 7), instead of (7 ; 6). At the bottom, (8 ; 9) stays unchanged.

In the diagram, the permuted values belonged to the same block, whose set of values stayed the same. Here they cross a boundary: the summary changes. This swap moves a strong response by one cell; it is not a translation of the entire image. It is enough to refute the claim that every local shift would be invisible, without demonstrating the behavior of all possible translations.

To decide whether this pooling suits a real task, we would need to specify the allowed shifts, the required localization accuracy and the outputs to compare. This counterexample explains a limit; it attributes no performance to a model.

Check your reasoning

  • Recalculate each affected block and preserve the unaffected blocks.
  • Distinguish a permutation within a block, crossing a boundary and shifting the entire image.
  • State conditional stability without claiming general invariance.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must be specified to define local pooling?

The window size, the stride, the summary rule and the handling of boundaries. In this unit, the windows stay entirely within the map and each channel is processed separately.

Recall 2How do you count the output rows without padding?

If H is the height, k the window side length and s the stride, count ⌊(H − k)/s⌋ + 1 starting positions. The division counts the steps; the final term counts the initial window. The same reasoning applies to the width; the channels are preserved.

Recall 3What do the maximum and the mean distinguish within the same window?

The maximum keeps the strongest response. The mean adds all the responses and divides by the number of cells. It keeps a value between the extremes; an isolated peak does not contribute in the same way as distributed activity.

Recall 4Why does the summary not allow the window to be reconstructed?

Two different windows can give the same maximum or mean, in particular by permuting their cells. The summary alone therefore recovers neither the individual values nor their arrangement.

Recall 5What limit prevents a promise of general invariance to shifts?

A permutation within a block does not change its summary, but crossing a boundary changes the sets being compared. The effect depends on the stride and the windows; the maximum can also keep a spurious peak.
