Level 2 · C026·M2

Admission and capacity

Your goalDecide whether a task can start, reserve its slot and release it without exceeding a stated capacity.

Before you start
c019-m5 : clocks and persistence · c025-m5 : O, Omega and Theta · c020-m5 : counterexamples and sensitivity · c024-m5 : measurement quality · c026-m1 : queue and priority

✿01 See the idea

A workshop prepares photos for printing. Its program allows at most 3 photos to be processed at the same time. A and B have already started; C and D are waiting in that order. Before choosing which photo to process, there is a practical question: is there a slot available for it?

Imagine a board holding 3 reusable permits. Each photo being processed holds 1 permit until its processing ends. C can take the last permit; D must wait. Being at the front of the queue gives the next turn without creating an extra slot.

Admission is the transition from waiting to reserving a resource. Here, a task means processing a photo. Capacity is an upper limit on simultaneous reservations; it counts neither waiting requests nor photos already completed. Reserving allows processing to start without guaranteeing its success.

The workshop and all its values are fictional. Capacity is fixed for this exercise, without measuring a real machine. Each task requires the same number of permits; we track only this resource, assuming that the other conditions for starting are met. The ordering rule comes from the queue studied earlier.

The rule to remember

Check for a slot and reserve it in a single indivisible operation; if the check fails, reserve nothing. An admitted task returns exactly the permit it held, even if its work fails.

✿02 Follow an example

Worked example

Admit C, make D wait, then try again

A and B hold 2 permits out of a capacity of 3. C and D are waiting; each requests 1 permit. The queue accepts at most 2 waiting photos. No other event occurs during the sequence described. Before reading, decide whether C can fill capacity exactly.

  1. Name what is being counted

    K denotes total capacity; n, the number of permits held; d, the number requested by the next task; L, the number of free permits. These quantities are integer counts in permits. Capacity K is strictly positive, as is the request d.

    q counts waiting photos, in tasks; Q is their upper limit, in the same unit. In this scene, d = 1 permit per admission. We assume fixed capacity, an accurate initial count, a single reservation per task and a single release per reservation. A reservation still held during cleanup remains included in n.

    0≤n≤K;L=K−n
    0≤q≤Q

    This relation is the invariant: it must remain true after every event. Here L = 3 − 2 = 1 permit. The queue contains q = 2 tasks, with Q = 2 tasks; it reaches its own limit without filling the processing permits.

  2. Check the request from C

    Capacity is respected if the permits already held plus the request are at most equal to the upper limit. We can also compare the request with the free permits. These checks are equivalent because L = K − n.

    n+d≤K⇔d≤L

    For photo C: 2 + 1 = 3 permits, and 3 ≤ 3. The check passes. Equality is allowed: it means the last slot will be reserved, not that a hidden safety slot must remain free.

  3. Reserve before starting

    The check and reservation form an atomic operation: no other requester can reserve from the same intermediate state. In a concurrent program, reading “a free slot” and then starting work without reserving is not enough. A semaphore is a permit mechanism that makes acquiring an available permit indivisible.

    The prime here denotes the state after admission. After reservation, n′ = n + d = 3 permits held and L′ = L − d = 0 free permits. C leaves the queue: q′ = 2 − 1 = 1 task. Processing the photo can now begin.

    n′+L′=3+0=3 permis

    Immediate check: the sum of held and free permits still equals capacity. Work on the photo takes place after this reservation; reserving has not yet produced a correct image.

  4. Refuse to start D without changing the counts

    For D, the proposed total would be 3 + 1 = 4 permits. It would exceed capacity by 4 − 3 = 1 permit. This total is hypothetical: it must never become the admitted state.

    Starting is refused for now. The held count remains 3 permits, the free count 0 permits, and the queue keeps D, or 1 task. A failed acquisition gives nothing to release.

    A blocking acquisition waits for a permit to become available before succeeding. A nonblocking attempt immediately returns failure if it does not obtain one. This choice describes whether the requester waits, not the policy for retaining the request: in our workshop, D remains in a bounded queue and will be retried. Another policy could abandon the attempt.

  5. Return the permit held by A, even after failure

    Suppose processing A ends with an error. Its cleanup also finishes; the resource is then returned. The count becomes 3 − 1 = 2 permits held. This leaves 3 − 2 = 1 free permit. The result for photo A is a failure; releasing its slot is a separate event.

    The program must provide cleanup that runs whenever work exits, including on error. In Python, a finally clause or exiting a context manager can perform this release. It applies only after a successful acquisition, exactly once. An abrupt process termination requires a separate recovery mechanism, outside the assumptions of this sequence.

  6. Retry D using the current state

    No competitor intervenes here. D therefore repeats the check with 2 permits held: 2 + 1 = 3 ≤ 3. Its reservation succeeds; D leaves the queue. The queue goes from 1 − 1 to 0 waiting tasks.

    The final state contains 3 permits held and 0 free permits. Being woken after a release does not replace acquisition: if another task had obtained the permit before D, D would have had to wait or fail again. Capacity alone gives no waiting time.

  7. Check the tasks and the balance

    Let us recount the names without repeating the checks: initially A and B; C enters, D fails to enter, A exits, then D enters. B, C and D remain, or 3 permits held. The refused attempt by D is not counted as an admission.

    n final=2+2−1=3 permis

    The balance adds the 2 successful admissions to the initial occupancy and subtracts the release by A. It confirms the recount. At every step, n stays between 0 and 3 permits and q between 0 and 2 tasks. These bounds protect the counts; they demonstrate neither a good choice of capacity for a machine nor successful photos.

Explain it in your own words

Hide the steps and describe the path of the permit returned by A. Why did D hold no permit on its first attempt? Explain what would prevent C and D from taking the same slot if their requests arrived together.

✿03 Common mistakes

  • “C has priority, so we can start it even when all slots are occupied.”

    The ordering rule chooses who attempts admission; the check determines whether permits are available. With n = K, a positive request does not fit. Keep the task in the queue if the policy allows for it; do not exceed the upper limit.

    Review permits as separate from the queue

  • “I saw a free slot: I can start and then update the counter.”

    A competitor can observe the same slot between these operations. The check must succeed by reserving the slot before work starts. The last exercise replays this defect with C and D.

    Replay the concurrent requests

  • “D did not obtain a slot; I will release one anyway to be careful.”

    A refused attempt holds no permit. Releasing without acquisition or releasing twice creates fictional availability. Conversely, A must return its permit even if its processing fails.

    Review the refusal and the release by A

Exercise 1 · Application · boundary cases

Empty workshop, then full workshop

Keep capacity at 3 permits and the request at 1 permit. Calculate the state after an admission to the empty workshop. Then start again from a full workshop and describe the outcome of a nonblocking attempt by D. In each case, state whether there is a permit to release.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

When starting empty, n is 0; when starting full, n is K. Apply the same check to both states.

Hint 2

Only a successful acquisition gives the task a permit to hold.

Compare with the solution

When empty: 0 + 1 = 1 ≤ 3. After reservation, 1 permit is held and 3 − 1 = 2 permits are free. The holder will have to return its permit on exit.

When full: 3 + 1 = 4 > 3. The nonblocking attempt fails immediately. The 3 permits remain held and 0 are free. D must not release a permit it has not acquired. A blocking acquisition would wait; its duration remains unknown.

Check your reasoning

  • Write the check for each initial state and keep the counts unchanged after refusal.
  • Find 2 free permits in the first case, 0 in the second.
  • Link release to a successful acquisition without confusing waiting with immediate failure.

Exercise 2 · Application · distinguish the bounds

The waiting queue can also be full

Start again from the state just after C is admitted: n = 3 permits, and only D is waiting. Photo E arrives, then F, with no processing finishing in between. The queue accepts at most 2 tasks; beyond that, the workshop explicitly refuses the new request and removes no one. Who is waiting after each arrival? Is F promised a start?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The arriving photos cannot obtain any processing permit. Check their slots in the queue separately.

Hint 2

For F, compare the proposed number of waiting tasks with the upper limit Q without changing n.

Compare with the solution

E finds only D in the queue. After adding E, the queue contains D then E: 1 + 1 = 2 tasks, exactly the allowed bound. The 3 permits remain held by A, B and C.

Adding F would propose 2 + 1 = 3 waiting tasks, or 1 too many. The request from F is explicitly refused; D and E remain waiting. F is neither running nor retained for later. Even D and E have no guaranteed start time here.

These are two distinct admissions: accepting a request into the queue, then reserving a processing permit for it. Our refusal rule prevents an unbounded queue; it does not describe every possible policy.

Check your reasoning

  • Keep the order D then E and the upper limit of 2 waiting tasks.
  • Refuse F without replacing an existing task or assigning it a permit.
  • Distinguish a request accepted into the queue, admission to processing, and a promised time limit.

Exercise 3 · Diagnosis · repair the mechanism

C and D see the same slot

Start again with A and B running. A faulty program lets C and D each read n = 2. They separately check n + 1 ≤ 3, then both start before the actual reservation. How many photos are really running? Why is a counter displaying 3 not enough? Repair the sequence and also handle the case where C fails after a real acquisition.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Count the names A, B, C and D, even if the counter has lost an update.

Hint 2

Make the check and reservation a single operation. The second requester must see the result of the first.

Hint 3

Separate work failure from acquisition failure: the cleanup obligations differ.

Compare with the solution

There are really 2 + 1 + 1 = 4 photos running, beyond the upper limit 3. If both writes start from the same old value, both can display 3: an apparently valid count can hide 4 effective reservations.

The repair reserves before starting, by acquiring a permit indivisibly. If C obtains the last one, the state reaches 3 permits held. D can no longer acquire: it waits or receives immediate failure, depending on the interface chosen. Its processing must not start solely on the basis of the earlier counter reading.

If C then fails, it held a permit: its cleanup must return it exactly once. The count returns to 2 permits held and 1 free; D can attempt another acquisition. If C had failed to acquire, it would have had nothing to return.

Check your reasoning

  • Recount 4 active photos independently of the displayed counter.
  • Place the atomic reservation before starting and do not claim that the check alone is enough.
  • Provide for release after successful or failed work, only if the permit was obtained.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is the difference between being in the queue and being admitted to processing?

The queue retains a waiting request. Admission to processing reserves the necessary permits before starting. In the workshop, the queue limit and the processing limit apply to separate counts.

Recall 2With n permits held out of K and a request d, what check is needed? Is equality allowed?

Check n + d ≤ K, or d ≤ K − n, for valid integer counts and a positive request. Equality fills capacity exactly; it is allowed. The check and reservation must form an indivisible operation.

Recall 3What changes with a nonblocking attempt when all permits are held?

It immediately returns acquisition failure; a blocking call would wait for a permit. Failure authorizes no release. Retaining the request, retrying it or abandoning it is a matter of policy to be specified separately.

Recall 4An admitted task fails. What happens to its permit, and how can you check the counts?

After cleanup, it returns the permit it obtained exactly once. Check the named holders, then the balance: initial occupancy + successful admissions − releases. A refused attempt is not an admission.

Recall 5What does occupancy always staying at or below the upper limit fail to prove?

It proves neither a correct result, nor a bounded waiting time, nor an upper limit suited to the machine. You must also check that the count represents the actual holders and that each exit returns its reservation.

Reconstruct the reasoning

Without rereading, reconstruct the sequence for C then D: state the units and upper limits; check and reserve in a single operation; describe the refusal without changing the counts; return the held permit on exit; retry using the current state. Finish with the names of the holders and the balance of entries and exits, then say what these checks do not prove.
