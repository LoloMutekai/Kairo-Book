Vectorization

Your goalReplace corrections made cell by cell with an array operation, preserving the values, their order, and their units.

Before you start
c032-m5 : computational rank · c013-m5 : recursion · c017-m5 : reproducibility protocol · c024-m5 : measurement quality · c036-m1 : arrays · c036-m2 : dimensions and axes

✿01 See the idea

A sensor in a greenhouse displays 19 °C in the morning, 21 °C at midday, and 24 °C in the evening. For this fictional exercise, we assume that it always reads 1.5 °C too high. You can correct each reading separately, or ask the whole array to undergo the same subtraction.

Imagine the readings in cells labelled morning, midday, and evening. The same instruction, “subtract 1.5 °C”, is applied to each cell. The cells stay in place: the morning result must still refer to the morning. We still obtain 3 temperatures, rather than an average temperature.

Here, vectorization means expressing the calculation as an operation on the whole numerical array. The library handles iterating over its elements. The arithmetic work remains: each value must be corrected. This notation guarantees neither parallel computation nor a measured speedup.

These numbers and this bias are invented data for learning. Subtracting the assumed bias does not prove that the results are the actual temperatures in the greenhouse. We are studying how to translate a known rule, rather than how to estimate this bias.

The rule to remember

Writing the operation for the whole array must preserve the meaning of the calculation in each cell, its position, and its unit.

✿02 Follow an example

Worked example

Remove the sensor bias without losing the readings

The input array contains [19 ; 21 ; 24] °C, in the order morning, midday, evening. The common bias is 3/2 = 1.5 °C. Let us find the corrected array and check that the vectorized notation preserves the intended calculation.

  1. Define the cells and what they represent

    Let x be the input array, y the output array, n = 3 the number of cells, and b = 1.5 °C the bias to subtract. Here, a scalar is a single number, such as b; x and y each contain a sequence of numbers. In the formula, x and y with subscript i denote the temperatures at position i, in °C. The index i and the count n have no unit.

    To read the indices of a NumPy array, we start at 0: i = 0 denotes morning, i = 1 midday, and i = 2 evening. The shape (3,) describes an array with one axis containing 3 cells. Drawing a row on the page does not add an axis to it.

    Assumptions: all inputs are numerical, present, and finite; they use the same unit; the order morning, midday, evening is known; the same bias applies throughout. Each output uses its reading and b, without depending on another output. This independence of calculation is not an assumption of statistical independence.

  2. Write the rule for one position

    The sensor reads too high. We therefore need to subtract b rather than add it. The subtraction involves compatible quantities: a reading in °C and a temperature difference in °C. The result remains a temperature in °C.

    yi=xi−b, pour i∈{0;1;2}

    The symbol ∈ means that i takes a value from the indicated set; the braces list the possible indices. This rule specifies the calculation that the array operation must reproduce. Neither an average nor a matrix product is required.

  3. Work through all the subtractions

    Morning: 19 − 1.5 = 17.5 °C. Using exact fractions, 19 − 3/2 = 35/2 °C.

    Midday: 21 − 1.5 = 19.5 °C, or exactly 39/2 °C.

    Evening: 24 − 1.5 = 22.5 °C, or exactly 45/2 °C. Each of the 3 cells receives its correction.

    y=[17.5;19.5;22.5] °C

  4. Let the array operation handle iteration

    In a program using NumPy, lectures must be a numerical array, and biais the scalar b. The Python expression corrigees = lectures - biais then performs the preceding subtractions. NumPy applies the same scalar to each cell; this extension is called scalar broadcasting here. The array corrigees keeps the shape of lectures.

    An explicit loop would have calculated lectures[i] - biais for each index i, then placed each result at the same position in the output. Vectorization describes this transformation at the array level; it does not skip the subtractions. Our manual calculation uses exact fractions. In a program, the chosen numerical type must also be taken into account when comparing results that may be rounded.

    A Python list and a numerical NumPy array do not support the same operations. A Python list does not allow this subtraction by a scalar. You must explicitly construct the numerical array before using this notation; removing the loop from the text is not enough.

  5. Check the associations and values

    The output contains 3 temperatures, in the same order and in °C. Inverse check: 17.5 + 1.5 = 19 °C; 19.5 + 1.5 = 21 °C; 22.5 + 1.5 = 24 °C. Each result allows us to recover its own input.

    The evening–morning difference must also remain unchanged: at the input, 24 − 19 = 5 °C; at the output, 22.5 − 17.5 = 5 °C. Subtracting the same bias from both terms cancels it out in their difference.

  6. Add an overall check without losing the cells

    Let us add the inputs: 19 + 21 = 40 °C, then 40 + 24 = 64 °C. The bias is subtracted 3 times: 3 × 1.5 = 4.5 °C. The expected sum after correction is therefore 64 − 4.5 = 59.5 °C.

    Actually adding the outputs gives 17.5 + 19.5 = 37 °C, then 37 + 22.5 = 59.5 °C. Both routes agree. This sum is an arithmetic check; it is not a temperature representative of the day.

    Checking the sum does not prove that all the associations are correct: errors can cancel each other out. It supplements the check of the cells and their labels, without replacing it.

  7. Define the limits of the equivalence

    Here, each correction is independent of the other results. If the midday rule used the already corrected morning result, simply applying the same subtraction to the array would no longer reproduce this new rule. We would first need to understand this dependency.

    Equivalence is checked through the values and their meaning. Computation time is a separate question: array operations can reduce the work done by the Python interpreter, but preparing them also has a cost. No timing measurements are provided here; no particular speed has been established for these 3 readings.

Explain it in your own words

Hide the results. Describe what the subtraction does to the midday cell, then to all the cells. Why does the shape stay the same? Also explain why a correct sum is not enough to check the labels.

✿03 Common mistakes

  • “I have a list of numbers, so removing the loop is enough.”

    Identify the object type. The expression lectures - biais described on this page assumes a numerical NumPy array; a plain Python list does not define this subtraction. Construct the array, then check the meaning of the operation on one cell before extending it.

    Reread the transition from loop to array

  • “My corrected sum is right, so I have the corrected array.”

    The sum 59.5 °C is a single number. The requested output contains 3 temperatures associated with the times of day. Restore the results by position, then use the sum only as an additional check.

    Compare the array and the sum in the diagram

  • “Two arrays of the same size necessarily associate the right values.”

    Size does not carry the labels morning, midday, evening. When biases differ by time of day, you need to check their order before subtracting corresponding cells. Reconstruct the reading–bias pairs; the last exercise shows an error that the sum does not detect.

    Repair the associations in the last exercise

Subtracting the new bias from the old outputs would have applied an additional correction. Here, we are replacing a calibration assumption: we therefore need to return to the same raw readings.

Exercise 3 · Transfer · check correspondences

The correct sum hides an incorrect calibration

A new fictional record specifies a bias to subtract of 0.5 °C in the morning, 1.5 °C at midday, and 2.5 °C in the evening. The raw readings remain the same. Someone reverses the order of the biases and reports [16.5 ; 19.5 ; 23.5] °C, in the order morning, midday, evening. They cite the size and sum to validate it. Repair the array and explain why these checks are insufficient.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Place the bias with the same label below each reading. You should not subtract every possible combination.

Hint 2

Calculate the sums of the proposed array and the repaired array separately. An error in the morning can cancel out an error in the evening.

Compare with the solution

The reading and bias arrays each have shape (3,). For this operation between arrays of the same shape, we subtract elements at the same position, after checking that they refer to the same time: morning with morning, midday with midday, evening with evening. The numbers alone do not provide automatic matching by the name of the time of day.

Morning: 19 − 0.5 = 18.5 °C. Midday: 21 − 1.5 = 19.5 °C. Evening: 24 − 2.5 = 21.5 °C. The correct output is [18.5 ; 19.5 ; 21.5] °C.

Correct sum: 18.5 + 19.5 = 38 °C, then 38 + 21.5 = 59.5 °C. Proposed sum: 16.5 + 19.5 = 36 °C, then 36 + 23.5 = 59.5 °C. The sums are equal; nevertheless, the morning and evening temperatures in the proposed array are wrong.

The decisive check therefore concerns the reading–bias associations, then the corresponding results. Here, the same shape guarantees size compatibility, without guaranteeing that the chosen order has the correct meaning.

Check your reasoning

  • You restore each reading–bias pair using the labels.
  • You recover [18.5 ; 19.5 ; 21.5] °C.
  • You show that both sums equal 59.5 °C.
  • You explain how the shape and sum allow this error to go undetected.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does vectorization change in the calculation of the corrected temperatures?

We express the subtraction at the level of the whole numerical array, and the library iterates over its cells. Each temperature still undergoes its own subtraction; the values, their order, and their units must be preserved.

Recall 2How does a single bias act on the whole array?

The same scalar is subtracted from each element. The output array keeps its shape. This scalar broadcasting is distinct from a sum that reduces the array to a number.

Recall 3When biases differ by time of day, why are a correct shape and sum insufficient?

Subtraction between arrays of the same shape matches positions, without understanding the times of day. Reversed biases can produce errors that cancel each other out in the sum. You need to check the reading–bias pairs and their results.

Recall 4What condition makes our array subtraction equivalent to correcting cell by cell?

Each output uses only the reading at the same position and the intended bias, with compatible units. A rule that depends on the previous result would require different reasoning. You also need an array type that defines the elementwise operation.

Recall 5Does a shorter expression prove faster computation?

No. It can assign more work to array operations, but it proves neither parallelism nor a speed gain. You would need a suitable timed comparison using the same calculation and the same data.

Reconstruct the reasoning

Reconstruct without rereading: name the cells, their units, and their order; write the rule for one cell; extend it to the numerical array; check each association and the values, then add an overall check.
