Level 2 · C022·M4

Least privilege and fail-closed behavior

Your goalChoose the permissions needed for a specific copy operation and block it from starting when authorization cannot be established.

Before you start
c021-m5 : origin, authentication and authorization · c018-m5 : contract tests and test doubles · c012-m5 : counterexamples · c022-m1 : asset, threat and scope · c022-m2 : identity and permissions · c022-m3 : evidence of consent and revocation

✿01 See the idea

You ask the Copieur program to take note-source and create a copy at remise/copie. Giving it the keys to every file would be convenient, but would also let it change or delete the note. For this task, it only needs to read the source and write to the intended destination.

Least privilege means giving an actor only the permissions needed for its task, on the relevant resources and for the time needed. Here, a privilege is a power to act granted to the program. Reducing that power limits the actions an error could carry out using those permissions; it does not guarantee that the copy will be correct.

Now imagine that the consent check stops responding. No response does not mean authorization. A fail-closed rule blocks the copy until the required conditions are established. The reason remains “check unavailable”, distinct from “consent denied”. The check can be tried again when it becomes available.

The scene, its permissions and its counts are fictional. We follow the same copy operation throughout the page. The diagrams distinguish the powers granted to the program from the decision to start this specific request. A known identity or a technical permission does not replace consent.

The rule to remember

Grant the power needed for the task; require positive authorization for the current request; block it if a condition is false or undetermined.

✿02 Follow an example

Worked example

Give Copieur just enough power

The task is to read note-source and then write a new remise/copie, without deleting the source or reading the output back. Compare a broad grant of permissions with the grant sufficient for this task, then examine a check failure.

  1. Define the need and the assumptions

    The subject is the Copieur program, whose identity has been verified. A resource is the object being acted on; here, note-source and remise/copie. An elementary permission associates an action with a resource for this subject. We therefore count distinct action–resource pairs, in permissions; these are neither seconds nor probabilities.

    We assume that reading the source and writing the new destination are sufficient: the remise folder exists, the destination does not yet exist and writing does not replace any file. The targets refer to unambiguously identified objects and remain the same between checking and use. The mechanism that enforces permissions is reliable and every operation passes through it. If these assumptions change, the need and the check must be reviewed.

    N denotes the set of permissions needed for this task. P denotes the set of permissions effectively granted to Copieur. It includes inherited permissions, obtained indirectly, for example through a group to which the program belongs, and wildcard permissions, which cover an entire category, for example all actions. The bars |P| and |N| count their elements. The symbol ⊆ means “is a subset of”. For the task to be possible with these permissions, N ⊆ P is required. Here, least privilege aims for P = N, for the duration of this copy operation alone.

    N={(lire, note-source);(écrire, remise/copie)}

  2. Count what the broad grant provides

    The broad rule permits reading, writing and deleting on each resource: 3 actions for 2 resources. Each action forms a different pair with each resource; multiply to count all the pairs.

    This gives 3 × 2 = 6 permissions. Listing them: read the source, write the source, delete the source, read the copy, write the copy and delete the copy. The count includes available powers even if no one uses them.

    |P|=3×2=6 droits

  3. Separate necessity from excess

    The bars |N| denote the number of elements in N. Reading the source contributes 1 required permission; writing the destination contributes 1 other permission. Their sum gives |N| = 1 + 1 = 2 permissions.

    P does contain N. We can therefore subtract required permissions from granted permissions to count the excess. P ∖ N denotes the permissions in P that are not in N. We find 6 − 2 = 4 unnecessary permissions for this task: writing or deleting the source, reading or deleting the copy.

    |P∖N|=|P|−|N|=4 droits, puisque N⊆P

  4. Reduce permissions and check the other way round

    Replace the broad grant with only the pairs in N, granted to Copieur for this task. This leaves 2 permissions; the excess becomes 2 − 2 = 0 permissions. A wildcard permission that remained active would make this count wrong: check the effective powers, not just the most recently written list.

    Check independently through the actions: reading note-source remains allowed; writing remise/copie remains allowed; deleting note-source is denied. Then mentally remove the read permission: the program can no longer obtain the content. Instead, remove the write permission: it can no longer produce the destination. Each retained permission is necessary under our assumptions.

    The result concerns powers, not a quantified reduction in risk. Even with 0 excess, a program can write incorrect content to the destination entrusted to it.

  5. Establish the rule for starting

    Let q be the specific request: Copieur reads note-source and then writes remise/copie, for this task. D(q) means “the required effective permissions are verified for this request”; C(q) means “explicit consent that is still valid covers this same request”. These propositions have no physical unit. The symbol ∧ means “and”; ⇔ means “if and only if”.

    In this limited model, the authorization rule requires each condition, both D(q) and C(q), to be established as true by a complete current check. If a condition is false, starting is denied. If the check cannot reach a conclusion, starting is also blocked, with an undetermined reason. Unknown consent is not turned into denied consent or granted consent.

    Autoriser q⇔D(q) établi vrai∧C(q) établi vrai

  6. Replay the failure and follow the denial

    The permissions check succeeds, but the consent check is unavailable. C(q) remains undetermined. The rule blocks the operation before it starts: 0 copy operations started in this trial. A positive response saved from an earlier check does not establish current consent.

    The component that performs the copy must receive this block and stop. If it ignores a negative return value or catches an error in order to continue, the system no longer follows the fail-closed rule, even if the checker correctly reported failure. The user can be informed and the check retried without broadening permissions.

    To check the rule on paper, contrast the cases: established permissions and consent allow the operation to start; a missing permission, revoked consent or an unavailable check blocks it for different reasons. Actual verification should also observe that no protected operation has started in the blocked cases. Nothing in this scene is executed on a real system.

✿03 Common mistakes

  • “Fewer permissions must mean least privilege.”

    A list that is too short may prevent the task or retain the wrong permissions. First check that all required pairs are present, then remove pairs that serve no purpose. The number of permissions alone is not enough.

    Revisit the need and the check through actions

  • “The check is down; use the last yes.”

    Earlier consent may have been revoked or may refer to another destination. Under our rule, an incomplete current check blocks the operation from starting. Retain “unavailable” as the reason and retry the check before any new copy operation.

    Replay the check failure

  • “The checker denies the request, so the copy must be blocked.”

    The component that copies must still honor the denial, with no path that bypasses it. An ignored negative return value or an error turned into permission lets the request through. Reading a checker does not prove this entire path.

    Distinguish the code read from the blocking behavior to be demonstrated

Compare with the solution

Retain read note-source and write remise/copie: 2 permissions. Deleting note-source exceeds the task; remove 1 permission.

Without reading, the content cannot be obtained; without writing, the copy cannot be created. The usefulness of each pair, with its specific resource, justifies the choice. Removal assumes that no other inherited or wildcard permission grants deletion again.

Exercise 2 · Diagnosis · construct a counterexample

A negative excess?

Remove 1 permission from the minimal set and retain only read note-source. Someone calculates 1 − 2 and claims that the permissions are even better restricted. Diagnose the error, count what is missing and give the minimal repair.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Before using the subtraction from the example, check its assumption N ⊆ P.

Hint 2

The missing permission belongs to N but not to the remaining list.

Compare with the solution

The remaining list contains 1 permission. It does not contain write remise/copie: N is no longer a subset of P. The formula in the example for counting the excess by subtraction therefore no longer applies.

Here, the number of missing permissions is 2 − 1 = 1 permission, because the only remaining pair is necessary. No unnecessary permission is present: the actual excess is 0. A negative number cannot count unnecessary permissions.

Add only write remise/copie; this restores the 2 required permissions. Valid consent does not make up for the missing permission: until the authorized repair has been made and verified, the copy operation must not start.

Check your reasoning

  • You identify the subset assumption that has become false.
  • You distinguish 1 missing permission from 0 unnecessary permissions.
  • You repair the set using the specific destination, without granting permission to write to every file.

This behavior allows the request through on failure: it violates our fail-closed rule. The message from the checker is insufficient if the copy component ignores it. The repair must make blocking mandatory before any read or write for this new copy operation.

Allowed trial: identity, targets, permissions and current consent are established; starting is authorized. Creation and content still need to be checked afterwards, because authorization does not prove that the copy succeeded.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Why is choosing the shortest list of permissions not enough?

It must still allow the task. Retain all required action–resource pairs, then remove those that exceed the need, taking effective permissions and duration into account.

Recall 2When can you count unnecessary permissions by subtracting required permissions from granted permissions?

When all required permissions are included in the granted permissions. Otherwise, missing permissions and unnecessary permissions must be distinguished; their difference does not count the excess.

Recall 3What does a fail-closed rule decide when the consent check is unavailable?

It blocks the operation from starting, because current authorization is not established. The reason remains undetermined; we do not claim that the person refused, and we do not reuse an earlier yes as current permission.

Recall 4What is missing before you can conclude that an operation is blocked when you have only read the code that returns a denial?

You must verify that all protected operations pass through this check and that the component taking action honors its result, including during a failure. The denial produced must actually prevent the operation from starting.

Reconstruct the reasoning

Without rereading, reconstruct this sequence: name the task, the subject and the resources; identify the required permissions; check effective permissions and remove the excess; establish current consent; block on denial or an undetermined check; follow this decision through to the component taking action. Then explain why 0 excess does not prove success. Reading or an assisted answer does not establish that any level has been attained.
