Endianness, offset and structure

Your goalLocate a field in a file, check that it is complete and decode its integer using the stated byte order.

Before you start

✿01 See the idea

A workshop timer saves a small record: a cycle counter and the programmed duration. You receive the file, but not the device. To recover the counter, you need to know where it starts, how many bytes belong to it and how to combine them. The scene, format and all values are fictional.

Imagine a strip of cells. Each cell contains a byte; the numbers in the diagram give its value in decimal. The position of a cell does not give that value. An offset counts bytes from a stated origin: here, the start of the file. The first cell is at position 0, because no bytes precede it.

A structure is the layout that divides this strip into named fields. Our layout assigns 1 byte to a marker, 1 byte to a version, 2 bytes to the counter, then 2 bytes to the duration. The fields follow one another without any separating bytes. The file therefore contains 6 bytes; its layout comes from a given specification, rather than a guess based on the values.

Endianness, or byte order, states which byte has the greater weight in an integer that occupies several cells. In little-endian order, the first byte is the least significant; in big-endian order, it is the most significant. Here, “most significant” means that its contribution is multiplied by 256. Changing this convention does not move the field or reverse the bits within each byte.

The rule to remember

State the origin and structure; calculate the field range; check that it is available; apply the byte order and meaning specified by the format.

✿02 Follow an example

Worked example

Read the timer counter without running the file

The fictional specification states: marker 77, version 1, then counter and duration, each occupying 2 bytes as unsigned integers in little-endian order. The duration is in minutes; the counter counts cycles. The file of 6 bytes contains, in decimal and in this order: 77, 1, 52, 18, 10, 0. Let us recover the counter and the position of the next field.

  1. Establish the reading rules

    The observed bytes start with the stated marker 77 and version 1. This is consistent with our layout; this check does not prove the origin of the file. Here we assume that this is the specification to apply.

    N is the available length, in bytes. o is the offset of the first byte of the field from the start of the file, also in bytes. n is the width of the field, in bytes. These are integers; o is nonnegative and n is strictly positive. The offset is a position within this file, rather than an address in a program’s memory.

    The fields follow one another without padding: no bytes are inserted to align them at particular positions. Another format might specify padding; in that case, adding only the data sizes would no longer determine all positions.

  2. Find the start and the exclusive end

    The marker and version precede the counter: o = 1 + 1 = 2 bytes. Its width is n = 2 bytes. Let e denote the position immediately after the field; we obtain it by adding the width to the start.

    e=o+n=2+2=4 octets

    The range [o ; e[ contains positions o through e − 1, so here 2 and 3. The byte at position 4 already belongs to the duration. The offset counts bytes preceding the field, rather than the ordinal obtained by counting cells from 1.

  3. Check availability before decoding

    0≤o;0<n;o+n≤N

    Here o + n = 4 ≤ 6 = N: the entire field is within the available bytes. We isolate exactly 52 then 18; the marker, version and duration take no part in decoding the counter.

    After this field, N − e = 6 − 4 = 2 bytes remain available. If a read returned only 1 byte for a field requiring 2, we would need to report an incomplete field before interpreting its value.

  4. Assign weights according to endianness

    B = 256 is the base for representing numbers in bytes: a cell can take values from 0 to 255. p denotes the value of the first byte of the field, q the second, in increasing order of position. p, q and B are dimensionless. V is the decoded unsigned integer; the format then gives it the meaning of a cycle count.

    V=p+B×q en petit-boutiste
    V=B×p+q en grand-boutiste

    Little-endian order puts the least significant byte first. Like units followed by groups of 256, p contributes p and q contributes B × q. This concerns the byte order within a field, rather than the direction of reading the entire file. For a field occupying 1 byte, there is no order between bytes to choose.

    Unsigned means that the field represents a nonnegative integer. With 2 bytes, there are B × B = 65536 possible values, from 0 to 65535. A signed integer or another interpretation would require an additional convention; our formulas cannot infer it.

  5. Calculate and recover the original bytes

    The specification requires little-endian order: p = 52, q = 18. The contribution of the most significant byte is 256 × 18 = 4608. Let us add the contributions.

    V=52+256×18=4660 cycles

    Independent check: 4660 = 18 × 256 + 52, with 0 ≤ 52 < 256. Euclidean division of the result by 256 therefore recovers the quotient 18 and remainder 52. In little-endian order, we write this remainder first, then this quotient: we recover exactly the pair in the file.

    The result also lies within the stated unsigned range. However, this bound is not enough to choose the endianness: the incorrect reading 13312 + 18 = 13330 would also fit. The specification determines which reading to use.

  6. Move through the structure and check the boundary

    The next field starts at e = 4 bytes because there is no padding between them. Its width is 2 bytes, so it ends at 4 + 2 = 6. This exclusive end equals the size 6: the last field fits exactly within the file.

    The last occupied byte is at position 5, rather than 6. An exclusive end can equal N; this does not allow a byte to be read at position N. The decoded counter is 4660 cycles, but its value indicates neither its position nor the start of the next field.

✿03 Common mistakes

  • “At position 2, I must read the value 2.”

    The position counts preceding bytes; the value is the content of the cell. At position 2, our file contains 52. Draw two separate rows again: positions above, values inside.

    Separate positions and contents on the strip

  • “Big-endian means reversing the entire file.”

    Endianness concerns the weights of bytes within each numeric field. The fields keep their positions. For the same pair 52 then 18, assigning the weight 256 to the first gives 13330, without moving the marker or the duration.

    Review the weights and the counter check

  • “If the start of the field is in the file, I can read it.”

    The presence of the start does not guarantee that the end is present. Always compare o + n with the available size. When only 1 byte of a field occupying 2 is received, adding a 0 byte invents data that the file does not provide.

Exercise 2 · Diagnosis and re-encoding

Change a convention while preserving the value

A reader mistakenly treats the counter as big-endian, without modifying the file. What integer does it obtain? Then imagine a variant of the same format that actually specifies big-endian order for this field: which bytes would have to be written at positions 2 and 3 to preserve 4660 cycles?

Assisted answer: try this exercise without help later.

Hint 1

In the incorrect reading, the first byte 52 receives the weight 256.

Hint 2

Re-encoding the same value and rereading the same bytes using another convention are different operations. Use the quotient and remainder of 4660 divided by 256.

Compare with the solution

The mistaken reader calculates 256 × 52 + 18 = 13312 + 18 = 13330. It used the correct location and width, but the wrong convention.

To write 4660 in big-endian order, the quotient 18 comes first and the remainder 52 follows. We would therefore need 18 at position 2, then 52 at position 3. The correct reading would be 256 × 18 + 52 = 4660 cycles.

The other fields keep their positions in this declared variant. The original file remains governed by its little-endian specification; we do not change its convention because a result looks more appealing.

  • I give the pair 18 then 52 for big-endian re-encoding.

Exercise 3 · Transfer and justified decision

An incomplete reception and a local origin

A reception using the same format supplies only 5 bytes; the last expected byte is missing. The format sheet calls the area starting at the counter the “readings block”, at offset 2 from the start of the file. It places the duration at relative offset 2 from this block. Recover its absolute position and decide whether the duration can be decoded. A colleague suggests adding a 0 byte: how would you respond?

Assisted answer: try this exercise without help later.

Hint 1

A relative offset is counted from its origin. Add the start of the block to the local offset.

Hint 2

Compare the exclusive end of the duration with the length actually received. Distinguish the expected size from the available size.

Compare with the solution

The local origin is 2 bytes from the start of the file. The local offset of the duration is 2 bytes: absolute position = 2 + 2 = 4 bytes. Using 2 directly as the absolute position would read the counter again.

The duration requires the range [4 ; 6[. But 6 > 5: only 1 byte is available from its start and 1 is missing. The counter, whose end is 4, remains fully available. We can declare the counter readable and the duration incomplete, without claiming to have decoded the entire record.

The last byte was 0 in the complete example, but reading this reception cannot create it. No rule in our format permits replacing a missing end with 0 padding. The duration must remain unknown and the incomplete field must be reported; the received 10 is not enough to certify 10 minutes.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must be stated with an offset? Why is a position different from a value?

State the origin and the unit of displacement, here bytes from the start of the file. A position counts preceding cells; their content is independent. A relative offset must be added to the position of its origin to obtain an absolute position.

Recall 2How do you check that a field starting at o with width n is available within N bytes?

o and n are integers, o ≥ 0 and n > 0. Check o + n ≤ N before decoding. The range [o ; o + n[ excludes its end; its last byte is at o + n − 1.

Recall 3For bytes p then q of an unsigned integer occupying 2 bytes, what weights do the two byte orders assign?

Little-endian: p + 256 × q. Big-endian: 256 × p + q. p and q denote byte values in file order; the order of bits within each byte does not change.

Recall 4What information must the format layout give before bytes can be assigned a meaning?

The positions or the rule for calculating them, the widths, any padding and the interpretation of the fields: byte order, signed or unsigned, and a unit if there is one. Bytes alone do not inherently denote a cycle counter or a duration.

Recall 5How can another operation check the decoded counter? Why is this check insufficient to establish the format?

Divide 4660 by 256: quotient 18, remainder 52. Write the remainder then the quotient to recover the little-endian bytes. This checks the calculation under the chosen convention; it proves neither that this convention is correct nor that the file is authentic.
