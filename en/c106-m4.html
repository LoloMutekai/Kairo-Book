Deep architectures

Your goalRead a fictional convolutional architecture as a table of shapes, parameters and receptive fields, then decide whether a residual connection is possible.

Before you start

✿01 See the idea

Imagine a small fictional network that receives a square image with a side length of 32 pixels and 3 color channels, and must choose between 10 invented classes. A single convolution looks only at a neighborhood of 3 × 3 pixels: this is too small to recognize a whole object. A deep architecture therefore stacks blocks, and each block reads the summaries produced by the previous one.

In this example, a block contains a convolution with a 3 × 3 kernel, padding 1 and stride 1, followed by pooling with a 2 × 2 window and stride 2. Pooling divides the side length by 2. The maps become smaller; the next convolution, using the same small window, then covers a larger area of the original image. In exchange, the channel counts increase: 16, 32, then 64. Resolution is traded for more feature descriptors.

Three quantities let us read an architecture without training it. The shape of each output tells us the dimensions passed between layers. The parameter count includes the weights and biases that learning will adjust. The receptive field is the side length of the image area that can influence an output cell. A further design idea is the residual connection: it adds the input of a block to its output, and this addition makes sense only if the two shapes are identical.

All values on this page are fictional. They are used for counting, rather than describing a real model, its accuracy or its speed. Training, data selection and regularization, covered in the prerequisites, are outside the scope of this unit.

The rule to remember

For each block: calculate the output side length using (H + 2p − k) ÷ s + 1; parameters using k × k × input channels × output channels, plus one bias per filter; receptive field using r + (k − 1) × j, where j is the cumulative stride. Residual addition requires identical shapes.

✿02 Follow an example

Worked example

Counting a fictional network with three blocks

A fictional image of 32 × 32 pixels with 3 channels passes through blocks A, B and C. Each block applies a convolution with a 3 × 3 kernel, padding 1 and stride 1, then 2 × 2 pooling with stride 2. The output channel counts are 16, 32 and 64. A dense layer, excluded from this count, ends with 10 classes. Let us calculate the shapes, parameters and receptive field.

  1. Define the quantities and assumptions

    H denotes the side length of an input map, in pixels; k the side length of the kernel, in pixels; p the padding added on each side, in pixels; s the stride, in pixels. Ce and Cs are the input and output channel counts, with no units. P is a parameter count: a filter has k × k × Ce weights and one bias, and the layer contains Cs filters. r is the receptive field in input pixels, and j is the spacing, in input pixels, between two neighboring cells of the current map.

    Assumptions: square images, borders extended with zeros, no dilation, pooling that divides the side length exactly, no learned parameters in pooling, and no parameter sharing between blocks. A real architecture may differ on any of these points; the counts must then be recalculated.

  2. Track the output shape

    With padding, the image has a side length of H + 2p pixels. The kernel occupies k pixels, and each move of s pixels adds a position:

    H′=H+2p−ks+1

    For block A: 32 + 2 × 1 = 34, then 34 − 3 = 31; dividing by 1 gives 31, and adding 1 gives 32. With this padding, the convolution preserves the side length. Pooling gives 32 ÷ 2 = 16; blocks B and C then give 8 and 4. The last map contains 4 × 4 cells, each with 64 channels.

  3. Count the parameters

    A filter must look at all input channels, giving k × k × Ce weights, and it has one bias; there are Cs filters:

    P=k2×Ce×Cs+Cs

    Block A: 3 × 3 = 9, times 3 = 27, times 16 = 432 weights, plus 16 biases: 448 parameters. Block B: 9 × 16 = 144, times 32 = 4608, plus 32: 4640. Block C: 9 × 32 = 288, times 64 = 18432, plus 64: 18496. The first two blocks total 5088 parameters, and the three blocks total 23584.

    Pooling learns nothing in this example. The final dense layer, which would receive the flattened last map to produce 10 outputs, is excluded from this count. It would connect each input value to each output, with one bias per output: the same counting logic, applied to different shapes.

  4. Calculate the receptive field

    Start with an output cell: r initially equals 1 pixel and j equals 1. A layer with window size k adds (k − 1) × j pixels to r, then j is multiplied by its stride s. The convolutions in this example have stride 1: j does not change between the convolution and pooling in the same block, so both increases use the same j.

    r←r+(k−1)×j,j←j×s

    Increase from convolution: 3 − 1 = 2. Increase from pooling: 2 − 1 = 1. Sum per block: 3 × j. Block A: 3 × 1 = 3, giving r = 1 + 3 = 4; pooling doubles the stride: j = 1 × 2 = 2. Block B: 3 × 2 = 6, giving r = 4 + 6 = 10; j = 2 × 2 = 4. Block C: 3 × 4 = 12, giving r = 10 + 12 = 22.

    A cell in the last map therefore summarizes an area of 22 × 22 pixels within an image with side length 32. A border cell sees fewer actual image pixels because part of its area falls on padding.

  5. Compare a large kernel with three small ones

    Three stacked 3 × 3 convolutions with stride 1 have a receptive field of 1 + 3 × 2 = 7 pixels, like a single 7 × 7 kernel. Let us count the weights with 16 input and output channels, excluding biases:

    One 7 × 7 kernel: 7 × 7 = 49, times 16 = 784, times 16 = 12544 weights. Three 3 × 3 kernels: 9 × 16 = 144, times 16 = 2304, times 3 = 6912 weights. With equal receptive fields and under these assumptions, the stack therefore requires fewer weights: 6912 versus 12544.

  6. Check using another method

    The cumulative stride links the final grid to the image: 4 × 2 × 4 = 32. Working backward with r ← (r − 1) × s + k from an output cell gives 22 again. Recounting the weights filter by filter gives 23584 again.

    These counts describe a fictional design. They say nothing about the accuracy, speed, memory use or validity of a trained model.

Explain it in your own words

Why does the second block see a larger area than the first with the same 3 × 3 kernel? Explain the role of the cumulative stride j, then state which assumption, if broken, would invalidate the side length calculations.

✿03 Common mistakes

  • “Stacking layers always requires more parameters than a large kernel.”

    Compare equal receptive fields. With 16 input and output channels, a 7 × 7 kernel requires 12544 weights and three 3 × 3 kernels require 6912. The cost depends on sizes and channels, rather than the number of layers alone.

    Review the kernel comparison

  • “Pooling increases the receptive field by the size of its window.”

    The increase from pooling equals (window size − 1) × j, or 1 × j here, using the current cumulative stride. The same block design adds 3 pixels to the receptive field in block A but 12 in block C, because j has increased.

    Redo the receptive field calculation

  • “You can always add the input of a block to its output.”

    Elementwise addition requires identical shapes. From 16 to 32 channels, it is impossible as it stands; a convolution with a 1 × 1 kernel on the shortcut, with 544 parameters here, can adapt the channels.

    Return to the shortcut exercise

Exercise 1 · Explained application

Remove the padding

In the same fictional example, block A no longer has padding: p = 0, with a 3 × 3 kernel and stride 1. What is the side length after convolution? Does the parameter count of the block change?

H′=H+2p−ks+1

Hint 1

Substitute p in the formula: the numerator becomes 32 − 3.

Compare with the solution

The numerator equals 32 − 3 = 29. Dividing by 1, then adding 1, gives 30. Each convolution without padding therefore removes 2 pixels from the side length, here 32 − 30.

The parameter count remains 448: it depends on k, Ce and Cs, rather than the side length of the image.

  • Check the loss of k − 1 pixels per convolution.
  • Distinguish the output side length from the parameter count.

Three small kernels or one large one?

P=k2×Ce×Cs+Cs

Hint 1

The receptive field of three stacked kernels equals 1 + 3 × (k − 1).

Hint 2

Count the weights for each option using the formula in the example, omitting biases.

Compare with the solution

Receptive field: 1 + 3 × 2 = 7 pixels for the three small kernels, as for the 7 × 7 kernel. Weights: 12544 for the large kernel, 6912 for the stack.

Exercise 3 · Guided reasoning

A residual shortcut

We want to add the input of block B to the output of its convolution, before pooling. The input has 16 channels and a side length of 16 pixels; the convolution preserves the side length and produces 32 channels. Is direct addition possible? If not, propose a shortcut with a 1 × 1 kernel and count its parameters. Also state the condition on the channels that would allow direct addition.

y=x+F(x)
Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Compare the shapes of the two terms: side length, then channels.

Hint 2

A 1 × 1 kernel has one weight per pair of input and output channels, plus one bias per filter.

Compare with the solution

The side lengths match because of padding, but the channel counts differ: 16 versus 32. Direct addition is impossible.

Shortcut with a 1 × 1 kernel: 16 × 32 = 512 weights, plus 32 biases: 544 parameters. It converts the input to 32 channels before addition.

Direct addition would be possible if the convolution kept the input channel count. This count does not tell us whether a shortcut improves a real task.

Check your reasoning

  • Compare side lengths and channels before adding.
  • Count both weights and biases for the shortcut.
  • Avoid concluding that accuracy improves.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Which formula gives the output side length of a convolution?

(H + 2p − k) ÷ s + 1, where H is the input side length, p the padding, k the kernel size and s the stride, assuming exact division.

Recall 2How many parameters does a convolutional layer contain?

k × k × input channels × output channels weights, plus one bias per filter. In this example, block A contains 448. Pooling in this example learns none.

Recall 3How is the receptive field calculated layer by layer?

r becomes r + (k − 1) × j, then j is multiplied by the stride of the layer. In this example, r equals 4, 10, then 22 pixels after blocks A, B and C.

Recall 4What do we gain from three kernels with side length 3 rather than one kernel with side length 7?

The same receptive field of 7 pixels with 6912 weights instead of 12544, for 16 channels and excluding biases. This proves nothing about accuracy.

Recall 5When can the input of a block be added to its output?

When the two shapes are identical. Otherwise, adapt the shortcut, for example with a convolution using a 1 × 1 kernel: 544 parameters to go from 16 to 32 channels in this example.

Reconstruct the reasoning

Specify the input shape; for each block, calculate the output side length, parameters and increase in receptive field using the cumulative stride; add the parameters of the layers included in the count and name those excluded; compare variants with equal receptive fields; add a residual shortcut only if the shapes match; keep these counts separate from any claim about the accuracy, speed or validity of a real model.
