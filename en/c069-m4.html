Level 1 · C069·M4

Countability

Your goalNumber every locker in an infinite grid without omissions or duplicates, then recover an address from its index.

Before you start
c014-m5 : invariants · c012-m5 : counterexamples · c006-m5 : composition · c069-m1 : equivalence relations · c069-m2 : orders · c069-m3 : injection and surjection

✿01 See the idea

Imagine a wall of lockers. An address gives the row first, then the column, each numbered from 0. The rows and columns can extend without limit. This infinite storage space is a fictional idealization: no real building contains infinitely many lockers.

You want to replace each address with a single index in a list. If you visit the whole of row 0 before moving to the next, you never reach row 1: the starting row has no last locker. The problem lies in the chosen route.

Change the route: visit together the addresses whose row + column sum is the same. These diagonals are finite. After the diagonal with sum 0, move to the one with sum 1, then the one with sum 2, and so on. Within each diagonal, the column increases from 0.

Here, countable will mean an infinite set that can be matched with the natural numbers, without omissions or duplicates. Each object gets a finite index; there is no need to finish the whole list. A list that keeps going can therefore work, even when the wall extends in several directions.

The rule to remember

To enumerate the grid, finish a finite diagonal before starting the next. Then prove that every address is reached and that each index identifies exactly one locker.

✿02 Follow an example

Worked example

Assign an index to locker (3, 2), then recover its address

The fictional address a = 3, b = 2 gives the row followed by the column. We use the route in the drawing, with the first index equal to 0. Let us calculate its index and justify why the same method works for the whole grid.

  1. Specify the objects and the meaning of countable

    ℕ denotes the natural numbers 0, 1, 2, and so on. E = ℕ × ℕ is the set of addresses: each ordered pair (a, b) represents exactly one locker. a and b are integer indices with no physical unit. Their order matters: the row comes before the column.

    A set is countably infinite when there is a bijection between that set and ℕ. For our function p : E → ℕ, this requires injectivity, meaning different indices for different addresses, and surjectivity, meaning an address for every natural number. A bijection is a function that is both injective and surjective.

    Here we reserve countable for the infinite case. At most countable means finite or countably infinite. Some texts also use countable in this broader sense: stating the convention avoids mistaking a difference in terminology for a mathematical disagreement.

  2. Arrange the addresses by finite diagonal

    s = a + b is the diagonal number, also an integer with no physical unit. On diagonal s, vary b from 0 to s and set a = s − b. The order is therefore (s, 0), then (s − 1, 1) if s is positive, through to (0, s). There are s + 1 lockers.

    For any fixed address, the sum s is finite. Only the earlier diagonals and part of its own diagonal come before it. Since each of these diagonals is finite, the locker will be reached after a finite number of visits. This is precisely what failed with the route that visited one row after another.

    s=a+b=3+2=5

  3. Count the lockers before the diagonal

    T(s) denotes the number of lockers in the diagonals strictly before s. These diagonals have 1, 2, and up to s lockers, respectively. Thus T(s) = 1 + 2 + ⋯ + s for positive s, and T(0) = 0.

    To obtain the sum, write it once in increasing order, once in decreasing order, then add corresponding terms. Each pair equals s + 1 and there are s pairs: 2T(s) = s(s + 1). Divide by 2 because the sum has been counted 2 times. The product of these consecutive integers is even, so the quotient is an integer. The formula also gives 0 for s = 0.

    T(s)=s(s+1)2

    Here s + 1 = 6. The product 5 × 6 equals 30, then 30 ÷ 2 = 15 lockers. Check without the formula: 1 + 2 + 3 + 4 + 5 = 15. T(s) counts lockers; it does not count diagonals.

  4. Add the offset within the diagonal

    n denotes the index, an integer with no physical unit. The first locker on the diagonal has b = 0; the locker in column b has exactly b lockers before it on that diagonal. We therefore add b to the T(s) lockers already visited. The function p maps an address to this index.

    n=p(a,b)=T(a+b)+b

    For our locker: n = 15 + 2 = 17. At index 17, there are 17 lockers before this one, since numbering starts at 0. Adding another 1 would change the indexing convention.

    Diagonal s = 5 uses the indices from 15 to 20 inclusive: the last locker has b = s. The next diagonal starts at T(6) = 6 × 7 ÷ 2 = 21. Our index 17 does belong to this block.

  5. Reverse the route and check uniqueness

    To recover an address from n, find the diagonal s whose block contains n: T(s) ≤ n < T(s + 1). Then subtract the start of the block to recover b; the rest of the sum s gives a.

    b=n−T(s);a=s−b

    Here 15 ≤ 17 < 21, so s = 5. We obtain b = 17 − 15 = 2, then a = 5 − 2 = 3. We recover the original address in the correct order.

    In general, T(s + 1) − T(s) = s + 1: successive blocks are disjoint and meet without gaps. If addresses have the same index, that index places them in the same block, so their sum s is the same. Subtracting n − T(s) then forces the same b, and s − b forces the same a. This proves injectivity for all addresses.

  6. Establish that the numbering covers all natural numbers

    The blocks start at T(0) = 0 and their starts increase without bound: for positive s, T(s) is a sum of s integers all at least 1, so T(s) ≥ s. For any fixed integer n, we therefore find a unique block such that T(s) ≤ n < T(s + 1). For example, it is enough to examine the starts in order until the first one that exceeds n.

    The offset b = n − T(s) then satisfies 0 ≤ b < s + 1. Since b is an integer, b ≤ s. Thus a = s − b and b are natural numbers; their sum is s and their index T(s) + b gives n again. This proves surjectivity.

    The function p is therefore bijective. It establishes that the grid E is countably infinite. The proof concerns arbitrary natural numbers; the calculated values and the drawn fragment provide concrete checks, without replacing this general scope.

✿03 Common mistakes

  • “Countable means I will eventually finish counting everything.”

    An infinite enumeration has no last visit. The condition concerns each fixed locker: it must be reached at a finite index. For the grid, diagonals provide this property. The convention for finite sets is stated at the start of the example.

    Review the definition and the argument that each locker is reached

  • “I can finish the entire starting row before moving up.”

    Row 0 already contains infinitely many lockers. Waiting for its end prevents you from visiting (1, 0). Use finite diagonals and check the route through the indices in the drawing.

    Reread why the route through whole rows fails

  • “The drawing has no omissions or duplicates: that is sufficient proof.”

    An address outside the drawing could still be missed. To reach a conclusion about the infinite grid, use an arbitrary address to show that it is reached, then use the blocks T(s) ≤ n < T(s + 1) for uniqueness and coverage of the indices.

    Review the proofs using blocks of indices

List a diagonal in order

Hint 1

Vary b from 0 to 3 and require a = s − b.

Hint 2

The first index is T(3). Each increase in b adds 1 to the index.

Compare with the solution

The addresses are (3, 0), (2, 1), (1, 2), (0, 3). There are 3 + 1 = 4 of them, since both bounds for b are included.

T(3) = 3 × (3 + 1) ÷ 2 = 6. Adding each successive value of b gives the indices 6, 7, 8, 9. After these 4 lockers, the next diagonal starts at index 6 + 4 = 10. The last index 9 and the next start are consecutive.

Recover the locker from its index

A ticket for the same wall carries the index n = 23. Recover its address (a, b), showing the bounds of the chosen block. Then recalculate the index from this address to check your answer.

Hint 1

The example calculated T(6) = 21. Calculate the next start before choosing the diagonal.

Hint 2

Once you have found the block, b is the index minus the start of the block; a completes the sum s.

Compare with the solution

T(6) = 21 and T(7) = 7 × 8 ÷ 2 = 56 ÷ 2 = 28. Since 21 ≤ 23 < 28, the diagonal is s = 6.

b = 23 − 21 = 2, then a = 6 − 2 = 4. The ticket therefore identifies (4, 2), row then column.

Check: 4 + 2 = 6, so p(4, 2) = T(6) + 2 = 21 + 2 = 23. The coordinates are natural numbers and the index matches the ticket.

Exercise 3 · Proof · repair a proposal

Is the sum of the coordinates enough?

To simplify the labels, a colleague proposes g(a, b) = a + b. Compare locker (3, 2) with the locker whose coordinates are swapped. What property does g lack? Then explain why p(a, b) = T(a + b) + b fixes this problem and why its proof must also cover all indices.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The addresses are distinct when the coordinates differ, but does their sum change?

Hint 2

Separate the roles of T(s), which chooses a block of indices, and b, which chooses a position within that block.

Compare with the solution

The addresses (3, 2) and (2, 3) are distinct. Yet g assigns both of these 2 addresses the value 5. The proposed function is therefore not injective: the diagonal number is not enough to identify a locker.

The numbering p assigns 15 + 2 = 17 to the first and 15 + 3 = 18 to the second. Within a diagonal, the offset b separates the lockers; between diagonals, disjoint blocks separate the indices. This argument applies beyond these particular addresses.

Surjectivity must still be guaranteed: the blocks start at 0, meet without gaps and increase without bound. Each n belongs to a block, and the subtractions b = n − T(s), then a = s − b give its address with natural number coordinates. Fixing one particular collision would not have been enough to establish the full bijection.

Check your reasoning

  • You present an explicit collision for g and name the missing property of injectivity.
  • You justify the separation of indices within blocks and between blocks.
  • You add the argument that all indices are covered, without restricting yourself to the drawing.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What convention do we adopt for countable and at most countable?

Here countable means infinite and in bijection with ℕ. At most countable means finite or countably infinite. Each object in an infinite enumeration has a finite index; the whole list does not need to end.

Recall 2Why do diagonals reach an address that a route through whole rows can miss?

Address (a, b) belongs to the finite diagonal s = a + b. A finite number of finite diagonals come before it, followed by a finite offset within its diagonal. A route through whole rows would wait in vain for the end of its infinite starting row.

Recall 3How can you reconstruct p(a, b), and what does each term count?

Set s = a + b. T(s) = s(s + 1)/2 counts the lockers in the earlier diagonals; b counts those already passed in the current diagonal. The index is p(a, b) = T(s) + b, starting at 0.

Recall 4How can you recover an address from an index n?

Find the unique s such that T(s) ≤ n < T(s + 1). Set b = n − T(s), then a = s − b. The bounds give 0 ≤ b ≤ s, so the coordinates are natural numbers. The sum gives s again and the index gives n again.

Recall 5What remains to be proved after correctly numbering a fragment of the grid?

A proof is needed for every address and every index: no duplicates because the block and offset are unique; no gaps because the blocks start at 0, are consecutive and increase without bound. Checking a fragment does not prove these general statements.

Reconstruct the reasoning

Without rereading, reconstruct the argument: definition of a bijection with ℕ; failure of the route through whole rows; finite diagonals; sum of the earlier sizes; offset within a diagonal; address recovered from an index. Finish by explaining why neither avoiding a collision nor a finite drawing is enough to prove countability.

What you understand
A numbering must let you identify an object and recover that object unambiguously. The ideal grid requires a proof for an infinite set; a bounded collection in a computer is a finite case, and therefore at most countable under our convention.
