Recursion

Your goalFollow the counting of nested boxes, distinguish calls from their returns, and explain why this descent ends.

✿01 See the idea

You want to count the screws in a drawer without missing those hidden in a small box. It contains a bag of 3 screws, a box with bags of 2 and 4 screws, then a bag of 1 screws. All these numbers are fictitious, chosen so that you can repeat the count by hand.

For a bag with a known count, the answer is immediate: you read its number of screws. For a box, you ask for the count of each item inside, then add the answers. If an item is another box, the same rule applies to it: this is recursion, a function calling itself on part of its input.

A call is a request for work; a return is the value given back when that work is finished. A call that starts another call is the parent of that other call. The call on the small box must wait for the counts of its bags. The outer call keeps what it has already counted and waits for the small box. These tasks that have started but are still unfinished form the call stack.

In the drawing, each line goes from a box to an item directly inside it. A bag has no contents to open: it is called a leaf. The boxes are finite, do not contain themselves, and do not change during counting. These conditions give a precise meaning to “descending to something smaller”.

The rule to remember

Return the count of a bag directly; for a box, call the same function on each item inside and add its returns. Also check that the descent can reach a base case.

✿02 Follow an example

Worked example

Count the whole drawer without skipping a return

The input is [3, [2, 4], 1]. The brackets describe a box, and the integers give the counts of its bags. We visit the items from left to right. We need to obtain a number of screws, then check that number and the number of calls separately.

  1. Define the domain and the base case

    C denotes our counting function: C(x) is the number of screws returned for the item x. x can be an integer n greater than or equal to 0, representing a bag already counted, or a list L, representing a box. The letters x and L denote structures, with no physical unit; n and the results of C count screws.

    C(n)=n pour un entier n ≥ 0

    This is the base case: the call returns n without calling itself again. Booleans, negative values, and all objects other than these integers and lists are excluded. The nesting is finite, has no cycles, and no list is modified. We state these assumptions; the counting rule does not automatically check every possible input.

  2. Describe the work for a box

    To count L, this call starts its own total T at 0 screws. For each item x in L, it waits for C(x), then adds that return to T. After the last item, it returns T. T is a number of screws; each box call has its own distinct T. The symbol ← means “replace the local value with the result on the right”.

    T←T+C(x)

    Addition keeps the unit of screws because the total and the return have the same unit. For an empty box [], no items are visited: T stays at 0 and the call ends. This is the terminal case of an empty list.

    C([])=0 vis

  3. Start outside, then suspend the parent

    The outer call starts at 0 screws. Its first item is bag 3: the base case returns 3 screws in 1 call. The outer call therefore adds 0 + 3 = 3 screws.

    The next item is [2, 4]. The outer call requests C([2, 4]) and keeps its total of 3 screws while waiting. It cannot do the next addition yet: the return from this small box is missing. The last outer bag has not yet been visited.

  4. Descend into the small box and combine its results

    The small box starts with its own total of 0 screws. Bag 2 returns 2: the inner total becomes 0 + 2 = 2 screws. It then calls bag 4. Just before that return, the stack drawing shows the outer call, the small box, and this bag still active. The bag then returns 4 screws, which the small box adds to its total:

    2+4=6 vis

    There are no more inner items to visit. The small box therefore returns 6 screws. This return is an integer; the list [2, 4] remains the input. For this small box, there were 3 calls in total: the box call and the 2 bag calls.

  5. Resume outside and finish the calculation

    The outer call resumes with its previous total of 3 screws. It adds the inner return, giving 3 + 6 = 9 screws. Only then does it call the last bag, which returns 1 screws.

    C([3,[2,4],1])=9+1=10 vis

    All the outer items have returned their counts. The outer call returns 10 screws to the person who requested it. Returning this total at the end of the list avoids stopping after the first bag.

  6. Check by another route

    To check the screws, set the boxes aside and list only the bag counts: 3, 2, 4, 1. Direct addition gives 3 + 2 = 5, then 5 + 4 = 9, then 9 + 1 = 10 screws. It matches the result obtained through the nested returns.

    To check the calls, count each input processed, including the boxes: 4 bags + 2 boxes = 6 calls. A box adds no screws of its own. The maximum number of calls active at the same time is only 3 for this drawer; completed calls have already left the stack.

  7. Justify termination for the drawer in the drawing

    Each box call visits a finite list and calls the function on an item strictly inside it. In our drawing, the paths end at bags; no line leads back to a box already waiting. The bags return their numbers directly. Once their returns have been received, each box finishes in turn.

    The empty box also terminates: its loop has nothing to do and returns 0 screws in 1 call. A base case written somewhere would not be enough if the calls kept returning to the same box. The argument applies to this finite structure with no cycles; it does not guarantee that a program has enough memory for an arbitrary depth.

Explain it in your own words

Hide the results. Describe what the outer call keeps during the inner count, then work out the total and the number of calls again. Explain why these numbers count different things and where the termination argument uses the drawing.

✿03 Common mistakes

  • “The function calls itself, so it must keep starting over forever.”

    Look at the input used by the new call. Here it processes an item inside the box; a bag immediately returns its count. An empty box also terminates without a new call. Termination depends both on the base cases and on progress towards them.

    Review the base case and the justification of termination

  • “When the small box opens, the outer total is replaced by its total.”

    The calls have distinct local totals. While the inner call has 2 screws, the outer call keeps 3 screws while waiting. The inner return of 6 screws is then added to the outer total; it does not overwrite it.

    Reread the snapshot of the call stack

  • “There are 6 calls, so the function returns 6 screws.”

    A call counts a task started; here its return counts screws. Bag 3 requires 1 call and returns 3 screws. Check the result by adding the bag counts, then count the rectangles in the drawing separately.

    Check screws and calls separately

Exercise 1 · Warm-up · distinguish input from return

A bag, then the empty box

Without opening the example, give the return of C(3) and that of C([]). For each of these separate trials, count the calls and explain what makes them terminate. Give the unit of each result.

Assisted answer: try this exercise without help later.

Hint 1

A bag already carries its count: the function should not create that many calls.

Hint 2

In an empty list, no item changes the initial total.

Compare with the solution

C(3) returns 3 screws: the base case handles the bag directly. There is 1 call, with no further call inside it.

C([]) returns 0 screws: the initial total remains unchanged because there are no items. There is 1 call, the call for the empty box. A return of 0 is a defined result; it is not a missing return.

Check your reasoning

  • I express returns in screws and counts of work in calls.
  • I explain why the bag terminates directly and why the box has no items to visit.
  • I distinguish a result of 0 from a missing result.

Exercise 2 · Application · trace on paper

Identify the work still waiting

Return to the drawer [3, [2, 4], 1]. Just before the return from bag 4, draw the stack and write the total for each box. Continue the returns to the final result. How many calls have there been in all?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The outer call has already received the count from the first bag. The small box has already received the count from its first bag, but not the next.

Hint 2

The return from the last inner bag finishes the small box first. The outer call adds only the result the box returns to it.

Compare with the solution

From bottom to top, the stack contains the outer call with 3 screws, the small box with 2 screws, then the call on bag 4. That makes 3 calls active at the same time. The last outer bag is not in this stack.

The inner bag returns 4 screws. The small box finishes its addition: 2 + 4 = 6 screws, then returns this total. The outer call resumes: 3 + 6 = 9 screws. It then calls the last bag and obtains 9 + 1 = 10 screws.

In total, 2 box calls and 4 bag calls give 6 calls. Counting all the calls since the start is different from counting those still active at the instant shown in the drawing.

Check your reasoning

  • I keep the inner and outer totals separate.
  • I let the small box finish before resuming the outer addition.
  • I distinguish the total number of screws, the cumulative calls, and the active calls.

Exercise 3 · Transfer · repair a rule

A base case that exists but is never reached

Someone keeps the base case for bags but, when visiting the items in a box, asks again for the count of the entire box instead of the current item. They claim: “The base case exists, so this will finish.” Using our drawer, show where their argument fails, repair the request, and explain why a box containing a link to itself would still be outside the contract.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Look at the input of the new call as soon as the first outer item is visited: has it become smaller?

Hint 2

The repair must follow the line to the current item, then wait for its return. A link to itself does not descend into a part strictly inside it.

Compare with the solution

At its first item, the outer call asks again for the count of the same entire box. This new call does the same thing before obtaining a return. Bag 3 never receives the request that would have triggered its base case. Having this base case in the rule therefore does not prove it will be reached; in practice, the growing stack can exhaust the resources of the program.

You must call C(x) on the current item x, wait for its return, add it to the local total, then move to the next item. This again gives 10 screws for our drawer, as in the example.

If a box contains itself, even this repaired rule can follow a link back to the same object and encounter the same task indefinitely. The assumption that there are no cycles is missing. We exclude this structure from the contract of the lesson; devising automatic cycle detection would be another task.

Check your reasoning

  • I show the lack of progress from the first faulty call inside the outer call.
  • I replace the input of the call with the current item and still wait for its return.
  • I distinguish a repaired rule for our drawing from a guarantee for a cyclic structure.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What allows our counting to terminate without a new call?

A bag represented by an integer n directly returns n screws. An empty box returns the initial total of 0 screws without visiting any items. These terminal cases need no further calls inside them.

Recall 2What does the small box return, and what does the outer call do during its calculation?

It returns an integer count of 6 screws, obtained by adding the returns from its bags. The outer call keeps its local total of 3 screws while waiting; it then resumes the addition with the return received.

Recall 3Why does the stack not contain all the calls made since the start?

It keeps the calls that have started and are still unfinished. A completed call leaves it. For our drawer, 6 calls take place in all, with at most 3 calls active at the same time.

Recall 4Why is the existence of a base case not enough to guarantee termination?

The calls must be able to reach it. Here the lists are finite, the calls follow the items inside them, and no cycle leads back to a box waiting for a return. Repeatedly calling the same box makes no progress.

Recall 5How can separate counts check the number of screws and the number of calls?

Adding the bag counts directly gives 10 screws. Counting all the inputs processed gives 4 bags and 2 boxes, making 6 calls. The units tell us what each result measures.

Reconstruct the reasoning

Without looking at the lesson, reconstruct this sequence using the drawer: define a base case, start a local total for each box, call the function on an item inside it, wait for its return and add it, then finish visiting the items. Next, work out the direct check of the screws and the assumption that would prevent going round in circles.
