Unit tests

Your goalBuild a test for a gauge function: set the inputs, predict the result independently, call the function and compare, then state what this test establishes.

Before you start
c013-m5 : recursion · c014-m5 : invariants · c015-m1 : exceptions · c015-m2 : assertions

✿01 See the idea

A watering tank can hold 10 L. You prepare a trial with 5 L: the gauge should show that the tank is half full. Before connecting a sensor or a screen, you want to check just the function that converts a volume and a capacity into the fraction filled. The scene and all its values are fictional.

The test supplies the inputs itself. It calls the small function, collects what it returns and compares it with a result predicted in advance. This expected result comes from the rule for the tank: here, one half. If you use what the function has just returned as the expected result, you lose this independent reference.

A unit test is this executable check of a small unit of a program, here a function called directly. A test case brings together specific inputs and an expected result. The assertion you have already met provides the comparison; the test also organizes the setup and the call that make this comparison useful.

The first diagram follows a case where the results agree. The second changes only how full the same tank is: it explains why a function that always returns one half can pass the first case and be wrong elsewhere. None of these trials checks the actual amount of water, the sensor or the screen.

The rule to remember

Prepare a known case, set the expected result from the rule, call the function, and compare the actual result with the expected result. A pass applies to the case actually run.

✿02 Follow an example

Worked example

Write and run the test for the tank midpoint

For the fictional 10 L tank containing 5 L, let us build the test named test_part_remplie_milieu. We will set the expected result before the call. We will use exact fractions so that the comparison checks the calculation without introducing a rounding tolerance.

  1. State what the function must do

    v is the supplied volume, in litres; C is the supplied capacity, in litres; p is the fraction filled, with no unit. The contract is the rule the function must follow. For this trial, C is strictly positive and v is between 0 and C. The inputs are known and expressed in the same unit; the function does not query any device.

    p=vC

    Litres are divided by litres, so p is not a volume. The teaching function is named part_remplie and takes the arguments volume and capacite. Its body contains the Python statement return volume / capacite. With exact inputs, the same arguments give the same result; no external state changes it.

  2. Prepare the inputs and the independent expected result

    Half of 10 L is 5 L: the expected result a is 1/2, or 0.50 with no unit. You can check it using the fraction below. This reference comes from the filling rule and a calculation by hand, before looking at the program output.

    a=510=12

    In Python, the statement from fractions import Fraction makes Fraction available, which constructs exact rational numbers. Fraction(5) represents the supplied whole-number volume; Fraction(1, 2) represents the exact expected result. In the test, write volume = Fraction(5), capacite = Fraction(10), then attendu = Fraction(1, 2), in that order. The second argument of Fraction is the denominator when supplied.

  3. Call the function to be checked

    Next write obtenu = part_remplie(volume, capacite). The variable obtenu receives the result actually returned by the call in this trial. It does not receive a copy of the expected value. Let r denote this result, with no unit, like a.

    For the given definition, the operation performed is 5 ÷ 10: r is 1/2, or 0.50 with no unit. The word return sends this number back to the caller. This function neither fills the tank nor displays the gauge.

  4. Compare and check another way

    End the test body with assert obtenu == attendu. The double sign == compares; the sign = in the previous lines assigns a value to a variable. Here the comparison is true. If it were false, an ordinary Python run with assertions enabled would raise AssertionError, the exception for a failed assertion.

    We can make the comparison explicit using the difference δ, the Greek letter delta: δ = r − a. This difference has no unit. Finding no difference in this case does not amount to a proof for all volumes.

    δ=r−a=12−12=0

    Check using the inverse operation: r × C = 1/2 × 10 L = 5 L. This recovers the supplied volume. This check links the output to the physical meaning of the calculation and can reveal a mix-up of units in the test setup.

  5. Run the test, then interpret its scope

    Put these lines in a function named test_part_remplie_milieu, with no arguments. As with the functions you have already met, its header starts with def and ends with a colon; its statements are indented, meaning they are shifted to the right under the definition. Then, outside this definition, call test_part_remplie_milieu(). The prefix test_ is a readable name here: without a direct call, a definition alone does not run its body. A testing tool could organize the calls; we do not need one for this trial.

    In this direct call, reaching the end without an exception means that the executed assertion held for these inputs. Observing silence without checking that the call took place would not be enough. Assertions must remain enabled; this small trial must not be run in a Python mode that disables them.

    A version that always returns 1/2 would also pass this midpoint case. The other fill levels in the exercises will help distinguish it. Even successful local comparisons do not prove that the sensor supplies the correct volume or that the screen receives the result.

Explain it in your own words

Hide the example. Recall the inputs, the expected result and its justification, the call and the assertion; then explain how you run the test and why the real tank remains outside what it proves.

✿03 Common mistakes

  • “I use what the function returned as the expected result.”

    Set the expected result from the contract and an independent calculation before the call. Comparing a variable with its own copy cannot detect an incorrect value; the last exercise asks you to repair this test.

    Repair the comparison reference in the last exercise

  • “I have written a test function, so the test has passed.”

    The definition prepares statements. In our direct trial, call test_part_remplie_milieu() and check that the assertion is actually reached with assertions enabled. A function that is never called has not compared anything yet.

    Return to the step that runs the test

  • “The calculation test passes: my entire gauge works.”

    Name the exact inputs supplied and the output checked. Here the test calls the function without a sensor or a screen. The real path between these parts needs another check, and a pass for one case does not cover all arguments.

    Review the scope and counterexample in the diagrams

Exercise 2 · Choose a useful test

The function always returns one half

An incorrect version always returns Fraction(1, 2), whatever its arguments. It passes the case of 5 L in 10 L. Add the case of 8 L in this same tank: predict the expected result, find the signed difference for the incorrect version and say whether the equality assertion holds.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The expected result changes with the volume. The output of the incorrect version does not change.

Hint 2

Subtract the expected result from the actual result, in that order. A negative difference here means that the returned fraction is too small.

Compare with the solution

The independent expected result is 8/10 = 4/5, or 0.80 with no unit. The correct version returns 4/5; its difference from the expected result is 0. Inverse check: 4/5 × 10 L = 8 L, the given volume.

The incorrect version returns 1/2, or 0.50 with no unit. Its difference is 1/2 − 4/5 = -3/10, or -0.30 with no unit. The fractions are not equal: the assertion fails in this case. The new fill level reveals this specific fault; it does not prove that every other possible error would be detected.

Check your reasoning

  • You keep the same capacity and change only the volume for the trial.
  • You distinguish the expected 4/5 from the actual 1/2 returned by the incorrect version.
  • You justify the failure using the difference -3/10 and limit your conclusion to this fault.

Exercise 3 · Repair with justification

The test that accepts its own error

For 8 L in the 10 L tank, a test runs obtenu = part_remplie(volume, capacite), then attendu = obtenu, then assert obtenu == attendu. It is indeed called, with assertions enabled. Explain why it accepts the version that always returns one half, then replace only the setup of the expected result. What evidence will still be needed for the gauge screen?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

A copy of a value also preserves any error it may contain.

Hint 2

Rewrite the predicted fraction from the volumes, without consulting obtenu.

Compare with the solution

With the incorrect version, obtenu is 1/2 and its copy attendu is 1/2. The difference is 0: the comparison is true, although the rule required 4/5. This test has no reference capable of contradicting this output.

Prepare attendu = Fraction(4, 5) before the call, because 8/10 = 4/5. Then keep the call to part_remplie and the assertion. The incorrect version will be rejected, since 1/2 is not equal to 4/5. Do not replace the call with the expected value: that would remove the very function you want to check.

This repaired test checks a calculation output. You still need to check separately that the screen receives and displays this output along the actual authorized path. No test of the calculation alone establishes this path. An answer obtained after a hint or after reading this correction remains an assisted answer and is not enough to establish that a level has been achieved.

Check your reasoning

  • You explain why a value and its copy are equal even if that value is wrong.
  • You set 4/5 independently and keep the call to the function being tested.
  • You separate the local comparison from evidence for the path to the screen.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does the unit test case for the gauge contain?

Fixed inputs, an independently justified expected result, a function call and a comparison of the output with that expected result. The trial must actually be run.

Recall 2Why does attendu = obtenu weaken the test?

The expected result becomes a copy of what you want to check. The comparison then accepts this output even if it contradicts the rule for the tank; a reference calculated from the contract is needed.

Recall 3Is defining test_part_remplie_milieu enough to perform its comparison?

No. In our direct trial, you must call test_part_remplie_milieu() outside its definition, with assertions enabled. The function name alone does not run its body.

Recall 4Why does the midpoint case let a function that always returns 1/2 pass?

For 5 L out of 10 L, 1/2 is exactly the expected result. With 8 L in the same tank, the expected result becomes 4/5: this case reveals the constant output.

Recall 5What does local success of the calculation fail to prove for the tank?

It checks neither the actual volume nor the sensor nor the path to the screen. It establishes only that the comparisons actually run held for their inputs, under their assumptions.
