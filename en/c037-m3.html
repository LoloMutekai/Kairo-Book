Level 1 · C037·M3

Joins

Your goalEnrich a register using a shared key, choose which rows to keep, and predict the rows produced when a key is repeated.

Before you start

✿01 See the idea

At a tool lending club, the register records past loans but contains only the code of each tool. A separate catalogue gives its name. To prepare a readable statement, you want to copy the correct name beside each loan. All the data in this scene are fictional.

Loan P has code A. The first catalogue entry has code B: copying rows at the same height would give P the wrong tool. Look for A wherever it appears in the catalogue. Loan R also has code A: it must find the same entry. Positions do not make the connection; the code values do.

A join matches rows from tables according to a condition. Here, the condition is equality of the tool code. We call the column chosen for this matching the join key. Its values can repeat in the register: P and R remain distinct loans. A join key is therefore not necessarily a unique row identifier.

That leaves loan S, whose code C is missing from the catalogue. An inner join keeps only the pairs found. A left join also keeps each loan with no catalogue entry, with a missing name. “Left” refers to the table we have chosen to keep: here, the register. The choice depends on the question asked, rather than the position in the diagram.

The rule to remember

For each loan, produce a row for each catalogue entry with the same code. If there is no entry, omit the loan from the inner join; keep it with a missing name in the left join.

✿02 Follow an example

Worked example

Give loans a tool name without losing any loans

The register contains P→A, Q→B, R→A and S→C. The catalogue contains B→saw, A→drill and D→sander. Let us construct the inner and left joins on the tool code, then check every row and every count.

  1. State what a row represents

    A row in the register represents a past loan, identified by P, Q, R or S. A row in the catalogue represents a tool entry. The tool code is a label with no physical unit; it is neither a quantity nor a position. P and R can have the same code because they are different loans.

    We compare text codes that are filled in and written in exactly the same way. A equals A; A differs from B. Here, there are no missing input keys, no approximate matching, and no search for the nearest date. For this exercise, the catalogue provides a fixed name for each code present, and all its names are filled in. A new result row will be a loan–entry pair, or a loan kept without an entry.

  2. Count matches before copying

    uvlfje wbbsni xjcjsn mwevgx innwok vorpmk fldt Their values are 2, 1 and 1 loans. The input total is 2 + 1 = 3, then 3 + 1 = 4 loans.

    Let m_A, m_B and m_C be the numbers of entries that match each loan with these codes: 1, 1 and 0 entries respectively. These are numbers of matches per loan. The catalogue also contains 1 entry for D; in total, 1 + 1 + 1 = 3 entries. D matches no loan in the register.

  3. Produce every pair in the inner join

    P finds A→drill: we write (P, A, drill). Q finds B→saw: (Q, B, saw). R in turn finds A→drill: (R, A, drill). S finds no entry for C: it produces no pair. We have listed the entire inner join result, without merging P and R.

    For a given code, each loan matches every compatible entry. We therefore multiply the number of loans by the number of matches per loan. For A: 2 × 1 = 2 rows. For B: 1 × 1 = 1 row. For C: 1 × 0 = 0 rows.

    The symbol N with subscript i denotes the number of rows in the inner join result. Subscripts A, B and C are the codes; subscript i stands for “inner”. The + sign combines the counts for the codes present in the register:

    Ni=nA×mA+nB×mB+nC×mC

    Numerically, 2 + 1 = 3, then 3 + 0 = 3 rows. Listing P, Q, R independently gives the same count. S is missing because the inner join requires a matching pair.

  4. Keep the loan without an entry using the left join

    The matching pairs remain the same. For S, we add (S, C, missing name). U denotes the number of loans without a match: here 1 loan, since C is the only code in the register without an entry. Each loan without an entry produces 1 retained row, rather than 0 rows.

    The symbol N with subscript g denotes the number of rows in the left join result; subscript g is the label used for “left”. The calculation adds the unmatched loans to the matching pairs:

    Ng=Ni+U=3+1=4 lignes

    The label “missing” is our reading aid, rather than a value found in the catalogue. It means neither that the tool does not exist nor that its name equals 0. It says only: no entry matches in the table provided. Code C remains known because it comes from the register.

  5. Check the meaning, then the number of rows

    Check the matches: P and R have drill, Q has saw, and S keeps its code with a missing name. No loan has been given sander, because none has code D. Looking up the keys by hand confirms the names independently of the additions.

    Check the counts: the left join result contains 4 rows for 4 loans, each present 1 time. This holds here because the initial catalogue contains at most 1 entry for each code. The difference 4 − 3 = 1 row corresponds precisely to S. This check does not justify assuming that every left join preserves the initial number of rows: the exercise with the repeated A entry will test this limit.

    For a statement of all loans, the left join result meets the request and makes the missing entry visible. For a list limited to loans associated with an existing entry, the inner join result is suitable. In both cases, the result count must be interpreted according to what a row represents.

Explain it in your own words

Hide the results and describe what happens to P, R and S. Why must P and R remain distinct? Which assumption ensures that there is exactly 1 row per loan in the left join result here?

✿03 Common mistakes

  • “I put the tables side by side, lining up their rows.”

    The first entry has code B, while P has code A. Look for equal codes throughout the right table. Moving an entry within the catalogue must not change the name associated with a loan.

    Compare the tables and their codes

  • “If the name is missing, I replace it with 0 or delete the loan.”

    A missing match is neither a name equal to 0 nor a measured quantity. In the complete statement, keep S and its code C with a missing name; in the inner join, explain explicitly why S is excluded.

    Review the handling of S and the checks

  • “A left join always produces as many rows as there were at the start.”

    It keeps each left row at least 1 time. A repeated key on the right produces several pairs for the same loan. Count the matching A entries before deciding whether the number of loans has changed.

    Test the repeated A entry in the last exercise

An additional A entry

In the initial catalogue, add 1 entry A→power screwdriver, without removing A→drill. The register stays the same. List the inner and left join outputs, calculate their sizes, then assess the claim “we have more loans”. What check restores an unambiguous name for each code?

Hint 1

P now matches every entry with code A; repeat the same process for R.

Hint 2

Add S only to the left join result, then distinguish the pairs from the identified loans.

Compare with the solution

For A, the number of entries changes from 1 to 2. P produces (P, A, drill) and (P, A, power screwdriver). R produces (R, A, drill) and (R, A, power screwdriver). Q still produces (Q, B, saw). S produces no inner join pair.

Contribution from A: 2 × 2 = 4 rows. Including B: 4 + 1 = 5; including C: 5 + 0 = 5 inner join rows. The left join also keeps (S, C, missing name), giving 5 + 1 = 6 rows.

The left join result exceeds the register by 6 − 4 = 2 rows. These are the additional pairs for P and R; the register still contains 4 loans. The claim therefore confuses produced pairs with recorded events.

For this catalogue, which is meant to give a unique name for each code, flag the ambiguity for A, check the correct entry with its source, then restore unique codes on the right before repeating the join. Deleting R would erase a real loan; arbitrarily keeping the first entry would hide the conflict. The join does not determine which name is correct.

Check your reasoning

  • Produce every pair for P and R, without stopping at the first A entry.
  • Find the inner and left join sizes both by listing the rows and by calculation.
  • Distinguish the number of loans from the number of rows produced by the join.
  • Repair the catalogue after checking its source, without deleting a loan or choosing an entry arbitrarily.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What determines the match between a loan and a catalogue entry?

Equality of the tool code chosen as the join key. Their positions in the tables do not determine the match. This code can repeat in the loan register.

Recall 2What happens to S, with no entry for C, in the inner and left joins?

The inner join excludes it because there is no pair. The left join keeps S with its code C and a missing name, if the register is the left table. This missing name is neither a numeric value nor proof that the tool does not exist.

Recall 3Why can a repeated code on the right multiply the rows?

Each loan matches all compatible entries. For A repeated in the last exercise, 2 loans × 2 matches per loan give 4 rows of pairs for this code.

Recall 4When does the left join keep exactly 1 row per loan, and what must still be checked?

When each loan matches at most 1 entry on the right, with any unmatched loan kept 1 time. You must still check the codes and associated names: the correct number of rows does not guarantee the correct matches.

Reconstruct the reasoning

Hide the course and reconstruct the statement: name what each row represents, state the key being compared, justify keeping the loans, work through the matches, and handle the missing entry. Then add the conflicting A entry and explain why the output grows without a new loan. Finish by checking the names and counts.
