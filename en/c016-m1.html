Modules

Your goalSeparate a calculation rule from its use, import its module and trace the names through to the result.

Before you start
c013-m5 : recursion · c015-m5 : diagnosis

✿01 See the idea

You are preparing a fictional order for seed packets: 6 packets containing 125 g each. The quantity ordered can change; the rule “number of packets × mass per packet” stays the same. Keeping the rule in portions.py and the day’s order in commande.py makes it easy to locate each responsibility.

A module is a unit of code that Python can load under a name. Here, it takes the form of a code file: portions.py contains a function named masse. commande.py is the calling file: it chooses the data and requests the calculation. A function describes an operation; a module groups code under a name that another file can use.

The statement “import portions” makes the module available under the name portions in the caller. The expression “portions.masse” refers to the function masse belonging to that module. The dot connects the module’s name to the name being looked up inside it: it is neither a decimal separator nor multiplication.

Imagine a recipe sheet stored in a folder named portions. Opening the folder lets you find the recipe; you still need to supply the quantities to set up the calculation. The analogy stops there: Python actually executes the code at module level when it first loads the module. We will therefore choose carefully what goes there.

The rule to remember

Importing makes the module available; calling its function supplies the data and produces the result. Keep the order data in the caller.

✿02 Follow an example

Worked example

Distribute the order calculation across the files

We are working with Python in a folder containing portions.py and commande.py. From this folder, we run the file commande.py with Python. We assume a fresh interpreter, saved files, no name collision for portions and a successful import. Each packet contributes exactly 125 g of seeds in our fictional model; packaging is excluded.

  1. Describe the rule without fixing the order inside it

    In portions.py, define a function called masse, with the parameters nombre and par_sachet. Its body consists only of the statement “return nombre * par_sachet”, indented inside the function according to the syntax learned when studying functions. The symbol * means multiplication in Python. No call or display statement is placed after this definition in portions.py.

    nombre receives a nonnegative integer representing the number of packets. par_sachet receives the mass of seeds per packet in grams. The function returns the total mass in grams. The data for this order will be supplied in the call: they are not fixed inside the function. We assume these inputs are valid; no input checking is added here.

    To trace the calculation by hand, n denotes the number of packets, a dimensionless quantity; p is the mass per packet, in grams; M is the total mass, in grams. The parentheses in M(n, p) indicate the data that M depends on. The same rule is expressed by the following product.

    M(n,p)=n×p

  2. Load the module before looking up the function

    The first statement in commande.py is “import portions”. Write the name portions without the .py extension and without quotation marks. In our folder, Python finds portions.py, executes its code at module level, then makes this module available under the name portions.

    Executing the definition creates the function masse; it does not execute its body. Since portions.py contains only this definition here, loading it does not calculate any order or display anything. This is not a general property of imports: a statement placed outside a function in a module may be executed when the module is loaded. Within the same interpreter, an ordinary import normally reuses a module that has already been loaded.

  3. Call the correct name and pass the data

    The next statement in commande.py is “total = portions.masse(6, 125)”. The = sign assigns the value returned by the call to total. The comma separates the arguments; their order associates 6 with nombre and 125 with par_sachet.

    portions refers to the module, and masse to the function being looked up in that module. The parentheses trigger its call. In this example, nombre and par_sachet are parameters local to the function; total is a name in the caller. The result passes through return: the function does not need to read total in commande.py.

  4. Perform the calculation and trace the return

    Each packet contributes p grams; repeating this contribution n times justifies multiplication. The body calculates 6 × 125 = 750 g. return passes this number to the caller, where total therefore receives 750. Python does not automatically attach the unit to this number; grams are part of our calculation convention.

    M(6,125)=6×125=750 g

  5. Display and then check the result

    The last statement in commande.py is “print(total)”. It displays 750. The calculation took place during the call, the assignment stored its value, then print displayed it. Removing print does not remove the preceding call or turn the calculation into an import.

    Arithmetic check: adding 6 copies of a mass of 125 g gives 750 g. Inverse check: 750 g ÷ 125 g per packet gives 6 packets. With 0 packets, the rule would return 0 g. These checks concern the model of equal masses, rather than an actual weighing.

    Reading check: point out, in order, the import, the call with its arguments, the return in the function, the assignment to total and the display statement. If you cannot connect a value to this sequence, the numerical result alone does not show that you understand the separation into modules.

Explain it in your own words

Hide the solution and reconstruct the statements in commande.py. Then explain what portions.py defines and why importing this module is not enough to assign a value to total. Identify which file to change if the number of packets changes.

✿03 Common mistakes

  • “After import portions, I can write masse directly.”

    With this form of import, only the name portions is added in the caller. Write portions.masse to look up the function in the module. A name masse defined elsewhere in the caller could even refer to a different calculation: the prefix makes the origin explicit here.

    Find the name used in the call

  • “Importing always calls every function in the file.”

    Python executes the code at module level when it first loads the module, but defining a function does not execute its body. Locate the parentheses in the call to masse in commande.py. A call placed outside a function in portions.py would, however, be executed during this loading.

    Separate loading from calling

  • “My file is in the right folder, so Python will always find the right module.”

    The course assumes no name collision for portions and that the file is run from the stated folder. Check the saved name portions.py, the statement import portions and the folder from which you run the file. Do not name commande.py portions.py: reusing the module’s name would blur the separation. A file’s name alone does not prove which code another environment will load.

    Review the conditions for running the file

Exercise 2 · Application and checking

Add packets without copying the rule

The same order gains 2 packets, still containing 125 g each. Identify the file to modify, write the new call and calculate the mass. Then check this result by separating the original order from the added packets.

Hint 1

The rule in portions.py receives a number; it does not need to know the day’s order.

Hint 2

Calculate the new number, then compare the direct product with the sum of the masses of the batches.

Compare with the solution

The number becomes 6 + 2 = 8 packets. Only the use in commande.py changes. After the import, write “total = portions.masse(8, 125)”. The function in portions.py keeps its body unchanged.

The direct calculation gives 8 × 125 = 1000 g. The added packets contribute 2 × 125 = 250 g. Another route: 750 + 250 = 1000 g. The routes agree because each packet contributes the same mass.

The number 8 remains data passed to the function, rather than a constant to write into its body. You can therefore handle the new order with the same rule.

Check your reasoning

  • You change the data in commande.py and keep the function with its parameters in portions.py.
  • You obtain 1000 g and state the unit convention.
  • You recover the result using 750 g + 250 g.

An unexpected display during import

Someone adds “print(masse(6, 125))” at the end of portions.py, outside the function. In a fresh interpreter, commande.py contains only import portions. The mass is displayed. Explain the path, then propose an arrangement that keeps a silent calculation module and lets the caller choose what to display.

Assisted answer: try this exercise without help later.

Hint 1

Distinguish the function body from the statement added at module level.

Hint 2

The first loading executes this added statement. The module itself knows the name masse that it has just defined.

Compare with the solution

During the first loading, Python defines masse, then reaches the statement added outside the function. This statement calls masse with 6 and 125, receives 750, then displays it. The import triggers a call here because the code at module level explicitly requests it; it does not automatically call every defined function.

Remove the display statement from portions.py. In commande.py, keep “import portions”, then write “total = portions.masse(6, 125)” and finally “print(total)”, with each statement on its own line. The calculation file defines the rule; the caller decides the day’s calculation and its display.

Check the repair under the stated conditions: loading portions alone should display nothing; running commande.py should display 750. This expectation applies to these specific files. A trial with a module that has already been loaded could hide the effect of the moved statement: start again with a fresh interpreter.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is the difference between portions.py and the function masse?

portions.py is the module, the file that contains code and defines names. masse is a function defined inside it: it receives data and returns their product. The caller accesses this function through the module.

Recall 2After import portions, how do you call masse and what does the dot mean?

Write portions.masse with the arguments in parentheses. portions is the name available in the caller; the dot looks up the name masse in this module. This form of import does not directly define masse in the caller.

Recall 3What executes when our module is first loaded?

The code at module level executes. The definition makes the function available without executing its body. A call placed outside the function would, however, be executed when the module is loaded. An ordinary import normally reuses the module within the same interpreter.

Recall 4How do the data and the result cross the boundary between the files?

The call passes the number of packets and the mass per packet as arguments. The parameters receive them in the function. return returns the total mass; the assignment stores it in total in the caller, then print can display it.

Recall 5If the quantity ordered changes, what do you modify and what do you check?

I change the arguments of the call in commande.py and keep the rule with its parameters in portions.py. I calculate the new product, then check it using the sum of the masses of the batches. Grams are an explicit convention of the calculation.
