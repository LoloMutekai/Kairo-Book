Functions

Your goalDefine a function for rice quantities, trace its calls, and explain where the returned value goes.

Before you start
c008-m5 : manual traces · c012-m5 : counterexamples

✿01 See the idea

You write a rule for rice quantities on a recipe card. The card can stay on the table without any order being calculated. When you supply the number of portions, you ask for the rule to be applied. The result goes back to the order that requested it.

Here, a function is a named calculation rule that the program can call. We name it besoin. Its definition describes how to calculate; a call asks for that calculation to be carried out with a specific input. Writing the definition and making a call are separate steps.

The scene and its quantities are fictional. We set 75 g of dry rice per portion, with no rounding. Orders use whole numbers of portions from 0 to 8. This convention helps us trace the program; the calculation does not weigh any rice.

In the diagrams, first read the card on its own, then follow the path of a call. The name n is the parameter: the name that receives the input inside the function. The supplied value, such as 3, is the argument. Here, the Python word return means “send this value back to the calling program”.

The rule to remember

Define the rule; supply the argument when making the call; calculate with the local parameter; return the result; resume the program at the point of the call.

✿02 Follow an example

Worked example

A rice quantity card and successive calls

The rule besoin must return the mass of dry rice corresponding to the supplied number of portions. Let us trace quantite = besoin(3), then quantite = besoin(4), keeping the same definition between calls.

  1. Set the quantities and the domain for the scene

    n denotes the requested number of portions, a whole number from 0 to 8. d denotes the amount per portion, fixed at 75 g per portion. m denotes the returned mass, in grams. We use the same amount per portion in every call, with no rounding or change of recipe.

    m=d×n

    Multiplying grams per portion by a number of portions gives grams. In the code, the inputs and results are just numbers: our convention assigns these units to them. The function as we will write it checks neither the type of the argument nor its bounds; here we supply arguments within the stated domain.

  2. Define the function without calculating the order

    The header line is “def besoin(n):”. def introduces a definition; besoin is the chosen name; the parentheses contain the parameter n; the colon opens the body. On the next line, indented as in the first diagram, we write “return 75 * n”. The symbol * means multiplication in Python.

    Indentation is the leading spacing that makes this line part of the function body. Executing the definition associates the name besoin with the function, but does not execute that body. No argument has been supplied yet, and no numerical result for the rice quantity has been returned.

  3. Call the function and pass the argument

    The program reaches “quantite = besoin(3)”. It must first obtain the value on the right of the = sign before assigning it to the name quantite. The parentheses after besoin request a call with the argument 3.

    During this call, the local parameter n receives the value 3. “Local” means that this name belongs to this execution of the function. If a name n also exists in the calling program, it is separate: receiving this integer in the parameter does not reassign that outer name.

  4. Calculate in the body, then check another way

    The body uses the n of this call. Since each portion requires 75 g, we multiply the amount per portion by the 3 portions received.

    m=75×3=225 g

    Check by adding the amounts for each portion: 75 + 75 + 75 = 225 g. This other way of counting gives the same product. It checks the calculation for this argument, without proving every possible call on its own.

  5. Return to the assignment

    return sends back the calculated value, 225, and ends this call. The program resumes where it was waiting for the result. To follow the trace, replace the expression besoin(3) with its value: the line becomes “quantite = 225”.

    quantite now denotes the number 225, interpreted here in grams. The program has obtained a reusable value. This call displays nothing, because its body contains no display instruction.

  6. Make a new call with a new argument

    At the line “quantite = besoin(4)”, the parameter of this new call receives 4. It does not keep 3 just because the definition is the same. The calculation returns 75 × 4 = 300 g; the assignment then replaces the previous value of quantite with 300.

    Check: the order increases by 4 − 3 = 1 portion. The mass increases by 300 − 225 = 75 g, the expected amount for 1 extra portion.

  7. Use return values in a calculation

    To combine the orders, we can write “total = besoin(3) + besoin(4)”. This expression makes new calls; each supplies a value for the addition. The total is therefore 225 + 300 = 525 g. return makes this use of the results possible.

    Check using the total number of portions: 3 + 4 = 7 portions, then 75 × 7 = 525 g. We obtain the same mass. Adding returned values does not restart the calculation with a mass mistaken for a number of portions.

  8. Distinguish display and return

    print is a display function: a call such as print(75 * n) shows the calculated number. If this line replaces return in besoin and the body ends there, the function no longer returns that mass; Python gives it the return value None.

    None is a special value that indicates the absence of a numerical result here. It is not the number 0. With the original definition, besoin(0) does calculate 75 × 0 = 0 g and returns that number. We therefore need to distinguish a numerical return value of 0, a return value of None, and the absence of a call.

Explain it in your own words

Hide the steps. Trace a call again from the assignment line to the return, naming the argument and the parameter. Then explain why the definition alone and the display of a number do not provide the same evidence as a returned value.

✿03 Common mistakes

  • “I have written def besoin(n), so my order has already been calculated.”

    The definition associates a name with a rule. Calculating the order requires a call and its argument. With the card on its own, the body has not been executed yet.

    Compare the card on its own with the path of a call

  • “n stays equal to 3 for later orders.”

    n is the parameter name, not a stored order. besoin(4) receives 4 and returns 300 g. Start again from the call line to give the local n its value.

    Trace the change to the new argument again

  • “If the number is displayed, quantite must receive it.”

    Display and return have separate roles. If the body only displays the mass and then ends, quantite receives None. For the call to supply the mass to the program, the definition must send it back with return.

    Repair the version that only displays the number

Exercise 3 · Diagnosis and repair

The number is visible, but the program does not receive it

A version of besoin replaces its return line with “print(75 * n)”, and then the body ends. The calling program sets “n = 5”, then executes “quantite = besoin(2)”. Which number is displayed? What are the values of quantite and the outer n afterward? Repair only the body line so that quantite receives the mass, and justify each answer.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The local parameter receives the argument of the call, even if a name n already exists elsewhere.

Hint 2

Separate what print shows from the value the function supplies to the assignment.

Hint 3

To repair the function, keep the same product but change the operation that supplies its value to the calling program.

Compare with the solution

In the call, the local n equals 2. The product is 75 × 2 = 150 g. print shows the number 150, but the function ends without returning this product: quantite receives None.

The n in the calling program remains 5. Binding the local parameter to the integer 2 does not reassign that outer name. We therefore need to track names in their context, even when they are spelled the same way.

Repair: put “return 75 * n” back on the indented body line. The same call then supplies the number 150 to quantite without displaying that number. Check: changing only print to return changes the return value and the display, while keeping the product and the outer n unchanged.

Check your reasoning

  • You distinguish the displayed 150, the received None, and the 5 kept in the outer n.
  • Your repair contains return and returns the product calculated in the body.
  • You justify the local n using the argument and the outer n using the absence of any reassignment to that name.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does the definition of besoin do, and what triggers its calculation?

The definition associates the name besoin with a rule and describes its indented body. A call, with its argument, triggers the execution of that body. The definition alone does not return a mass yet.

Recall 2In besoin(4), where are the parameter and the argument?

n is the parameter named in the definition; 4 is the argument supplied by the call. The local n of this call receives 4.

Recall 3How does quantite receive the value of besoin(3)?

The body calculates 75 × 3 = 225. return sends back this value and ends the call; the program then resumes with quantite = 225. Our convention interprets this number in grams.

Recall 4If n equals 5 in the calling program, does besoin(2) replace it with 2?

No. The local parameter receives 2 for this call; the outer name n remains associated with 5. Our body calculates with its parameter without reassigning the outer name.

Recall 5Why is displaying the mass and then ending the body different from returning it?

print shows the number. Without an explicit return of this mass, the function supplies None to the caller when it ends. return supplies the mass as a reusable value. None is distinct from the numerical result 0 obtained for 0 portions.
