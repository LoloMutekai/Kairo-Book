Locks and semaphores

Your goalChoose a lock to protect a shared update and a semaphore to limit admissions, then check that both are released.

Before you start
c016-m5 : documentation · c007-m5 : execution traces · c012-m5 : counterexamples · c019-m1 : processes and memory space · c019-m2 : threads and races

✿01 See the idea

In a fictional workshop, workers A, B and C process cases at 2 interchangeable workstations. A shared register counts completed cases. The register shows 8 cases; each newly completed case must add 1 to the count. The workers represent threads of the same program that can read and write this shared memory.

To change the register, imagine a single key: whoever takes it reads the count, increases it and writes the new count before returning the key. The others wait. A lock provides this mutual exclusion: sections protected by the same lock do not overlap.

To enter the workshop, imagine 2 tokens instead, each allowing use of a workstation. A semaphore counts these available permissions. A successful acquisition consumes 1 permit; a release returns 1. When no permits remain, a new request must wait or give up, depending on the chosen mode.

These protections meet different needs. The 2 workstations can operate together, but an update to the register must remain exclusive. A workshop permit therefore does not prevent another worker from accessing the register. The scene and its numbers are fictional; no actual duration or performance is measured.

The rule to remember

Protect the entire read–modify–write sequence with the same lock; reserve a permit for the entire time a workstation is occupied; release each successful acquisition exactly 1 time.

✿02 Follow an example

Worked example

Keep the register accurate without inventing workstations

A, B and C each have a case to process. The capacity is 2 workstations and the initial count is 8 completed cases. We first compare the updates by A and B, then track the permits until C leaves. These comparisons use the same cases. Each successfully completed case counts as 1; the workers release their locks and permits even if an error interrupts processing.

  1. Define what each protection guarantees

    x denotes the count of completed cases; L is the shared lock for the register. A critical section is the section that accesses shared state and must be protected: here, reading x, calculating its new value, then writing it back. L does not contain this count or work out which accesses need protection.

    K denotes the workshop capacity; p is the number of available permits; h is the number of permits acquired and not yet returned. These are integer counts: x is counted in cases; K, p and h in permits, with each permit allowing use of a workstation. L names a lock object and is not a measured quantity.

    We assume acquisitions are indivisible: concurrent requests cannot take the same available permit. All workers use the same synchronization objects within the same process. Assignment of an actual workstation is assumed to be handled separately: the semaphore does not do this. Individual reads and writes of the count are assumed to be indivisible in our trace; their combination is not. No worker abruptly disappears, and the exit mechanism actually runs.

  2. Reconstruct the loss without protection

    A reads 8 and B also reads 8 before any write. Each calculates 8 + 1 = 9. A writes 9, then B writes 9 using its old copy. The register ends at 9 cases.

    For 2 cases actually completed, the expected count is 8 + 2 = 10 cases. The difference of 10 − 9 = 1 case reveals a lost update. This counterexample shows a possible race; it does not mean that every execution without a lock gives this result.

  3. Lock the entire critical section

    The protocol becomes: acquire L, read x, add 1, write x, then release L on exit. If A acquires L first, A writes 9. B waits to acquire it before reading, so B reads 9, calculates 9 + 1 = 10 and writes this result.

    If B goes first, the names change but the final count remains 10. Protecting only the write would fail: old copies could still be prepared outside the lock. Every concurrent operation that needs to observe or change the register consistently must follow this same protocol.

    A guaranteed exit, such as the exit from a context manager block, releases L even if the program signals an error. It does not automatically undo a change already written. Keep this section short: the case is processed outside L.

  4. Write the permit rule

    Initially, p = K = 2 and h = 0. The property to preserve, called an invariant, is:

    0≤p≤K;p+h=K

    The prime mark indicates the value immediately after the operation. A successful acquisition removes an available permit and adds a held permit:

    p′=p−1;h′=h+1

    This is possible only if p is strictly greater than 0. A legitimate release does the reverse: p′ = p + 1 and h′ = h − 1. It returns a permit previously acquired and still held. A denied acquisition changes neither p nor h.

  5. Admit A and B, deny C without waiting

    A acquires a permit: p = 2 − 1 = 1. B acquires another: p = 1 − 1 = 0. They hold 1 + 1 = 2; the check gives 0 + 2 = 2 permits.

    C now attempts a nonblocking acquisition. With p = 0, it fails: p remains 0, h remains 2. C does not start its case and releases nothing. A blocking acquisition would instead wait until a permit was obtained; this wait does not create a workstation or establish a guaranteed admission order.

  6. Return and then reassign permits

    A completes its case, updates the register under L, then returns its permit: p = 0 + 1 = 1, h = 2 − 1 = 1. In our chosen trace, C now retries and succeeds: p = 1 − 1 = 0, h = 1 + 1 = 2. B and C occupy the workstations.

    B then finishes, updates the register and returns its permit: p = 0 + 1 = 1. At this point, A and B have added their cases; the protected count is 10. C is still working. When C finishes, its update gives 10 + 1 = 11 cases and its release gives p = 1 + 1 = 2. Only 0 permits remain held.

  7. Combine the protections without confusing their releases

    Each worker therefore follows this sequence: obtain a permit; process the case; acquire L to record success; release L; return the permit when leaving the workstation. Permit release must be guaranteed as soon as its acquisition succeeds, including if processing fails before success is recorded. Freeing a place does not establish that the case was completed successfully.

    Wait for the permit before taking L. Otherwise, a worker could hold the register lock while waiting for a workstation whose occupant needs the register to finish: each would wait for the other. Using a different lock for each worker does not provide the required shared exclusion.

    Count check: 11 − 8 = 3 completed cases. Capacity check: at the end, 2 + 0 = 2 permits, all available. These checks concern different properties. The protocol establishes neither a maximum waiting time nor faster work.

Explain it in your own words

Hide the trace. Explain when B must read the register, why C returns nothing after being denied and why its permit must nevertheless be returned if processing fails after admission. Then reconstruct the case count and the count of places separately.

✿03 Common mistakes

  • “I lock only the write: the register is protected.”

    The workers may have read the same old value before this protected write. Put the read, calculation and write in the same critical section, under the same lock L. B must read only after acquiring L.

    Replay the loss, then the critical section

  • “The semaphore already protects the register.”

    With 2 permits, A and B can be admitted together and lose an update. Keep the semaphore for the workstations and add L around the register. A semaphore initialized to 1 can provide exclusion if the protocol is followed; here, that would limit admission to 1 worker at a time.

    Compare the register key and the entry permits

  • “When leaving my attempt, I always return a permit.”

    Return a permit only if this attempt acquired it, and exactly 1 time. After a denial, nothing was taken. After an acquisition followed by an error, a guaranteed exit must return it. A bounded semaphore flags a return that would exceed the initial capacity; it does not replace this tracking of acquisitions.

    Diagnose an extra permit return

Exercise 1 · Identification and justification

Where does protection begin?

In the same workshop, A and B read 8 outside L. Each then takes L, writes its copy increased by 1, then releases L. Give the final count in this trace, the expected count and the change needed in when the lock is acquired.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Acquiring the lock late does not refresh a copy already read.

Hint 2

Replay each write, then place the acquisition of L before the register is read.

Compare with the solution

A and B have each prepared 8 + 1 = 9. The writes are separate but copy the same value: the final count is 9, whereas 2 completed cases require 10. The register is missing 1 case.

Acquiring L must come before the read; release must come after the write. In this order, the second worker reads 9 and produces 10. The protection covers the dependency between reading and writing, not just the final action.

Check your reasoning

  • I distinguish 9 observed in the trace from 10 expected.
  • I place reading, adding and writing under the same shared lock.

Exercise 2 · Paper trace

Track permits and choose protections

Start again with 2 free permits. A acquires; B acquires; C makes a nonblocking attempt and fails; A returns a permit; C retries and acquires. Note p and h after each event. A colleague proposes removing L because the semaphore admitted A and B together: answer with a register trace at the time of this admission.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

With each successful acquisition, a permit changes category: available becomes held.

Hint 2

Check p + h = K after each line. Then imagine A and B reading the register before any write.

Compare with the solution

After A: p = 1, h = 1. After B: p = 0, h = 2. After C is denied: p = 0, h = 2; neither category changes.

After A returns a permit: p = 1, h = 1. After C enters: p = 0, h = 2. Each sum equals 2, with no negative permit count.

The semaphore lets A and B work together. Without L, they can read 8, then each write 9. Admission then respects capacity while the register loses 1 case. L must be retained for the shared update.

Check your reasoning

  • I keep p and h unchanged after the denial.
  • I check that the 2 permits are conserved.
  • I provide the counterexample 8 → 9 rather than merely asserting that the semaphore is insufficient.

Exercise 3 · Diagnosis and repair

An error followed by a duplicate release

The workshop is empty, with p = 2. A acquires, then its processing fails before any update to the register. A first block returns its permit; another exit block returns it again. Calculate what an ordinary semaphore counter would report, explain the anomaly and propose a protocol that also handles a denied acquisition.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Write the sequence of p values starting with the capacity. The register counts only successfully completed cases.

Hint 2

Separate successful acquisition, failure of the work and release. A guaranteed exit must be set up after successful acquisition and perform 1 return.

Compare with the solution

After acquisition: p = 1. The first return restores p = 2. The duplicate return would take an ordinary semaphore to 2 + 1 = 3 free permits, beyond the 2 workstations. The register remains at 8: A did not complete its case successfully.

A bounded semaphore rejects this second return because its counter would exceed its initial capacity. This detection signals a protocol error; it does not make the case successful. Repair requires removing the duplicate return and assigning every release to the same guaranteed exit.

Protocol: attempt acquisition; if denied, exit without working or releasing; if successful, guarantee release throughout processing. Record only a completed case under L, and also guarantee that L is released if this section is interrupted. The program must be fixed, rather than its capacity artificially increased.

Check your reasoning

  • I reconstruct the sequence 2, 1, 2, then 3 in the faulty protocol.
  • I distinguish the counter of places from successful completion of the case.
  • My repair returns exactly 1 permit per successful acquisition, even after an error, and none after a denial.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What must the lock cover to increment the register correctly?

The entire read–modify–write section, with the same lock object for all workers. Reading before acquisition can retain an old value, even if the write is protected.

Recall 2What does a successful acquisition change, and what does a denial change?

Success removes 1 available permit and adds 1 held permit. A denial changes neither count; it gives no permit to return.

Recall 3Why keep a register lock when the semaphore admits 2 workers?

Permits allow work to overlap up to the capacity. They do not make the shared update exclusive; the lock then prevents concurrent reads and writes from losing a case.

Recall 4If processing fails after admission, what must be returned and what can be claimed?

Return the acquired permit exactly 1 time through a guaranteed exit, and release any lock actually acquired. This release does not prove that the work succeeded or undo a write already performed.

Recall 5What does respecting the permit count alone fail to guarantee?

It guarantees neither the accuracy of the shared register, nor a maximum waiting time, nor admission order, nor a speed gain. It bounds admissions if all workers follow the same protocol.

Reconstruct the reasoning

Reconstruct the path of a case: obtain a permit, work, protect read–modify–write under the shared lock, then return what was acquired. Justify the case count and the conservation of permits separately. Describe what happens after a denial or an error; reading and an assisted answer do not establish an attained level.
