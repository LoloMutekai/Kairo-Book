Bits, bytes and representation

Your goalRead the value of a byte in several bases, check its limits and state the convention that gives it meaning.

Before you start
c069-m5 : congruences and Euclid · c019-m5 : clocks and persistence · c053-m5 : proxy, construct and validity

✿01 See the idea

In the workshop, each box has a label stored in a small file. The file for our box contains exactly 1 byte. Before giving it a meaning, let us look at this byte as a row of 8 cells. Each cell has 2 possible states, which we write as 0 and 1: this is a bit. The drawing represents these logical states without assuming any particular storage technology.

The cells do not all carry the same weight when we read an integer. The rightmost cell counts units; its neighbour has twice that weight; each step to the left doubles the weight again. A bit written as 1 contributes its weight; a bit written as 0 contributes nothing. In our row, only the weights 64 and 1 contribute.

The file, the boxes and their documentation are fictional. The convention in this workshop states: “the byte contains the box number as an unsigned integer”. Unsigned means here that we read a positive integer or 0. This number has no physical unit; it does not count the objects stored in the box.

A byte is a group of 8 bits. Its size remains 1 byte whatever its contents. Binary, decimal and hexadecimal notation are ways to display a value: changing the display does not change the bits in the file. The meaning of these bits still depends on the convention used to read them.

The rule to remember

Distinguish the stored bits, their value under a stated convention, and the notation chosen to display that value.

✿02 Follow an example

Worked example

Find the box number

The fictional label file contains 1 byte, displayed as 01000001 in binary, with the most significant bit on the left. The documentation specifies an unsigned integer that identifies the box. Let us find its decimal value, its hexadecimal notation and the limit of this field.

  1. Establish what we are reading

    We are reading the states in the file; we are not executing any instructions it might contain. Here the documentation defines a simple numeric label. The file size is an amount of storage, in bytes or bits. Its interpreted value U is an integer with no physical unit.

    The base of a notation indicates how many distinct digits it uses and the factor by which the weight increases from one position to the next. In binary, the base is 2. In decimal, it is 10. Writing a value with more digits does not automatically change the space it occupies in the file.

  2. Associate each bit with its position

    i is the index of a cell, counted from the right, from 0 to 7. b with subscript i, written bᵢ, is the digit in that cell, equal to 0 or 1. Its weight is 2 raised to the power i, as written in the formula below. U is the sum of the contributions from all the cells. The digits, indices, weights and U have no physical unit.

    U=∑i=07bi×2i

    The symbol ∑ means to add the contributions for all the indicated indices. In other words: multiply each digit by the weight of its cell, then add the products. The weights from right to left are 1, 2, 4, 8, 16, 32, 64, 128. Raising the base to the power 0 gives 1.

    bi×2i

  3. Calculate the decimal value

    The bit with weight 128 is 0; the bit with weight 64 is set; the following cells are 0 up to the last cell, with weight 1. Add the contributing weights rather than counting the digits written as 1.

    U=0×128+1×64+0×32+0×16+0×8+0×4+0×2+1×1=65

    Result: box number 65. The file still occupies 1 byte, or 8 bits. The leading 0 keeps the field width visible; omitting it in an abbreviated notation would not remove any bit from the file.

  4. Check by grouping into hexadecimal digits

    Hexadecimal uses base 16: the usual decimal digits, followed by A, B, C, D, E and F for the values from 10 to 15, in that order. A group of 4 bits has 16 configurations, so it corresponds exactly to a hexadecimal digit. Our byte divides into 2 groups of this size, starting from the right.

    The left group 0100 has the value 4; the right group 0001 has the value 1. The hexadecimal notation is therefore 41. In this pair, let g be the value of the left digit and d the value of the right digit. Each lies between 0 and 15, inclusive; g and d have no unit.

    U=g×16+d=4×16+1=64+1=65

    This second calculation gives 65 again without repeating the products for each bit. The same value is therefore written as 01000001 in base 2, 65 in base 10 and 41 in base 16. Specifying the base avoids reading 41 as a decimal number. Here these notations are displays, not text stored in place of the byte.

  5. Check the capacity and meaning

    Each bit has 2 choices. Adding a cell doubles the number of possible rows: with 8 bits, we obtain 256 configurations. This count does not assume that the configurations are equally likely. For unsigned integers, each row represents a different value, starting at 0, inclusive.

    28=256; maximum =256−1=255

    Another check: with all the bits set, the sum of the weights is 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255. Our value 65 lies within this interval. The largest identifier is not 256, because the first identifier is 0.

    The “box number” convention gives the result its meaning. The bits alone do not say whether they encode a quantity, a letter or flags. Nor do they establish the physical contents of the box. Reading a byte, converting it and knowing what it denotes are distinct operations.

✿03 Common mistakes

  • “I count the set bits to get the value.”

    A set bit contributes the weight of its position. In our byte, the 2 set bits contribute 64 and 1, giving 65. Align the digits under the weights before adding.

    Review the cells and their weights

  • “The display 41 always means the same number.”

    Ask for the base. Here hexadecimal gives 4 × 16 + 1 = 65. The notation can change without modifying the file. Do not treat a display as a storage size.

    Repeat the hexadecimal check

  • “With 256 configurations, the largest identifier is 256.”

    The identifiers start at 0. There are 256 values from 0 to 255, inclusive. Repeat the check with all the weights, then verify that the number remains a box identifier.

    Correct the workshop record

Exercise 1 · Read a change

The last cell is cleared

On the label for the same box, the rightmost bit changes from 1 to 0. All the others stay the same. Write the new byte in binary, calculate its unsigned value and the decrease in the number. Does the file size change?

Hint 1

The changed cell has weight 1. Remove its contribution without moving the other cells.

Compare with the solution

The new pattern is 01000000 in binary. Only the weight 64 contributes: the value is 64. The number decreases by 65 − 64 = 1.

The field keeps its 8 cells. Its size remains 1 byte. Check: setting the last bit again adds 1 to 64 and gives 65 again. Changing the contents does not reduce the field width.

Check your reasoning

  • The pattern keeps 8 bits, including the leading 0.
  • The decrease is justified by the weight of the cell, not by the total number of digits.
  • The value with no unit and the size in bytes are kept separate.

Exercise 2 · Reconstruct a representation

Prepare the next number

The workshop reassigns the label to number 66, written in decimal. Construct its binary byte and its hexadecimal pair under the same convention. Justify the set bits and check the conversion back to the decimal value.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The largest weight that fits into 66 is 64. What remainder still needs to be represented?

Hint 2

In hexadecimal, use 4 groups of 16, then represent the remainder in the right digit.

Compare with the solution

We include 64; the remainder is 66 − 64 = 2. The intermediate weights are too large for this remainder. The cell with weight 2 is set and the cell with weight 1 is 0. The pattern is 01000010 in binary.

Grouping gives 0100 followed by 0010, which are the digits 4 and 2. The hexadecimal pair is 42. Check: 4 × 16 + 2 = 64 + 2 = 66. The conversion is reversible under the stated conventions.

Check your reasoning

  • Each subtraction explains the choice for the next cell.
  • The 8 bits and the 2 hexadecimal digits represent the same integer.
  • Converting back to decimal gives 66 again without changing the convention for the field.

Exercise 3 · Examine a conclusion

The workshop record mixes levels

A record describes our label: “file of 1 byte; 256 configurations; identifiers from 0 to 256, inclusive; box 65 therefore contains 65 objects”. Separate the correct statements from the conclusions that need revision. Also give the hexadecimal notation for the largest permitted identifier.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Count the integers in an interval, including its starting bound. Does a box number measure what the box contains?

Hint 2

F represents 15. Compare F × 16 + F with the sum of all the binary weights.

Compare with the solution

The size of 1 byte and the 256 configurations are correct in our model. The correct interval runs from 0 to 255, inclusive: 255 − 0 + 1 = 256 values. Including 256 as an identifier would add one value too many. This integer does not fit in the unsigned field of 8 bits; the format would need to be revised to allow it.

The maximum is written as FF in hexadecimal: each F has the value 15, so 15 × 16 + 15 = 240 + 15 = 255. This gives the same maximum as setting all the bits.

The number 65 identifies a box; it does not measure its contents. The record provides no observation of the number of objects. We can state the identifier read and the field limits, then request a suitable observation to count the contents. Converting the bits correctly is not enough to validate this last conclusion.

Check your reasoning

  • The number of configurations and the largest value are distinguished.
  • The notation FF is justified by a calculation, then compared with the binary weights.
  • The conclusion about the objects remains unestablished; no replacement number is invented.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is the difference between a bit, a byte and the value of our label?

A bit has 2 logical states. A byte groups 8 bits. Under the unsigned convention, the row in this lesson has the value 65, with no physical unit; its size is 1 byte.

Recall 2How can you find the value of a binary byte without simply counting the set bits?

Start with weight 1 on the right, double at each cell to the left, multiply each digit by its weight and add. The index i counts from 0; the weight is 2 to the power i.

Recall 3Why does our hexadecimal display 41 represent 65 in decimal?

The left digit counts groups of 16: 4 × 16 + 1 = 65. The 2 digits correspond to the 2 groups of 4 bits in the same byte. The display does not change its bits.

Recall 4Why do 256 configurations give an unsigned maximum of 255?

The 8 bits offer 2 to the power 8 configurations, giving 256. The values start at 0, so the largest is 256 − 1 = 255.

Recall 5What allows us to interpret the value of the label as a box number?

The fictional format documentation imposes this convention. The same row of bits could have another meaning under another convention. The box number establishes neither its contents nor an execution of the file.
