Level 3 · C166·M3

Convolution

Your goalCalculate the convolution of two finite sequences, explain why one of them is read backwards, then check the result using a product evaluated at two points.

Before you start
c165-m5 : duality · c046-m5 : approximation error · c027-m5 : complex numbers · c166-m1 : Fourier series · c166-m2 : transform

✿01 See the idea

At the counter of a fictional snack bar, a screen displays the number of juice orders minute by minute: 2, then 5, then 1. These 3 readings are invented for the lesson. The cook does not want to react to a single minute: the workload is assessed using the current minute and those before it.

Each reading therefore leaves an echo. An order arriving during minute m contributes to that minute, then to the next, then to the minute after that, with a weight that depends only on the age k of the reading, meaning the number of minutes since it was recorded. We write this weight as hk and call h the kernel. For this cook, the weights are 1, 1 and 1: a recent reading and a reading 2 minutes old count equally; an older reading no longer counts.

Adding all the echoes gives the output y. At each minute n, the output adds the contributions sent by past readings. This operation is called the convolution of the sequence x with the kernel h. It replaces raw readings with a smoother measure of workload, and extends a little beyond the last reading because the echo of that reading continues.

This explains the phrase “read backwards”. To obtain the output for minute n, we pair the weight hk with the reading from k minutes ago, at index n − k, and this index decreases as k increases. The reversal follows from pairing each weight with the reading of the matching age.

The previous units break a signal down into frequencies. The question here is what this kind of filtering becomes when viewed in terms of frequencies: a simple product. We will check this only at 2 frequencies, using exact calculations, without rebuilding the whole theory.

Assumptions on this page: finite real sequences, 0 outside their index ranges, and a known kernel that is the same at every minute. Infinite signals and their convergence conditions are not covered here.

The rule to remember

The output for minute n adds, for each age k, the weight hₖ multiplied by the reading at index n − k; the indices of the two factors add up to n.

✿02 Follow an example

Worked example

An order display smoothed using a window of 3 minutes

Fictional values: the readings are x = (2, 5, 1) orders per minute and the kernel is h = (1, 1, 1), with dimensionless weights. Calculate the sequence y, check it using a product, then compare it with a moving average with window length 3.

  1. Name the quantities and state the assumptions

    The reading xm is the number of orders in minute m, with the starting index 0. The weight hk is dimensionless. The output yn is a number of orders over the window of minutes that contribute. The sequences are finite, real and 0 outside their index ranges.

    yn=∑khkxn−k

    The sum runs over the k for which hk and xn-k exist; the other products are 0 by assumption. The kernel does not depend on n: every minute is treated in the same way.

  2. Count the outputs

    An output exists whenever a reading pairs with a weight. The first pairing puts x0 with h0; the last puts the last reading with the last weight. There are therefore nx + nh − 1 outputs.

    ny=nx+nh−1=3+3−1=5

    Check: the output indices run from 0 to 5 − 1, and 5 exceeds 3 because the kernel has more than one weight.

  3. Calculate the output at index 0

    For n = 0, only k = 0 is available, because no reading has a negative index. The output contains just one product.

    y0=h0x0=1×2=2

    The first output uses only the first reading: the filter has nothing in memory yet.

  4. Calculate the central output

    For n = 2, three weights pair with three readings: (k, n − k) is (0, 2), (1, 1) and then (2, 0). In each pair, the indices add up to 2.

    y2=h0x2+h1x1+h2x0=1+5+2=6+2=8

    The kernel is traversed in one direction and the readings in the other: as k increases, the index of x decreases. Here the three products are 1, 5 and 2, because the weights are 1.

  5. Calculate the other three outputs

    Since each weight is 1, a product reduces to the reading itself. For n = 1: y1 = h0x1 + h1x0 = 5 + 2 = 7. For the index just after the centre: y3 = h1x2 + h2x1 = 1 + 5 = 6, because h0 would need a reading at index 3, which does not exist. For n = 4: y4 = h2x2 = 1 × 1 = 1.

    y=(2,7,8,6,1)

    The units are orders over the window. The values 2 and 1 are at the boundaries: the window is only partly filled there.

  6. Check using a product at two points

    Associate each sequence with a sum of powers of a number z, called a polynomial in z:

    X(z)=x0+x1z+x2z2

    H(z) is defined in the same way using h, and Y(z) using y. Multiplying X(z) by H(z) creates, for each pair of reading m and weight k, the term xmhk multiplied by z to the power m + k. Collecting terms with the same exponent n brings together exactly the pairs such that m + k = n: this is the convolution rule. Therefore, for every number z:

    Y(z)=∑nynzn=X(z)H(z)

    For z = 1, every power is 1: we compare sums. The readings total 8, the kernel totals 3, and 8 × 3 = 24; the outputs total 24, which agrees.

    8×3=24=24

    For z = −1, the signs alternate. X(−1) = x0 − x1 + x2 = -2, H(−1) = 1, and the product is -2. The outputs give y0 − y1 + y2 − y3 + y4 = -2: the second check agrees too.

    -2×1=-2=-2

    The connection with frequencies is as follows: for z = e^{iω}, where ω is an angle, these sums are transforms of the sequence at a frequency. z = 1 corresponds to the 0 angle, hence 0 frequency (the sum), and z = −1 to a half turn, hence the fastest alternation. The sign of the exponent is a convention; it does not change these two cases. The check is not a complete proof: swapping two outputs of the same parity, such as y1 and y3, would leave both products unchanged.

  7. Interpret y as a moving average

    A uniform kernel, divided by the number of minutes in the window, turns the sum into an average in orders per minute. With a full window, y2 ÷ 3 = 8 ÷ 3 = 2.67 orders per minute.

    A moving average programmed to use only existing values does not always divide by 3: it divides by the number of available readings. It gives 2 ÷ 1 = 2 at index 0, 7 ÷ 2 = 3.50 at index 1, and 2.67 at index 2. These are the first 3 outputs of the convolution, each divided by its own divisor. It is therefore not a convolution with a fixed kernel at the boundary. The outputs after the last reading are not kept.

Explain it in your own words

Explain in your own words why yₙ contains several products at the centre but just one at the boundary, then say which error the check at z = 1 and z = −1 cannot detect.

✿03 Common mistakes

  • “Convolution multiplies the two sequences term by term.”

    A term-by-term product keeps the length and pairs equal indices. Convolution pairs indices whose sum is n and adds all these products; the central output in the example contains three of them.

    Review the calculation of the central output

  • “The output has the same number of values as the readings.”

    For finite sequences that are 0 elsewhere, there are nₓ + nₕ − 1 outputs. A moving average implemented in code may keep only the first outputs; this is a boundary choice, not the convolution rule.

    Review the output count

  • “A moving average is everywhere the convolution with a fixed kernel equal to one divided by the width.”

    At the boundary, a calculation that averages the available values changes its divisor. Compare the divisor 2 with the divisor 3 at index 1 to see the difference.

    Redo the exercise on the boundary of an average

Exercise 1 · Direct application

A two-minute window

Fictional values: keep the readings x = (2, 5, 1), but let the kernel retain only the current minute and the previous one, with weights (1, 1). How many outputs are there, what are their values, and how can you check their total?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Apply the counting rule using the length of the new kernel.

Hint 2

For each n, list the index pairs (reading, weight) whose sum is n; the boundaries have only one pair.

Hint 3

The total of the outputs must equal the total of the readings multiplied by the total of the weights.

Compare with the solution

The kernel has 2 weights, so there are 3 + 2 − 1 = 4 outputs. With the weights equal to 1, each output adds the readings present in its window: 2 at index 0, 5 + 2 = 7 at index 1, 1 + 5 = 6 at index 2, then 1 at the next index.

Check: the expected total is 8 × 2 = 16. Adding 2, 7, 6 and 1 does give 16. The check does not detect two swapped outputs of the same parity; comparing the index pairs avoids this error.

Check your reasoning

  • The number of outputs is obtained using the counting rule, not by counting visually.
  • Each output is justified using its index pairs.
  • The total of the outputs is compared with the product of the totals.

Exercise 2 · Guided transfer

A kernel with unequal weights

Fictional values: the same readings x, but an asymmetric kernel g = (3, 1): the weight 3 applies to the reading from the current minute, and the weight 1 to the reading from the previous minute. Calculate the outputs at indices 0 and 1 and the last output, then say what would happen if you forgot to read x backwards.

yn=g0xn+g1xn−1
Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Write yₙ for n = 0, then n = 1, using the formula in the question.

Hint 2

The last output has only one pair: which reading is last, and which weight still reaches it?

Compare with the solution

The output at index 0 is 3 × 2 = 6. The output at index 1 is 3 × 5 + 1 × 2 = 15 + 2 = 17. There are 4 outputs, so the last is at index 4 − 1: only g1 still reaches the last reading, and 1 × 1 = 1.

Without reading backwards, you would pair the weight 1 with the next reading instead of the previous one. The kernel, which is not symmetric, would then give a number other than 17 at index 1. With the symmetric kernel in the example, this error was not visible.

Check your reasoning

  • The formula is applied using index n − k for the reading.
  • The three requested outputs are exact and their products are written out.
  • The consequence of forgetting the reversal is connected to the asymmetry of the kernel.

Exercise 3 · Transfer to code

The boundary of a moving average

A moving average with window length 3 averages, at each index, the values in the window that exist. Using the readings x from the example, give its values at indices 1 and 2, compare index 1 with convolution by the uniform kernel with weight one divided by 3, then explain the difference.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

At index 1, how many readings does the window actually contain?

Hint 2

Convolution with a fixed kernel always divides by the same width: which one?

Hint 3

Reuse the outputs y₁ and y₂ from the example.

Compare with the solution

At index 1, the window contains 2 readings: the average is 7 ÷ 2 = 3.50 orders per minute. The fixed kernel divides 7 by 3 and gives 2.33. At index 2, the window is full and both calculations give 2.67.

The difference comes from the divisor: the average of the available values divides by the number of readings present, and the fixed kernel by the width. At the start, the latter therefore counts as though the missing minutes were 0. Neither is wrong in itself; they answer two different questions.

Check your reasoning

  • The divisor changes at the boundary for the average of the available values.
  • The fixed kernel is identified as a convolution, and the boundary rule as a departure from it.
  • The difference is explained without judging which would be preferable for actual use.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does yₙ = Σ hₖ xₙ₋ₖ calculate?

The output at index n: the sum, over the age k, of the weight hₖ multiplied by the reading at index n − k. The two indices add up to n.

Recall 2How many outputs are there for nₓ readings and a kernel of nₕ weights, with finite sequences that are 0 elsewhere?

nₓ + nₕ − 1 outputs.

Recall 3Why is Y(z) = X(z)H(z)?

In the product, the term xₘhₖ includes z raised to the sum m + k. Collecting terms with the same exponent n recovers the convolution.

Recall 4Why is an average of the available values not a convolution with a fixed kernel at the boundary?

It divides by the number of readings present, which changes at the start; a fixed kernel always divides by the width.

Recall 5What does the check at z = 1 and z = −1 detect, and what does it miss?

It detects errors in the sum and the alternating sum; it misses the swap of two outputs of the same parity.

Reconstruct the reasoning

Reconstruct without looking: a reading sends an echo, a copy of the kernel shifted to that reading’s minute; the output for a minute adds the echoes arriving there, meaning the products hₖ xₘ such that m + k = n; there are nₓ + nₕ − 1 outputs. Multiplying the polynomials X(z) and H(z) gives the same sums, hence the check at z = 1 and z = −1. A moving average of the available values keeps the first outputs and changes its divisor at the boundary.
