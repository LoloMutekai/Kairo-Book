Paths

Your goalWrite the address of a file from the root or from the current folder, then resolve it segment by segment to open the correct file.

Before you start
C002·M4 : correcting errors

✿01 See the idea

In your fictional workshop (atelier), a folder named recettes (recipes) and a folder named photos each contain a file named granola.txt. The first holds your granola recipe; the second holds the caption for a photo of the jar. If you just say “open granola.txt”, which file should open? The name does not settle it: you also need to specify the route to reach it.

A folder contains files and other folders. Everything is stored under a single starting folder, the root, written as “/”. A path describes a route through this tree: names separated by forward slashes. Each name along the route is called a segment.

A path that begins with “/” starts at the root: it is an absolute path. /atelier/recettes/granola.txt identifies the recipe wherever you are. Without an initial forward slash, the path is relative: it starts at the current folder, meaning the folder you are in when the path is read.

Two segments have special meanings. “.” refers to the current folder itself. “..” refers to its parent, the folder immediately above it that contains it. From photos, ../recettes/granola.txt therefore goes up to atelier, then down to the recipe.

The scene follows the conventions of Unix systems, using forward slashes. It is fictional: no file on your computer is read, and other systems, such as Windows, write their paths differently. Here, “.txt” is simply part of the name; its role will be studied in the next unit.

The rule to remember

First look at the beginning: “/” means start at the root; otherwise, start at the current folder. Then read the segments in order: a name takes you down to that folder, “..” takes you up a single folder, and “.” keeps you where you are.

✿02 Follow an example

Worked example

Reaching the recipe from photos

You are in /atelier/photos. Write the shortest relative path to the recipe, resolve it segment by segment, then check the result another way. All depths count segments in the fictional tree shown in the diagram.

  1. Define the quantities and assumptions

    The depth of a folder or file is the number of named segments in its absolute path. The root has depth 0, /atelier has depth 1, and /atelier/photos has depth 2. The unit is the segment: count names, not letters.

    Let p be the depth of the current folder, q the depth of the target, and c the depth of their nearest common folder: the deepest folder that contains both the starting point and the target. These are nonnegative integers, measured in segments.

    Assumptions for this scene: each folder has a single parent, no shortcut connects two branches, names are compared letter by letter, and the target exists. If any of these assumptions fails, the following count must be reconsidered.

  2. Break down the absolute address of the target

    /atelier/recettes/granola.txt begins with “/”: start at the root. Its segments are atelier, recettes, and granola.txt, so q = 3 segments. This path does not mention photos: entering photos does not change it.

  3. Find the nearest common folder

    Compare the two addresses from the left: /atelier/photos and /atelier/recettes/granola.txt share atelier, then diverge. The nearest common folder is /atelier, so c = 1. To reach it from photos, each “..” removes exactly one segment; p − c steps up are therefore needed.

    p−c=2−1=1 remontée

  4. Go down to the target and write the path

    From /atelier, there are q − c = 3 − 1 = 2 segments left to go down: recettes, then granola.txt. Write the steps up first, then the steps down: ../recettes/granola.txt.

    The total number n of segments in the shortest relative path, measured in segments, is therefore the sum of the steps up and the steps down. The formula counts neither “.” nor detours.

    n=(2−1)+(3−1)=1+2=3 segments
    n=(p−c)+(q−c)

  5. Resolve segment by segment

    The path does not begin with “/”: start at the current folder, at depth 2. The segment “..” removes the last folder: depth 1, now in /atelier. The segment recettes adds a folder: depth 2. The segment granola.txt adds the file: depth 3.

    The destination is /atelier/recettes/granola.txt. The file opened contains the recipe, not the caption.

  6. Check in two ways

    First check: the destination depth, 3, equals q = 3, and the route passed through the common folder /atelier. Second check: the absolute path /atelier/recettes/granola.txt, read from recettes or from photos, reaches the same file because it ignores the current folder.

    Countercheck: without the parent segment, recettes/granola.txt read from photos would look for /atelier/photos/recettes/granola.txt, at depth 2 + 2 = 4. No recettes folder exists under photos: resolution fails. From /atelier, however, p − c = 0 and the same path text of 2 segments finds the recipe. The starting point is part of the relative address.

Explain it in your own words

Why does the same path text, recettes/granola.txt, open the recipe from /atelier but nothing from /atelier/photos? Explain using depths, without looking at the diagrams.

✿03 Common mistakes

  • “A file name is a complete address.”

    A name is unique only within its folder. Here, 2 files are named granola.txt and only 1 contains the recipe. Give the absolute path, or specify the current folder before using a relative path.

    Review the workshop tree

  • “Two dots take you back to the root.”

    “..” goes up a single folder. From /atelier/photos, it leads to /atelier, at depth 1, rather than the root, at depth 0. To go up further, repeat the segment; at the root, it keeps you where you are.

    Review resolution segment by segment

  • “Changing the current folder moves the files.”

    The current folder is just a starting point for reading relative paths. The recipe stays at /atelier/recettes/granola.txt; only the relative path to it changes, as the countercheck from /atelier shows.

    Review the two checks

Compare with the solution

/atelier/photos/granola.txt begins with “/”: it is absolute. Its segments are atelier, photos, and granola.txt, giving 3. It identifies the photo caption regardless of the current folder.

photos/granola.txt is relative: it has 2 segments and starts at the current folder. From /atelier, at depth 1, it reaches depth 1 + 2 = 3, at /atelier/photos/granola.txt: the same caption. Neither path leads to the recipe.

Check your reasoning

  • Count the names without counting the slash for the root.
  • Identify the file reached, rather than giving only its name.

Hint 1

Find the nearest common folder for /atelier/recettes and /atelier/photos/granola.txt.

Hint 2

Steps up: p − c. Steps down: q − c.

Absolute path: /atelier/photos/granola.txt, valid from any current folder.

A misleading path

You are in /atelier/recettes. A message tells you: “your recipe is at ./../photos/granola.txt”. Resolve this path, recording the depth after each segment, identify the file reached, then explain in two sentences why sending only “granola.txt” would not let someone else reopen the correct file.

The segment “.” does not change the depth.

Hint 2

The path is relative and has 4 segments. Start: depth 2. “.” keeps you where you are: 2. “..” goes up to /atelier: 1. photos goes down: 2. granola.txt reaches the file: 3.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Where does a path that begins with “/” start, and does it depend on the current folder?

It starts at the root. It identifies the same file regardless of the current folder.

Recall 2Where does a relative path start?

At the current folder. The same path text can lead somewhere else, or nowhere, if the current folder changes.

Recall 3What do “.” and “..” do during resolution?

“.” keeps you where you are. “..” goes up a single folder to the parent, without going above the root.

Recall 4Why is “granola.txt” alone insufficient in the workshop?

This name exists in recettes and in photos. Without an absolute path or a current folder, you do not know which file to open.

Recall 5How do you find the number of “..” segments in the shortest relative path?

The depth of the current folder minus the depth of its nearest common folder with the target.

Reconstruct the reasoning

A file name exists only within a folder. An absolute path starts at the root; a relative path starts at the current folder. Resolve it segment by segment: a name goes down, “..” goes up a folder, and “.” keeps you where you are. For the shortest route, go up to the nearest common folder, then down to the target; the destination depth must equal the target depth.
