✿01 See the idea

Will the dispenser take rice from the jar? It has 300 g of rice and receives an order requiring 300 g. Before taking any rice, it must answer a simple question: is there enough in stock? If there is enough, it prepares the order; otherwise, it refuses and keeps the rice.

This question is a condition: an expression that gives a truth value here. Python writes True for true and False for false; these are values of the bool type, called Boolean, with no unit of mass. Comparing the quantities does not remove a single grain. A branch is the group of instructions chosen according to this answer.

Saying “at least the required amount” includes the case where there is exactly enough. Our stock of 300 g therefore qualifies. With 299 g for the same required amount, it would be 1 g short: refusal would be the expected answer, with no program failure.

All quantities in this scene are fictional. We count rice in whole grams and people in nonnegative whole numbers. The portion size is fixed; the stock does not change between the comparison and the decision. Each case starts again with its own initial stock. We calculate what the program specifies; we do not control any real device.

The rule to remember

Compare first; execute only the chosen block. The test “stock >= besoin” accepts equality. Refusal preserves the entire initial stock.

✿02 Follow an example

Worked example

The order that exactly empties the jar

The initial stock is 300 g. The order requires 75 g per person for 4 people. Let us find the required amount, the test result, the chosen branch, and the stock after the decision. Each operation concerns this order alone.

  1. Name what the program receives and calculates

    stock denotes the mass initially available, in grams. personnes is the number of people, counted in people; dose is the mass of rice allocated to each person, in grams per person. These names hold integers in our scene. Writing stock = 300 gives the variable stock the value 300; the unit g is our convention for reading it and is not added to the number in the code.

    besoin will be the required mass, in grams. apres will be the mass remaining after the decision, also in grams. statut will hold text, either “préparé” (prepared) or “refusé” (refused). The names apres and statut describe the model’s results; stock will keep its initial value here to make checking easier.

  2. Calculate the required amount before choosing

    Each person requires the same portion. We therefore multiply the portion size by the number of people, using the instruction besoin = dose * personnes. The asterisk * is Python’s multiplication sign. The symbol = assigns the result to besoin: it does not ask a question.

    75 g/personne×4 personnes=300 g

    We can now compare stock and besoin: they are expressed in the same unit. Comparing a mass with a number of people without calculating the required amount would not have the intended meaning.

  3. Read the test and handle equality

    The expression stock >= besoin reads “the stock is greater than or equal to the required amount”, or “there is enough stock”. >= includes equality; > requires strictly more; < means strictly less. To ask whether values are equal, we use ==. These comparisons give True or False without assigning new values to the variables.

    300≥300: vrai, donc True

    Equality is sufficient under our rule. True is not a quantity of rice: it is the answer to the question. The jar still contains 300 g just after the test.

  4. Follow the block introduced by if

    The Python keyword if introduces the conditional choice. On the first line of the choice, write if stock >= besoin followed by a colon. This sign ends the header and introduces a block. A block groups the instructions that depend here on the same choice.

    On the next line, move the start 4 spaces to the right and write apres = stock - besoin. On the following line, at the same indentation, write statut = "préparé" (the string means “prepared”). This spacing is called indentation: Python uses it to recognize the instructions in the block. The minus sign - performs subtraction; quotation marks surround the text assigned to statut.

    The test is True: these instructions execute. We subtract because this branch represents preparing the whole order. The calculation gives 300 − 300 = 0 g, then statut receives the text “préparé”, meaning prepared. These assignments do not establish that any physical weighing has taken place.

  5. Mark out the other branch with else

    Aligned with if, write else followed by a colon. else means “otherwise”: this block is chosen when the if test is False. Under this header, with the same indentation of 4 spaces, put apres = stock; on the next line, at the same indentation, put statut = "refusé" (the string means “refused”).

    In our equality case, the else block is skipped. Execution reaches this part of the program but does not execute its instructions. For this if/else choice, only 1 branch executes. The refusal block copies the initial stock into apres because no rice is taken.

  6. Check the result and the boundary for refusal

    Mass check: the order accounts for 300 g and the remainder is 0 g; 300 + 0 = 300 g. Adding them gives back the starting stock. The remainder is nonnegative: the comparison allowed a subtraction that leaves a nonnegative mass.

    Now start again with 299 g, keeping the required amount at 300 g. The stock is 1 g short: stock >= besoin gives False. The else block then preserves 299 g. Carrying out 299 − 300 = -1 g anyway would break the rule: this subtraction belongs only to the block chosen when there is enough.

  7. Check the conventions at the limits

    With > in place of >=, the test would be false at equality: this variant would refuse and keep 300 g instead of preparing the order and leaving 0 g. A program can therefore be correctly written while applying a rule that does not suit the order.

    With 0 people and 0 g in stock, the required amount is 75 × 0 = 0 g. The test 0 >= 0 is true and the remainder is 0 g. Our convention accepts an empty order: “préparé”, meaning prepared, does not establish that any rice was taken in this case. Requiring a nonempty order would need an additional rule, beyond the present choice.

Explain it in your own words

Hide the steps. Describe the order’s path, naming the question, the chosen block, and the assignments. Why is the jar not already empty when the test gives True? Then explain what changes when the stock is 1 g short.

✿03 Common mistakes

  • “At the boundary, > and >= are equivalent.”

    Repeat the test with 300 g available and 300 g required. There is exactly enough: >= gives True, > gives False. Repair the choice by translating “at least” into >=, without adding an arbitrary margin.

    Review the boundary diagram

  • “The else block always executes after the if block.”

    Reread the headers at the same margin. The test selects either the block under if or the one under else. Then identify each indented line: an instruction back at the left margin after the blocks is no longer protected by this choice.

    Find the block boundaries again

  • “False means that my program has failed.”

    For 299 g available against 300 g required, False is the correct answer to “is there enough?” Refusal is expected and preserves 299 g. Look for a program error if the required amount is subtracted from the stock anyway, rather than because the order is refused.

    Check the order with insufficient stock

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does stock >= besoin produce, and what does this comparison change in the jar?

It produces True or False, a truth value with no unit of mass. The test alone does not change any quantity. The instructions in the chosen block then calculate the remainder.

Recall 2Why must the dispenser use >= rather than >?

The rule accepts exactly enough: 300 g for 300 g must give True. >= includes equality; > rejects it. This is a difference in the rule, even if the quantities are close.

Recall 3What happens to the other block when an if/else chooses its branch?

If the test is True, the if block executes and the else block is skipped. If the test is False, only the else block executes. Only 1 branch of this choice is followed.

Recall 4How does Python recognize which instructions depend on the choice?

The header ends with a colon; the instructions in the block are indented by the same amount. if and its else are aligned. A line at the left margin after the blocks no longer belongs to their conditional instructions.

Recall 5What is the difference between = and ==? Why is False not a failure?

= assigns a value to a name; == compares values and answers True or False. False can be the correct answer to a question: when there is not enough rice, the refusal branch is the intended behavior.
