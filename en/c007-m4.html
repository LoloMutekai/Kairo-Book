Environments

Your goalIdentify the tool actually selected and its components to explain why the same granola recipe sheet can be processed in one workshop and blocked in the other.

Before you start

✿01 See the idea

The granola recipe sheet is waiting at /atelier/recettes/granola.csv. You want to turn it into a formatted document. In software workshop A, the recette program finds what it needs. In workshop B, the program with the same name cannot find the page layout component. Yet the input file has not moved.

A working environment here is the set of tools and components available to carry out this task. A component is a piece of software used by a tool. When the tool needs it to work, that component is a dependency. The CSV reader can read our text table; the page layout component can arrange its content on the final sheet.

The current directory tells us where the terminal is when interpreting relative paths. It is not enough to tell us which program the name recette will call. To find out, we need to look at which directories the terminal searches for tools, then record the path of the program actually selected.

This entire setup is fictional: the recette program, its options, its paths, and its components were invented for this page. The commands shown are to be read on paper; no installation or execution is requested. We are comparing stated environments, without taking measurements on a real computer.

The rule to remember

Keep the file; identify the selected tool; compare the required components with the components present; then check the result of the work.

✿02 Follow an example

Worked example

Identify the tool before fixing page layout

The current directory remains /atelier and the file remains /atelier/recettes/granola.csv. A’s tool is /atelier/env-A/bin/recette; B’s is /atelier/env-B/bin/recette. Each requires the CSV reader and page layout. A has the 2 components; B has only the CSV reader. We want to find out why the same command text can lead to different results.

  1. Establish what we are comparing

    The file contains the granola recipe sheet as a text table. Its content, its path, and the current directory are identical in every comparison. The recette programs in A and B are assumed to be executable: this means the system can launch them. We are comparing neither real versions nor execution times.

    In this setup, the name recette refers only to these programs. The search goes through the stated directories in order and selects the first recette program found. It does not select the one with the most components. This rule applies only to this scene; it does not describe every possible terminal situation.

  2. Go from the name to the actual path

    Resolving a name here means finding the path of the program it refers to. The command -v recette request displays what the terminal would select for that name. It does not perform page layout. With /atelier/env-B/bin searched before /atelier/env-A/bin, the expected answer in our setup is /atelier/env-B/bin/recette.

    If the order is reversed, the expected path is /atelier/env-A/bin/recette. We have 1 tool path in A and 1 in B: 1 + 1 = 2 possible paths in this setup. The shared name recette is therefore not enough to identify the program. A path identifies the selection here; on its own, it does not certify the exact version of its content.

  3. Inspect components by name

    The fictional --inspecter option asks the recette program to describe its components without producing a sheet. The recette --inspecter command is assumed to return an accurate and complete inventory for the selected tool. For A: CSV reader present, page layout present. For B: CSV reader present, page layout absent.

    Match each required component with its status in the workshop being inspected, then count only the required components actually present. This precaution justifies the calculation that follows: a component unrelated to the task cannot replace page layout in the count. No component is counted more than once.

  4. Calculate how many are missing, then name what is missing

    R stands for the number of required components; P, the number of those components present in the workshop being considered; M, the number of required components missing. These are whole-number counts, measured in components. The value of P changes depending on the workshop. The letters are abbreviations to help read the calculation, not code to be programmed.

    M=R−P

    Why subtract? Each required component is either present or missing in this inventory. Removing the present components from the count of all required components leaves the missing ones. This rule assumes that the inventory correctly distinguishes the names and that nothing has changed during the inspection.

    Atelier A : 2−2=0 composant manquant
    Atelier B : 2−1=1 composant manquant

    In B, the missing component is page layout. The number alone signals that something is missing; its name tells us what to examine. Moving the granola file does not supply this component.

  5. Check the calculation and the scope of its conclusion

    Check by putting the counts back together: present and missing components must add up to all required components. For A: 2 + 0 = 2 required components. For B: 1 + 1 = 2 required components. We get 2 in each case.

    Check by name: A’s list leaves no required component unmatched. In B’s list, only “page layout” remains unmatched. This second method prevents us from mistaking a correct total for a correct match between components.

    Our fictional processing rule is explicit: if all required components are present, the recette recettes/granola.csv command produces the sheet; otherwise it refuses and names what is missing. It therefore predicts a sheet produced in A and a refusal in B. In a real workshop, 0 missing components at inspection would demonstrate neither successful execution nor a correct document: the input could be invalid, or the program could encounter another error.

  6. Prepare a replay sheet that preserves the useful context

    A replay sheet describes how to repeat the same work. Here it records the directory /atelier, the file /atelier/recettes/granola.csv, the selected workshop, the search order, the path returned by command -v recette, the inventory returned by recette --inspecter, and the command recette recettes/granola.csv. It distinguishes the predicted result from the result actually observed.

    To compare B then A on paper, keep the file and directory; change the stated search order, then record the path and inventory again. The component missing from B explains the refusal in our model. Switching to A predicts that a sheet will be produced without moving the recipe. On a machine, we would still need to check that production and its content before reporting success.

Explain it in your own words

Hide the example. Explain why B can be selected even though A is better equipped. Then reconstruct the calculation of how many components are missing and the check by name. Finish by saying what would still need to be observed before reporting that a sheet has actually been produced.

✿03 Common mistakes

  • “I am in the right directory, so I am using the right tool.”

    The directory /atelier locates the file, but the workshops provide distinct tools. Record the resolved path of recette. Then compare its components with those the task requires; the current directory does not answer these questions.

    Review the shared file and the environment boxes

  • “The name recette guarantees the same tool and the same version.”

    The same name leads to 2 possible paths here. Repeat the resolution using the stated search order. The path proves the selection in this setup; for a real version, we would need more information about the tool’s content.

    Review the step from the name to the actual path

  • “A component has been installed, so my command will use it.”

    You need to know which environment has the component available and which tool the command selects. If B remains selected with the same inventory, the presence of page layout in A does not fill the gap in B. Then check the result of the work separately.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does an environment contain in the granola scene? Why is the current directory not enough to describe it?

The tools and components available for the task. The current directory locates relative paths; it does not say which recette tool will be selected or which components that tool will find.

Recall 2Why can the name recette lead to different tools? What does command -v recette tell us here?

The workshops provide the same name in distinct directories. The search selects the first program found in the stated order. The request displays the selection; it does not produce the sheet.

Recall 3What is a dependency, and how can you work out what is missing from B without reciting its count?

A component the tool needs. Compare each required component with B’s inventory: CSV reader present, page layout absent. Count the required components without a match, then check by combining the present and missing components.

Recall 4What must you keep to compare B then A without moving the sheet?

The same file and directory; for each case, the search order, the path actually selected, the inspected components, and the command. Separate the expected result from the observed result: a complete inspection does not prove successful production.
