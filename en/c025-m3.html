Sorting

Your goalSort a list of cards by duration, work through an insertion sort, and check that the cards and the relative order of ties are preserved.

Before you start

✿01 See the idea

You are preparing the files for a workshop. Each card has a letter and an estimated duration: A, 8 min; B, 3 min; C, 5 min; D, 3 min. These durations are fictional. The cards arrive in the order A, B, C, D. To consult the shortest files first, you want to arrange them in increasing order of duration.

Sorting changes positions without changing what is on the cards. The sort key is the information being compared: here it is the duration, rather than the letter. Increasing order means that the duration does not decrease as you move along; equal durations can follow each other. The result is B, D, C, A, with durations 3, 3, 5, 8 min.

How can you do this without guessing the whole row? Keep a small sorted block on the left. Take the next card, set it aside, then shift the cards in that block with longer durations to the right. Insert the card into the space left open. This is insertion sort.

B and D have the same duration. We add a rule: when durations are equal, keep the cards in their order of arrival. A sort that preserves this relative order is called stable. This choice leaves B before D; increasing order of duration alone would also allow D before B.

The rule to remember

Take a card, shift only the cards with strictly greater keys, then insert it. Check the order of the keys, the preservation of the cards and, if required, stability.

✿02 Follow an example

Worked example

Sort the files while keeping ties in order

Starting list: [A: 8 min; B: 3 min; C: 5 min; D: 3 min]. The letters identify distinct cards. The key is numeric, known, and unchanged during sorting. A stable sort in increasing order is required. We will count duration comparisons and card shifts without using them to infer an execution time.

  1. State the contract and define the notation

    T denotes the list; n is its number of cards, here 4. T[j] is the card at index j. Indices are integers without units, counted from 0. k(F) is the duration of card F, in minutes. The symbol ≤ means “less than or equal to”. A sorted list must satisfy:

    k(T[j])≤k(T[j+1])

    This condition applies to every adjacent pair, from j = 0 to j = n − 2, when the list contains at least 2 cards. Every original card must also appear exactly once, with its duration. Stability additionally requires cards with the same key to stay in their initial order. The keys must be comparable according to a consistent rule; missing durations are not considered here.

  2. Describe a repeatable pass

    p is the number of cards already sorted at the start of a pass. The prefix, meaning the block on the left of length p, is sorted; initially p = 1, because card A alone is enough. Set the next card x = T[p] aside and set j = p − 1 to examine the prefix from right to left.

    While j ≥ 0 and k(T[j]) > k(x), copy card T[j] into position T[j + 1], then decrease j by 1. Check the bound j ≥ 0 first to avoid reading outside the prefix. When the loop stops, write x into T[j + 1]. Increase p by 1 and repeat while p < n.

    The copy is a shift to the right, rather than a swap with x. Saving x before copying prevents its loss. The sign > is strict: a card with the same duration is not shifted to make way for the new one. We will count only the duration comparisons actually performed, including the one that stops the shifting; bound checks are not counted. The final write of x is not counted as a shift.

  3. Insert B into the prefix A

    Set B aside. Compare 8 > 3: this is true, so shift A to the right. The prefix is exhausted; there are no more durations to compare. Insert B at the beginning.

    The list becomes [B: 3; A: 8; C: 5; D: 3], in minutes. The prefix [B, A] is sorted. B required 1 duration comparison and 1 shift.

  4. Insert C without redoing the beginning

    Set C aside. In the prefix [B, A], first compare 8 > 5: true, so shift A. Then compare 3 > 5: false, so keep B in place and insert C immediately after B.

    The list becomes [B: 3; C: 5; A: 8; D: 3]. The prefix [B, C, A] is sorted. This pass required 2 comparisons and 1 shift. Since the start, that makes 1 + 2 = 3 comparisons and 1 + 1 = 2 shifts.

  5. Insert D and handle equality

    Set D aside. Compare 8 > 3: true, shift A. Compare 5 > 3: true, shift C. Compare 3 > 3: false, because 3 = 3. B therefore stays in place; insert D between B and C.

    The result is [B: 3; D: 3; C: 5; A: 8]. This pass required 3 comparisons and 2 shifts. In total: 3 + 3 = 6 comparisons; 2 + 2 = 4 shifts. These counts are measured in operations, rather than minutes.

  6. Check the result in other ways

    Order: 3 ≤ 3 ≤ 5 ≤ 8, in minutes. Preservation: the letters A, B, C, D each appear once, with their initial durations. Stability: B preceded D and still comes before it. The total duration is preserved:

    (8+3)+(5+3)=11+8=19 min

    After sorting, 3 + 3 + 5 + 8 also equals 19 min. This sum is an additional check; it does not replace checking identities, because other values could have the same total.

    Check the shifts separately using the pairs initially in the wrong order: A before B, A before C, A before D, and C before D. There are 4 such pairs. In this insertion sort, each shift resolves exactly one such pair without creating a new one. The pair B, D, whose keys are equal, is not included.

  7. Explain why the procedure terminates with the correct result

    The invariant is the contract preserved between passes: the prefix is sorted stably and contains exactly the cards from the beginning that have already been processed. It holds for A alone. Inserting x after the cards with smaller or equal keys and before those with greater keys extends the prefix without losing any cards; the rest of the list awaits its turn.

    Within a pass, j decreases until it reaches a sufficiently small key or the left bound. Between passes, p increases until it reaches n: here there are n − 1 = 3 insertions. At the end, the prefix occupies the whole list. If the list is empty or contains 1 card, no pass is needed. The resulting count describes this input; it gives neither a machine execution time nor a general cost rule.

✿03 Common mistakes

  • “I sort the durations; the letters can stay where they are.”

    The duration belongs to a card. Keeping A first and assigning it 3 min would change the data. Always move the whole card, then check every letter–duration association.

    Revisit the contract and the identity check

  • “Sorting forbids duplicates, so I can remove D.”

    B and D are distinct cards with the same key. Sorting keeps both of them; removing a card would be filtering. The sign ≤ allows equality, and stability specifies their order.

    Review the cards with the same duration

  • “Shifting when durations are equal makes no difference.”

    The durations remain in increasing order, but B would be shifted when D arrives. D would then come before B. Using ≥ instead of > destroys the stability required for this input.

    Examine the sort that moves tied cards

Key order: 3 ≤ 3 ≤ 5 ≤ 8, so this check passes. Preservation: every letter appears once with its duration; this check also passes, as does the total of 19 min. But B preceded D in the input and now comes after it: stability fails.

When inserting D, the test 3 ≥ 3 is true, so B is shifted in turn and D takes the position before it. Restore > to move only cards with strictly greater keys. The result is then [B, D, C, A]. The defect is demonstrated by the order of the letters, rather than by a difference between equal durations.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1Which properties should you check after sorting the files?

Adjacent durations must be in nondecreasing order, every card must remain present with its duration and, if the contract requires it, ties must keep their relative order of arrival.

Recall 2What do you know about the block on the left before each insertion?

It is already sorted stably and contains exactly the original cards already processed. Set the next one aside, shift the cards with greater keys to the right, then insert it.

Recall 3Why use > rather than ≥ for shifts?

A card with the same duration must stay before the new card. Shifting on equality would reverse their relative order and could destroy stability.

Recall 4Why set x aside before shifting the cards?

The first copy to the right may overwrite the position holding x. Saving it preserves the card to be inserted; write it back into the open space after the shifts.

Recall 5What do the 6 comparisons and 4 shifts tell us about our input?

They count operations according to a precise convention: duration comparisons actually evaluated and shifts to the right, excluding bound checks and final writes. They give neither a machine execution time nor a general cost rule.
