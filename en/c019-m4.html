Level 1 · C019·M4

Queues and saturation

Your goalTrack requests in a queue, calculate the waiting time that builds up, and explain how a limit on queue slots affects saturation.

Before you start
c016-m5 : documentation · c007-m5 : execution traces · c012-m5 : counterexamples · c019-m1 : processes and memory space · c019-m2 : threads and races · c019-m3 : locks and semaphores

✿01 See the idea

At a community centre, people send their documents to the same printer. Instead of competing for the machine, their requests wait in a queue: a list where new requests are added at the end and the oldest request is taken to start the work. The order “first in, first out” is often called FIFO. Being taken from the queue and having finished printing remain separate events.

In our fictional scene, 5 requests arrive at the start of each 60 s interval. The printer can complete 3 during that interval. Before the first batch is sent, 2 requests are already waiting. Before calculating anything, predict the direction of change: the printer can work without a break and still leave more and more requests behind.

A queue absorbs a difference in timing between submission and processing. If arrivals exceed processing capacity over a sustained period, the excess builds up as long as every request is accepted. This is sustained overload. A bounded queue also has storage saturation: it is full and a new request can no longer enter under the usual rule.

The diagrams follow the same printer. We first count with enough slots to accept everything, then replay the same submissions with a limit of 8 waiting requests. All the data are invented for the calculations; no actual machine throughput is measured here.

The rule to remember

In each interval, distinguish requests offered, admitted, completed, and rejected. An extra waiting slot does not create extra processing capacity.

✿02 Follow an example

Worked example

The printer queue, then bounded admission

Let us replay 2 intervals of 60 s, with 2 requests at the start, 5 new ones per interval, and a capacity of 3 completed print jobs per interval. We first accept everything, then add the limit of 8 slots, rejecting new requests that do not fit.

  1. Set the observations and assumptions

    All requests take the same time to process. The printer processes only one at a time, without a break when work remains, and without breakdowns or cancellations. Each batch arrives in full at the start of the interval, before processing begins. Nothing arrives between batches; the order within a batch is fixed.

    Q is the number of requests waiting just before the current batch; Q′ is the number left at the end of the interval. The prime means “after this interval”. No work is in progress at our interval boundaries: each print job finishes before or exactly at the boundary. We therefore never count a request in progress as a request still in the queue here.

    A counts requests offered in the batch; E counts those admitted; R counts those rejected; D counts those actually completed during the interval. C is the maximum number of requests that can be completed in that interval. All these quantities are counts of requests. T is the interval duration, in seconds. Here A = 5, C = 3, and T = 60 s. The duration of a print job is T/C = 20 s per request.

  2. Count the first interval without rejection

    Add the batch to the older requests, since they are all waiting their turn: 2 + 5 = 7 requests available. The machine completes 3, leaving 7 − 3 = 4. Subtraction means removing requests that have actually been completed.

    Q′=Q+E−D

    This conservation rule applies with or without a limit. Without rejection, E = A. Actual processing exceeds neither the available work nor the capacity: D = min(C, Q + E), where min means “the smallest of the numbers given”. Here there is enough work, so D = C.

  3. Use the remaining count and diagnose overload

    In the second interval, the starting count is 4, rather than 2. With enough slots still available, the batch gives 4 + 5 = 9 requests; after processing, 9 − 3 = 6 remain. The queue grows by A − C = 5 − 3 = 2 requests per interval as long as everything is accepted and the machine has enough work.

    To compare over the same duration, A/C = 5/3, or approximately 1.67 with no unit, is greater than 1. This ratio compares offered demand with capacity; it is neither a probability nor the printer’s actually observed fraction of time spent working. If these batches repeat indefinitely without rejection, the remaining work grows indefinitely in our model.

    The case A = C would not reduce an existing queue in this regular model. Clearing the backlog requires processing capacity to exceed admitted requests. With irregular arrivals or varying durations, comparing averages alone cannot guarantee a delay.

  4. Replay with a limit on slots

    B now denotes the maximum number of waiting requests, with 0 ≤ Q ≤ B and B = 8 requests. The chosen rule rejects excess new requests, keeps older ones, and does not retry automatically. All admission takes place before the batch is processed.

    E=min(A,B−Q);R=A−E

    The first interval fits in full: 7 ≤ 8, so the remaining count is still 4. Before the next batch, only B − Q = 8 − 4 = 4 slots are free. Of the 5 offered requests, E = 4 enter and R = 5 − 4 = 1 is rejected.

    Before processing, the queue reaches 8 requests. After the 3 completed print jobs, Q′ = 8 − 3 = 5 requests. This remaining count replaces 6 in the calculation without rejection: the paths diverged at admission, rather than during printing.

  5. Check that every request has a state

    Over the 2 intervals, there were 2 requests at the start and 2 × 5 = 10 new ones, giving 12 requests to account for. The machine completed 2 × 3 = 6 requests. Without rejection: 6 completed + 6 waiting = 12.

    With the limit: 6 completed + 5 waiting = 11 requests admitted in total, including the initial ones. Adding 1 rejected gives 12 = 12 again. A rejected request was neither printed nor left in this queue.

    The limit applies to the queue before printing starts, rather than just to the final remaining count. Real producers may submit while a consumer removes a job and executes it. The moments when slots become free then matter: our batch calculation does not replace that sequence of events.

  6. Choose what happens when the queue is full

    Our rejection rule allows the sender to be told that the request was not admitted. Another rule could make the sender wait until a slot becomes free; this slows submission only if the sender actually waits. You must then check that the sender is not holding a lock needed by the consumer. A replacement rule could instead remove an older request to accept the new one: that would be a different contract, which must be stated and accounted for.

    The limit bounds the number of stored requests; it guarantees a memory limit in bytes only if request size is also bounded. It does not promise more completed print jobs per interval. Immediately retrying rejected requests can even increase the offered load.

    A useful trace therefore distinguishes admission, the start and end of processing, and any rejection. Removing a request from the queue frees a slot, but does not by itself prove that the document has been printed.

Explain it in your own words

Reconstruct the counts without rereading the operations. Why might a queue have rejected a request even though its final remaining count is below its limit? Then explain when removal becomes a completed print job under our assumptions.

✿03 Common mistakes

  • “A larger queue will make printing faster.”

    The limit B measures storage in requests; C measures the number that can be completed during an interval. Adding slots changes admission and waiting, without changing C. Replay the expansion in the last exercise and observe rejection returning.

    Compare the small and large queues

  • “You only need to subtract capacity each time.”

    Capacity is a maximum. If the queue provides only 2 requests, the printer cannot complete 3. Use D = min(C, Q + E) before calculating what remains; the count must never become negative.

    Reconstruct conservation and actual processing

  • “The queue stays the same size, so everything is fine.”

    A bounded queue can remain stable because it rejects the excess. Distinguish offered requests from admitted ones and check the balance that includes rejections. Even a removed request may be in progress or may have failed; look for actual completion of processing.

    Revisit the balance with rejected requests

Exercise 1 · Direct application

The machine can do more than arrives

The same printer starts with Q = 0 requests, receives only A = 2 requests, and keeps C = 3 over 60 s, with B = 8. Give E, R, D, and Q′. What does the unused capacity represent?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

First count the requests available after admission. There are enough slots.

Hint 2

D is the smaller of the capacity and the number of requests present.

Compare with the solution

All requests enter: E = 2 and R = 0. The stored count is 0 + 2 = 2 requests. So D = min(3, 2) = 2 completed requests.

Q′ = 2 − 2 = 0 requests. The difference C − D = 3 − 2 = 1 represents an unused processing opportunity over this interval; it does not correspond to a request that disappeared.

Check your reasoning

  • Distinguish C, the maximum capacity, from D, the number actually completed.
  • Obtain no remaining requests, without inventing a print job or a rejection.
  • Check Q + A = D + Q′ + R in requests.

Exercise 2 · Replay and delay on paper

The next batch and its last admitted request

Start again from Q = 5 requests, with no work in progress, B = 8, A = 5, and C = 3. Calculate the free slots, E, R, and Q′. Then follow the last new request admitted: how long does it wait before starting, and how much time passes until it finishes? Each print job takes 20 s; no job moves ahead of it.

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

Calculate B − Q before deciding how many new requests can enter.

Hint 2

After admission, count the requests ahead of the last one; that request itself is not part of its wait before starting.

Hint 3

Multiply this count by the duration of a print job. For the time until completion, add its own processing time.

Compare with the solution

Accepting everything would require 5 + 5 = 10 slots. Only 8 − 5 = 3 remain. So E = 3 and R = 5 − 3 = 2. After admission followed by processing, Q′ = 5 + 3 − 3 = 5 requests.

The final stored count equals the starting count, despite 2 rejections. The balance for this interval reveals this: 10 initial or offered requests = 3 completed + 5 still waiting + 2 rejected.

The full queue contains 8 requests before processing starts; the last one has 8 − 1 = 7 ahead of it. Its wait before starting is 7 × 20 = 140 s. It finishes after 140 + 20 = 160 s, measured from its admission.

These durations exceed 60 s: this request will therefore remain for later intervals. New batches will join behind it. With different durations, a print job already in progress, or a change in order, this multiplication would no longer give its waiting time directly.

Check your reasoning

  • Exclude rejected requests from admitted requests before calculating what remains.
  • Show that a stable stored count can hide rejections.
  • Separate the wait before starting from the time until completion.
  • Relate the calculated delay to the assumptions of equal durations and processing order.

Exercise 3 · Transfer and objection

More slots: is saturation resolved?

Start again from Q = 5 requests, but increase B to 10. Batches remain at 5 and the machine still completes at most 3 requests per interval. Calculate the remaining count and rejections for the next 2 intervals. Respond to “we have enlarged the queue, so the problem is solved”. Finally, starting from the last remaining count, what happens with a batch reduced to 2 requests?

Rate your confidence before comparing

Assisted answer: try this exercise without help later.

Hint 1

The first batch fits exactly within the new limit. The remaining count becomes the starting count for the next interval.

Hint 2

For the next batch, compare the requested storage with the limit, then count rejections and completed print jobs separately.

Hint 3

To reduce the stored count, compare new admissions with the number actually completed.

Compare with the solution

The new limit is 8 + 2 = 10 slots. In the first interval: 5 + 5 = 10 requests, all admitted without rejection; after processing, 10 − 3 = 7 remain.

In the next interval, 7 + 5 = 12 slots would be needed. The limit allows only 10, so 12 − 10 = 2 requests are rejected. The remaining count is 10 − 3 = 7 requests.

The larger limit delayed rejection without increasing processing capacity. At the end of the intervals, it retains more requests than the old limit: 7 instead of 5. More waiting has been allowed; the printer has not been made faster.

Reducing the next batch to 2 gives 7 + 2 = 9 requests, which all fit. After processing, 9 − 3 = 6 remain. The decrease is 3 − 2 = 1 request per interval as long as these conditions and enough work are maintained. This is a real reduction in submissions, rather than rejected attempts that would return immediately.

Check your reasoning

  • Use the remaining count from the first interval for the second.
  • Find rejections despite the new limit.
  • Explain the effects on storage, completed processing, and waiting separately.
  • Identify why actually reducing submissions allows the backlog to be cleared here.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What does a queue hold, and what does its first in, first out order guarantee?

It holds requests awaiting handling. Adding at the end and removing the oldest fixes the order of handling; removing a request does not yet demonstrate that its processing is complete. With our printer, completion of printing must then be checked.

Recall 2How can you find the remaining count Q′ without inventing print jobs?

Define E, the number admitted, then D = min(C, Q + E), the number that can actually be completed. The remaining count is Q′ = Q + E − D. The quantities count requests over the same interval; C is a maximum.

Recall 3For our batch admission with rejection of new requests, where do E and R come from?

With 0 ≤ Q ≤ B, there are B − Q slots left before processing. E = min(A, B − Q) requests enter; R = A − E are rejected. The limit bounds storage without increasing capacity C. Older requests are kept.

Recall 4Why does a stable final stored count fail to prove that all requests are served?

Bounded admission can reject the excess. Compare the starting requests and offered requests with those completed, still waiting, and rejected. Looking only at queue size hides rejections and does not check processing results.

Recall 5When can waiting time be calculated as number of requests ahead × duration of a print job?

When the printer is initially free, works without a break in the stated order, and all durations are identical, with no job moving ahead. The product gives the time before starting. Add the duration of the request’s own print job to obtain the time until completion.

Reconstruct the reasoning

Without looking at the formulas, reconstruct a request’s path: offer, admission or rejection, waiting, handling, completion of processing. Then reconstruct the balance of counts and explain why expanding storage does not change the printer’s throughput. Finish with the assumptions that allowed its waiting time to be calculated.
