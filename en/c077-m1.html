Level 2 · C077·M1

Sample, frequency and PCM

Your goalRelate the sampling instants of a recorded sound to its PCM codes, then check its byte count without confusing rate, amplitude and duration.

Before you start
c027-m5 : complex numbers · c011-m5 : binomial · c036-m5 : annotated graphs · c021-m5 : origin, authentication and authorization

✿01 See the idea

A small bell rings in front of a microphone. For 1.5 s, the recorder regularly takes a reading of the electrical signal produced by the microphone. Imagine a notebook where each line holds a reading at the next instant: the order of the lines matters as much as the values.

A sample is a value taken at an instant, for a channel. A channel is a sequence of readings, for example those from a microphone. The sampling rate indicates how many instants are recorded per second and per channel. Here, 16000 Hz means 16000 readings per second on our channel. This number does not say how many times the bell vibrates per second: the frequency of the sound describes its oscillations, while the sampling rate describes the rate at which the recorder takes readings.

The converter then chooses, from the available amplitude levels, the one that represents each reading: this is quantization. Its code is an integer. PCM stands for pulse code modulation: in our case, these codes are stored at a fixed width, without compression. Time is discretized by the sampling instants; amplitude is discretized by the coding levels.

The bell, values and duration are fictional. The drawing enlarges only the first 4 codes so they can be read. No sound is loaded or played; we are checking its digital representation, not the fidelity of a real recording.

The rule to remember

The rate determines the spacing of the instants; the bit depth determines the possible codes; the channels multiply the values to store at the same instant.

✿02 Follow an example

Worked example

How many bytes for our bell?

The fictional ringing is recorded for T = 1.5 s, at fₛ = 16000 Hz, with C = 1 channel and b = 16 bits per signed integer code. The first codes are 0, 4096, 0, -4096. Let us calculate the sampling instants, the number of codes and their raw size, then recover the duration.

  1. Define the format contract before counting

    fs is the sampling rate, in Hz, meaning instants per second and per channel. T is the duration in seconds. C is the number of channels, with no unit. b is the code bit depth, in bits per sample. A bit takes either the value 0 or 1; a byte groups 8 bits. Here b is a multiple of 8: no extra padding is needed.

    We assume a constant positive sampling rate, no lost samples, synchronized channels and a whole number of instants. We count raw uncompressed PCM, excluding the header and any other information. The first instant is t = 0; the recorded interval extends to T, with the final boundary excluded.

    The bytes alone do not give this whole contract. We need to know the sampling rate, channels, bit depth, whether the codes are signed, and the byte order. Under the convention used here, the least significant byte comes first: this is little-endian byte order. This convention changes how the codes are read, not their number.

  2. Place the readings on the time axis

    Δt denotes the time between successive instants, in seconds. We take the reciprocal of the rate because we want the time per instant rather than the instants per second. n is an integer index with no unit, starting at 0; tn is the corresponding instant.

    Δt=1fs;tn=nΔt

    Here the exact fraction of a second is Δt = 1/16000 s. Since a second contains 1000 milliseconds, Δt is 0.0625 ms. This is a time interval, with no direct relation to sound volume.

  3. Distinguish instants from stored values

    N denotes the number of instants per channel. We multiply the rate by the duration because each second contributes the same number of instants. A frame groups the samples from all channels at the same instant; there are therefore N frames, but N × C amplitude codes.

    N=fsT=16000×32=24000

    N is indeed an integer: our assumption is satisfied. With C = 1, this gives 24000 × 1 = 24000 codes. A code equal to 0 takes up as much space as any other: we do not remove the instants when the signal crosses 0.

  4. Read the amplitude without assigning it a physical unit

    qn denotes the amplitude code at index n, an integer with no physical unit. In this signed PCM using two’s complement, b bits can encode the integer range below. Two’s complement is the binary convention used here to represent negative integers in this range; we do not need to decode every bit to count the size.

    −2b−1≤qn≤2b−1−1
    216=65536 codes ; -32768≤qn≤32767

    Our codes 0, 4096 and -4096 lie in this range. Their signs indicate opposite sides of the reference level; a negative code does not mean a negative time. Without calibration of the microphone and converter, 4096 becomes neither a pressure in pascals nor a level in decibels. Quantization represents amplitudes using a finite set of levels; it does not preserve their exact analog values.

  5. Convert codes to bytes

    o is the number of bytes per code. We divide b by the number of bits in a byte: o = 16/8 = 2 bytes per code. A frame occupies C × o = 2 bytes. B denotes the total size of the PCM data alone, in bytes.

    B=NCo=24000×1×2=48000 octets

    The multiplication counts all frames, all their channels and all the bytes in each code. The raw data rate D is the size per second: D = fs × C × o = 32000 bytes/s. In bits, this gives 32000 × 8 = 256000 bits/s. Do not confuse bits/s with bytes/s.

  6. Recover the duration and check the final boundary

    Dividing the size by the data rate should give seconds. This reverse check can reveal, for example, a forgotten channel or conversion to bytes.

    T=BfsCo=4800032000=32 s

    We recover 1.5 s. The indices run from 0 to N − 1 = 23999. The last sample is therefore at t = 23999/16000 s; it precedes the boundary T by one step Δt. The exact calculation 23999/16000 + 1/16000 = 3/2 s checks this convention: the interval between the first and last instants is not the entire duration represented by N frames.

    The consistent totals are 24000 instants, 24000 codes and 48000 raw bytes for 1.5 s. They prove neither the absence of noise nor the possibility of perfectly recovering the analog sound: those questions require other assumptions.

✿03 Common mistakes

  • “The recorder’s sampling rate gives the pitch of the sound.”

    The rate indicates when readings are taken; pitch concerns the oscillations of the signal. Reread the axes of the drawing: changing amplitude values does not automatically change the time spacing. We cannot deduce the frequency of the bell from the number 16000 Hz alone.

    Review what each axis measures

  • “A PCM code of 16 bits occupies 16 bytes.”

    A byte groups 8 bits. We therefore need to divide: 16/8 = 2 bytes per code. Then start again from the number of frames and the number of channels before multiplying the sizes.

    Repeat the conversion, then the reverse check

  • “Changing the number of hertz written alongside the bytes is enough to improve the recording.”

    Reading the same list of codes at a different declared rate changes its playback duration. It receives no new readings. To represent the same sound at another rate, we need to calculate a new sequence using a suitable method; changing a label does not do this work.

Hint 1

First recover the number of codes from the bytes. Then divide by the rate actually used by the player.

Hint 2

Distinguish correcting erroneous information from producing new signal values.

Compare with the solution

The player finds 48000/2 = 24000 codes, still on 1 channel. Their playback duration becomes 24000/32000 = 0.75 s. The rate has been multiplied by 2: the same ringing is played through 2 times as fast.

Since the problem establishes that capture was at 16000 Hz, we restore that information and recover 1.5 s. This adds no samples and corrects no defects in the capture. Without reliable information about the initial rate, the size alone would not let us decide which duration is correct; the division also assumes that the channels and code format are known.

✿05 Recall from memory

Close the lesson, answer each question, then reveal the answer. Explain any missing steps in your own words.

Recall 1What is a sample, and what does a frame add?

A sample is a signal value for a channel at an instant. A frame groups the samples from all channels at that same instant. In mono, the two counts coincide.

Recall 2What does fₛ give, and how can we recover the time spacing?

fₛ gives the instants per second and per channel; Δt = 1/fₛ gives their spacing in seconds. This rate alone does not give the oscillation frequency of the sound.

Recall 3In our integer PCM, what does the bit depth determine?

It determines the number of possible amplitude codes and the width of each code. With 16 signed bits, our range runs from -32768 to 32767; each code occupies 2 bytes, even when it equals 0.

Recall 4How can we reconstruct the byte calculation and then recover the duration?

N = fₛ × T frames; each frame holds C codes of o bytes, with o = b/8 here. Thus B = N × C × o, then T = B/(fₛ × C × o). We need uncompressed PCM, complete frames and a constant rate, and must exclude headers from the count.

Recall 5Why does changing only the declared rate change the playback duration?

The list contains the same number of codes, but the player consumes a different number per second. Correcting a false rate restores its interpretation; it creates neither additional readings nor evidence of acoustic fidelity.
